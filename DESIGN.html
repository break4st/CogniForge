一、系统概述

1.1 背景

传统 AI Coding 的四大痛点：

  • 上下文不可控 — 依赖 RAG 导致信息遗漏与幻觉
  • 长周期不稳定 — 上下文窗口膨胀，后期产出质量急剧下降
  • 无流程约束 — vibe coding 模式不可复现、不可审计
  • 无法对齐企业研发体系 — 缺乏审批、评审、质量门禁
目标：构建一个「可持续运行」的 AI 软件开发系统，覆盖从需求到复盘的全生命周期。

1.2 全流程管线

PRD→ 架构→ 设计→ 编码→ 测试→ 上线→ 复盘

1.3 六大核心原则

Principle 1
文档即状态
所有系统状态持久化为结构化文档（Git），文档是唯一真相来源
Principle 2
无 RAG
上下文由确定性的 glob 规则加载，杜绝语义检索的不确定性
Principle 3
多 Agent 协作
8 个专职 Agent，每个只做一件事，职责边界清晰
Principle 4
DAG 驱动
13 步有向无环图定义执行流程，拓扑排序保证依赖正确
Principle 5
人工审批
每步执行后暂停，等待人工 approve/reject，绝不黑盒连续执行
Principle 6
全链路可审核
每次 AI 操作的输入、输出、推理过程完整记录，可追溯

审批约束

  • 每个 DAG 步骤执行后 强制暂停，等待人工审批
  • 审批通过 → advance 进入下一步；审批拒绝 → 返工后重新提交
  • 系统设计上 不允许自动连续执行多步

可审核性要求

  • 所有 AI 产物必须记录：输入上下文、Prompt、输出产物、推理过程、关键决策
  • 每条操作独立序列化为 JSON 审计日志文件
  • 审计日志包含：操作者角色、操作类型、耗时、状态、人工审核标记

八、Agent 实现设计

核心设计变更 (v2.0)：Agent 不再自己用 Python 生成文档/代码，而是委托给 Claude Code agent。 Claude Code 以 claude -p --tools Read,Write,Edit,Bash --permission-mode auto 模式运行， 拥有完整的工具链能力，可以读上下文、写文件、跑命令。

8.1 委托模式

class PMAgent(BaseAgent):
    def run(self, input_data):
        if self.agent is None:
            raise AgentError("requires Claude Code agent")
        return self._run_agentic(...)

    def _run_agentic(self, ...):
        prompt = build_task_prompt(...)          # 中文指令
        response = self.agent.generate_agentic(  # Claude Code agent
            prompt, role="pm")
        # Claude Code 自己读了 DESIGN.html、已有 PRD，
        # 生成了 HTML 并写入 .cogniforge/wiki/prd/prd-003.html
        git_stage_and_commit(output_path)

8.2 Agent Role → Claude Code Role 映射

CogniForge AgentClaude Code role系统提示词要点
PMAgentpm读 DESIGN.html + 已有 PRD → 生成自包含 HTML PRD
ArchitectAgentarchitect读 PRD + DESIGN.html → 生成 SAD 架构文档
DesignAgentdesign读 PRD + SAD → 生成 LLD 详细设计
DevAgentdev读 LLD + CLAUDE.md → 写代码 + 写测试 + 跑 pytest
ReviewAgentreviewer读 LLD + 代码 → 生成 CR 报告
QAAgentqa读 LLD + 代码 → 生成测试用例 + 跑测试 + 出报告
TechLeadAgenttechlead读全部上下文 → WBS 分解 + 质量评估
DevOpsAgentdevops读 SAD + LLD → 生成部署配置

8.3 Agent 执行流程

CogniForge Agent.run(input_data)
  ↓
self.agent.generate_agentic(prompt, role="pm")
  ↓
subprocess: claude -p "prompt" \
  --tools Read,Write,Edit,Bash \
  --permission-mode auto \
  --append-system-prompt "你是 PM Agent..." \
  --output-format json
  ↓
Claude Code agent:
  ├─ Read DESIGN.html          # 了解视觉风格
  ├─ Read 已有 PRD 文件         # 了解文档格式
  ├─ Think                     # 理解需求，设计文档结构
  ├─ Write output_file.html    # 生成自包含 HTML
  └─ Return result             # 返回确认信息
  ↓
CogniForge: git add + git commit
  ↓
REPL: 显示文件链接 + 审批菜单

8.4 Role System Prompt

每个角色都有预定义的中文系统提示词（ROLE_PROMPTS），通过 --append-system-prompt 附加到 Claude Code 的默认系统提示词（默认系统提示词已包含 CLAUDE.md）。

设计原则说明
Agent 只做编排CogniForge Agent 构建 prompt、调用 Claude Code、git commit
Claude Code 做执行读上下文、推理、生成文件 — 真正需要 AI 的工作
无 Python fallback没有 Claude Code agent 时报错，不再用 Python 拼文档
Operational 保留pytest 运行、git 提交等纯操作逻辑保留在 Agent 中

九、执行引擎

9.1 步进式执行模型

绝不自动连续执行多个步骤。每步执行后强制暂停，等待人工 approve/reject。被拒绝需返工后重新审批。
  1. 执行当前步骤任务
  2. 暂停并等待人工审批
  3. 人工决策：approve 通过 或 reject 返工
  4. 审批通过 → advance 进入下一步
  5. 重复 1-4 直至 RETRO 完成

9.2 CLI 审批命令

cogniforge status           # 查看当前状态 + 审批状态 + 操作历史
cogniforge start            # 启动工作流 / 从中断恢复
cogniforge agent <role>     # 手动执行指定 Agent → 委托给 Claude Code
cogniforge approve          # 人工审批通过当前步骤
cogniforge reject           # 拒绝 → 返工
cogniforge advance          # 审批通过后进入下一步
cogniforge wait             # 阻塞等待人工确认
cogniforge repl             # 自然语言 REPL 交互
cogniforge history          # 完整操作审计追踪

9.3 状态持久化

工作流全量状态持久化到 .cogniforge/workflow_state.json：

  • 当前步骤 + 是否等待审批
  • 每步审批记录（审批人、时间、备注、状态）
  • 每步执行结果 + 产物清单
  • 完整操作历史 timeline
中断恢复：进程退出后重新 cogniforge start 自动从上次断点恢复，无需手动干预。

9.4 REPL 交互模式 (v2.0)

cogniforge repl 提供 Claude Code / Codex CLI 风格的自然语言 REPL：

设计理念

两层 LLM 使用：
1. REPL 层：Claude Code -p 纯文本模式 — NL→JSON 分类、字段提取
2. Agent 层：Claude Code -p --tools ... 完整 agent 模式 — 读上下文、写文件、跑命令

架构

User 输入自然语言

    ↓
REPL 分发 action（run_agent | approve | reject）

    │  ├─ Write 输出文件
    │  └─ Bash 运行测试
    ↓
REPL: 显示文件链接 + 审批菜单
    ↓
循环

解析容错

LLM 返回可能带 markdown 代码块标记（```json ... ```），REPL 自动剥离后 parse JSON。解析失败时自动重试一次。

断点恢复

REPL 启动时自动检查 .cogniforge/workflow_state.json，若已存在则从当前步骤继续。可在 REPL 和手动命令间自由切换。

TEST 分支处理

QA agent 执行后根据 data.passed 判断结果：通过则引导用户选择 UAT 或继续修复，失败则自动进入 FIX 步骤。

十三、系统特性

优势限制
可控性确定性上下文，无 RAG 不确定性文档膨胀，需持续维护
审计性Git 全量追溯，AI 操作完整记录流程复杂，学习成本高

  • 操作日志 — 全量审计日志，不可篡改
  • Prompt 注入防护 — 输入校验，LLM 输出审查
