# CogniForge 软件架构设计 — 微服务架构

## System Overview
CogniForge 采用微服务架构，由 API 网关统一接入，用户服务与认证服务分离，支持 JWT 无状态鉴权，Redis 分布式缓存加速，满足可扩展、高可用的 AI 软件组织平台需求。

## Architecture
整体采用微服务架构风格，分为四层：接入层（API Gateway）、服务层（用户服务、认证服务）、数据层（PostgreSQL + Redis），以及监控与治理层。服务间通过 RESTful API 同步通信，认证信息通过 JWT 令牌传递，Redis 用于会话缓存和令牌黑名单。

## Components


### API Gateway
**Type**: 网关服务

统一入口网关，负责请求路由、速率限制、请求/响应转换、跨域处理

**Responsibilities:**
- 请求路由分发
- JWT 令牌前置校验
- 速率限制与流量控制
- 跨域 CORS 处理
- 统一日志记录与监控埋点

### User Service
**Type**: 业务微服务

用户领域服务，管理用户生命周期与概要数据

**Responsibilities:**
- 用户注册与资料管理
- 用户信息 CRUD
- 用户搜索与列表
- 用户状态管理（激活/冻结/删除）

### Auth Service
**Type**: 认证微服务

认证与授权服务，处理用户身份验证和令牌管理

**Responsibilities:**
- 用户登录认证（密码校验）
- JWT 令牌签发与刷新
- 令牌黑名单管理（登出场景）
- OAuth2/第三方登录集成
- 密码加密与重置流程

### Redis Cache
**Type**: 缓存中间件

分布式缓存层，用于加速认证查询和会话缓存

**Responsibilities:**
- JWT 刷新令牌缓存
- 令牌黑名单缓存
- 用户会话缓存
- 速率限制计数器

### Database (PostgreSQL)
**Type**: 持久化存储

主数据库，存储用户与认证相关持久化数据

**Responsibilities:**
- 用户数据持久化
- 认证流水记录
- 数据完整性保障

## System Topology

客户端 → [API Gateway] → 路由分发 → [Auth Service] ←→ [Redis Cache] 和 [User Service] ←→ [(PostgreSQL)]. API Gateway 位于最外层，所有外部请求必须经过网关；Auth Service 依赖 Redis 缓存令牌状态；User Service 直接操作 PostgreSQL；服务间通过内部 REST 接口通信，JWT 令牌在请求头 Authorization: Bearer <token> 中传递。

## Data Flow

1. 客户端发起请求 → API Gateway 2. Gateway 提取 JWT 令牌 → 调用 Auth Service 验证令牌有效性（查 Redis 黑名单 + JWT 签名验证）3. 验证通过后 Gateway 将请求路由至目标服务（如 User Service）并附带用户身份上下文 4. 目标服务处理业务逻辑，必要时查询 PostgreSQL 或请求其他服务 5. 响应经 Gateway 统一格式后返回客户端。登录流程：用户凭证 → Gateway → Auth Service → 校验密码 → 签发 JWT → 返回令牌 → Gateway → 客户端。
