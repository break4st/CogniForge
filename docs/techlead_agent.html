Tech Lead Agent — 技术主管代理

类名: TechLeadAgent(BaseAgent)  |  文件: src/cogniforge/agents/techlead_agent.py (552 行)  |  角色标识: techlead

1. 概述

Tech Lead Agent 是 CogniForge 工作流中的调度和治理中枢，负责将 LLD 转化为可执行的 WBS 任务、评估质量门禁、执行流程控制以及生成复盘总结。它将"思考型"任务（WBS 生成、质量评估）委派给 LLM，同时保持"操作型"决策（流程控制）在代码层面。

设计理念：Tech Lead 不是在 LLM 中做流程决策，而是在代码中做决策（decide_next/control_flow），将 LLM 限制在需要推理能力的任务（WBS 分解、质量评估）上。

3. Action 路由

Tech Lead 是所有代理中 action 最丰富的——通过 action 参数路由到不同处理逻辑：

run(input_data):
  action = input_data["action"]
  ├─ "create_wbs"       → _structured_create_wbs()     [需要 LLM]
  ├─ "evaluate_quality" → _agentic_evaluate_quality()   [需要 LLM]
  ├─ "decide_next"      → _decide_next()                [纯代码]
  ├─ "control_flow"     → _control_flow()               [纯代码]
  └─ "retro"            → _retro()                      [纯代码]

4. WBS 创建流程（核心）

create_wbs:
  1. 查找模块的 LLD 文档
  2. 构建 RepoConventions (从 config + 可选 SAD 补充)
  3. WBSAssembler.assemble(module, lld_path)
     ├─ 机械分解 (decomposition_rules) → task stubs
     ├─ LLM 丰富 (enrichment) → 完整 task dicts
     └─ 覆盖率分析 (coverage_validator)
  4. assembler.validate_all() → 四维质量门禁验证
  5. 检查上游问题 (_detect_upstream_issues)
     - service_contracts 缺少 output/signature
     - interfaces 缺少 response 定义
     → 有 upstream_issues → 返回 blocked
  6. _register_wbs_tasks() → 逐 task 注册到 TaskEngine
     - 提取 context / lld_refs / expected_output_files / layer
     - 提取 source / implementation_boundary / validation
     - 提取 dev_agent / file_locks / acceptance_criteria
     - 创建 task → _save_task() → 写 JSON + git add
  7. _build_and_write_wbs_output()
     - 构建 WBSIndex (meta/source/nodes/edges/execution_batches/coverage/quality_gates)
     - 写入 wbs.json + tl-turn-result.json
  8. 返回结果含 task_count, coverage, quality_gates

4.1 上游问题检测

在生成 WBS 之前，_detect_upstream_issues() 检查 LLD 完整性：

  • incomplete_contract: service_contracts 中的 method 缺少 output schema 或 signature
  • missing_response: interfaces 中的接口缺少 response 定义

发现问题则返回 status=blocked 并附 suggested_action，要求 MDE 补齐。

4.2 执行批次计算

compute_execution_batches() 基于任务依赖 DAG 计算并行执行批次，使 Dev Agent 能够安全地并行执行无依赖冲突的任务。

5. 质量评估流程

evaluate_quality:
  1. 确定 report doc_id (quality-{module}-{seq})
  2. 构建 prompt → 要求 LLM 阅读 LLD/代码/CR 报告/测试报告
  3. agent.generate_agentic(prompt, role="techlead")
  4. 校验生成的 quality report 是否符合 quality-report-schema.json
  5. 写入、渲染、提交

6. 复盘流程 (RETRO)

retro:
  1. 统计模块任务状态: done/failed/blocked/total
  2. 计算估算 vs 实际工时比率
  3. 构建 retro_data:
     - metrics: 完成率 + 估算准确率
     - upstream_feedback: {pm, se, mde, wbs_rules}
     - process_improvements
  4. 写入 .cogniforge/wiki/reports/retro-{module}-001.json

8. 四维质量门禁

assembler.validate_all() 执行四维验证 + Schema 验证：

维度检查内容
覆盖率LLD artifacts 是否都有对应任务覆盖
Schema每个 task dict 是否符合 wbs-task-schema.json
依赖task deps 是否形成有效 DAG（无循环依赖）
完整性必需字段是否填写完整
