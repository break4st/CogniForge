BaseAgent — 代理抽象基类

类名: BaseAgent(ABC)  |  文件: src/cogniforge/agents/base.py (278 行)  |  类型: abstract

1. 概述

BaseAgent 是所有 CogniForge 代理的抽象基类，定义了统一的生命周期、审计跟踪、文档访问控制和结果格式化机制。每个具体代理通过实现 run() 方法来提供特定角色行为。

2. 设计原则

  1. 单一职责： 每个 Agent 只做一件事
  2. 明确输入输出： run() 的 input_data dict 和返回值 dict 形成清晰契约
  3. 必须读写文档： Agent 通过 wiki_system 读取和持久化结构化文档
  4. 限定修改范围： 只能修改 AgentDefinition 中声明的 allowed_modify 路径
  5. 全部可审核： 每个操作通过 run_with_audit() 自动记录审计日志

3. 构造函数参数

参数类型必需说明
roleAgentRole是代理角色枚举 (pm/architect/design/techlead/dev/reviewer/qa/devops)
wiki_systemWikiSystem是Wiki 文档系统，提供读写和列出文档的能力
context_loaderContextLoader是确定性上下文加载器（非 RAG）
configConfig否配置对象，默认使用 Config()
audit_logAuditLog否审计日志记录器，默认使用 AuditLog(config)
agentBaseLLMAdapter否LLM 适配器，为 None 时代理无法调用 LLM
task_engineAny否任务引擎（TechLead 使用），其他代理可能不使用

4. 抽象方法

4.1 run()

@abstractmethod
def run(self, input_data: dict) -> dict:
    """执行代理逻辑。子类必须实现。"""

每个具体代理的 run() 是入口点，接收 input_data 字典，返回标准化的结果字典。

5. 审计跟踪 (Audit Trail)

5.1 run_with_audit()

def run_with_audit(self, input_data: dict) -> dict

包装 run()，自动记录以下信息：

记录项说明
input_context输入数据的键列表、任务信息、可用文档
output_artifacts生成的产物路径列表
output_summary结果消息
reasoning推理过程（LLM 原始输出）
decisions关键决策列表
duration_ms执行耗时（毫秒）
statussuccess / failed
error异常信息（仅失败时）
异常处理：如果 run() 抛出异常，run_with_audit() 仍会记录一条状态为 "failed" 的审计条目，然后重新抛出异常。

def write_document(
    self,
    doc: Document,
    commit_message: str = None,
) -> None

写入前通过 _check_allowed_path() 验证路径是否在 AgentDefinition.allowed_modify 范围内。

6.3 _check_allowed_path()

def _check_allowed_path(self, path: str) -> None

将路径与 AgentDefinition 中声明的 allowed_modify 前缀列表进行匹配。如果路径不在任何允许范围内，抛出 AgentError。

8. 结果格式化

8.1 format_result()

def format_result(
    self,
    status: str,           # "success" | "failed"
    message: str = "",
    artifacts: list[str] = None,   # 产物路径列表
    data: dict = None,             # 结构化数据
    reasoning: str = "",           # LLM 原始输出
    decisions: list[str] = None,   # 关键决策
) -> dict

返回标准化的结果字典：

{
    "status": "success",
    "message": "...",
    "artifacts": ["path/to/file.json"],
    "data": {},
    "agent": "pm",           # 从 self.role.value 自动填充
    "reasoning": "...",
    "decisions": []
}

10. AgentDefinition 集成

构造函数中自动通过 get_agent_definition(role) 加载对应 AgentDefinition：

self.definition = get_agent_definition(role)  # AgentDefinition Pydantic 模型
if not self.definition:
    raise AgentError(f"No definition found for role {role}")

AgentDefinition 提供：

  • definition.allowed_modify — 用于路径权限检查
  • definition.responsibilities — 代理职责列表
  • definition.input_docs / definition.output_docs — 输入输出文档类型

11. 生命周期

构造 → run_with_audit(input_data)
         ├─ _capture_input_context() → 记录输入
         ├─ run(input_data)          → 子类实现
         │    ├─ load_context()      → 加载上下文
         │    ├─ read_document()     → 读取文档
         │    ├─ agent.generate_*()  → LLM 交互
         │    ├─ write_document()    → 持久化产物 (_check_allowed_path)
         │    └─ format_result()     → 格式化结果
         ├─ _log_operation()         → 记录审计
         └─ return result
