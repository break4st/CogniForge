DevOps Agent — 部署与基础设施代理

类名: DevOpsAgent(BaseAgent)  |  文件: src/cogniforge/agents/devops_agent.py (156 行)  |  角色标识: devops

1. 概述

DevOps Agent 是 CogniForge 工作流的最后一环，采用 混合模式——部署配置生成委派给 Claude Code CLI（Agentic 模式），而 deploy 和 rollback 操作则保留为代码中的操作存根，为将来的 CI/CD 集成预留接口。

设计理念：部署配置生成需要理解系统架构和模块设计（需要 LLM 推理），而 deploy/rollback 是高度环境相关的操作（需要凭证、基础设施访问），在当前阶段保留为操作存根，等待与具体 CI/CD 系统集成。

3. Action 路由

DevOps Agent 通过 action 参数路由到三种不同的处理逻辑：

run(input_data):
  action = input_data["action"]
  ├─ "prepare_deploy"  → _agentic_prepare_deploy()   [LLM 委派 + Claude Code]
  ├─ "deploy"          → _deploy()                    [操作存根]
  └─ "rollback"        → _rollback()                  [操作存根]

3.1 部署配置生成 (prepare_deploy)

_agentic_prepare_deploy():
  1. 提取 module + environment + version
  2. 确定 doc_id → deploy-{module}-{environment}-{seq}
  3. 输出路径 → .cogniforge/wiki/ops/{doc_id}.json
  4. 构建 Prompt:
     - JSON 结构模板 (meta + config: docker/env_vars/network/health_check)
     - 先阅读 .cogniforge/wiki/sad/ 了解系统架构
     - 先阅读 .cogniforge/wiki/lld/{module}/ 了解模块设计
     - 输出 Docker 配置、环境变量、网络设置、健康检查
  5. agent.generate_agentic(prompt, role="devops")
  6. 校验输出的 JSON (deploy-config-schema.json)
  7. 渲染 HTML → git commit

3.2 部署执行 (deploy) — 操作存根

_deploy():
  → 返回 status="success"
  → message: "Deploy {module} to {environment} (operational stub)"
  → data: {module, environment}

3.3 回滚执行 (rollback) — 操作存根

_rollback():
  → 返回 status="success"
  → message: "Rollback {module} to {version} (operational stub)"
  → data: {module, version}
操作存根：deploy 和 rollback 当前为占位实现，返回成功状态但无实际操作。这是有意的设计选择——部署操作需要环境特定的凭证和基础设施访问，将在与 CI/CD 系统集成时实现。

5. 部署配置版本管理

DevOps 支持按环境分版本管理部署配置——doc_id 格式为 deploy-{module}-{environment}-{seq}，同一模块的不同环境（dev/staging/prod）有独立的配置历史。

6. Prompt 结构

为以下模块准备部署配置，以 JSON 格式输出并写入:

输出路径: {json_path}
JSON 结构: {
  "meta": {
    "doc_id": "deploy-{module}-{env}-{seq}",
    "type": "deploy",
    "title": "部署配置 - {module}",
    "author": "devops_agent",
    "created": "{now}"
  },
  "config": {
    "module": "...",
    "environment": "...",
    "docker": {},
    "env_vars": {},
    "network": {},
    "health_check": {}
  }
}

输入数据:
module: {module}
environment: {environment}
version: {version}

要求:
1. 先阅读 .cogniforge/wiki/sad/ 了解系统架构
2. 先阅读 .cogniforge/wiki/lld/{module}/ 了解模块设计
3. 在 config 字段中包含: Docker 配置、环境变量、网络设置、健康检查
4. 使用中文、只写 JSON 不写 HTML、完成后回复确认

7. 与 Claude Code 的通信

DevOps Agent 在 prepare_deploy 中使用 agent.generate_agentic(prompt, role="devops")，Claude Code 获得：

  • 文件读取能力： 阅读 SAD 系统架构和 LLD 模块设计
  • 写入能力： 将部署配置 JSON 写入指定路径

deploy 和 rollback 不涉及 LLM——纯代码操作存根。

8. 在工作流中的位置

DAG: PRD → ... → CODING → CR → TEST → FIX → UAT → RETRO
                                                        ↑
                                                   DevOps Agent
                                                   (prepare_deploy 在部署阶段前)

DevOps Agent 当前在 UAT 之后介入，为部署做配置准备。实际部署（deploy）和回滚（rollback）在 CI/CD 管道中触发。

9. 错误处理

场景处理方式
LLM agent 为 None（非 deploy/rollback）抛出 AgentError
JSON 解析失败返回 status="failed" + 错误原文
Schema 验证失败返回 status="failed" + 前 3 项错误
未知 action返回 status="failed"
deploy / rollback始终返回 success（操作存根）
