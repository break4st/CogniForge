QA Agent — 质量保证代理

类名: QAAgent(BaseAgent)  |  文件: src/cogniforge/agents/qa_agent.py (222 行)  |  角色标识: qa

1. 概述

QA Agent 是 CogniForge 的质量门禁第二关，采用 混合模式——测试用例生成和报告编写委派给 Claude Code CLI（Agentic 模式），而测试执行（pytest）则由 QA Agent 本身以子进程方式执行（操作模式）。

设计理念：测试生成需要理解设计文档和代码（需要 LLM 推理），而测试执行是确定性操作（pytest + 状态码判断）。QA Agent 将两者分离，操作部分不消耗 LLM Token。

3. Action 路由

QA Agent 通过 action 参数路由到三种不同的处理逻辑：

run(input_data):
  action = input_data["action"]
  ├─ "generate_tests"  → _agentic_generate_tests()   [LLM 委派 + Claude Code]
  ├─ "report"          → _agentic_report()            [LLM 委派 + Claude Code]
  └─ "execute_tests"   → _execute_tests()             [纯代码: subprocess.run(pytest)]

3.1 测试生成 (generate_tests)

_agentic_generate_tests():
  1. 提取 module + test_cases (可选预定义用例)
  2. 确定 doc_id → test_case-{module}-{seq}
  3. 输出路径 → .cogniforge/wiki/qa/{doc_id}.json
  4. 构建 Prompt:
     - JSON 结构模板 (meta + test_cases 数组)
     - 先阅读 .cogniforge/wiki/lld/{module}/ 了解设计
     - 阅读 src/{module}/ 下的代码了解实现
     - 覆盖正常路径、边界条件、错误处理
     - 生成对应的 pytest 测试代码写入 tests/test_{module}.py
  5. agent.generate_agentic(prompt, role="qa")
  6. 校验输出的 JSON (test-case-schema.json)
  7. _commit_result() → 渲染 HTML + git commit
     (同时提交 tests/test_{module}.py 作为 extra_paths)

3.2 测试报告 (report)

_agentic_report():
  1. 确定 doc_id → test-report-{module}-{seq}
  2. 输出路径 → .cogniforge/wiki/reports/{doc_id}.json
  3. 构建 Prompt:
     - 阅读 tests/test_{module}.py 和 src/{module}/ 代码
     - 运行 pytest 获取测试结果
     - content 字段包含: 测试覆盖率、通过/失败统计、风险评估
  4. agent.generate_agentic(prompt, role="qa")
  5. 校验输出的 JSON (test-report-schema.json)
  6. 渲染 HTML → git commit

3.3 测试执行 (execute_tests)

_execute_tests():
  1. 以子进程运行: pytest -v --tb=short tests/test_{module}.py
  2. capture_output=True, text=True
  3. 判断 returncode → passed
  4. 返回 status="success"/"failed" + stdout/stderr
  5. 如果 pytest 未安装 → 降级跳过 (status="success", 无报错)
降级策略：如果 pytest 未安装，QA Agent 不会失败——返回 passed=True 并标注 "pytest not found, skipping"。这确保在 CI 环境尚未配置完整时工作流不会阻塞。

6. 与 Claude Code 的通信

QA Agent 在 generate_tests 和 report 两个 action 中使用 agent.generate_agentic(prompt, role="qa")，Claude Code 获得：

  • 文件读取能力： 阅读 LLD 设计文档、源代码、已有测试文件
  • Shell 执行能力： 运行 pytest 获取测试结果
  • 写入能力： 将测试用例 JSON 和 pytest 测试代码写入文件

execute_tests action 则直接使用 Python subprocess.run() 调用 pytest，不涉及 LLM。

7. 在工作流中的位置

DAG: ... → CR → TEST → FIX → UAT → RETRO
                 ↑
            QA Agent

测试阶段必须通过才能进入 UAT（质量门禁要求：tests_passed）。

8. 错误处理

场景处理方式
LLM agent 为 None（非 execute_tests）抛出 AgentError
JSON 解析失败返回 status="failed" + 错误原文
Schema 验证失败返回 status="failed" + 前 3 项错误
pytest 未安装降级跳过 (passed=True, "pytest not found")
未知 action返回 status="failed"
