Dev Agent — 开发代理

类名: DevAgent(BaseAgent)  |  文件: src/cogniforge/agents/dev_agent.py (244 行)  |  角色标识: dev

1. 概述

Dev Agent 是 CogniForge 中的代码实现代理，采用 Agentic 委派模式——将整个开发任务（读取设计文档、编写代码、运行测试）委派给 Claude Code CLI Agent。它构建结构化的开发 Prompt，从 TaskContext 中提取接口签名、数据模型、领域对象、业务规则和验收标准，确保 LLM 严格遵循设计实现。

设计理念：Dev Agent 不在代码中拆分实现步骤，而是构建一个包含所有设计约束的结构化 Prompt，让 Claude Code 在完整工具访问权限下自主完成任务。这种方式适用于需要文件读写和 shell 操作的开发任务。

3. 运行模式

Dev Agent 有两种运行模式：

run(input_data):
  code 存在？ → _write_direct()    # 直写模式（已有代码，直接写入文件）
  code 不存在  → _run_agentic()     # Agentic 模式（通过结构化 Prompt 委派给 Claude Code）

3.1 Agentic 模式（主模式）

_run_agentic(task, module):
  1. 提取 task 属性: name, description, context, acceptance_criteria
  2. 提取上游产物 (upstream_artifacts)
  3. _build_structured_prompt() → 构建 11 段结构化 Prompt
  4. agent.generate_agentic(prompt, role="dev") → 委派给 Claude Code
  5. 扫描 src/{module}/ 收集产物列表
  6. 返回结果

3.2 直写模式

_write_direct(module, task, code):
  1. 创建 src/{module}/ 目录
  2. 写入代码文件
  3. git add
  4. 返回产物路径

4. 结构化 Prompt 构建

_build_structured_prompt() 是 Dev Agent 的核心——它从 TaskContext 提取以下 11 个段落，构建完整实现说明：

段落来源内容
1. 任务task.name + task.description任务名称和描述
2. 上游产物context.upstream_artifacts已完成任务的文件列表（可直接 import）
3. API 接口context.scope.interfacesmethod, endpoint, parameters, response body, error_codes
4. 服务契约context.scope.service_contractssignature, precondition, postcondition, exceptions
5. 数据模型context.scope.data_models字段定义 (name/type/required) + indexes
6. 领域对象context.scope.domain_objectsentity/DTO/值对象/枚举 的 attributes + source
7. 业务规则context.scope.business_rulesinvariants, state_machines (transitions + irreversible_rules), cross_service_rules
8. 错误处理context.scope.error_handling错误处理策略
9. 验收标准task.acceptance_criteria每项标注 verification_type 和 description
10. 外部契约context.external_contracts依赖的外部接口 (module + method + endpoint)
11. LLD 参考context.lld_path完整 LLD 文档路径

最终 Prompt 以严格指令结束：

实现以下开发任务。接口签名、数据模型字段和业务规则来自详细设计文档(LLD)，必须严格遵守。

[... 11 段结构化内容 ...]

要求：
1. 以上所有接口签名、字段定义、前置/后置条件必须精确实现
2. 每个验收标准必须有对应代码实现来保障
3. 所有错误码和异常场景必须实现
4. 编写对应的单元测试
5. 完成后运行测试验证
6. 完成后用中文回复确认

5. TaskContext Scope 模型

TaskContext 的 scope 字段包含从 LLD 中精确提取的实现约束：

scope 字段类型说明
interfaceslist[dict]API 接口的完整定义（method/endpoint/parameters/response/error_codes）
service_contractslist[dict]服务层方法契约（signature/precondition/postcondition/exceptions）
data_modelslist[dict]数据模型定义（fields/indexes/ownership）
domain_objectslist[dict]领域实体/DTO/值对象/枚举
business_rulesdictinvariants + state_machines + cross_service_rules
error_handlingdict错误处理策略

6. 与 Claude Code 的通信

Dev Agent 通过 agent.generate_agentic(prompt, role="dev") 委派任务，这实际上是调用 Claude Code CLI 以工具使用模式运行。Claude Code 拥有：

  • 文件读写能力： 直接读取 LLD 文档和写入源代码
  • Shell 执行能力： 运行 pytest 验证测试
  • 代码搜索能力： 查找现有代码模式确保一致性
与 PM/Architect/Design 的区别：PM/Architect/Design/TechLead 通过直接 API 调用使用 DeepSeek（generate_think_then_json），而 Dev/Reviewer/QA/DevOps 通过 Claude Code CLI 使用工具模式（generate_agentic）。这是因为后者需要文件系统操作能力。

7. 错误处理

场景处理方式
LLM agent 为 None抛出 AgentError（需要 Claude Code agent）
任务执行异常返回 status="failed" + 错误消息
