概述

文件传输模块
⚙️ 业务服务
通过SCP/SFTP协议将可执行文件和配置传输到远程服务器，支持大文件分片传输和传输完整性校验
依赖: SSH连接池密钥管理服务审计日志服务
PythonFastAPIREST/HTTPSSSH/SCP/SFTP
🗄️

服务接口 (2)

🔧 FileTransferService 4 方法
uploadFile
(request: FileUploadRequest, config: TransferConfig) -> FileUploadResponse
将文件通过SCP/SFTP协议传输到远程服务器，传输完成后计算文件校验和
前置条件
SSH会话session_id对应的连接在SSH连接池中已建立且可用；remote_path在远程服务器上存在且有写权限
后置条件
文件已通过SCP/SFTP成功传输到远程服务器的remote_path/file_name路径；传输会话状态为completed或failed
InvalidSessionError→ 400session_id不存在或对应的SSH连接已中断RemotePathError→ 502remote_path在远程服务器上不存在或当前用户无写权限TransferTimeoutError→ 504文件传输超过transfer_timeout未完成TransferFailedError→ 502SCP/SFTP底层传输失败（网络中断、磁盘空间不足等）
uploadFileChunk
(sessionId: String, chunkIndex: Integer, chunkData: String, totalChunks: Integer, config: TransferConfig) -> FileUploadResponse
分片上传文件的一个分片，全部分片收集完成后自动在远程服务器上组合完整文件
前置条件
传输会话已存在且当前状态为uploading；chunkIndex在[0, totalChunks)范围内；chunkData非空
后置条件
当前分片已通过SFTP写入远程临时文件；当chunkIndex等于totalChunks-1时自动组合所有分片并计算最终校验和
InvalidSessionError→ 400传输会话ID不存在或状态不为uploadingInvalidChunkError→ 400分片序号重复、不连续或超出范围TransferFailedError→ 502分片传输过程中发生SCP/SFTP错误
retryTransfer
(sessionId: String, config: TransferConfig) -> FileUploadResponse
重试失败的传输任务，重新建立传输并执行完整的文件传输流程
前置条件
传输会话存在且状态为failed；retry_count小于config.max_retries
后置条件
retry_count加1；文件被重新传输；会话状态根据传输结果转换为uploading或仍为failed
InvalidSessionError→ 400传输会话ID不存在MaxRetriesExceededError→ 409重试次数已达到config.max_retries上限TransferFailedError→ 502重试传输过程中仍然失败
verifyFileIntegrity
(sessionId: String) -> FileChecksum
重新计算远程服务器上已传输文件的校验和，用于验证传输完整性
前置条件
传输会话存在且状态为completed
后置条件
返回远程服务器上文件的当前校验和；可在返回外部与期望值比对以验证完整性
InvalidSessionError→ 400传输会话ID不存在FileNotFoundError→ 502远程服务器上目标文件不存在或已被删除
数据访问依赖
findBySessionId(sessionId: String) -> FileTransferSession?
save(session: FileTransferSession) -> void
updateStatus(sessionId: String, status: TransferStatus) -> void
incrementRetryCount(sessionId: String) -> Integer

SSH连接池中存在sessionId对应的活跃连接；localFilePath指向的本地文件存在且可读

本地文件通过SFTP协议已传输到远程服务器的remoteDir/fileName；返回布尔值表示传输成功与否

computeRemoteChecksum
(sessionId: String, remoteFilePath: String, algorithm: String) -> FileChecksum
在远程服务器上执行校验和计算命令，返回文件的校验和值
前置条件
SSH连接池中存在sessionId对应的活跃连接；remoteFilePath在远程服务器上存在且可读
后置条件
在远程服务器上执行校验和计算命令并返回计算结果，返回值中包含算法名称和校验和值
SftpTransferException→ 502远程命令执行失败或文件不可读

业务规则

不变量
  • !单个传输会话在同一时刻只能处于一种状态：uploading、completed、failed三者之一
  • !传输会话的retry_count必须始终小于等于config.max_retries
  • !completed为传输终态，不可再执行任何传输操作
  • !分片传输时所有分片的chunkIndex必须连续覆盖0到totalChunks-1的完整范围
  • !同一session_id的传输操作具有互斥性，不可并发执行
状态机
🎯 FileTransferSession
uploadingcompletedfailed
→文件或全部分片传输成功且校验和验证通过by FileTransferService.uploadFile / uploadFileChunk
→传输过程中发生不可恢复错误（网络中断、磁盘空间不足、权限拒绝）by FileTransferService.uploadFile / uploadFileChunk
→调用retryTransfer方法重新传输by FileTransferService.retryTransfer
🚫 completed为终态，一旦到达不可转换为任何其他状态🚫 failed状态只能通过retryTransfer转换为uploading，不可直接跳转为completed
⚡ 同一session_id的传输操作使用Redis分布式锁防重入，锁超时时间为config.transfer_timeout + 30秒；不同session_id的传输互不影响，可并行执行
跨服务规则
文件传输前须确认SSH连接池中的session_id对应一个有效的、已建立连接的SSH会话
传输完成后须向审计日志服务发送审计事件，包含session_id、file_name、remote_path、status、checksum等信息
大文件（超过config.chunk_size）自动触发分片传输模式，分片状态的协调由部署执行服务在调用层面管理

接口定义 (1)

POST/internal/file/upload文件上传
内部接口，通过SCP/SFTP将文件传输到远程服务器，部署执行服务调用此接口完成文件上传
参数类型描述
session_idStringSSH会话ID，从SSH连接池获取
remote_pathString远程目标路径，即远程服务器上的目标目录
file_dataBinary文件内容，Base64编码字符串或分片数据
file_nameString文件名，传输后在远程服务器上以此名称保存
Response 200
字段类型
session_idString
statusString
checksumString
错误码
状态码说明
400请求参数缺失或格式错误，如session_id为空、file_data格式不正确
401未授权调用，内部服务认证不通过
502远程SCP/SFTP传输失败，如网络中断、权限拒绝、磁盘空间不足
504传输超时，超过配置的transfer_timeout阈值
⚠️

错误处理

处理策略

文件传输模块采用分级错误处理策略：参数校验错误直接返回4xx；SCP/SFTP传输底层错误统一封装为502并记录详细错误日志；超时错误返回504并将传输会话标记为failed状态；所有传输错误支持重试机制，最多重试max_retries次

统一错误响应体
字段类型

errorstring
detailstring
400
参数校验错误
请求缺少必要参数或参数格式不正确时触发，传输会话不会创建

内部服务调用认证不通过时触发
502
远程传输失败
SCP/SFTP传输过程中发生网络错误、权限拒绝、远程路径不存在或磁盘空间不足时触发，传输会话标记为failed状态，可配置重试

传输超时
单次传输超过配置的transfer_timeout阈值时触发，传输会话标记为failed状态
