概述

审计日志服务
⚙️ 业务服务
统一审计日志服务，接收各业务服务的操作日志并持久化，支持多维筛选查询

服务接口 (1)

🔧 AuditLogService 2 方法
create_log
(params: AuditLogCreateDTO) -> AuditLog
创建一条新的审计日志记录，由各业务服务在关键操作完成后同步调用
前置条件
params 必填字段（action、actor、resource_type、resource_id、result）均非空且通过 Pydantic 格式校验
后置条件
审计日志已成功写入 audit_logs 表并返回包含系统生成的 id 和 created_at 的完整记录
ValidationException→ 400请求参数校验失败，必填字段缺失或字段格式不合法DatabaseWriteException→ 500数据库写入失败，如连接异常、主键冲突或约束违反
query_logs
(params: AuditLogQueryDTO) -> AuditLogPageDTO
按资源类型、时间范围和分页参数查询审计日志，供 Web 管理控制台展示审计追踪记录
前置条件
params.page >= 1，params.page_size 在 [1, 100] 范围内，start_time 不晚于 end_time（如同时传值）
后置条件
返回符合筛选条件的分页结果：total 为总记录数，items 为当前页条目列表；无匹配记录时 items 为空列表、total 为 0
ValidationException→ 400分页参数超限（page < 1 或 page_size > 100）或时间范围矛盾DatabaseQueryException→ 500数据库查询异常（连接超时、语法错误等）

业务规则

不变量
  • !审计日志不可修改：一旦写入成功，任何操作不可更新或删除已存在的审计日志记录
  • !审计日志不可重写：相同 id 的记录不存在，由数据库 UUID 主键唯一性天然保证
  • !操作结果 result 字段取值仅限于 success 和 failure，不允许其他任意值
  • !审计日志的 created_at 由数据库自动生成，不允许客户端在请求中指定
跨服务规则
所有业务服务（项目管理服务、环境配置服务、部署引擎服务、密钥管理服务）在完成关键业务操作后，必须同步调用审计日志服务的 POST /api/audit/logs 接口记录操作日志
审计日志服务自身不为自己产生的操作记录审计日志，其操作由调用方负责记录
审计日志写入的容错策略：调用方应尝试重试一次（最多一次），重试仍失败时记录服务自身日志但不应阻断主业务流程的继续执行
审计日志查询接口仅面向 Web 管理控制台开放，不提供给其他业务服务直接调用

错误处理

处理策略

统一通过 FastAPI 异常处理器捕获业务异常，返回 JSON 格式错误响应。参数校验失败返回 400，服务器内部错误返回 500。所有异常记录服务自身日志便于排查
