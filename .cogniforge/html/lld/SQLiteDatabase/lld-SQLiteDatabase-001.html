概述

SQLiteDatabase
🗄️ 数据库层
SQLite 数据库，通过 SQLAlchemy ORM 管理项目、环境、密钥、部署记录、脚本模板等数据，提供事务支持与数据一致性保障。
依赖: EncryptionUtil
SQLiteSQLAlchemyAlembic
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 数据库表结构定义与管理 索引设计与优化 迁移脚本编写与执行 连接池管理 事务支持 为上层服务提供数据持久化能力
范围外: 业务逻辑处理 SSH 通信 加密解密（依赖 EncryptionUtil） 前端展示 API 网关路由 部署流程编排
拥有组件: CMP-001

迁移策略

工具: Alembic命名: V{序号}__{描述}.sql

回滚策略: 每次迁移均实现 upgrade() 和 downgrade() 函数；SQLite 下避免 ALTER TABLE DROP COLUMN，必要时重建表；所有迁移需在测试环境验证通过后方可应用于生产。

📈

容量估算

1年: 约 8 万行，总存储量 < 50 MB（含日志）3年: 约 20 万行，总存储量 < 150 MB
热表: deployments environments

分区策略: SQLite 原生不支持分区；必要时通过定期归档部署日志（如将一年前记录移至历史表）控制单表体积。

编排流程

数据库迁移自动执行流程

应用启动时自动检测并执行数据库迁移，确保与实际数据模型同步。

1
检查数据库文件 (5s 超时)
检查 SQLite 数据库文件是否存在，若不存在则创建空文件。
失败处理: 记录错误并终止启动
2
加载 Alembic 配置 (5s 超时)
初始化 Alembic 环境，获取当前数据库修订版本。
失败处理: 记录错误并终止启动
3
比较并应用迁移 (30s 超时)
运行 alembic upgrade head，将数据库升级到最新版本。
失败处理: 记录详细错误，终止启动，等待人工修复后重启
重试策略: 最多 0 次，间隔 0s
可重试错误: 无
不可重试错误: ALL

错误处理

处理策略

上层服务调用数据库时，所有 SQLAlchemy 异常在 Repository 层统一捕获，转换为标准化错误字典或异常，同时数据库层通过事务回滚保障一致性。

统一错误响应体

DATA_NOT_FOUND
触发条件：按主键或条件查询不到记录；处理方式：返回错误提示，资源不存在。
