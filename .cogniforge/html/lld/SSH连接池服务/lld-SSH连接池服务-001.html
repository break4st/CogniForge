服务接口 (2)

🔧 SshPoolService 4 方法
GetConnection
(request: GetConnectionRequest) -> GetConnectionResponse
获取到目标服务器的 SSH 连接。优先复用池中空闲连接（需验证未过期、健康可用），若无空闲且池未满则调用密钥管理服务获取解密私钥后新建连接
前置条件
request.host/port/username/key_fingerprint 均非空且格式合法；全局活跃连接数未达到 max_concurrent_connections；密钥管理服务 gRPC 端点可用
后置条件
返回一个已通过 SSH 握手和密钥认证的有效连接句柄；该连接标记为 in_use 状态；返回的 expires_at = 当前时间 + connection_ttl_seconds；若复用了空闲连接则 last_used_at 更新
InvalidArgumentError→ 400host/port/username/key_fingerprint 任一为空、port 超出 1-65535 范围或格式不合法AuthenticationError→ 401密钥管理服务返回密钥不存在、指纹不匹配或密钥已吊销PoolExhaustedError→ 429目标主机连接数已达 max_pool_size 或全局连接数已达 max_concurrent_connectionsConnectionFailedError→ 503SSH 连接建立失败，包括 TCP 连接被拒绝、网络不可达或握手超时KeyServiceUnavailableError→ 503调用密钥管理服务 GetDecryptedKey 时 gRPC 调用失败或超时
ReleaseConnection
(connection_id: UUID) -> boolean
使用方用完 SSH 连接后归还到连接池。根据连接是否过期决定复用或销毁，避免资源泄漏
前置条件
connection_id 对应的 SshConnection 必须存在且状态为 in_use
后置条件
若连接未过期则状态变为 idle 并放回空闲队列；若已过期则关闭连接并释放资源；连接从 in_use_set 中移除
ConnectionNotFoundError→ 404connection_id 在连接池中不存在或已被移除InvalidStateError→ 409连接当前状态不是 in_use（如已释放、空闲或已关闭），防止重复释放
HealthCheck
(pool_key: string) -> List[SshConnectionStatus]
对指定连接池的所有空闲连接执行健康检查，发送 SSH channel keepalive 探测连接活性，发现异常连接自动进入重连流程
前置条件
pool_key 格式为 host:port:username 三元组；对应的连接池实例存在
后置条件
所有空闲连接收到 SSH keepalive 请求；响应正常的连接保持 idle 状态；无响应或报错的连接标记为 unhealthy 并触发自动重连；返回池中所有连接的当前状态列表
ConnectionNotFoundError→ 404pool_key 对应的连接池实例不存在
CloseConnection
(connection_id: UUID) -> boolean
主动关闭并移除一条 SSH 连接，用于手动清理或系统回收（如服务器拓扑变更时）
前置条件
connection_id 对应的连接存在且状态不为 in_use（不允许强制关闭正在使用的连接）
后置条件
SSH 会话通道正常关闭（发送 SSH_MSG_DISCONNECT）；TCP 连接断开；连接从池中彻底移除；相关资源释放
ConnectionNotFoundError→ 404connection_id 在连接池中不存在InvalidStateError→ 409连接正处于 in_use 状态，不允许强制关闭

🔧 KeyServiceClient 1 方法
GetDecryptedKey
(key_fingerprint: string, requestor: string, request_id: UUID) -> GetDecryptedKeyResponse
通过 gRPC 调用密钥管理服务的 GetDecryptedKey 接口，获取解密后的 SSH 私钥，用于建立 SSH 连接认证
前置条件
key_fingerprint 非空且格式合法；请求中 requestor 为本服务注册标识「SshPoolService」；request_id 为每次调用新生成的 UUID
后置条件
返回解密后的 PEM 格式私钥内容（仅内存中存在）；key_type 标明算法类型（RSA/ECDSA/ED25519）；返回的 fingerprint 与请求的 key_fingerprint 一致
KeyNotFoundError→ 404key_fingerprint 在密钥管理服务数据库中不存在KeyRevokedError→ 403密钥已被管理员吊销或已超过有效期DecryptionFailedError→ 500密钥解密失败（密文损坏、AES-GCM 认证标签校验失败或算法不匹配）GrpcTimeoutError→ 504gRPC 调用超时（默认 10 秒），密钥管理服务可能负载过高

业务规则

不变量
  • !到同一目标服务器（相同 host:port:username）的活跃连接数在任何时刻都不得超过 max_pool_size
  • !所有 SSH 连接建立前必须通过密钥管理服务获取解密后的私钥，不得直接使用配置中的明文密钥或缓存密钥
  • !解密后的私钥内容仅在进程内存中存在，使用完毕后立即置空销毁，严禁写入磁盘、日志、数据库或任何持久化存储
  • !每条 SSH 连接都有明确的 expires_at 超时时间，超过后即使调用方未归还也必须强制回收销毁
  • !空闲连接在 idle_timeout_seconds 内未被分配则必须关闭并从池中移除，不准长期空占系统资源
  • !同一 connection_id 不可被同时分配给多个调用方，即状态为 in_use 的连接不可再次进入 GetConnection 分配逻辑
状态机
🎯 SshConnection
idlein_useunhealthyclosed
→GetConnection 从空闲队列中分配此连接by SshPoolService
→ReleaseConnection 归还且未过期by 调用方（部署编排服务）
→ReleaseConnection 归还但已超过 expires_at，直接关闭by SshPoolService
→空闲超时回收（expires_at 到期但调用方未归还的兜底机制）by SshPoolService（后台协程）
→HealthCheck 检测到连接异常（SSH keepalive 无响应或报错）by SshPoolService（健康检查协程）
→自动重连成功（重新建立 SSH 会话成功）by SshPoolService（重连协程）
→自动重连达到 max_retry_count 全部失败by SshPoolService（重连协程）
→手动 CloseConnection 调用by SshPoolService
→空闲超时回收（idle_timeout_seconds 到期）by SshPoolService（后台协程）
→手动 CloseConnection 调用by SshPoolService
🚫 closed 是终态：连接一旦进入 closed 状态，不可再转换为任何其他状态，对应的 SshConnection 实例从池中移除🚫 unhealthy → closed 不可逆：重新建立的是全新的 SSH 连接（新 connection_id），旧连接不会回到 idle🚫 closed 对应的文件描述符和 socket 资源完全释放，不允许任何复用尝试
⚡ 每个 ConnectionPool 实例持有一个独立的 asyncio.Lock，GetConnection 和 ReleaseConnection 在操作 idle_connections 队列和 in_use_set 集合前必须先获取锁；全局连接计数使用 asyncio.Semaphore 控制，避免全局锁竞争；后台健康检查协程与业务请求协程通过锁隔离，健康检查只在锁空闲时执行
跨服务规则
调用密钥管理服务 GetDecryptedKey 必须携带全局唯一的 request_id（UUID v4），密钥管理服务在审计日志中记录每次解密请求的 requestor、fingerprint 和 request_id
解密后的私钥在本服务中使用完毕后立即从内存中销毁（bytes 对象置空并触发 gc.collect），本服务不缓存私钥内容于任何数据结构中
当目标远程服务器集群的拓扑信息发生变更（如节点下线、IP 变更），依赖配置刷新通知本服务清理对应 host:port 的所有连接池实例
部署编排服务通过 GetConnection 获取连接句柄后，后续的 SCP/SFTP 文件传输和远程命令执行由部署编排服务直接通过同一 SSH 连接进行，本服务仅负责连接的获取、归还和健康管理
本服务无状态不持久化，重启后所有连接池清空，调用方需要在服务重启后重新 GetConnection

错误处理

处理策略

连接级错误按类型分级处理：网络级错误（连接拒绝、超时）自动重试最多 3 次后上报；认证级错误（密钥无效）立即终止并通知调用方；资源级错误（池满）返回 429 限流。所有错误以统一 gRPC 错误码格式返回，detail 字段包含请求 ID 用于审计追踪。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400

密钥认证失败
