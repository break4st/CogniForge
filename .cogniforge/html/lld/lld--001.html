概述

Deployment Service
⚙️ 业务服务
本模块负责执行「一键部署」的核心业务流程。它接收来自前端的部署请求，协调SSH客户端、加密服务等组件，完成从文件上传到远程脚本执行的完整部署流水线，并对整个生命周期进行状态管理和日志记录。
依赖: SSH Client ServiceEncryption ServiceProject ServiceEnvironment ServiceHistory & Log Service
Python 3.10+FastAPISQLite 3
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 部署任务的创建、执行与状态管理 部署前的本地文件、远程连接权限预检查 通过SFTP上传文件至远程服务器 在远程服务器上创建版本目录并执行部署脚本 部署过程实时日志记录
范围外: SSH连接的建立与管理（由SSH客户端组件提供） 凭证的加解密（由加密服务组件提供） 部署历史的持久化存储（由历史与日志服务组件提供） 项目与环境的配置管理（由项目服务组件和环境服务组件提供）
拥有组件: CMP-004
实现契约: CTR-004
消费契约: CTR-005 CTR-006 CTR-007 CTR-008

服务接口 (1)

🔧 DeploymentService 3 方法
execute_deployment
(deployRequest: DeployRequest) -> Deployment
异步执行完整的部署流水线：预检查 -> SFTP上传 -> 远程执行部署脚本 -> 记录日志与更新状态。
前置条件
deployRequest 中的 environmentId 对应的环境已通过连接测试且未被其他部署任务占用；本地 filePath 路径存在且可读。
后置条件
数据库中生成一条部署记录，其状态为终态(SUCCESS/FAILED/CANCELLED)；若成功，远程服务器目标路径下存在新部署的文件。
EnvironmentNotFoundException→ 404environmentId 在数据库中不存在FileNotFoundForUpload→ 400filePath 对应的文件不存在DeploymentInProgressException→ 409同一环境已有非终态的部署任务SshConnectionException→ 500创建SSH连接或认证失败DeploymentExecutionException→ 500远程执行部署脚本返回非零退出码
get_deployment_status
(deploymentId: Long) -> Deployment
根据ID查询部署任务的详细状态。
前置条件
deploymentId 对应的部署记录存在。
后置条件
返回该部署记录的当前状态信息。
DeploymentNotFoundException→ 404deploymentId 对应的记录不存在
cancel_deployment
(deploymentId: Long) -> Deployment
取消一个尚未开始执行的部署任务。
前置条件
deploymentId 对应的部署记录存在且状态为 PENDING。
后置条件
该部署记录的状态更新为 CANCELLED，且异步任务被中止。
DeploymentNotFoundException→ 404deploymentId 对应的记录不存在DeploymentNotCancellableException→ 409部署状态不为 PENDING，无法取消
数据访问依赖
DeploymentRepository.findById(deploymentId) -> Deployment?
DeploymentRepository.save(deployment) -> Deployment
DeploymentRepository.existsActiveByEnvironmentId(environmentId) -> boolean

业务规则

不变量
  • !一个环境同一时间只能有一个部署任务处于非终态（PENDING， UPLOADING， RUNNING）。
  • !部署任务的生命周期只能向前推进，终态（SUCCESS， FAILED， CANCELLED）不可逆转。
状态机
🎯 Deployment
PENDINGUPLOADINGRUNNINGSUCCESSFAILEDCANCELLED
→用户发起取消操作by User
→预检查通过，开始上传文件by System
→文件上传完成，开始执行远程脚本by System
→文件上传过程中发生错误by System
→远程脚本执行成功（退出码0）by System
→远程脚本执行失败（退出码非0）或执行过程异常by System
🚫 状态一旦变为 CANCELLED， SUCCESS 或 FAILED，则不可再变更为其他状态。
⚡ 创建部署时，需在数据库层面检查同一环境是否已有非终态记录，并利用唯一约束或乐观锁防止并发创建。
跨服务规则
在部署开始前，必须调用「环境服务组件」的 testConnection 接口（或复用其逻辑）对目标环境进行连接性预检查。
所有部署过程的日志输出，应通过调用「历史与日志服务组件」的 log 接口进行追加记录，实现日志的持久化和实时推送。

错误处理

处理策略

所有API层错误通过FastAPI异常处理器统一捕获，转换为标准错误响应格式。业务逻辑层异常向上抛出自定义异常，由控制器层映射为对应的HTTP错误码。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
4xx
客户端错误
包含参数校验失败(400)、资源未找到(404)、业务规则冲突(409)等。
5xx
服务端错误
包含SSH连接失败、文件I/O错误等内部处理异常，统一返回500，具体原因记录日志。
