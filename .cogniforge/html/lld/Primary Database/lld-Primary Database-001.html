概述

模块: Primary Database
主数据库（PostgreSQL 15+），作为系统唯一持久化数据源，存储所有业务数据。为 Project Management Service、Environment Management Service、Deployment Orchestrator、Key Management Service、Audit Service 提供结构化数据存取能力。采用 schema 分层隔离不同业务域，支持事务 ACID 保证，所有表使用 UUID 主键和 TIMESTAMPTZ 时间戳。
PostgreSQL 15+

错误处理

主数据库作为系统持久化层，所有错误由上层 Service 层封装处理，数据库层仅保证错误码和错误信息的准确传递。 (1)连接管理 — 使用连接池（max_open_conns=50, max_idle_conns=25, conn_max_lifetime=30min）。连接超时统一设置为 5s，写入超时 10s，查询超时 30s。超时错误返回 code=500 及 message='database operation timeout'。连接池耗尽时返回 code=503 及 message='database connection pool exhausted'。 (2)约束冲突 — 唯一约束（如 username、email、project name、environment name）冲突时返回 code=409 及明确冲突字段名，如 'project name already exists'。外键约束违反（如引用的项目 ID 不存在）返回 code=400 及 'referenced resource not found'。NOT NULL 约束违反由 ORM 层在参数校验阶段拦截。 (3)事务管理 — 涉及多表写操作（如创建项目同时写入审计日志、级联删除环境及其关联部署）使用数据库事务保证原子性。事务执行失败自动 ROLLBACK，返回 code=500。事务隔离级别使用 READ COMMITTED。Deployment Orchestrator 的状态更新操作使用悲观锁（SELECT FOR UPDATE）防止并发状态覆盖。 (4)数据完整性 — 所有表主键使用 UUID v4 避免自增 ID 暴露业务量。TIMESTAMPTZ 类型统一使用 UTC 时区存储，应用层负责时区转换。JSONB 字段在写入时由数据库层校验 JSON 合法性，格式无效返回 400。BIGSERIAL 类型用于日志流水表的主键生成。 (5)索引策略 — users(username, email) 建立唯一索引；projects(name) 建立唯一索引；environments(project_id, name) 建立联合唯一索引；deployments(project_id, created_at) 建立复合索引，task_id 建立唯一索引；deployment_logs(deployment_id, created_at) 建立复合索引；audit_logs(created_at) 建立索引支持分区裁剪，(resource_type, resource_id) 建立复合索引支持资源维度查询。 (6)分区策略 — audit_logs 表按 created_at 月分区（RANGE PARTITION BY created_at），每月自动创建新分区。deployment_logs 表按 created_at 月分区。超出当前分区的写入由应用层校验拒绝。 (7)NULL 策略 — 所有 JSONB 字段存储空值时使用 NULL 而非 '{}'，便于分区裁剪和索引优化。可选时间字段（started_at、completed_at）在状态未到达前为 NULL。条件为非必填字段在无值时使用 NULL。
