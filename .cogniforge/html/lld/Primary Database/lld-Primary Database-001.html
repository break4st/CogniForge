概述

Primary Database
系统主数据库PostgreSQL，持久化存储项目、环境、部署记录、审计日志、用户数据、SSH密钥元数据及部署文件等核心业务数据。作为系统的持久化层，为所有服务层模块提供数据存储和查询能力。采用连接池管理数据库连接，通过唯一约束和外键保障数据完整性。
PostgreSQL

数据模型 (8)

数据库表 8

🗄️ users权威定义

用户账户表。存储系统用户的核心身份信息和账号状态。username和email分别具有唯一约束。role字段控制用户的操作权限范围。is_active字段用于账号启用/禁用控制，禁用账号无法进行任何需要认证的操作。所有审计日志和资源创建记录通过created_by/operator字段关联此表。

字段
字段名类型描述
id *uuid用户唯一标识（主键），服务层自动生成UUID v4
username *varchar(100)用户名，唯一约束，登录凭证之一
email *varchar(255)用户邮箱，唯一约束，用于通知和密码找回
password_hash *varchar(255)密码bcrypt哈希值，不存储明文密码
display_namevarchar(100)用户显示名称，界面展示用
role *varchar(50)用户角色枚举：admin（系统管理员）、operator（运维操作员）、viewer（只读查看者）
is_active *boolean账号是否启用，默认true；禁用后拒绝该用户的所有认证请求
created_at *timestamp用户创建时间，默认为当前UTC时间
updated_at *timestamp用户信息最后更新时间，密码变更或资料修改时自动更新

🗄️ projects权威定义

项目表。存储项目的核心元信息，每个项目通过UUID唯一标识。name字段具有唯一约束，确保项目名称全局不重复。项目是系统的核心资源容器，环境（通过project_environments关联）、部署、文件均归属于某个项目。created_by字段关联users表记录创建者。

字段
字段名类型描述
id *uuid项目唯一标识（主键），服务层自动生成UUID v4
name *varchar(255)项目名称，唯一约束，长度1-255字符
descriptiontext项目描述，长度不超过2000字符
created_by *uuid创建者用户ID，关联users表
created_at *timestamp创建时间，默认为当前UTC时间
updated_at *timestamp最后更新时间，记录变更时自动更新

🗄️ project_environments权威定义

项目-环境关联表。记录项目与环境的多对多关联关系。通过project_id外键关联projects表，environment_id外键关联environments表。联合主键(project_id, environment_id)确保项目与环境不重复关联。此表使Project Management Service能够查询项目下的环境列表。

字段
字段名类型描述
project_id *uuid项目ID，联合主键一部分，关联projects表
environment_id *uuid环境ID，联合主键一部分，关联environments表
created_at *timestamp关联创建时间，默认为当前UTC时间

🗄️ environments权威定义

部署环境配置表。存储每个部署环境的SSH连接信息，通过project_id外键关联projects表实现项目间数据隔离。auth_type字段区分密钥认证（密钥）和密码认证（密码）两种方式，密码认证时password字段存储加密后的连接密码，密钥认证时key_id关联ssh_keys表中的密钥记录。同一项目下环境名称唯一，由联合唯一约束(project_id, name)保障。host字段存储服务器IP或域名，port默认为22。

字段
字段名类型描述
id *uuid环境唯一标识（主键），服务层自动生成UUID v4
project_id *uuid所属项目ID，关联projects表，实现项目间数据隔离
name *varchar(255)环境名称，同一项目下唯一（联合唯一约束）
host *varchar(255)服务器主机地址（IP或域名）
port *integerSSH连接端口号，默认22，范围1-65535
username *varchar(255)SSH登录用户名
auth_type *varchar(50)认证方式枚举：'密钥'（密钥认证）或'密码'（密码认证）
key_iduuid关联的SSH密钥ID，auth_type为'密钥'时必须提供，关联ssh_keys表
passwordtext连接密码（应用层AES-256-GCM加密存储），auth_type为'密码'时必须提供
tagsjsonb环境标签JSON数组，用于环境分类和检索，如["生产", "华北"]
descriptiontext环境描述说明，长度不超过2000字符
created_at *timestamp创建时间，默认为当前UTC时间
updated_at *timestamp最后更新时间，配置变更时自动更新

🗄️ ssh_keys权威定义

SSH密钥表。存储导入的SSH密钥对信息，包括密钥元数据（名称、类型、指纹）和加密后的私钥内容。private_key_encrypted字段使用Key Management Service的应用层AES-256-GCM加密后持久化，确保数据库层面的密钥数据安全。public_key以明文存储用于展示和指纹计算。type字段枚举RSA、ECDSA、Ed25519三种算法类型。fingerprint为公钥的SHA256摘要，导入时由服务层生成。通过created_by字段记录密钥导入操作人，用于审计追溯。

字段
字段名类型描述
id *uuid密钥唯一标识（主键），服务层自动生成UUID v4
name *varchar(255)密钥名称，用户在导入时指定的可读标识，唯一约束
public_key *textSSH公钥内容，OpenSSH authorized_keys格式明文存储
private_key_encrypted *text加密后的SSH私钥内容，服务层使用AES-256-GCM加密后持久化
type *varchar(20)密钥算法类型枚举：RSA、ECDSA、Ed25519
fingerprint *varchar(64)SSH公钥SHA256指纹，导入时由服务根据公钥内容计算
created_by *varchar(255)密钥导入操作人标识，从认证上下文中获取
created_at *timestamp记录创建时间，默认为当前UTC时间
updated_at *timestamp最后更新时间，密钥信息变更时自动更新

🗄️ files权威定义

部署文件表。存储部署操作所需的文件元数据和二进制内容。每个部署版本对应一个文件记录，通过project_id与项目关联。content字段以bytea格式存储文件原始二进制内容，size记录文件字节数，checksum存储SHA256校验和用于完整性验证。uploaded_by关联users表记录上传操作人。Deployment Orchestrator通过file_id关联此表获取部署文件内容。

字段
字段名类型描述
id *uuid文件唯一标识（主键），服务层自动生成UUID v4
project_id *uuid所属项目ID，关联projects表
name *varchar(255)文件名称，包含扩展名，如deploy.tar.gz
content *bytea文件二进制内容，以bytea格式直接存储在数据库中
size *bigint文件大小，单位字节
checksum *varchar(64)文件内容SHA256校验和，十六进制字符串，用于传输完整性验证
uploaded_by *uuid上传者用户ID，关联users表
created_at *timestamp上传时间，默认为当前UTC时间
updated_at *timestamp最后更新时间，文件信息变更时自动更新

🗄️ deployments权威定义

部署记录表。存储每次一键部署操作的核心信息，包括目标项目、目标环境、部署文件、版本号、当前状态及执行日志。status字段控制状态机流转：pending（等待执行）→ running（执行中）→ completed（成功）/ failed（失败）。logs字段以JSON数组格式记录部署各步骤（获取环境配置、获取SSH密钥、下载文件、文件传输、目录创建、脚本执行）的执行输出。version自动生成格式为yyyyMMdd-HHmmss-{deployment_id前8位}。通过project_id、environment_id、file_id分别关联projects、environments、files表。

字段
字段名类型描述
id *uuid部署唯一标识（主键），服务层自动生成UUID v4
project_id *uuid所属项目ID，关联projects表，实现项目间数据隔离
environment_id *uuid目标环境ID，关联environments表
file_id *uuid部署文件ID，关联files表
version *varchar(50)部署版本号，自动生成策略为yyyyMMdd-HHmmss-{deployment_id前8位}，也可手动指定
status *varchar(20)部署状态枚举：pending（待执行）、running（执行中）、completed（成功）、failed（失败）
notestext部署备注说明，用户在发起部署时可附带
logsjsonb部署执行日志JSON数组，每项含step（步骤名）、message（日志内容）、level（日志级别：info/warn/error）、timestamp（记录时间，ISO 8601格式）
started_attimestamp部署开始执行时间，status转为running时由Deployment Orchestrator记录
completed_attimestamp部署完成时间，status转为completed或failed时记录
created_at *timestamp记录创建时间，默认为当前UTC时间
updated_at *timestamp最后更新时间，状态变更或日志追加时自动更新

🗄️ audit_logs权威定义

审计日志表。记录系统中所有重要操作事件，包括部署操作、环境变更、密钥操作、项目变更等。action_type字段按'{模块}.{操作}'格式记录操作类型（如deployment.create、environment.create、environment.test-connection、key.import、project.create），result字段记录操作结果（success/failure），details字段以JSONB格式存储操作的详细上下文信息。通过project_id和environment_id实现与项目和环境维度的关联，支持跨模块的审计追溯。timestamp由调用方传入（记录业务操作的实际发生时间），created_at为日志记录入库时间。

字段
字段名类型描述
id *uuid审计日志唯一标识（主键），服务层自动生成UUID v4
action_type *varchar(100)操作类型，格式为'{模块}.{操作}'，如deployment.create、environment.create、key.import、project.create
operator *varchar(255)操作人标识，记录执行操作的用户或系统账号名
project_iduuid关联项目ID，操作涉及的项目（可选，全局性操作可不关联）
environment_iduuid关联环境ID，操作涉及的环境（可选）
detailsjsonb操作详情JSON，包含操作请求的上下文信息，如部署版本号、环境配置参数、操作请求字段等
result *varchar(20)操作结果枚举：success（成功）、failure（失败）
timestamp *timestamp操作发生时间戳，由调用方传入，记录业务的真实操作时间
created_at *timestamp日志记录创建时间，默认为当前UTC时间

错误处理

处理策略

PostgreSQL数据库层提供连接池管理、查询超时控制、自动重试和故障转移机制。连接池由各服务层的数据库驱动（asyncpg/psycopg2）管理，配置最大连接数、空闲连接超时和等待队列长度。数据库异常（连接失败、约束违反、死锁）由服务层Repository捕获并转换为业务异常。不直接对外暴露HTTP接口，所有数据库访问均通过各服务的数据访问层中转。

08001
数据库连接失败
服务层无法与PostgreSQL建立TCP连接。可能原因：数据库服务宕机、网络不通、连接池耗尽、认证失败。各服务的数据访问层应配置连接重试机制（最多3次，间隔1s/2s/4s），重试全部失败后由服务层组件捕获并抛出DatabaseConnectionError，由上层转换为HTTP 500响应。
23505
唯一约束违反
INSERT或UPDATE操作违反表的唯一约束。常见场景：创建项目时name已存在（projects.name）、创建环境时同一project_id下name重复（environments联合唯一约束(project_id, name)）、导入密钥时名称冲突（ssh_keys.name）、注册用户时username或email重复（users.username/users.email）。各服务层Repository捕获此错误码后转换为对应的业务异常（如ProjectNameConflictError），由上层转换为HTTP 409响应并返回具体冲突字段说明。
23503
外键约束违反
INSERT或UPDATE操作引用不存在的外键记录，或DELETE操作存在依赖子记录。常见场景：创建环境时project_id或key_id在父表中不存在、创建部署时environment_id或file_id不存在、删除项目时仍有关联的环境或部署记录。各服务层Repository捕获后由上层转换为HTTP 404（引用不存在）或HTTP 409（存在子记录阻止删除）。
40P01
死锁检测
并发事务因循环等待被PostgreSQL死锁检测机制终止。通常发生在多个事务以不同顺序锁定相同表时。各服务层应配置死锁重试逻辑（捕获后等待随机毫秒后重试1次），同时规范所有数据访问层的事务中表锁定顺序，降低死锁概率。
57014
查询超时
SQL语句执行超过statement_timeout配置阈值。各服务层为不同查询设置合理的超时时间：简单查询（按主键/索引查询）5s、复杂查询（多表关联/模糊搜索）15s、批量写入操作30s。超时发生后由上层转换为HTTP 504或HTTP 500响应。
53300
连接数超限
数据库活动连接数达到max_connections上限，拒绝新连接。各服务层连接池应配置合理的max_size（建议服务层每实例10-20），并设置连接等待超时（建议5s）。此错误通常表明连接泄漏或突发流量，需通过监控告警排查。
