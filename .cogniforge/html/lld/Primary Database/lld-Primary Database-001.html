概述

Primary Database
🗄️ 数据库层
关系型数据库（PostgreSQL 15），存储系统全部持久化数据，包括用户账号、项目信息、环境配置、SSH 密钥元数据、部署记录与审计日志。作为系统的数据核心层，通过外键约束维护跨表数据完整性，通过 B-tree 索引保障常用查询性能，通过连接池管理各微服务的数据库访问。所有表的 DDL 和数据迁移统一由本模块管理，各微服务通过独立数据库账号按最小权限原则访问。
PostgreSQL 15Docker + Docker Compose

系统用户账号表，存储用户身份认证信息和角色权限。被 projects、environments、deployments 等表通过 created_by 外键引用。由 API Gateway 或独立认证模块管理数据写入，本模块仅提供 DDL 定义。

迁移策略

工具: Flyway命名: V{4 位序列号}__{描述性英文名称}.sql，如 V0001__create_users_table.sql

回滚策略: 每个版本必须提供对应的回滚脚本，命名格式为 V{4 位序列号}__{描述性英文名称}__rollback.sql。回滚由运维人员手动触发，不支持自动回滚。回滚需经过变更审批流程后才可执行。生产环境回滚前必须备份受影响表数据。

容量估算

1年: users: 50 行, projects: 500 行, ssh_keys: 1,000 行, environments: 1,500 行, deployments: 5,000 行, audit_logs: 100,000 行3年: users: 200 行, projects: 2,000 行, ssh_keys: 5,000 行, environments: 6,000 行, deployments: 25,000 行, audit_logs: 500,000 行
热表: deployments（高频更新状态和进度） audit_logs（高频追加写入、按时间范围查询）

分区策略: audit_logs 表按 logged_at 进行按月范围分区（RANGE PARTITION BY MONTH），保留 12 个分区后自动轮换裁剪。deployments 表数据量可控暂不分区，但预留分区字段 logged_at 便于后续扩展。其余表数据量较小不需分区。

连接池: 每个微服务 10-15 个连接，总连接池大小约 80 连接（PostgreSQL max_connections 建议设为 150 预留余量）超时: 连接超时 30 秒，空闲连接回收 300 秒，连接最大存活时间 1800 秒

错误处理

处理策略

数据库层错误统一通过 PostgreSQL SQLSTATE 错误码分类，由各微服务的数据库驱动层捕获并转换为业务异常。连接池使用 HikariCP 风格配置，空闲连接超时自动回收。唯一约束冲突、外键违规、死锁等可重试错误由调用方按策略指数退避重试。连接池耗尽时快速失败（fail-fast），不阻塞等待。

统一错误响应体
字段类型
codeinteger (DB 错误码)
errorstring (错误分类标识)
detailstring (详细错误信息，包含违规约束名和冲突值)
23505
唯一约束冲突
INSERT 或 UPDATE 违反 UNIQUE 约束，如项目名称重复、密钥指纹重复。调用方应当捕获后返回 409 Conflict。推荐最大重试 1 次。
23503
外键约束违规
INSERT 或 UPDATE 时引用的外键记录不存在，如 environment_id 引用不存在的环境。调用方应当返回 400 或 404。
40P01
检测到死锁
并发事务死锁，PostgreSQL 自动回滚当前事务。调用方应当在捕获后全量重试事务，指数退避间隔 100ms/200ms/400ms，最多 3 次。
08003
数据库连接断开
PostgreSQL 连接意外断开，连接池自动移除失效连接并创建新连接。调用方应当重试操作。
08006
连接失败
数据库不可达或拒绝连接。连接池启动重连机制，间隔 1s/2s/4s/8s 指数退避。调用方应当返回 503 Service Unavailable。
53100
磁盘空间不足
数据库所在磁盘空间不足，无法执行写入操作。触发运维告警，人工介入清理或扩容。
57014
查询取消或超时
查询执行超过 statement_timeout 配置阈值（默认 30s）。调用方应当优化查询或拆分为批量操作。
