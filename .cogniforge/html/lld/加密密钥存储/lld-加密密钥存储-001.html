概述

加密密钥存储
🗄️ 数据库层
专用于SSH私钥的安全存储模块，数据经AES-256加密后落盘，与主数据库隔离，仅允许密钥管理服务通过内部网络访问
PostgreSQL 15
🗄️

数据模型 (3)

数据库表 3

🗄️ encrypted_keys权威定义

加密SSH私钥主表，存储经AES-256-GCM加密后的私钥密文及元数据，支持密钥生命周期管理（active/revoked/compromised）

字段
字段名类型描述
id *uuid主键，UUID v4自动生成
name *varchar(128)密钥名称/标签，用于人工辨识
encrypted_private_key *textAES-256-GCM加密后的SSH私钥密文（Base64编码）
public_keytext公钥内容（OpenSSH格式），用于指纹校验和身份确认
fingerprint *varchar(64)SSH密钥指纹（MD5格式），用于密钥唯一标识和快速检索
algorithm *varchar(32)密钥算法，如 RSA、Ed25519、ECDSA 等
encryption_key_version *varchar(32)加密时使用的主密钥版本号，用于密钥轮转时识别解密密钥
key_checksumvarchar(128)原始私钥的SHA256校验和，解密后用于完整性验证
status *varchar(20)密钥状态：active=可用，revoked=已吊销，compromised=已泄露
descriptiontext密钥备注说明
metadatajsonb扩展属性，如密钥来源、标签、自定义字段等
created_at *timestamptz记录创建时间
updated_at *timestamptz记录最后更新时间
deleted_attimestamptz软删除时间戳，非NULL表示已删除

索引名唯一列

🗄️ key_access_audit权威定义

密钥访问审计表，记录所有密钥解密、读取、删除等敏感操作的审计轨迹，满足安全合规要求

字段
字段名类型描述
id *bigserial自增主键
key_id *uuid被访问的密钥ID，关联encrypted_keys.id
requester_service *varchar(64)请求方服务名称，如 key_management_service、ssh_connection_pool
requester_identityvarchar(128)请求方内部身份标识，如用户ID或实例ID
action *varchar(32)操作类型：decrypt=解密，read=读取密文，delete=删除，list=列举
result *varchar(16)操作结果：success=成功，failure=失败，denied=拒绝
failure_reasonvarchar(256)失败或拒绝原因描述
client_ipvarchar(45)请求来源IP地址（支持IPv4/IPv6）
detailtext操作详情附加信息
accessed_at *timestamptz操作发生时间
索引
索引名唯一列
pk_key_access_audit✓id
idx_key_access_audit_key_idkey_id
idx_key_access_audit_accessed_ataccessed_at
idx_key_access_audit_resultresult
idx_key_access_audit_actionaction

🗄️ master_encryption_keys权威定义

主加密密钥版本管理表，存储用于加密SSH私钥的AES-256主密钥材料（自身加密存储），支持密钥轮转

字段
字段名类型描述
id *uuid主键，UUID v4自动生成
key_version *varchar(32)密钥版本标识符，如 v1、v2、v20260501，全局唯一
encrypted_key_data *text经KMS或passphrase加密后的主密钥材料（Base64编码）
algorithm *varchar(32)加密算法，默认 AES-256-GCM
is_active *boolean是否为当前激活的主密钥（只有一条记录为true），新增密钥使用此版本加密
activated_attimestamptz密钥激活时间
deactivated_attimestamptz密钥停用时间（轮转时记录）
created_at *timestamptz记录创建时间
notestext密钥轮转备注，如轮转原因、旧版本兼容说明等
索引

📈

容量估算

1年: encrypted_keys: ~500行（按100个环境、每环境平均5次密钥轮转估算）；key_access_audit: ~50万行（每次部署触发1-2次解密，预估年部署量25万次）；master_encryption_keys: ~5行（年度密钥轮转2-4次）3年: encrypted_keys: ~1,500行；key_access_audit: ~150万行；master_encryption_keys: ~15行
热表: encrypted_keys（高频读取：部署流程每次均需读取密钥密文） key_access_audit（高频写入：每次密钥操作均需写入审计记录）

分区策略: key_access_audit表按月分区（RANGE分区 on accessed_at），支持自动创建新分区，提升清理旧数据和查询性能；encrypted_keys和master_encryption_keys数据量小，无需分区

🔗

连接配置

连接池: 最小5，最大20（加密密钥存储仅密钥管理服务访问，并发量低）超时: 连接超时5秒，读超时10秒，写超时10秒
服务账号权限
密钥管理服务key_mgr_userSELECT（读取密钥密文、查询元数据、审计记录） INSERT（写入密钥密文、写入审计记录、新增主密钥版本） UPDATE（更新密钥状态、更新活跃主密钥标记） DELETE（仅软删除，设置deleted_at字段）

错误处理

处理策略

数据库层采用事务保障一致性，所有写操作在事务内完成；密钥访问审计记录独立于业务事务，采用异步写入确保不阻塞主流程；加密/解密异常由上层密钥管理服务捕获并记录，数据库层不处理加解密逻辑
