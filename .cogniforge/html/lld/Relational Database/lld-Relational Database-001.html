概述

模块: Relational Database

关系型数据库作为系统的主存储，持久化所有业务数据。在微服务共享数据库架构下，所有服务（Student Service、Class Service、Grade Service、Statistics Service、API Gateway）共同访问同一关系型数据库实例。数据库包含五张核心业务表：users（用户认证）、students（学生信息）、classes（班级信息）、grades（年级信息）和 study_records（学习记录）。数据库层面不设跨表外键约束，各表之间的引用完整性由应用层（微服务）通过 REST 调用校验保证，以保持服务间的松耦合。索引策略覆盖所有高频查询和筛选场景，包括唯一索引（学号、年级名称、用户名）、单列索引（班级 ID、名称、科目、日期）和联合索引（学生+科目+日期）。系统采用连接池管理数据库连接，所有写操作均在事务中执行，读操作支持读写分离以提升查询性能。SQL 聚合查询（COUNT、SUM、AVG、MAX、MIN）用于实时统计数据计算，不采用预聚合持久化策略，保证数据源始终为最新。

接口定义 (8)

数据库连接池

datasource: jdbc:mysql://<host>:<port>/cogniforge

系统使用 HikariCP 连接池管理数据库连接。连接池配置：初始连接数 10，最小空闲连接数 5，最大连接数 50，连接超时 30 秒，空闲超时 10 分钟，最大生命周期 30 分钟。所有服务共享同一数据源配置。连接池提供读/写分离能力——写操作路由到主库，聚合查询（如统计计算）可路由到只读从库以分摊读压力。连接有效性检测使用心跳 SQL（SELECT 1），间隔 60 秒。

参数类型描述
jdbc_urlstringJDBC 连接 URL，包含主机、端口、数据库名及连接参数（useSSL=true&characterEncoding=utf8mb4&serverTimezone=Asia/Shanghai）
pool_namestring连接池名称，用于监控区分
maximum_pool_sizenumber最大连接数，默认 50
connection_timeoutnumber连接超时时间（毫秒），默认 30000

事务管理

transaction: TX_REQUIRED

所有写操作（INSERT、UPDATE、DELETE）均在事务中执行。事务传播行为采用 REQUIRED（支持当前事务，不存在则创建新事务）。隔离级别采用 READ_COMMITTED（读已提交），避免脏读同时保持较好的并发性能。事务超时默认 10 秒。Service 层的 @Transactional 注解管理事务边界，确保一组数据库操作要么全部成功提交，要么全部回滚。跨服务的分布式事务由应用层通过最终一致性保证，不采用 XA 分布式事务。

参数类型描述
propagationstring事务传播行为: REQUIRED
isolationstring事务隔离级别: READ_COMMITTED
timeoutnumber事务超时时间（秒），默认 10
rollback_forstring触发回滚的异常类型: Exception.class

错误处理

Relational Database 按以下规则处理异常：1）连接失败——应用启动时数据库不可达或运行中连接中断时，连接池抛出异常，应用应重试连接并记录 ERROR 级日志，重试间隔 5 秒，最多重试 3 次后触发服务启动失败告警；2）唯一约束冲突——INSERT 或 UPDATE 操作违反 UNIQUE INDEX（学号重复、年级名称重复、用户名重复）时，数据库抛出 DuplicateKeyException 或 IntegrityConstraintViolationException，由各 Service 层捕获后转化为 409 Conflict HTTP 响应返回给调用方；3）死锁——并发写入产生死锁时（DeadlockLoserDataAccessException），数据库自动选择牺牲一个事务并回滚，应用层检测到死锁异常后自动重试当前事务最多 3 次，每次重试前随机等待 100-500ms 以降低再次冲突概率；4）查询超时——复杂聚合查询（如年级统计跨多表关联）超过配置的查询超时阈值（默认 10 秒）时抛出 QueryTimeoutException，由 Service 层捕获后记录 WARN 日志，返回 504 Gateway Timeout 响应并考虑添加索引优化或拆分查询；5）事务回滚——任何 RuntimeException 在事务方法内抛出时触发事务回滚（rollbackFor = Exception.class），保证数据一致性，回滚后不需要重试的分支返回 500 Internal Server Error 给调用方；6）连接池耗尽——所有连接被占用且等待超过 connectionTimeout（30 秒）时，连接池抛出 SQLException，由 Service 层捕获后返回 503 Service Unavailable 响应体为 {"error": "service_unavailable", "message": "数据库连接池已满，请稍后重试"}；7）数据截断——写入的字段长度超过表定义（如 VARCHAR(100) 写入超过 100 字符）时抛出 DataTruncation 异常，由 Service 层捕获后转化为 422 响应并提示具体字段超长；8）SQL 注入防御——所有 SQL 操作必须使用参数化查询（PreparedStatement / MyBatis #{param}）或 ORM 框架（MyBatis/Spring Data JPA），禁止字符串拼接 SQL。所有数据库操作记录慢查询日志，执行时间超过 1 秒的 SQL 输出 WARN 级日志，包含 SQL 文本、参数值和执行耗时，供后续 DBA 优化参考。
