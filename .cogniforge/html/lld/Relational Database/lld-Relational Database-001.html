概述

模块: Relational Database

基于 MySQL/PostgreSQL 的关系型数据库层，作为系统的核心持久化存储，承载所有业务数据的存储与访问。采用按业务领域分表的 schema 设计原则，包含 5 组业务模块共 10 张核心业务表：学生(student)、班级(class)、班级-学生关系(class_student)、年级(grade)、学生统计(student_statistics)、班级统计(class_statistics)、年级统计(grade_statistics)、统计任务(statistics_task)，以及基础设施表：用户(user)、审计日志(audit_log)、schema 迁移记录(schema_migrations)。全部采用逻辑删除（deleted_at 标记）保证数据可追溯。外键约束在业务层通过 Service 调用校验（Student/Class/Grade/Statistics Service 各自负责所属表的写入），数据库中不设物理外键以降低耦合和提升写入性能。所有表使用 InnoDB 引擎（MySQL）并统一使用 utf8mb4 字符集；时间字段统一使用 datetime 类型，创建/更新时间由数据库自动填充。核心查询字段建立索引以覆盖各 Service 的查询模式（学号唯一索引、年级下同级班级名称联合唯一索引、外键关联索引等）。

接口定义 (7)

数据库连接初始化

内部接口 - 各 Service 启动时调用

各业务 Service 在启动时通过配置中心读取数据库连接参数（host、port、database、user、password），建立连接池。连接池采用 HikariCP（Java）/ pg-pool（Node.js）等成熟实现，支持健康检查和自动重连

健康检查 - 数据库连通性

各 Service 内部健康检查

各 Service 定期执行 SELECT 1（MySQL）或 SELECT 1（PostgreSQL）探测数据库连通性，响应超时（>3s）触发告警并尝试重连

Schema 迁移执行

内部接口 - 应用部署时执行

应用部署时自动执行 schema_migrations 表中未应用的迁移脚本。迁移脚本文件按编号顺序存放在 db/migrations/ 目录，幂等执行（每个版本只执行一次）。迁移失败时回滚当前版本并中止部署，人工介入排查

事务模板

各 Service Repository 层通用模式

所有写操作（INSERT/UPDATE/DELETE）必须在事务内执行，事务边界由 Service 层控制。默认隔离级别 READ COMMITTED。事务内操作顺序要求：先查后写避免死锁，多个行更新按主键 ID 升序锁定。事务超时默认 10 秒，超过自动回滚

数据库主从读写分离

内部架构模式

数据库采用主从复制架构（MySQL Replication / PostgreSQL Streaming Replication）。写操作（INSERT/UPDATE/DELETE）路由到主库（Master），读操作（SELECT）根据场景路由：实时性要求高的查询（如写入后立即查询详情）走主库，允许秒级延迟的报表/统计查询走从库（Slave）。主从延迟监控阈值为 5 秒，超过触发告警并自动将查询切回主库

慢查询日志

数据库监控配置

启用数据库慢查询日志，记录执行时间超过 200ms 的 SQL。慢查询日志输出到文件或集成监控系统（如 Prometheus + Grafana），用于 DBA 和开发团队优化索引和查询性能。定期（每周）审查慢查询并进行索引优化

数据备份恢复

运维操作

数据库全量备份每日凌晨 02:00 执行（mysqldump / pg_dump），保留最近 7 天备份。增量 Binlog 日志保留 72 小时。备份文件加密存储至远程对象存储。灾难恢复 RTO 目标 30 分钟，RPO 目标 1 小时

⚠️

错误处理

数据库层错误统一在各 Service 的 Repository 层捕获并转换为业务异常向上抛出，不外泄原始数据库错误信息到 API 响应。分类处理：连接超时（ECONNREFUSED / 08001）→ 重试最多 3 次（指数退避，间隔 100ms/500ms/2s），重试耗尽后抛出 ServiceUnavailableError；死锁检测（1213 / 40001）→ 自动回滚当前事务后重试最多 2 次，重试耗尽后抛出 ConcurrencyConflictError；唯一键冲突（1062 / 23505）→ 转换为 ConflictError(message: '记录已存在') 携带具体字段名；外键约束违反（1451 / 23503）→ 转换为 BadRequestError(message: '关联数据不存在')；查询超时（statement_timeout）→ 记录慢查询日志并抛出 TimeoutError(message: '查询执行超时')。事务回滚后连接归还连接池，不影响后续请求。批量写入（如统计数据入库）中单条失败不影响整体，跳过失败记录并记录告警日志。数据迁移失败时回滚当前版本并中止后续版本执行。所有数据库操作必须有对应的 Prepared Statement 参数化查询防止 SQL 注入；禁止在业务代码中拼接 SQL 字符串。逻辑删除字段（deleted_at）必须由 Repository 层统一在基础查询方法中附加 WHERE 条件（软删除过滤器），各业务 Service 的 Repository 继承该过滤器以确保不遗漏。
