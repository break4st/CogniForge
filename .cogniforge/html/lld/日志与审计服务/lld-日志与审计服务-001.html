概述

日志与审计服务
⚙️ 业务服务
日志与审计服务是从消息队列中消费部署日志，将其持久化存储，并提供部署历史与详情查询 API 的后端服务。它维护部署记录的完整生命周期，并为前端和审计需求提供数据。
依赖: RabbitMQ（消息队列，消费部署日志）PostgreSQL（持久化存储）API 网关（请求入口）
PythonFastAPIPostgreSQLRabbitMQJWT (JSON Web Tokens)
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 消费 RabbitMQ 消息队列中的部署日志，存储为结构化的部署记录 提供按项目、时间范围、状态等条件查询部署记录的 REST API 记录密钥创建、吊销等安全审计事件 管理 DeploymentRecord 实体的生命周期和状态转换 确保日志持久化存储的可靠性和一致性
范围外: 部署流程的编排与执行（归属部署编排服务） 项目、环境、密钥等数据的管理（归属对应服务） 前端页面渲染 消息队列的运维管理
拥有组件: CMP-007
实现契约: CTR-005

编排流程

部署日志消费主流程

从消息队列消费部署日志，解析并持久化存储的流程

1
消费消息 (30s 超时)
从 RabbitMQ 队列中取出部署日志消息
失败处理: 记录消费失败日志，消息重新入队
2
解析消息 (10s 超时)
验证消息格式和必要字段，提取部署事件数据
失败处理: 丢弃消息并记录错误日志，发送告警
3
持久化存储 (10s 超时)
将部署记录写入数据库，初始状态为 in_progress 或根据消息确定
失败处理: 重试写入，最多 3 次；仍失败则记录错误并丢弃消息
重试策略: 最多 3 次，间隔 30s
可重试错误: NETWORK_ERROR, TIMEOUT
不可重试错误: AUTH_ERROR, CONFIG_ERROR

错误处理

处理策略

所有 API 异常通过全局异常过滤器捕获，统一返回标准 JSON 错误体；消息消费异常单独记录并依赖重试机制。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
请求参数错误
当查询参数不符合预期的类型或范围（如 project_id 非 UUID、status 不在枚举值中）时返回 400，detail 中说明具体参数问题。
401
认证失败
当请求缺少有效 JWT 或令牌已过期时返回 401，detail 提示认证失败原因。
403
权限不足
当调用方无权访问指定项目的部署记录时返回 403，detail 说明权限不足。
404
记录不存在
当查询单条部署记录（如 GET /api/v1/deployments/{id}）但记录 ID 不存在时返回 404，detail 包含未找到的 ID。
422
请求体验证失败
当请求体 JSON 格式错误或字段不满足约束（如缺少必填字段）时返回 422，detail 列出验证失败的具体字段和原因。
500
内部服务错误
当数据库连接失败、消息队列异常、未知运行时错误发生时返回 500，detail 为通用错误描述，原始异常记录在服务器日志中。
503
服务不可用
当依赖服务（如 RabbitMQ）不可达、数据库连接池耗尽时返回 503，detail 提示服务暂时不可用，请稍后重试。
