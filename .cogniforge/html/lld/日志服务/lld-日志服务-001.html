概述

日志服务
⚙️ 业务服务
日志服务负责接收部署引擎在执行每一步操作时产生的结构化日志条目，将其持久化到数据库，并通过WebSocket即时推送给发起部署的桌面客户端。同时提供历史日志检索能力。
依赖: 部署引擎 (CMP-006)数据持久层 (CMP-011)API网关 (CMP-002)
Python 3.11+FastAPISQLite (via SQLAlchemy)asyncio
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 接收部署引擎产生的步骤日志并结构化存储 管理WebSocket连接，按部署ID分组实时推送日志至客户端 部署结束时推送最终状态消息并主动关闭WebSocket连接 提供历史日志查询接口，支持按部署ID、项目、环境、时间范围等过滤
范围外: 部署流程的编排与执行 环境配置管理及SSH连接 用户认证与鉴权（由网关层统一处理） 日志的聚合分析与告警
拥有组件: CMP-007

服务接口 (1)

🔧 LogService 4 方法
connect_log_stream
async connect_log_stream(websocket: WebSocket, deployment_id: int) -> None
客户端通过WebSocket连接到指定部署的日志流，服务端持续推送日志条目。
前置条件
deployment_id 必须存在且部署正在进行中
后置条件
WebSocket连接建立，并持续推送日志直到部署结束或客户端断开
WebSocketDisconnect→ 当客户端网络断开或关闭连接时DeploymentNotFound→ 当提供的deployment_id无效时
receive_log_entry
async receive_log_entry(entry: LogEntry) -> None
接收部署引擎发送的结构化日志条目并持久化，同时广播到相关WebSocket客户端。
前置条件
entry.deployment_id 必须有效，且部署正在进行
后置条件
日志条目被保存到数据库，并广播至所有监听的WebSocket客户端
DeploymentNotFound→ 当deployment_id在部署表中不存在时DatabaseWriteError→ 当数据库操作异常时
send_deployment_status
async send_deployment_status(deployment_id: int, final_status: str) -> None
部署引擎通知日志服务部署已结束，日志服务生成最终状态消息并通过WebSocket推送。
前置条件
deployment_id 必须存在，final_status 为 'success' 或 'failed'
后置条件
最终状态消息被推送至所有相关WebSocket连接，并关闭这些连接
InvalidStatus→ 当final_status不是'success'或'failed'时
query_log_entries
async query_log_entries(filters: LogQueryFilter) -> PaginatedLogEntries
根据过滤条件查询历史日志条目，支持分页。
前置条件
过滤器对象必须有效（至少提供一个查询条件）
后置条件
返回符合条件的分页日志条目列表
InvalidFilter→ 当时间格式错误或page/per_page非正整数时DatabaseQueryError→ 当数据库操作异常时
不变量
  • ![invariant] 日志条目一旦创建便不可修改或删除，确保审计完整性
  • ![constraint] 每个部署任务只能有一个活跃的最终状态推送
  • ![precondition] WebSocket连接必须与一个有效的、正在进行的部署相关联
  • ![precondition] 只有正在进行的部署才能接收新的日志条目

错误处理

处理策略

统一错误处理策略：所有接口异常均返回标准化的错误对象，包含错误码、描述和解决方案。业务异常通过预定义的异常类型捕获，数据库异常重试一次后返回500错误，WebSocket异常记录日志并清理连接。
