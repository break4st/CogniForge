概述

环境配置服务
⚙️ 业务服务
部署环境配置管理服务，维护远程服务器连接参数和环境状态，提供环境的CRUD操作、连接测试、状态管理以及与项目的关联查询能力。所有环境配置数据持久化在 PostgreSQL 主数据库中，SSH 连接测试依赖 SSH 连接池服务和密钥管理服务
依赖: PostgreSQL主数据库密钥管理服务SSH连接池服务审计日志服务
PythonFastAPIPostgreSQL 15RESTJWTParamiko

业务规则

不变量
  • !环境名称在同一租户下必须唯一，不可创建或重命名至已存在的名称
  • !环境创建时初始状态必须为 unknown，由连接测试驱动后续状态转换
  • !环境必须关联一个有效的 SSH 密钥（key_id 引用 ssh_keys 表中的未删除记录）
  • !key_id 被修改时，status 必须自动重置为 unknown，确保下次部署前重新验证连接
  • !已软删除的环境不可用于部署、连接测试或项目绑定
  • !host + port + login_user 三元组应避免重复配置同一远程服务器（软约束，系统给出告警而非阻止）

🚫 状态转换仅由系统自动驱动（连接测试或密钥变更），不支持人工直接设置 status 字段🚫 unknown → online 和 unknown → offline 是初始状态的唯二合法出口，创建后不可停留在 unknown 而不做测试
⚡ 连接测试使用分布式锁防止同一环境的并发测试请求，锁 Key 格式 env:test-lock:{environment_id}，TTL 30 秒。并发请求中后到者直接返回 HTTP 429（Too Many Requests），由调用方决定重试策略
跨服务规则
所有写操作（创建、更新、删除、连接测试）完成后，必须调用审计日志服务 POST /api/audit/logs 记录操作，请求体包含 action、actor、resource_type（environment）、resource_id、detail 和 result 字段
创建和更新环境时，需向密钥管理服务校验 key_id 的有效性（密钥存在且未删除），不可直接写入未经校验的 key_id
连接测试时，先通过密钥管理服务获取解密后的 SSH 密钥明文，再调用 SSH 连接池服务建立 Paramiko SSH 连接
删除环境前须通过 deployments 表查询确认无关联的活跃（pending/running）部署记录，此查询依赖 PostgreSQL 的数据一致性
环境被软删除后，project_environments 表中的关联记录不会级联删除，由项目管理服务维护关联关系的清理逻辑
环境配置服务不直接操作 SSH 密钥的加密/解密，所有密钥操作委托给密钥管理服务

错误处理

处理策略

采用统一错误响应格式，业务层异常由全局异常处理器捕获并转换为标准 HTTP 响应。参数校验在 FastAPI 路由层通过 Pydantic 模型自动完成。数据库约束冲突（唯一键、非空）转换为业务语义的错误码。调用外部服务（SSH 连接池、密钥管理）的异常统一包装为 503，审计日志写入失败不应阻塞主流程
