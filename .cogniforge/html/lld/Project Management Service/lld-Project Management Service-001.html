概述

Project Management Service
⚙️ 业务服务
管理项目生命周期的微服务，提供项目的创建、编辑、删除、查询、项目与环境的关系绑定、项目级别配置管理等核心能力。接收来自 API Gateway 的 RESTful 请求，直接操作 Primary Database 持久化项目数据，关键操作同步发送审计日志至 Audit Service。项目与环境的关联通过 project_id 外键隐式维护，由 Environment Management Service 在环境创建时校验项目存在性。
依赖: API GatewayPrimary DatabaseAudit Service
Python 3.11+FastAPIasyncio + uvicornPostgreSQL 15Docker + Docker Compose

业务规则

不变量
  • !同一用户下项目名称唯一，比较不区分大小写
  • !项目名称长度 1-100 字符，不可为纯空白字符串
  • !项目标签最多 10 个，每个标签长度 1-30 字符
  • !仅 status=active 的项目可修改信息和配置
  • !仅 status=active 的项目可被删除（归档），已归档项目不可二次删除
  • !项目下存在 status=pending 或 running 的部署记录时，禁止删除和归档该项目
状态机
🎯 Project
activearchived
→deleteProject / archiveProjectby 项目创建者或管理员
→restoreProjectby 管理员
🚫 deleteProject 操作将状态改为 archived 后，记录不可在普通查询中显示（仅管理员可通过直接 ID 查询访问）🚫 restoreProject 恢复操作仅管理员可执行，普通创建者不可自行恢复已归档项目
⚡ 使用 PostgreSQL 行级锁（SELECT FOR UPDATE）保护状态变更操作。更新时使用 COALESCE(updated_at, now()) 乐观锁检测，若 updated_at 与读取时不符则重试。同一项目不允许并行状态变更。
跨服务规则
项目创建/更新/删除后同步发送审计事件到 Audit Service 的 POST /internal/audit/log 接口，审计调用失败不影响主流程（异步 fire-and-forget，本地记录失败日志）
删除项目前通过 Deployment Orchestrator 的 GET /api/v1/deployments 接口（filter by project_id）查询是否存在活跃部署记录
项目状态变更后，Environment Management Service 和 Deployment Orchestrator 无需同步感知——关联查询时通过 project_id 自行校验项目存在性
所有涉及项目存在性的跨服务查询（如环境创建时校验 project_id）直接查询本服务的 projects 表数据库视图（Primary Database 共享），不经过 HTTP 级联调用

错误处理

处理策略

Project Management Service 对所有请求参数进行前置校验，校验失败返回 400；业务逻辑错误（重复名称、状态冲突、活跃部署阻止操作）返回 409；资源不存在返回 404；认证和鉴权委托 API Gateway 处理，本服务不直接签发或验证 JWT，但仍实现内部角色检查返回 403。所有未预期异常由全局异常处理器捕获，返回 500 并记录错误日志，同时向 Audit Service 发送失败审计事件。

500
服务内部错误
数据库连接失败、审计调用失败、未预期的运行时异常
