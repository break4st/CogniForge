概述

Audit Service
⚙️ 业务服务
全操作审计日志服务，记录所有关键操作事件。提供统一的审计日志写入接口，供 Project Management Service、Environment Management Service、SSH Execution Service、Deployment Orchestrator、Key Management Service 等微服务调用记录关键操作。审计日志持久化存储至 Primary Database，并提供查询和导出能力供 Web Console 管理界面使用。
依赖: API GatewayPrimary Database
Python 3.11+FastAPIasyncio + uvicornPostgreSQL 15Docker + Docker Compose
🗄️

服务接口 (1)

🔧 AuditService 4 方法
writeAuditLog
(request: AuditLogWriteRequest) -> AuditLogWriteResponse
写入审计日志。校验请求体必填字段和字段格式，补全 id（UUID v4）和 logged_at（当前 UTC 时间），同步写入 PostgreSQL audit_logs 表。写入成功后返回审计记录标识和时间戳。
前置条件
request.action 非空且长度 <= 255；request.actor 非空；request.resource_type 为 ResourceType 枚举值；request.resource_id 为合法 UUID；request.result 为 success 或 failure；PostgreSQL 连接可用且 audit_logs 表可写入
后置条件
审计日志记录已持久化到 Primary Database audit_logs 表（INSERT），包含系统生成的 id（UUID v4）和 logged_at（服务端 UTC 时间戳）。返回 AuditLogWriteResponse（audit_id + logged_at）。调用方可凭 audit_id 后续查询此条审计日志详情
ValidationException→ 400请求体校验失败：action 为空或超长（>255）、actor 为空、resource_type 为空或不是 ResourceType 合法值、resource_id 非 UUID 格式、result 不是 success/failureDatabaseWriteException→ 500PostgreSQL 写入失败（连接断开、约束冲突、磁盘满等），审计日志无法持久化
queryAuditLogs
(params: AuditLogQueryParams) -> AuditLogQueryResult
分页查询审计日志。支持按 actor/resource_type/resource_id/action/result 精确匹配和 start_time/end_time 时间范围筛选。多条件之间为 AND 关系。所有筛选条件均为可选，全空时返回全量日志。使用参数化查询防止 SQL 注入。
前置条件
params.page >= 1；params.size >= 1 且 <= 100；params.start_time 若提供则格式合法（ISO 8601）；params.end_time 若提供则格式合法；PostgreSQL 连接可用
后置条件
返回 AuditLogQueryResult（items + total + page + size）。items 为符合条件的审计日志列表，按 logged_at 降序排列。total 为总记录数（非当前页数）。不修改数据库中的任何数据
ValidationException→ 400page < 1、size 不在 1-100 范围、start_time/end_time 格式不合法、resource_id 非 UUID 格式UnauthorizedException→ 401请求未携带有效身份凭证或 Token 已过期ForbiddenException→ 403当前用户无审计日志查询权限（非管理员角色）DatabaseQueryException→ 500数据库查询异常（连接断开、查询超时等）
getAuditLogDetail
(auditId: UUID) -> AuditLog
查询单条审计日志详情。通过 audit_id 主键查询 audit_logs 表，返回包含完整 detail JSON 对象的所有字段。用于 Web Console 的审计日志详情查看功能。
前置条件
auditId 为合法 UUID 格式
后置条件
返回 auditId 对应的完整 AuditLog 实体（含 detail JSON 完整内容）。若 auditId 不存在则抛出 AuditLogNotFoundException。不修改任何数据
ValidationException→ 400auditId 格式不合法（非 UUID）UnauthorizedException→ 401请求未携带有效身份凭证ForbiddenException→ 403当前用户无权限访问此审计日志AuditLogNotFoundException→ 404auditId 对应审计日志记录在数据库中不存在DatabaseQueryException→ 500数据库查询异常
exportAuditLogs
(params: AuditLogExportParams) -> ExportResult
导出审计日志。应用与 queryAuditLogs 相同的筛选条件但无分页限制，将所有匹配记录导出为 CSV 或 JSON 格式字符串。导出数据量超过服务端配置限制时返回 413。
前置条件
params.format 为 csv 或 json；其他筛选条件校验规则同 queryAuditLogs；筛选后的数据量未超过服务端配置的导出上限（100000 条或 100MB）
后置条件
返回 ExportResult（file_content + file_format + filename）。file_content 包含符合筛选条件的所有审计日志数据（不分页）。CSV 格式首行为列标题行。JSON 格式为对象数组。不修改数据库中的任何数据
ValidationException→ 400format 不是 csv/json、其他筛选参数校验失败UnauthorizedException→ 401未授权，请求未携带有效身份凭证ForbiddenException→ 403无权限执行导出操作（非管理员角色）ExportLimitExceededException→ 413导出数据量超过服务端配置限制（默认最大 10 万条或 100MB）DatabaseQueryException→ 500数据库查询异常
数据访问依赖
insertAuditLog(auditLog: AuditLog) -> AuditLog — 插入审计日志记录（INSERT INTO audit_logs），返回含系统自动生成字段的完整实体
findAuditLogById(id: UUID) -> AuditLog? — 根据主键 ID 查询单条审计日志完整记录（含 detail JSON）
queryAuditLogsPaged(params: AuditLogQueryParams) -> (List[AuditLog], int) — 多条件动态组合查询+COUNT，支持分页和 logged_at 降序排序
exportAuditLogsRaw(params: AuditLogExportParams) -> List[AuditLog] — 无分页限制的条件查询，用于导出全量数据

业务规则

不变量
  • !审计日志一旦写入持久化存储后不可修改、不可删除，保证审计追踪的完整性和不可抵赖性
  • !每条审计日志必须包含 action、actor、resource_type、resource_id、result 和 logged_at 六个必填字段，缺一不可
  • !action 字段使用点号分层命名规范（如 project.create / env.update / deploy.submit），各服务间按约定命名确保全局唯一性和可检索性
  • !resource_type 必须为受控枚举值（project/environment/deployment/key/ssh_key），不允许写入未注册的资源类型
  • !result 字段仅允许 success 或 failure 两个取值，不允许其他值
  • !查询条件的各筛选字段之间为 AND 关系，不支持 OR 组合
  • !audit_logs 表的 logged_at 字段必须有索引以支持时间范围查询和降序排序分页
  • !detail 字段的内容格式由调用方自行定义，本服务仅做 JSON 对象格式校验和透传存储，不做业务内容解析
跨服务规则
Project Management Service、Environment Management Service、SSH Execution Service、Deployment Orchestrator、Key Management Service 通过 POST /internal/audit/log 接口向本服务写入审计日志，本服务不主动轮询任何其他服务获取审计事件
审计日志写入采用同步模式（请求-响应），调用方需等待写入确认。本服务不可用时调用方应记录本地日志降级处理（fire-and-forget），不影响主业务流程
审计日志的查询和导出接口通过 API Gateway 暴露给 Web Console，API Gateway 负责在转发前校验 JWT Token 和角色权限（仅管理员可访问审计管理功能）
审计日志的保留策略（如 90 天自动清理/归档）由 Primary Database 模块的运维侧管理，本服务不直接负责数据生命周期管理
本服务仅依赖 PostgreSQL，不依赖 Redis、RabbitMQ 等其他中间件，降低内部复杂度
本服务本身也执行关键操作（如日志归档触发），此时应调用自身的 writeAuditLog 接口记录自审计日志

错误处理

处理策略

Audit Service 对所有入参进行前置校验，校验失败返回 400。请求体 JSON 解析失败返回 422。写入接口采用同步模式确保调用方能感知写入结果；数据库写入异常返回 500。查询类接口数据库异常返回 500，不返回部分结果。所有未预期异常由全局异常处理器捕获返回 500。
