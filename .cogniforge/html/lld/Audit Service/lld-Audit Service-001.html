概述

Audit Service
记录系统中所有关键操作和变更的审计日志。提供审计日志的持久化存储和分页查询能力，供 API Gateway 路由审计日志查询请求，供其他服务通过内部接口写入审计记录。
依赖: API GatewayPostgreSQL
PythonFastAPIPostgreSQL 15
🗄️

数据模型 (2)

引用模型 1

🔗 audit_logs引用

↳ 引用自: lld-Primary Database-001 / audit_logs

审计日志表，记录系统中所有关键操作和变更事件。每次用户操作（如项目创建、环境配置变更、部署触发等）都会在此表中产生一条记录，用于安全审计和操作回溯。

字段
字段名类型描述
id *uuid审计日志唯一标识，主键
project_iduuid关联的项目 ID，外键关联 projects 表。系统级操作（如用户登录）可为空
action *varchar(100)操作类型标识，采用命名空间格式，如 project.create、environment.create、deployment.trigger、key.upload
actor *varchar(255)操作执行者标识，通常为用户名或用户 ID
detailsjsonb操作详情的 JSON 结构，包含请求参数快照、变更前后对比等扩展信息
ip_addressvarchar(45)操作发起方的 IP 地址，支持 IPv4 和 IPv6
created_at *timestamptz审计日志记录创建时间，即操作发生的时间

接口定义 (2)

GET/api/audit/logsQueryAuditLogs
查询审计日志（分页）。支持按 project_id 和 action 筛选，返回分页后的审计日志条目列表。查询结果按创建时间降序排列。
参数类型描述
project_idstring查询参数，按项目 ID 筛选（选填）
actionstring查询参数，按操作类型筛选（选填）
pageinteger查询参数，页码，从 1 开始，默认 1
page_sizeinteger查询参数，每页条数，默认 20，最大 100
Response 200
字段类型

itemsarray

⚠️

错误处理

Audit Service 采用统一的异常处理策略：(1) 参数校验异常 — 查询参数 page 小于 1 或 page_size 超出范围（1-100）时返回 400 Bad Request，附带具体校验错误详情；(2) 数据库查询异常 — 审计日志查询或写入时数据库连接失败或超时（超时阈值 10s）返回 502 Bad Gateway，并在服务器端记录错误栈用于排查；写入失败时不允许重试，避免产生重复审计记录；(3) 内部调用异常 — RecordAuditLog 接口的 action 或 actor 为空时返回 400 Bad Request，防止写入不完整的审计记录。所有错误响应体统一格式为: { code: integer, error: string, detail: string }。
