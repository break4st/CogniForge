概述

模块: Audit Service
审计日志服务（Audit Service）为全系统提供统一的审计日志集中管理和持久化存储能力。系统内所有服务（API Gateway、Deployment Orchestrator、Key Management Service、Project Management Service、Environment Management Service）通过统一的 REST API 写入审计记录，将用户操作和系统行为以结构化方式持久化到 PostgreSQL 数据库。同时提供审计日志的多维度查询检索和 CSV 导出能力，满足合规审计和操作追溯需求。审计日志采用只写追加模式，保证审计链路不可篡改。
GoGin / Go-ZeroPostgreSQL 15+

错误处理

所有对外接口统一返回 JSON 格式错误体：{ code: int, message: string }，400 参数校验失败、404 资源不存在、500 服务内部错误。 (1)参数校验层 — POST /api/audit/logs 接口严格校验所有入参：action 非空且不超过 128 字符、actor 非空且不超过 255 字符、resource_type 在预定义枚举范围内（project / deployment / key / environment）、resource_id 合法 UUID 格式、result 在 [success, failure] 枚举范围内，任一条件不满足返回 400 及明确中文错误描述；detail 为可选 JSONB 字段，若传入则校验 JSON 反序列化合法性，格式无效返回 400。 (2)数据持久化层 — 审计日志同步写入 PostgreSQL，写入成功后返回 200；若写入失败（数据库连接超时、磁盘满、分区不存在）返回 500。数据库连接异常时 Service 层封装可重试错误，结合指数退避策略最多重试 3 次。所有重试均失败后返回 500 并记录 ERROR 级别日志触发告警。audit_logs 表按月分区（RANGE PARTITION BY created_at），超出当前分区的写入返回 400 拒绝。 (3)查询层 — 查询接口所有筛选条件均为 AND 关系组合。分页参数 page 最小为 1，page_size 范围 1-100，越界返回 400。start_time 与 end_time 格式统一使用 ISO 8601（如 2026-05-20T00:00:00Z），格式不合法返回 400。查询结果集超过 10000 条时使用 LIMIT 限制行数，防止 OOM；前端统计值 total 通过 COUNT 聚合查询独立获取，不依赖结果集大小。 (4)导出接口 — Export 接口限制 start_time 与 end_time 时间跨度不超过 180 天，超限返回 400；若两个时间参数均不传则导出来最近 30 天数据。导出结果以 UTF-8 with BOM 编码的 CSV 文件流响应，Content-Type 为 text/csv，Content-Disposition 为 attachment；导出行数超过 100000 行时在响应头中添加 X-Total-Count 告知调用方实际行数，避免客户端等待流结束后才获取行数信息。 (5)幂等性与一致性 — 审计日志写入每条生成独立 log_id（UUID v4 自动生成），不强制幂等，调用方无需关注重复提交。日志采用只写追加模式（append-only），不支持 UPDATE 和 DELETE 物理操作，保证审计链路的不可篡改性。 (6)存储与归档策略 — 超过 retention_days（默认 90 天）的在线日志由后台定时任务（每日凌晨 2:00 执行）自动识别并归档标记；物理清理和冷存储迁移当前版本由 DBA 手动操作，后台任务仅完成逻辑标记。
