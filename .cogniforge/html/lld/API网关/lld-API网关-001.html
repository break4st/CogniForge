概述

API网关
🔀 网关层
系统统一入口，处理认证鉴权、请求路由、限流和跨域。所有客户端请求首先到达 API 网关，经过身份认证、权限校验、速率限制后转发至对应上游微服务。网关自身负责 JWT 令牌签发与验证，不将认证逻辑下沉到各个服务。每个透传接口的响应体字段与下游服务契约严格一致。
依赖: 项目管理服务环境配置服务部署编排服务审计日志服务密钥存储服务
GoGinJWTRedisgorilla/websocket

路由表 (8)

Path PatternUpstream说明
/api/v1/auth/**内部处理认证相关请求由网关自身 JWT 中间件处理，不转发到上游服务。登录成功后签发令牌，后续请求携带令牌通过 Auth 中间件验证。
/api/v1/health内部处理健康检查由网关自身直接响应，返回网关及各上游服务的连通状态汇总。
/api/v1/projects/**项目管理服务项目管理相关增删改查请求（含项目和项目下资源的嵌套路由），转发至项目管理服务。
/api/v1/environments/**环境配置服务环境配置相关请求（CRUD、连通性验证），转发至环境配置服务。
/api/v1/deployments/**部署编排服务部署编排相关请求（触发部署、状态查询、日志查询），转发至部署编排服务。注意：不含 ws 子路径，ws 由下一规则匹配。
/api/v1/ws/deployments/**部署编排服务部署 WebSocket 实时日志推送请求，转发至部署编排服务的 WebSocket 处理器。与 REST 接口使用不同的 upstream path，由网关按路径前缀区分路由。
/api/v1/audit-logs/**审计日志服务审计日志查询请求，转发至审计日志服务。仅 admin 角色可访问。
/api/v1/keys/**密钥存储服务密钥管理相关请求（添加密钥、查询密钥列表、获取密钥详情），转发至密钥存储服务。

中间件链

1. Logger — 记录每个请求的方法、路径、状态码、耗时和客户端 IP，输出到网关访问日志→2. CORS — 处理跨域请求，根据配置的允许源列表校验 Origin 头，预检请求直接返回 204→3. RequestID — 为每个请求生成唯一追踪 ID（UUID v4），注入请求上下文的 X-Request-ID 头→4. Auth (JWT Validation) — 验证 Authorization: Bearer <token> 头，解析 JWT claims 并注入上下文。公共端点跳过此步骤。→5. RateLimiter — 根据请求 IP、用户 ID 和端点路径匹配限流策略，超限则返回 429。公共端点仍受 IP 级别限流。→6. Router (Route Match) — 匹配请求路径和 HTTP 方法到 RouteRule，确定上游服务和转发目标。无匹配则返回 404。→7. Upstream Proxy — 将请求转发到匹配的上游服务，附加认证头（X-User-ID, X-User-Role, X-Request-ID）。等待响应或超时后返回给客户端。
🔐

认证授权

公开端点: /api/v1/auth/login /api/v1/auth/refresh /api/v1/health
认证方式: JWT Bearer Token，通过 Authorization 请求头传递，格式为 Bearer <access_token>。WebSocket 连接通过 query 参数 ?token=<access_token> 传递。网关在 Auth 中间件中完成 token 签名验证、过期校验和黑名单检查。
Token 策略: access token 2 小时，refresh token 7 天。access token 过期后使用 refresh token 换取新令牌，refresh token 过期后需重新登录。令牌吊销通过 Redis 黑名单实现，access token 的 jti 在登出或管理员强制下线时加入黑名单。

限流规则

全局 每 IP 1000 req/min（滑动窗口），防止单个客户端过度占用网关资源。公共端点 /api/v1/health 不受全局限流。
每用户 每 user 100 req/min（滑动窗口），认证用户按 user_id 计数，防止单个用户突发请求影响其他用户。
端点限制
POST /api/v1/deployments每 user 10 req/min，部署操作资源消耗大，需严格控制频率
POST /api/v1/auth/login每 IP 5 req/min，防止暴力破解密码
DELETE /api/v1/projects/:id每 user 5 req/min，删除操作不可逆，需限制频率
/api/v1/health不限制，确保监控系统可随时获取网关健康状态

数据模型 (4)

数据结构 4

📦 RouteRule自有

路由规则配置，定义路径模式到上游服务的映射关系。存储在网关启动配置文件中，支持前缀匹配和参数路径。

字段
字段名类型描述
path_pattern *string路径匹配模式，支持 :param 和 ** 通配符，如 /api/v1/projects/**
upstream *string上游服务名称，对应服务发现或配置文件中的服务标识
methods *[]string允许的 HTTP 方法，如 ["GET", "POST"]，空数组表示全部允许
auth_required *bool是否需要 JWT 认证，public 端点设为 false
rate_limit_profilestring限流策略配置名，对应 RateLimitPolicy.name，为空时使用全局默认策略

📦 JwtClaims自有

JWT 令牌负载结构体，网关签发和验证 JWT 时使用的标准 claims。令牌使用 HS256 算法签名，密钥由网关配置文件管理。

字段
字段名类型描述
user_id *string用户唯一标识，UUID 格式
username *string用户登录名
role *string用户角色，枚举值: admin/operator/viewer
sub *stringJWT 标准 subject，固定为 user_id
iat *int64签发时间，Unix 时间戳
exp *int64过期时间，Unix 时间戳
jti *stringJWT ID，用于令牌唯一标识和吊销校验

📦 RateLimitPolicy自有

速率限制策略配置，定义按 IP、用户或全局维度的限流规则。使用令牌桶算法，Redis 作为计数器存储后端。

字段
字段名类型描述
name *string策略名称，供 RouteRule.rate_limit_profile 引用
scope *string限流范围: global/ip/user
requests_per_second *int每秒允许的请求数
burst *int令牌桶突发容量，允许瞬时超过 rps 的峰值请求数
window_seconds *int时间窗口（秒），用于滑动窗口计数

📦 UnifiedResponse自有

统一 API 响应信封，所有网关响应（含成功和错误）均使用此结构装填。code 为 0 表示成功，非 0 表示业务错误；data 字段携带具体响应载荷。

字段
字段名类型描述
code *int状态码，0 表示成功，非零表示业务异常
message *string提示信息，成功时为 "success"，失败时为简要错误描述
dataany成功时的响应数据载荷，类型与具体接口定义一致
request_id *string请求追踪 ID，由 RequestID 中间件生成，用于日志关联和问题排查

错误处理

处理策略

所有请求经过统一错误处理中间件。认证失败返回 401，权限不足返回 403，参数校验失败返回 400，资源不存在返回 404，业务冲突返回 409，内部错误返回 500，上游服务不可用返回 502，限流触发返回 429。所有错误统一封装为 JSON 格式，包含错误码、简短描述和详细说明。不在错误响应中暴露内部实现细节或堆栈信息。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400

401
认证失败

403
