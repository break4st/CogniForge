🔧 DeployExecutor 2 方法
ExecuteAsync
(task: DeployTask) -> void
异步执行远程部署流程，依次完成五个阶段并实时更新状态和进度
前置条件
task 已持久化且 status=pending；任务在异步协程中独立执行
后置条件
按顺序执行：创建目录→传输文件→生成脚本→执行启动；所有步骤成功后 task.status=success；步骤失败时根据配置决定是否触发 Rollback；所有关键步骤结果写入 deploy_logs
SSHConnectionException→ 502SSH 连接池连接远程服务器失败（超时/认证失败/主机不可达）FileTransferException→ 502SFTP 文件传输过程中发生错误（磁盘不足/写入权限/网络中断）ScriptExecutionException→ 502远程脚本执行返回非零退出码或超时未响应DirectoryCreationException→ 502远程 mkdir 命令执行失败（权限不足/路径冲突）
Rollback
(task: DeployTask) -> void
部署失败后执行回滚，将远程服务器恢复到上一部署版本
前置条件
task.status=failed 且远程服务器上存在上一版本的目录结构
后置条件
更新 task.status=rollbacking；在远程服务器上切换 symlink 到上一版本目录；执行上一版本的 start.sh；成功则 task.status=rolled_back，失败则 task.status=rollback_failed
RollbackFailedException→ 502回滚过程中远程操作失败：上一版本目录不存在、symlink 切换失败、启动脚本执行失败

业务规则

不变量
  • !同一 project_id + environment_id 组合同时最多只能有一个活跃部署任务（pending/running/rollbacking 状态）
  • !部署任务的版本号在同一 project_id + environment_id 内唯一
  • !部署任务的状态转换必须严格遵循 DeployTask 状态机定义，不可跳跃或逆向
  • !远程服务器的版本目录路径格式固定为 /opt/app/releases/{version}/
  • !每个部署任务的 deploy_logs 按 created_at 升序排列，日志行写入后不可修改或删除
状态机
🎯 DeployTask
pendingrunningsuccessfailedrollbackingrolled_backcancelled
→DeployExecutor 获取待处理任务并开始执行by DeployExecutor
→用户在调度执行前手动取消by 用户
→所有部署步骤执行成功，服务启动正常by DeployExecutor
→部署步骤执行失败且无需回滚，或回滚条件不满足（如首次部署无上一版本）by DeployExecutor
→部署步骤执行失败，系统决定触发自动回滚流程by DeployExecutor
→用户手动取消正在执行的部署任务by 用户
→回滚操作成功完成，远程服务恢复到上一版本by DeployExecutor
→回滚操作在执行过程中也失败by DeployExecutor
🚫 success 状态不可转换到其他任何状态——已成功的部署视为最终态🚫 rolled_back 状态不可逆——回滚完成后不可再次恢复已失败的新版本🚫 rollback_failed 状态不可逆——回滚失败需要人工介入处理🚫 cancelled 状态不可恢复——取消后的任务不可重新激活
⚡ 创建部署任务时使用 SELECT ... FOR UPDATE 锁定目标 project_id + environment_id 的活跃任务行；状态更新使用乐观锁（version 字段或 updated_at 比较）防止并发覆盖；DeployExecutor 通过分布式锁（Redis）确保同一时刻每个活跃任务只有一个执行协程
跨服务规则
部署启动前 DeployExecutor 必须通过 SSH 连接池的 RPC 接口验证目标服务器可达（SSH 握手），不可达则任务标记为 failed
DeployExecutor 启动文件传输前必须从文件存储服务获取文件包及其 checksum，传输完成后比对两端 checksum 确保完整性
部署流程中每个关键阶段（创建目录/传输文件/生成脚本/启动服务/回滚）完成后必须调用审计日志服务记录操作详情
调用审计日志服务超时或失败时，部署流程不应中断，但需记录 warn 级别日志提示审计缺失
DeployExecutor 在远程服务器上生成脚本时，脚本内容必须包含错误处理和日志重定向，确保执行结果可追溯

错误处理

处理策略

错误分为三类：请求参数校验错误返回 4xx；部署执行过程中的远程服务器错误由 DeployExecutor 捕获后更新任务状态为 failed 并记录错误日志；内部系统依赖错误（SSH 连接失败、文件包获取失败）由调用方重试或触发自动回滚。部署执行失败时视情况触发回滚流程，回滚失败时标记任务为 rollback_failed 并记录详细错误
