概述

部署引擎服务
⚙️ 业务服务
部署流程编排核心，管理部署生命周期。负责部署任务创建与流程编排、部署状态追踪与持久化、部署日志实时记录与推送、版本回滚调度、异步任务下发至基础设施层。通过 Celery 异步任务队列协调 SSH 连接池、文件传输模块和脚本生成引擎完成远程部署执行。
依赖: 关系型数据库SSH连接池文件传输模块脚本生成引擎缓存环境管理服务项目管理服务
Python 3.11+FastAPICelery + RabbitMQPostgreSQL 15asyncsshRedis 7

业务规则

不变量
  • !同一项目同一环境同时最多只能有一个状态为 running 的部署记录
  • !回滚操作的目标版本必须是目标环境下已成功部署过的历史版本
  • !部署记录的 status 必须严格遵循 pending → running → success|failed 状态转换顺序，不可跳跃或逆转
  • !rollback_from 字段有值时，该记录的 version 必须与原始部署记录的 version 不同
  • !每个部署记录的 artifact_path 必须在文件系统中真实存在，创建部署时不做校验，但异步执行时失败会标记为 failed
状态机
🎯 Deployment
pendingrunningsuccessfailed
→Celery Worker 获取任务开始执行by DeploymentEngineService.handleDeploymentTask
→远程脚本执行成功，所有部署步骤完成by DeploymentEngineService.handleDeploymentTask
→远程执行出错、超时或SSH连接失败by DeploymentEngineService.handleDeploymentTask
🚫 success 状态不可再转换到任何其他状态🚫 failed 状态不可再转换到任何其他状态（回滚通过创建新部署记录实现，而非修改原记录状态）🚫 pending 不允许回退到任何前置状态（无前置）🚫 running 不可回退到 pending
⚡ 通过数据库行级锁（SELECT ... FOR UPDATE）控制同一 deployment_id 的并发状态更新；通过应用层分布式锁（Redis RedLock）控制同一 environment_id 下并发创建部署的互斥，锁 key 格式为 deploy:lock:{environment_id}，锁超时 30 秒
跨服务规则
创建部署前需通过关系型数据库的 DeploymentDataAccess 验证 project_id 和 environment_id 的外键约束有效性
部署执行中通过 SSHPoolAPI.get_connection 获取 SSH 连接，使用完毕后必须调用 SSHPoolAPI.release_connection 归还连接池
文件传输使用 FileTransferAPI.transfer_file 同步完成，部署引擎等待传输完成后才进入脚本执行阶段
脚本生成使用 ScriptGenerationAPI.generate_script 同步获取脚本内容，不直接操作脚本内容仅透传给远程执行通道
部署日志同时写入数据库持久化和 Redis Pub/Sub 频道 deployment:{deployment_id}:logs，数据库用于历史查询，Redis 用于 WebSocket 实时推送
回滚流程中若脚本生成引擎判定目标版本与当前版本一致，应返回 422 版本冲突错误阻止回滚

错误处理

处理策略

采用分层错误处理策略：REST 接口层返回标准 HTTP 错误码和统一错误体；异步任务层通过 Celery 重试机制自愈，网络类错误自动重试最多 3 次，业务逻辑错误（如状态冲突）直接失败并记录。SSH 连接错误由连接池层处理，部署引擎只感知最终连接结果。部署超时由 Celery 任务硬超时机制保障，超时后标记为失败并执行回滚策略。
