概述

部署引擎服务
⚙️ 业务服务
核心部署编排服务，负责完整的部署流程调度、版本管理、脚本生成和进度推送。接收Web控制台的部署请求，协调密钥管理服务、SSH连接池服务、文件传输服务完成远程部署，通过WebSocket实时推送执行日志。
依赖: 项目管理服务环境配置服务密钥管理服务SSH连接池服务文件传输服务审计日志服务PostgreSQL主数据库Redis缓存
PythonFastAPIPostgreSQL 15Redis 7RabbitMQRESTWebSocketJWT

业务规则

不变量
  • !一个项目-环境对在同一时刻最多只能有一个活跃部署任务（status=pending 或 running）
  • !版本号一经创建不可修改，格式固定为 vYYYYMMDD-HHmmss，基于部署触发时的系统时间生成
  • !部署日志（deployment_logs）为 append-only 结构，不可修改或删除已有日志记录
  • !status=success 的部署代表远程脚本已成功执行，但业务正确性由部署脚本自身保证，部署引擎不校验脚本执行结果语义
  • !部署状态不可从 success 或 failed 回退到任何其他状态
状态机
🎯 Deployment
pendingrunningsuccessfailed
→异步任务开始执行远程部署（executeDeployment）by system
→远程脚本执行完成且 exit_code=0by system
→远程脚本执行完成但 exit_code≠0by system
→前置步骤失败（密钥解密/SSH连接/文件传输/目录创建）by system
🚫 success 和 failed 为终态，不可转换到任何其他状态🚫 已成功的部署不可重新执行，如需重新部署必须创建新的部署记录
⚡ 状态更新使用数据库行级锁（SELECT FOR UPDATE）防止并发更新。RabbitMQ 消费端保证同一部署消息的串行处理（按 deploymentId hash 到固定队列分区）。Redis 部署进度缓存在部署完成/失败后设置 TTL=3600 自动清理
跨服务规则
部署引擎在触发远程执行前必须先调用密钥管理服务（POST /api/keys/{key_id}/decrypt）解密 SSH 私钥，解密失败则部署标记为 failed 并停止后续步骤
远程命令执行必须通过 SSH 连接池服务（POST /api/ssh/execute）完成，exit_code=0 视为执行成功，非零视为执行失败
文件传输必须通过文件传输服务（POST /api/transfer/upload）的 SCP 协议完成，传输失败时需清理远程已创建的部署目录
每次部署状态变更（pending→running, running→success, running→failed）必须调用审计日志服务（POST /api/audit/logs）写入审计记录
部署日志通过 WebSocket 实时推送到前端的同时，必须持久化到 deployment_logs 表，确保即使前端断线日志不丢失

错误处理

处理策略

统一使用标准错误响应格式，区分客户端错误（4xx）和服务端错误（5xx）。部署执行过程中的关键步骤（远程目录创建、文件传输、脚本执行）失败后主动记录日志并回滚已创建的远程资源，避免残留文件影响后续部署。
