概述

PostgreSQL主数据库
🗄️ 数据库层
关系型数据库，持久化存储项目、环境配置、部署记录、审计日志等全部结构化业务数据。使用 PostgreSQL 15，所有业务服务通过 SQL 协议直接访问本数据库，是本系统的唯一结构化数据持久化层
PostgreSQL 15
🗄️

数据模型 (7)

数据库表 7

🗄️ projects权威定义

项目信息表，存储所有项目的名称、描述等基本信息，支持软删除

字段
字段名类型描述
id *uuid项目唯一标识，使用 UUID v4
name *varchar(128)项目名称
descriptionvarchar(500)项目描述信息
created_at *timestamptz创建时间，默认为当前时间
updated_at *timestamptz最后更新时间，由触发器自动维护
deleted_attimestamptz软删除时间，非空表示已删除
索引
索引名唯一列
pk_projects✓id
idx_projects_deleted_atdeleted_at
idx_projects_namename

🗄️ environments权威定义

部署环境配置表，存储远程服务器的连接参数，包括地址、端口、登录用户和关联的 SSH 密钥

字段
字段名类型描述

name *varchar(64)环境名称，如「测试线」「灰度线」「正式线」

port *integerSSH 端口号，默认 22，范围 1-65535
login_user *varchar(64)SSH 登录用户名
key_id *uuid关联的 SSH 密钥 ID，逻辑外键引用 ssh_keys 表
status *varchar(20)环境连接状态：unknown/online/offline，默认 unknown
created_at *timestamptz创建时间
updated_at *timestamptz最后更新时间
deleted_attimestamptz软删除时间
索引
索引名唯一列
pk_environments✓id
idx_environments_key_idkey_id
idx_environments_statusstatus
idx_environments_deleted_atdeleted_at

status *varchar(20)部署状态：pending/running/success/failed，默认 pending

迁移策略

工具: Alembic命名: V{序号}__{描述}.sql

回滚策略: 每个迁移必须包含对应的 downgrade 脚本，支持版本回退。生产环境回滚需先执行 downgrade 至目标版本，再应用修复迁移。不允许跳过中间版本的直接回滚

📈

容量估算

1年: projects: ~500, environments: ~2,000, project_environments: ~3,000, deployments: ~50,000, deployment_logs: ~3,000,000, audit_logs: ~200,000, ssh_keys: ~1,0003年: projects: ~2,000, environments: ~10,000, project_environments: ~15,000, deployments: ~300,000, deployment_logs: ~15,000,000, audit_logs: ~1,200,000, ssh_keys: ~5,000
热表: deployments deployment_logs audit_logs

分区策略: deployment_logs 和 audit_logs 按 created_at 按月分区（PARTITION BY RANGE）。deployments 表在数据量超过 100 万行后按 created_at 按月分区

连接配置

连接池: 每个服务连接池最小 5 个连接，最大 20 个连接超时: 连接超时 5 秒，查询超时 30 秒，连接空闲回收 300 秒

错误处理

处理策略

数据库层通过约束（主键、唯一键、外键、NOT NULL）保证数据完整性，连接错误和查询异常由业务服务层捕获并返回统一错误响应。数据库连接使用连接池管理，超时和断开自动重试

detailstring
