概述

模块: Statistics Service

学习统计服务，负责学习数据的记录、统计分析和报告生成。作为微服务架构中的领域服务之一，通过 REST 内部接口对外提供学习数据录入和多维度统计查询能力，消费者为 API Gateway。服务内部职责包括：1）学习数据记录的创建和存储，支持每名学生每个科目下多条成绩记录的持久化；2）按学生维度统计学习情况，计算各科目的总分、平均分、最高分、最低分及记录条数，并汇总总体平均分；3）按班级维度汇总统计，计算各科目的班级平均分、最高分、最低分和及格率；4）按年级维度汇总统计，计算年级平均分和各班级的平均分与人数；5）异步消费消息队列中的统计任务，在业务操作触发时重新计算和刷新统计缓存。本服务不处理认证鉴权——该职责由 API Gateway 统一负责。数据存储采用关系型数据库，学习记录主表为 study_records，统计数据通过 SQL 聚合查询实时计算（不预聚合持久化），以简化数据一致性管理。对于高频查询的统计结果可接入 Redis 缓存（由 Cache 组件提供）来提升性能。本服务依赖 Message Queue 接收异步统计计算任务（topic: statistics.calculation），实现削峰填谷和解耦。

接口定义 (5)

统计管理内部接口（学习数据录入）

POST /internal/statistics/records

录入学习数据记录。接收学生 ID、科目、分数、记录日期和可选备注。核心校验规则：1）student_id、subject、score、record_date 为必填字段，缺失时返回 422；2）score 取值范围 0-100，超出时返回 422；3）record_date 格式必须为 YYYY-MM-DD，格式非法时返回 422；4）学生存在性校验：需确认 student_id 在共享数据库 students 表中存在，不存在时返回 422（提示学生不存在）；5）创建成功返回 201 及完整记录信息（含自动生成的 id 和 created_at）。同时，成功录入后发送异步消息到 MQ topic: statistics.calculation（task_type=student, entity_id=student_id, action=recalculate），触发相关统计缓存刷新。

参数类型描述
student_idnumber学生 ID，必填
subjectstring科目名称，如'数学'、'语文'，必填
scorenumber分数，取值范围 0-100，必填
record_datestring (date)记录日期，格式 YYYY-MM-DD，必填
remarksstring (optional)备注，选填

统计管理内部接口（学生统计）

GET /internal/statistics/students/{id}

查询指定学生的统计信息，按科目汇总。路径参数 id 为学生 ID。支持按日期范围筛选（start_date/end_date），不传时统计全部历史数据。核心逻辑：1）查询 study_records 表按 student_id 过滤，指定日期范围时附加 record_date BETWEEN start_date AND end_date 条件；2）按 subject 分组，聚合计算各科目的 total_scores（SUM）、average_score（AVG）、max_score（MAX）、min_score（MIN）、record_count（COUNT）；3）计算 overall_average 为所有科目所有记录的平均分（即所有记录 score 的 AVG）；4）仅统计有成绩记录的学生，无记录时返回空 subjects 数组和 overall_average=0；5）student_name 从共享数据库 students 表关联查询获取，学生不存在时返回 404。查询结果根据条件动态生成完毕直接返回，不做缓存（或由 Cache 组件按需缓存）。

参数类型描述
idnumber学生 ID，路径参数
start_datestring (date, optional)统计开始日期，格式 YYYY-MM-DD
end_datestring (date, optional)统计结束日期，格式 YYYY-MM-DD

统计管理内部接口（班级统计）

GET /internal/statistics/classes/{id}

查询指定班级的统计汇总数据。路径参数 id 为班级 ID。支持按科目（subject）和日期范围筛选。核心逻辑：1）先校验班级存在性——查询 classes 表，班级不存在时返回 404；2）查询共享数据库 students 表获取该班级下的所有学生 ID 列表；3）以这些 student_id 列表为条件，查询 study_records 表进行聚合计算；4）按 subject 分组，计算班级内所有学生在各科目的 class_average（AVG）、highest_score（MAX）、lowest_score（MIN）和 pass_rate（及格率 = 得分 >= 60 的记录数 / 总记录数 * 100，百分比数值）；5）class_average 为该班级所有记录（全部科目）的总体平均分；6）student_count 通过 COUNT 聚合 students 表中 class_id 匹配的记录数计算，反映班级当前实际人数。有 subject 参数时仅返回该科目的统计，无 subject 时返回全部科目的统计数组。

参数类型描述
idnumber班级 ID，路径参数
subjectstring (optional)按科目筛选，如'数学'，传此参数时只返回该科目的统计
start_datestring (date, optional)统计开始日期，格式 YYYY-MM-DD
end_datestring (date, optional)统计结束日期，格式 YYYY-MM-DD

统计管理内部接口（年级统计）

GET /internal/statistics/grades/{id}

查询指定年级的统计汇总数据。路径参数 id 为年级 ID。支持按科目和日期范围筛选。核心逻辑：1）先校验年级存在性——查询 grades 表，年级不存在时返回 404；2）查询共享数据库 classes 表获取该年级下的所有班级 ID 和名称；3）对于每个班级，查询其下的所有学生（通过 students 表 class_id 关联），再汇总这些学生的成绩记录进行聚合；4）grade_average 为该年级所有记录（全部班级、全部科目）的总体平均分；5）class_count 为年级下的班级数，student_count 为年级下的学生总数（去重），均实时聚合计算；6）classes 数组列出该年级下每个班级的 class_id、class_name、class_average（本班所有记录的平均分）和 student_count（本班人数）；7）subject 参数影响 grade_average 的计算范围（有 subject 时只计算该科目的平均分），但 classes 数组中每个班级的 class_average 始终为该班级全部科目的平均分（如需按科目过滤班级统计由班级统计接口提供）。

参数类型描述
idnumber年级 ID，路径参数
subjectstring (optional)按科目筛选，影响 grade_average 的计算范围
start_datestring (date, optional)统计开始日期，格式 YYYY-MM-DD
end_datestring (date, optional)统计结束日期，格式 YYYY-MM-DD

统计任务消息队列（consumer）

topic: statistics.calculation

Statistics Service 作为消费者订阅 MQ topic: statistics.calculation。当业务操作（如录入成绩、修改学生/班级/年级归属等）触发统计需求时，上游服务发送消息到此队列，本服务异步消费并执行统计计算。消费逻辑：1）反序列化消息体，解析 task_type（student|class|grade）、entity_id、action（recalculate|refresh）和 triggered_at；2）根据 task_type 决定统计范围——task_type=student 时重新计算该学生的所有统计摘要，task_type=class 时重新计算该班级下所有学生的汇总，task_type=grade 时重新计算该年级所有班级的汇总；3）action=recalculate 表示全量重新计算，action=refresh 表示增量刷新（当前先按全量重算实现，后续可优化为增量）；4）计算结果写入共享数据库的统计缓存表（如有）或直接更新 Redis 缓存；5）消费失败的消息根据 MQ 重试机制重新投递，重试 3 次仍失败后进入死信队列并告警。此接口定义在 SAD 中，本处引用以说明消息消费依赖。

参数类型描述
task_typestring任务类型枚举: student|class|grade，标识统计维度
entity_idnumber统计对象 ID，对应 student_id/class_id/grade_id
actionstring动作枚举: recalculate|refresh，标识全量重算或增量刷新
triggered_atstring (datetime)任务触发时间戳
⚠️

错误处理

Statistics Service 按以下规则处理异常：1）必填字段缺失——录入学习数据时缺少 student_id/subject/score/record_date 中任一字段，返回 422 Unprocessable Entity，响应体为 {"error": "validation_error", "message": "缺少必填字段", "fields": [缺失字段列表]}；2）分数越界——score 不在 0-100 范围内，返回 422，响应体为 {"error": "validation_error", "message": "分数必须在 0-100 之间", "field": "score"}；3）日期格式非法——record_date 不满足 YYYY-MM-DD 格式，返回 422，响应体为 {"error": "validation_error", "message": "日期格式错误，应为 YYYY-MM-DD", "field": "record_date"}；4）学生不存在——录入时 student_id 在 students 表中不存在，返回 422，响应体为 {"error": "validation_error", "message": "学生不存在", "field": "student_id"}；5）班级不存在——查询班级统计时 id 在 classes 表中不存在，返回 404 Not Found，响应体为 {"error": "not_found", "message": "班级不存在"}；6）年级不存在——查询年级统计时 id 在 grades 表中不存在，返回 404 Not Found，响应体为 {"error": "not_found", "message": "年级不存在"}；7）日期范围无效——start_date 晚于 end_date，返回 422，响应体为 {"error": "validation_error", "message": "开始日期不能晚于结束日期"}；8）MQ 消费异常——消费统计任务消息时发生异常，记录错误日志并触发消息重试，重试 3 次仍失败后发送到死信队列并触发告警通知；9）空统计结果——查询学生/班级/年级统计时无成绩记录，不属于异常，正常返回 200，subjects 为空数组，各项平均值返回 0。所有操作记录结构化日志，包含请求路径、方法、耗时和操作结果状态，日志级别：正常操作 INFO，业务校验失败 WARN，系统异常 ERROR。MQ 消费日志额外包含消息 ID、task_type、entity_id 和重试次数。
