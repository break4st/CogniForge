概述

认证中间件
🔀 网关层
JWT认证过滤器，嵌入API网关的请求处理链中，负责用户身份认证、Token签发和验证、会话管理、权限角色校验和Token刷新。所有发往后端业务服务的请求必须经过本中间件认证后才能路由到上游。提供统一的登录/登出/Token刷新入口，管理用户会话生命周期，基于RBAC模型对每个API端点进行角色级权限控制。
依赖: API网关Redis缓存PostgreSQL主数据库
GoGinJWT (JSON Web Token)Redis 7+PostgreSQL 15+

中间件链

1. Request → CORS Handler（跨域请求处理：允许指定Origin、Methods、Headers，处理OPTIONS预检请求直接返回204）→2. → Request Logger（记录请求方法、路径、来源IP、User-Agent、请求ID，结构化输出到日志系统）→3. → Rate Limiter（基于令牌桶算法：全局每IP 100 req/s 和 每用户 1000 req/min 双层限流，特殊端点另有独立配额）→4. → Auth Middleware（JWT认证和权限校验：提取Authorization Header → 验证JWT签名和有效期 → 检查Token黑名单 → 解析角色信息 → 校验路径权限 → 注入UserContext到Gin Context）→5. → Router（根据path_pattern匹配上游服务，路由请求到对应的后端业务服务或中间件自身管理的端点）→6. → Upstream Service（上游业务服务：部署编排/项目管理/环境管理/密钥管理/版本管理/审计日志）

错误处理

处理策略

认证中间件的错误分三层处理。第一层：Token级错误（缺失/无效/过期/黑名单）在中间件层面直接拦截返回401，不转发到上游服务，响应中不暴露内部细节。第二层：权限级错误（角色不足）在JWT验证通过后的权限校验层返回403，附带缺失的权限标识。第三层：基础设施错误（Redis连接失败、数据库查询异常）返回500并触发告警，但采取降级保护策略：Redis不可用时仅验证JWT签名跳过会话黑名单检查，确保已签发的有效Token仍能通过认证。

统一错误响应体
字段类型
codeinteger (HTTP状态码)
errorstring (错误类型)
detailstring (详细错误信息)
request_idstring (请求追踪ID)
400
请求参数错误
登录/刷新/登出接口的请求参数缺失或格式错误。触发条件：username为空、password为空、refresh_token格式不正确、请求体JSON解析失败。
401
认证失败
Token无效、已过期、在黑名单中，或用户名密码错误。不携带有效Token的请求将被中间件拦截，不会路由到上游服务。响应中不区分具体失败原因，防止攻击者枚举。
403
权限不足
用户JWT验证通过但其角色不满足接口的权限要求。例如：开发工程师（developer）尝试调用密钥管理接口或审计日志查询接口。响应detail字段会说明需要的最低角色。
429
请求频率限制
触发速率限制。全局每IP超过100 req/s、每用户超过1000 req/min、登录接口每IP超过10 req/min或同一用户名超过5 req/min时返回。响应头包含Retry-After字段（秒）。
500
内部服务错误
认证中间件内部异常：JWT密钥加载失败（启动时检测）、Redis连接异常（降级通过但记录告警）、用户数据查询失败。触发监控告警，运维人员需检查服务健康状态。
