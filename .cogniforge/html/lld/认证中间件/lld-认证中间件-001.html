概述

认证中间件
🔀 网关层
嵌入在 API 网关中的认证拦截模块，验证用户的登录会话和操作权限。负责 Token 校验、身份解析与上下文注入、基于角色的操作鉴权、未授权请求拦截。所有外部请求必须先经过本模块认证后才能路由到上游业务服务
依赖: Redis缓存
GoGinGo 1.22+Redis 7RESTful JSON API
🔀

中间件链

1. Request（原始 HTTP 请求到达 API 网关）→2. CORS（跨域检查，OPTIONS 预检请求直接返回）→3. RequestLogging（请求日志记录，记录来源 IP、路径、方法、时间）→4. Auth（认证中间件核心：Token 解析 → 黑名单检查 → 会话加载 → 上下文注入）→5. PathAuthz（路径级鉴权：根据 role_path_map 校验当前用户角色是否有权访问目标路径）→6. RateLimiter（请求频率限制：全局限流 + 每用户限流 + 特殊端点限流）→7. Router（路径匹配与路由分发：根据 path_pattern 将请求转发到对应 upstream 服务）→8. Upstream（上游业务服务处理请求并返回响应）→9. ResponseWrapper（统一响应格式封装，错误格式标准化）

认证授权

公开端点: /api/v1/auth/login /api/v1/health /api/v1/version
认证方式: JWT Bearer Token（Access Token 携带在 Authorization Header 中，格式为 Bearer <token>）
Token 策略: access_token 有效期 2 小时（7 200 秒），refresh_token 有效期 7 天（604 800 秒）。Access Token 过期后应使用 Refresh Token 获取新 Token，Refresh Token 过期后用户需重新登录

限流规则

全局 每 IP 100 req/s，超过后返回 429，适用于所有未在 public_endpoints 中声明的路径
每用户 每 user 1000 req/min，按 user_id 维度统计，超过后返回 429。适用于除 public_endpoints 外的所有认证请求
端点限制
POST /api/v1/auth/login每 IP 5 req/min，防止暴力破解密码
POST /api/v1/auth/refresh每 user 10 req/min，防止 Refresh Token 滥用
POST /api/v1/deploy每 user 10 req/min，部署操作为重型操作，限制频率防止误操作和资源耗尽
GET /api/v1/deploy/:taskId/status每 user 60 req/min，轮询场景适当地放宽限制
POST /api/v1/auth/logout每 user 30 req/min

错误处理

处理策略

认证中间件采用统一的 HTTP 状态码 + JSON 错误体格式返回错误信息。Token 校验失败返回 401，角色权限不足返回 403，请求频率超限返回 429，参数校验失败返回 400。认证失败的错误信息不应泄露用户是否存在（如登录时统一返回「用户名或密码错误」而非区分「用户不存在」和「密码错误」）。上游服务返回的错误透传给前端，本模块仅做统一格式封装

登录、刷新令牌等请求缺少必要字段或字段格式不符合要求时触发，detail 指明具体字段名
401
认证失败
未提供 Authorization Header、Token 格式错误、Token 过期、Token 被吊销（在黑名单中）、登录凭证无效等情况触发
403
权限不足
用户角色不满足接口所需的 role 要求时触发，由本模块基于 auth_policy.role_path_map 校验后拦截返回
404
资源不存在
透传上游服务返回的 404 错误，本模块不做额外处理
429
请求频率超限
超过 rate_limiting 配置的阈值时触发，全局限流或用户级限流到达上限后返回 429，响应头中应包含 Retry-After 字段告知客户端等待时间
500
服务器内部错误
Redis 连接失败、JWT 签发或解析异常、签名密钥缺失等不可预知错误。统一记录错误日志后返回泛化信息，不暴露内部错误详情
