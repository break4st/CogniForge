概述

SSH连接池
⚙️ 业务服务
管理到远程服务器的SSH连接复用，避免频繁建立连接。提供SSH会话的生命周期管理、连接复用和超时回收、断线重连机制以及连接健康检查功能。连接池以 (host, port) 为键维护会话映射，上层服务无需关心会话标识管理。
依赖: 密钥管理服务
PythonSSH/SCP/SFTP

服务接口 (1)

🔧 SshConnectionPoolService 5 方法
connect
(config: SshConnectionConfig) -> SshExecutionResult
建立到远程服务器的SSH连接并加入连接池管理，如池中已有同一地址的活跃连接则直接复用
前置条件
config.host 非空且为有效主机名/IP，config.port 在 1-65535 范围内，config.key_content 非空且为有效PEM格式私钥
后置条件
连接池中新增一条以 host:port 为键的会话记录，状态为 IDLE；如已有同键会话则返回现有会话
SshAuthenticationException→ 401SSH密钥认证失败（key_content 无效、与服务器公钥不匹配）SshConnectionException→ 502远程服务器不可达、DNS解析失败或连接超时PoolFullException→ 429连接池中总会话数已达 max_pool_size
execute
(config: SshConnectionConfig, command: String) -> SshExecutionResult
在远程服务器上执行命令，自动复用连接池中已有的 IDLE 会话或创建新连接
前置条件
config 参数完整有效，command 非空
后置条件
返回包含 stdout、stderr、exit_code 的执行结果；会话的 last_used_at 更新为当前时间；会话状态从 ACTIVE 回到 IDLE
SshAuthenticationException→ 401SSH密钥认证失败SshConnectionException→ 502远程服务器不可达或连接超时PoolFullException→ 429连接池已达最大容量且无可用空闲连接SshExecutionException→ 500命令执行过程中发生IO异常或远程异常中断CommandTimeoutException→ 504命令执行超过最大等待时间
disconnect
(host: String, port: Integer) -> void
关闭指定远程服务器的SSH连接并释放底层资源
前置条件
连接池中存在以 host:port 为键的会话
后置条件
对应的SSH连接被关闭，ssh_client 资源释放，会话从连接池中移除

healthCheck
(host: String, port: Integer) -> Boolean
通过发送心跳命令检测指定服务器的SSH会话是否健康可用
前置条件
连接池中存在以 host:port 为键的会话
后置条件
返回 true 表示会话可用（发送 exec('echo ok') 校验通过）；返回 false 表示会话已断开
SessionNotFoundException→ 404连接池中未找到 (host, port) 对应的会话
recycleIdleConnections
() -> Integer
遍历连接池，回收所有超过空闲超时阈值的SSH连接，释放系统资源
前置条件
无
后置条件
所有 last_used_at + idle_timeout < now 的会话被关闭并移除；返回被回收的会话数量

业务规则

不变量
  • !同一 (host, port) 组合在连接池中最多只有一个 IDLE 或 ACTIVE 状态的会话
  • !连接池中所有会话总数（含 IDLE + ACTIVE + RECONNECTING）不得超过 max_pool_size
  • !每个会话的空闲超时自 last_used_at 起计算，当 (now - last_used_at) > idle_timeout 时该会话为过期状态并可被回收
  • !SSH私钥内容（key_content）仅在建立连接时使用，连接建立成功后立即从内存中擦除明文引用，不写入日志、数据库或任何持久化存储
  • !会话进入 CLOSED 或 ERROR 状态后必须从连接池中移除，不可复用

🚫 CLOSED 和 ERROR 状态为终态，不可转换至任何其他状态🚫 CLOSED 状态的会话立即从连接池中移除，其 session_id 不再有效🚫 RECONNECTING 状态下连续失败超过阈值后不可再自动恢复，必须由外部干预（disconnect）
⚡ 连接池操作采用读写锁（ReadWriteLock）保护：同一 host:port 的连接建立操作互斥（写锁），避免竞态重复创建；execute 和 healthCheck 使用读锁并发执行；recycleIdleConnections 获取写锁后遍历全池
跨服务规则
SSH连接池与「密钥管理服务」协同：key_content 由密钥管理服务加密存储，部署执行服务在使用前调用密钥管理服务解密后传入 SSH 连接池，连接池自身不持久化任何密钥数据
SSH连接池与「部署执行服务」协同：部署执行服务作为 consumer 调用 execute 执行文件传输和启动脚本等远程操作，执行结果由部署执行服务解析并驱动后续部署状态流转
密钥明文生命周期约束：密钥管理服务将解密后的 key_content 传入 SSH 连接池，连接池在成功建立 SSH 连接后立即从调用栈和内存中擦除 key_content 明文引用，GC 后可回收
超时级联处理：当 SSH 连接池返回 502/504 错误时，部署执行服务应标记该环境部署失败并触发告警，避免无限重试耗尽连接池资源

⚠️

错误处理

处理策略

采用分层错误分类策略：连接层错误（认证失败、网络不可达）以 5xx 或 401 状态码返回；执行层错误（命令异常退出）通过响应中的 exit_code 和 stderr 携带；池层错误（池满、会话不存在）以 4xx 状态码返回。所有异常返回统一错误体格式。
