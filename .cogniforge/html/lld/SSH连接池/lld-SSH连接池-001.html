概述

SSH连接池
⚙️ 业务服务
管理到远程服务器的 SSH 连接，提供连接复用和生命周期管理。维护连接池内的连接状态，支持连接的健康检测、自动重连、空闲超时回收和并发数控制，供环境管理服务和部署引擎服务内部调用。
依赖: 密钥管理服务
GoGinGo 1.22+golang.org/x/crypto/ssh

TestConnection
(ctx context.Context, req *TestConnectionRequest) -> (TestConnectionResponse, error)
测试到指定远程主机的 SSH 连通性。获取解密密钥、建立 TCP 连接、完成 SSH 握手、记录握手耗时、立即关闭连接。不修改任何持久化数据。
前置条件
req.Host 非空且为合法主机地址、req.Port 在 1-65535 范围内、req.KeyId 在密钥管理服务中有效；当前全局连接数未达 maxGlobalConnections
后置条件
通过 req.KeyId 从密钥管理服务获取解密密钥并尝试 SSH 握手；握手成功返回 Connected=true 和实际延迟（毫秒），握手失败返回错误；连接测试完成后 socket 立即关闭，不加入连接池

TransferFile
(ctx context.Context, req *FileTransferRequest) -> (FileTransferResponse, error)
从连接池获取或新建 SSH 连接，通过 SFTP 协议将文件内容传输到远程服务器的指定路径。若远程父目录不存在则自动创建。传输完成后计算并返回文件的 SHA256 校验和。
前置条件
req.Host/Port/EnvKeyId 必须能匹配连接池中已有的 SSH 连接或成功创建新连接；req.RemotePath 必须是合法的 Unix 绝对路径；req.FileContent 大小不超过 500MB
后置条件
通过 SFTP 将 req.FileContent 写入远程服务器的 req.RemotePath 位置；写入完成后计算本地文件内容的 SHA256 摘要写入 response.Checksum；操作完成后连接归还到池中（状态 ACTIVE → IDLE）；写入失败时连接标记为 ERROR 并关闭

GetConnection
(ctx context.Context, host string, port int, keyId int64) -> (*SSHConnection, error)
从连接池获取到 (host,port,keyId) 的 SSH 连接。优先复用空闲连接（发送 keepalive 请求确认存活），无空闲时新建。新建连接调用密钥管理服务获取解密密钥后进行 SSH Dial。
前置条件
host 非空、port 在 1-65535 范围内、keyId 已通过密钥管理服务验证；该 (host,port,keyId) 组合的活跃连接数未达 maxConnectionsPerHost
后置条件
返回一个状态为 ACTIVE 的 SSHConnection：优先从空闲队列（FIFO）取出并执行一次心跳确认可用；无空闲连接时使用 keyId 获取解密密钥并新建 SSH 连接；连接的 LastUsedAt 更新为当前时间、UseCount 自增 1
ErrPoolExhausted→ 503该 (host,port) 的活跃连接数已达 maxConnectionsPerHost 或全局连接数已达 maxGlobalConnectionsErrAuthentication→ 401使用解密密钥建立 SSH 连接时认证失败ErrConnectionTimeout→ 408TCP 连接或 SSH 握手超时
ReleaseConnection
(connId string) -> error
调用方使用完连接后将连接归还给连接池。若连接仍健康则放入空闲队列等待复用，否则关闭并销毁。
前置条件
connId 在连接池管理范围内且当前状态为 ACTIVE
后置条件
连接状态从 ACTIVE 转换为 IDLE，连接被放回对应 HostConnectionPool 的空闲队列尾部；若连接已过期（ExpiresAt < now）或状态异常则直接关闭并从池中移除

业务规则

不变量
  • !同一 (host, port, keyId) 组合的活跃连接数不得超过 maxConnectionsPerHost，由 GetConnection 入口处的信号量控制
  • !全局连接总数（active + idle + reconnecting + error）不得超过 maxGlobalConnections，由全局计数器控制
  • !空闲连接超过 idleTimeout 必须被自动关闭并从池中移除，由后台 HealthCheck 协程定期扫描执行
  • !连接池中不存在重复连接：同一 (host, port, keyId) 最多一个空闲连接在空闲队列中，由链表查找保证
  • !出借给调用方的连接（ACTIVE）在 ReleaseConnection 归还前不可被其他 GetConnection 请求复用
  • !SSH 连接池不存储或缓存明文私钥：每次需要建立新连接时都调用密钥管理服务重新获取解密密钥，使用完毕后立即销毁内存中的私钥副本

🚫 连接一旦进入 CLOSED 状态不可再转换为任何其他状态，底层 ssh.Client 的 Close() 已调用，socket 已关闭🚫 连接进入 ERROR 状态后必须先转 CLOSED 再销毁，不可直接回到 IDLE 或 ACTIVE 状态复用
⚡ 全局连接池使用 sync.RWMutex 保护池元数据；每台主机的 HostConnectionPool 使用独立的 sync.Mutex，减少跨主机锁竞争；GetConnection 在创建新连接前使用双检锁模式——先尝试不加锁读取空闲队列，无可用连接时再获取锁二次检查，避免锁争用；ActiveCount 使用 atomic.Int64 计数器保证 GetConnection/ReleaseConnection 并发时计数的准确性
跨服务规则
调用密钥管理服务 GetDecryptedKeySession 后，连接池必须在使用完毕后立即清零内存中的明文私钥（使用 securezero 或手动覆写 []byte），禁止将私钥内容写入日志或审计记录
远程文件传输完成后，连接池应主动调用审计日志服务记录 transmission.complete 操作：action=transmission.complete, actor=deploy_engine, resource_type=deploy, resource_id=关联部署任务 ID, detail={host, remote_path, bytes, checksum}
连接测试完成后，连接池应主动调用审计日志服务记录 connection.test 操作：action=connection.test, actor=env_manager, resource_type=environment, resource_id=关联环境 ID, detail={host, port, key_id, latency_ms, connected}
密钥管理服务返回的解密密钥仅用于当前连接建立，连接池不得缓存解密后的密钥或指纹供后续连接复用
连接池的 HealthCheck 协程向远程服务器发送 keepalive 请求时不使用认证密钥——复用已建立的 ssh.Client 内置心跳，不产生额外的密钥服务调用

错误处理

处理策略

SSH 连接池所有错误统一返回标准 JSON 错误响应体。参数校验错误由 API 层捕获返回 4xx；SSH 连接/认证/传输错误由服务层捕获后分类映射到 4xx/5xx；密钥管理服务调用失败统一映射为 502。内部错误（如内存操作、goroutine panic）记录详细日志后返回通用错误消息，不泄露服务器内部状态或密钥信息。

操作超时：连接建立超过 connect_timeout、文件传输超过传输超时阈值。触发自动重连或重试机制。
413
Payload Too Large
文件内容超过 500MB 传输大小限制。仅远程文件传输接口产生此错误。
502
Bad Gateway
上游密钥管理服务调用失败：获取解密密钥会话时密钥管理服务返回错误或不可达。连接池应向上游调用方透传此错误。
503
Service Unavailable
连接池资源耗尽（全局连接数或单主机连接数已达上限）、连接意外断开或会话异常。调用方可等闲��回收后重试。
507
Insufficient Storage
远程服务器磁盘空间不足，无法写入文件。仅远程文件传输接口产生此错误。
500
Internal Server Error
服务端内部错误：SFTP 协议错误、校验和计算失败、goroutine 异常等。日志记录详细错误栈，响应体返回通用错误信息。
