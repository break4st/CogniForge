概述

SSH连接池
⚙️ 业务服务
管理到远程服务器的SSH连接池，复用连接减少握手开销。提供连接创建和复用、健康检查、自动重连、超时管理、并发连接控制能力，供部署编排服务通过内部REST接口执行远程命令。
依赖: 密钥存储服务
GoGingolang.org/x/crypto/ssh

服务接口 (1)

🔧 SSHConnectionPoolService 3 方法
Execute
(ctx context.Context, req *ExecuteRequest) -> (*ExecuteResponse, error)
在远程服务器上执行命令列表。通过连接池复用SSH连接减少握手开销，支持自动重连和超时控制。返回会话ID供后续排查追踪
前置条件
req.host 非空且为合法IP或域名；req.port 在 1-65535 范围内；req.auth_type 为 AuthType 枚举合法值（key/password）；req.auth_data 非空；req.commands 长度在 1-100 之间且每条命令不超过 4096 字符；无针对 (host, port, username) 的并发限制冲突
后置条件
从连接池获取或创建到目标服务器的SSH连接，在连接上依次执行 req.commands 中的每条命令，返回合并的 output、最终退出码和 session_id；执行完毕后连接归还池中（IDLE状态）；执行过程中连接断开时触发自动重连（最多 max_retry 次）；命令执行超时返回 TIMEOUT 错误并标记连接为 ERROR
ErrInvalidRequest→ 400请求参数校验失败（host为空、port越界、auth_type非法、commands为空或超长）ErrAuthFailed→ 401SSH握手认证失败（用户名不存在、密钥/密码错误、密钥PEM格式不合法或密钥权限不安全）ErrConnectionTimeout→ 408TCP拨号或SSH握手超过 connect_timeout 未完成ErrCommandTimeout→ 408单条命令执行超过 command_timeoutErrPoolExhausted→ 429目标服务器的活跃连接数已达 max_active 上限且等待超时ErrHostUnreachable→ 502TCP拨号返回 connection refused / no route to host 等网络层错误ErrInternal→ 500SSH库调用异常、连接意外断开、池内部状态损坏等不可预知错误
HealthCheck
(ctx context.Context) -> (*PoolStatus, error)
健康检查方法，遍历所有空闲连接发送 SSH keepalive 探活，清理已断开的连接，返回池状态快照。由内部定时器周期性触发
前置条件
连接池已初始化
后置条件
对池中所有 IDLE 状态的连接发送 SSH keepalive 请求校验可用性；不可用的连接标记为 ERROR 并关闭移除；返回当前连接池的聚合状态统计
ErrInternal→ 500健康检查遍历过程中池内部数据结构损坏
CloseIdleConnections
(ctx context.Context, idleThreshold time.Duration) -> (closedCount int, error)
关闭超过空闲阈值的连接，释放系统资源。由内部定时器周期性调用，间隔为 PoolConfig.idle_timeout
前置条件
idleThreshold > 0
后置条件
遍历池中所有 IDLE 状态的连接，关闭 last_used_at 超过 idleThreshold 的连接；返回被关闭的连接数量；EVICTED 状态的连接不触发健康检查
ErrInvalidArgument→ 400idleThreshold <= 0
数据访问依赖
acquireConnection(host: string, port: int, username: string, authType: string, authData: string) -> (*SSHConnection, error) — 从池中获取空闲连接或创建新连接，实现核心复用逻辑
releaseConnection(connId: string) -> error — 将连接归还池中，状态设为 IDLE，更新 last_used_at
markConnectionError(connId: string, errMsg: string) -> error — 标记连接为 ERROR，触发重连或关闭流程
closeConnection(connId: string) -> error — 关闭SSH连接并从池中移除，释放 TCP 资源
findIdleConnection(host: string, port: int, username: string) -> (*SSHConnection, error) — 按目标服务器查找空闲连接（LRU优先返回最久未使用的）
countConnectionsByTarget(host: string, port: int, username: string) -> (idle: int, active: int) — 统计目标服务器的连接分布，用于并发控制
iterateIdleConnections() -> ([]*SSHConnection, error) — 遍历所有空闲连接，供健康检查和空闲淘汰使用

业务规则

不变量
  • !每台目标服务器 (host, port, username) 的活跃连接数不得超过 max_active，空闲连接数不得超过 max_idle
  • !IDLE 状态的连接超过 idle_timeout 未使用必须被关闭并从池中移除
  • !ERROR 状态的连接不得超过 max_retry 次重连尝试，超过后标记为 CLOSED 终态
  • !同一 SSH 连接 (golang.org/x/crypto/ssh.Client) 在同一时刻只允许一个 session 执行命令，避免 TCP 复用冲突
  • !连接池启动时必须执行初始健康检查，确保可用连接正常
  • !认证凭证（auth_data）在使用完毕后必须在内存中及时清零，避免凭证残留
状态机
🎯 SSHConnection
CREATEDIDLEIN_USEERRORCLOSED
→SSH拨号和握手成功，连接加入空闲池待复用by SSHConnectionPoolService
→SSH握手期间发生不可恢复错误（认证失败/网络不可达），直接关闭by SSHConnectionPoolService
→acquireConnection 命中空闲连接，借出执行命令by SSHConnectionPoolService
→空闲超时淘汰（last_used_at + idle_timeout < now）或被健康检查发现连接已断开by 定时器/健康检查
→命令执行完毕（成功或失败），连接归还池中by SSHConnectionPoolService
→命令执行过程中连接断开或发生SSH协议层错误，释放 session 后标记by SSHConnectionPoolService
→自动重连成功（重新建立SSH连接），重试次数 +1by SSHConnectionPoolService
→重连已达 max_retry 上限或重连过程中发生不可恢复错误by SSHConnectionPoolService
→重新建立新连接（从CLOSED到CREATED是新连接，原连接已销毁）by SSHConnectionPoolService
🚫 CLOSED 状态为连接终态，已关闭的连接不可再进入 IDLE 或 IN_USE，如需使用必须创建新连接（进入 CREATED）🚫 IDLE -> ERROR 不可逆，空闲连接不会直接进入错误状态，只有 IN_USE 期间发生故障的连接才能进入 ERROR🚫 CREATED -> CLOSED（握手失败）不可重试进入 IDLE，调用方必须重新发起 Execute 请求触发新连接创建
⚡ 连接池内部使用 sync.RWMutex 保护连接映射表。acquireConnection 和 releaseConnection 操作加写锁保证线程安全。针对同一目标服务器的并发连接限制通过计数信号量（Semaphore）实现：acquire 时检查 active < max_active，不满足时阻塞等待（带超时）或直接返回 ErrPoolExhausted。健康检查和空闲淘汰使用读锁遍历连接列表，单个连接关闭时短暂升级为写锁。避免长时间持有锁导致吞吐下降
跨服务规则
部署编排服务调用 POST /internal/ssh/execute 前，应从密钥存储服务获取解密后的SSH凭证并传入 auth_data 字段，不得明文存储凭证
部署编排服务应确保同一目标服务器的命令执行请求可安全并发，SSH连接池内部通过计数信号量控制并发上限，超出时返回 429
SSH连接池不持久化连接状态到数据库，所有连接在服务重启后丢失，部署编排服务需要在重启后重新建立连接
若密钥存储服务返回的解密凭证格式不合法（如非PEM格式密钥），SSH连接池返回 401 错误，部署编排服务应根据错误类型决定是否重试获取凭证
审计日志服务需记录所有通过 SSH连接池执行的远程命令的调用信息（目标服务器、用户名、命令摘要、执行结果）供安全审计追溯。该职责由调用方（部署编排服务）负责触发审计日志记录
部署编排服务在接收到 502（目标服务器不可达）或 408（连接超时）错误时，应考虑目标服务器是否在维护中或网络分区，避免高频重试导致连接池被无效连接请求阻塞

⚠️

错误处理

处理策略

SSH连接池服务采用分层错误处理策略。参数校验错误直接返回 4xx；SSH协议层错误（认证失败、连接超时、网络不可达）映射为对应的 4xx/5xx 状态码；连接池资源耗尽返回 429 让调用方退避重试；内部状态异常统一返回 500 并记录详细错误日志用于排查。连接池内部优雅处理错误连接：标记为 ERROR 状态，关闭后从池中移除，不影响其他连接复用。

统一错误响应体
字段类型

errorstring

400
参数校验错误
请求参数不合法：host 为空、port 不在 1-65535 范围、auth_type 不是 key 或 password、commands 为空列表或条目超过限制（最大 100 条），detail 字段标注具体失败原因
401
SSH认证失败
SSH 握手阶段认证失败：用户名不存在、密钥/密码错误、密钥 PEM 格式解析失败、密钥权限不安全（权限过于开放会被 ssh 拒绝），不重试直接返回
408
连接或执行超时
connect_timeout 内未能完成 TCP 拨号或 SSH 握手，或 command_timeout 内命令未执行完毕，调用方可根据幂等性决定是否重试
429
连接池资源耗尽
目标服务器的活跃连接数已达 max_active 上限，且等待超时后仍无法获取可用连接，调用方应退避重试（建议至少等待 1s）
502
目标服务器不可达
TCP 拨号阶段返回 connection refused / no route to host 等网络层错误，说明目标服务器地址不可达或 SSH 服务未监听
500
服务内部错误
SSH 库调用异常、连接意外断开导致 session 创建失败、池内部状态损坏等不可预知错误，记录完整异常栈到日志用于排查
