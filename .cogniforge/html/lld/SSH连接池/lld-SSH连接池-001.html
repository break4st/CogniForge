概述

SSH连接池
⚙️ 业务服务
管理和复用SSH连接，提高远程执行效率。为部署编排服务、远程命令执行器和文件传输引擎提供统一的SSH连接管理能力，包括连接的建立、复用、空闲超时关闭、断线自动重连和周期性健康检测。属于执行层核心基础组件，业务服务通过内部API调用获取连接。
依赖: 密钥管理服务环境管理服务
Gogolang.org/x/crypto/ssh

服务接口 (1)

🔧 ConnectionPoolService 7 方法
Acquire
(ctx context.Context, req AcquireConnectionDTO) -> (*SSHConnection, error)
获取一个SSH连接到目标主机。优先从空闲池复用，无空闲连接且未达MaxActiveConns时新建，达到上限时阻塞等待直到有连接归还或超时。
前置条件
连接池已通过Init初始化且未调用Close；目标主机必须在环境管理服务中有有效注册；req.AuthKeyID必须在密钥管理服务中注册且未被禁用
后置条件
返回一个状态为ACTIVE的SSHConnection指针，LastUsedAt更新为当前时间；连接计入目标主机的active统计计数
ErrPoolClosed→ 503连接池已被Close，拒绝新连接请求ErrAcquireTimeout→ 408在Timeout/ConnectTimeout内未能获取到连接ErrAuthFailed→ 401密钥认证被目标主机拒绝（错误码6的SSH认证错误）ErrConnectFailed→ 502TCP拨号或SSH握手超时/被拒ErrInvalidConfig→ 400Host、Username或AuthKeyID为空
Release
(ctx context.Context, req ReleaseConnectionDTO) -> error
归还或关闭一个SSH连接。归还前对连接执行快速健康检查，不健康的连接自动关闭并从池中移除。
前置条件
req.ConnectionID必须是由Acquire返回的有效连接ID且该连接当前状态为ACTIVE
后置条件
连接归还到空闲池（state变为IDLE）并从active统计中移除；如果ForceClose=true或连接超过MaxConnLifetime，连接被关闭并从池中彻底移除
ErrConnectionNotFound→ 404ConnectionID不在连接池管理记录中ErrConnectionConflict→ 409连接状态不是ACTIVE（已被释放或在其他协程中关闭）
HealthCheck
(ctx context.Context, connectionID string) -> (HealthCheckReport, error)
对指定连接或所有空闲连接执行SSH keepalive健康检查。通过发送SSH keepalive请求验证会话活性。
前置条件
如果connectionID不为空，该连接必须存在于连接池管理中
后置条件
返回连接的健康检查报告；不健康的空闲连接自动关闭并从池中移除；不健康的活跃连接仅标记ERROR状态等待使用方释放
ErrConnectionNotFound→ 404指定的connectionID不存在ErrHealthCheckFailed→ 500健康检查过程本身出现内部错误（非连接问题）
GetStats
(host string) -> (map[string]*PoolMetrics, error)
获取连接池运行指标。包含总连接数、空闲/活跃连接数、命中/未命中次数、等待次数等统计。
前置条件
无
后置条件
返回当前时刻的指标快照，不修改任何状态；如果host为空则返回所有主机的指标
Close
(ctx context.Context, host string) -> (closedCount int, err error)
优雅关闭连接池。先标记池为关闭状态阻止新Acquire，然后等待正在使用的连接归还并关闭，最后强制关闭剩余空闲连接。
前置条件
无
后置条件
关闭所有指定主机（或全部）的连接，每个连接的状态变为CLOSED并释放TCP资源；标记池状态为已关闭
ErrPoolClosed→ 409连接池已被关闭，重复调用
RunBackgroundHealthCheck
(ctx context.Context) -> error
启动后台健康检查协程。每隔HealthCheckInterval对所有空闲连接执行health check，超过3次连续失败或idle超时的连接自动关闭。
前置条件
连接池已完成Init初始化；PoolConfig.HealthCheckInterval > 0
后置条件
启动一个后台goroutine按HealthCheckInterval周期执行空闲连接健康检查；goroutine在ctx取消时退出
ErrHealthCheckAlreadyRunning→ 409RunBackgroundHealthCheck在同一个池实例上被重复调用
Init
(cfg PoolConfig) -> error
初始化连接池实例。校验配置参数的合法性（超时值>0、连接数上限>0等），初始化锁和等待队列数据结构。惰性初始化，不预创建连接。
前置条件
连接池尚未初始化
后置条件
连接池进入就绪状态，PoolConfig被深度拷贝并保存为不可变配置；初始化后台指标计数器
ErrInvalidConfig→ 400PoolConfig参数非法（负数或零的MaxActiveConns等）ErrPoolAlreadyInitialized→ 409连接池已被初始化，重复调用

业务规则

不变量
  • !同一目标主机的活跃连接数必须小于等于PoolConfig.MaxActiveConns
  • !同一目标主机的空闲连接数必须小于等于PoolConfig.MaxIdleConns
  • !空闲连接超过PoolConfig.IdleTimeout未被使用时必须自动关闭并从池中移除
  • !连接存活时间超过PoolConfig.MaxConnLifetime时，在归还池操作中必须自动关闭重建
  • !连续HealthCheck失败超过3次的连接必须强制关闭并从池中移除
  • !连接池一旦标记为已关闭（CLOSED），所有后续Acquire调用必须立即返回ErrPoolClosed
  • !PoolConfig必须被深度拷贝，防止外部在初始化后意外修改配置
状态机
🎯 SSHConnection
IDLEACTIVECLOSEDERRORRECONNECTING
→Acquire从空闲池取出并标记为使用中by ConnectionPoolService.Acquire
→Release操作正常归还到空闲池by ConnectionPoolService.Release
→Release(ForceClose=true / MaxConnLifetime到期)直接关闭by ConnectionPoolService.Release
→IdleTimeout到期 / 健康检查失败 / MaxConnLifetime到期by 后台健康检查任务
→连接使用过程中发生I/O错误或SSH会话异常by 使用方服务（远程命令执行器/文件传输引擎）
→后台健康检查检测到连接无响应by 后台健康检查任务
→自动重连触发，在MaxRetryAttempts范围内尝试重建SSH连接by ConnectionPoolService
→重连成功，新SSHClient替换旧Clientby ConnectionPoolService
→达到MaxRetryAttempts仍失败，放弃重连并关闭by ConnectionPoolService
→关闭出错连接释放资源by ConnectionPoolService
🚫 CLOSED状态的连接不可再转换为任何其他状态，其底层SSH Client和TCP socket已被彻底释放🚫 CLOSED状态的连接ID不可被重用，即使后续对同一主机的Acquire也生成新的连接ID🚫 达到MaxRetryAttempts后从RECONNECTING到CLOSED的转换不可逆转
⚡ 连接池采用分桶锁设计：每个HostConnectionKey对应独立的sync.RWMutex，减少跨主机锁竞争；Acquire时在桶锁外完成TCP拨号，避免长时间持有锁；等待队列使用sync.Cond实现阻塞等待和广播通知；后台健康检查遍历空闲池时持有读锁，单连接检查完成即释放
跨服务规则
连接池通过AuthKeyID向密钥管理服务获取SSH私钥，密钥的AES-256解密由密钥管理服务完成，连接池仅持有解密后的临时凭证且使用后立即清理内存
连接建立失败时（认证错误除外）自动重试MaxRetryAttempts次，重试间隔指数退避（5s/10s/20s）。认证错误不重试，立即返回ErrAuthFailed
连接池不主动触发上游服务的重试或降级逻辑，仅通过错误码返回结果供上游决策（部署编排服务根据错误码决定是否重试整个部署任务）
远程命令执行器和文件传输引擎使用完连接后必须调用Release归还，严禁持有连接不释放。连接池侧设置IdleTimeout兜底清理泄漏连接
应用关闭时先调用Close关闭连接池，确保所有活跃连接执行完毕或超时强制关闭，然后才能安全退出进程

错误处理

处理策略

SSH连接池采用分级错误处理策略：连接获取阶段（Acquire）快速失败并返回明确错误码供上层重试或降级；连接使用阶段（用户服务持有连接时）的I/O异常由调用方捕获并决定是否释放连接或重试；后台健康检查发现的异常连接自动关闭并从池中移除，不对外暴露错误。所有错误均有结构化响应体，包含机器可读的错误码和人类可读的错误详情。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
4001
连接获取超时
在配置的connect_timeout内未能获取到可用连接。触发条件：池中所有连接均被占用且等待队列超时，或新建连接时TCP握手超时。调用方应等待后重试或降级处理。
4002
SSH认证失败
密钥管理服务提供的SSH密钥被目标主机拒绝。触发条件：密钥过期、密钥与目标主机不匹配、用户名不存在、目标主机公钥变更。调用方应通知用户检查密钥配置。
4003
SSH连接建立失败
TCP连接或SSH协议协商阶段失败。触发条件：目标主机端口未开放、防火墙拦截、不支持的密钥交换算法、协议版本不兼容。重试可能成功。
4004
连接池不可用
连接池已关闭或未初始化。触发条件：应用正在关闭过程中调用Acquire，或连接池初始化失败后调用服务。调用方应检查应用生命周期状态。
4005
连接标识不存在
指定的connection_id在当前连接池管理记录中不存在。触发条件：连接ID已被释放、从未被管理、或连接已在其他协程中被关闭。
4006
连接状态冲突
连接当前状态不允许执行请求操作。触发条件：尝试释放一个已被释放的连接，或尝试归还一个状态为CLOSED的连接。
4007
健康检查内部错误
执行健康检查过程中出现非连接相关的内部异常。触发条件：goroutine panic、共享数据结构损坏。记录告警日志并通知运维。
