概述

Redis
⚙️ 业务服务
内存缓存和实时状态存储，加速数据访问和实时状态追踪。提供用户会话缓存、部署任务实时状态缓存、环境连接测试结果缓存和配置缓存功能，降低数据库读压力。所有缓存操作通过统一的 CacheService 封装 Redis 客户端暴露给各服务调用。
Python 3.11+asyncio + uvicornRedis 7Docker + Docker Compose
🗄️

数据模型 (4)

状态存储 4

🗃️ sessions自有

用户会话缓存。以 Redis String 结构存储用户登录会话数据，由 API Gateway 在用户登录成功后写入。key 格式: session:{session_id}，value 为 JSON 序列化的会话对象。必须设置 TTL 防止内存泄漏。

字段
字段名类型描述
key_pattern *StringRedis key 格式: session:{session_id}
value_structure *JSON会话数据 JSON，包含 user_id、username、role、expires_at
ttl_seconds *Integer缓存过期时间，默认 3600 秒（1 小时），禁止无 TTL 的会话缓存

🗃️ deployment_status自有

部署任务实时状态缓存。以 Redis Hash 结构存储部署执行的实时进度，供 Deployment Orchestrator 在消费 RabbitMQ 进度消息后更新、Web Console 轮询查询。key 格式: deploy:status:{deployment_id}。

字段
字段名类型描述
key_pattern *StringRedis key 格式: deploy:status:{deployment_id}
fields *Hash（多个字段）Hash 字段: status(String)、current_step(String)、progress_pct(Integer 0-100)、logs(JSON array of String)、error_message(String)、started_at(DateTime)、finished_at(DateTime)
ttl_secondsInteger由调用方根据部署状态决定 TTL，终态（success/failed）建议 3600 秒，非终态建议 86400 秒

🗃️ connection_test_results自有

环境连接测试结果缓存。以 Redis String 结构存储 SSH 连接探测的结果，由 Environment Management Service 在连接测试完成后写入。key 格式: connection_test:{environment_id}:{timestamp}。

字段
字段名类型描述
key_pattern *StringRedis key 格式: connection_test:{environment_id}:{unix_timestamp}
value_structure *JSON测试结果 JSON，包含 reachable(Boolean)、latency_ms(Integer)、error(String)、tested_at(DateTime)
ttl_seconds *Integer测试结果 TTL 固定 300 秒（5 分钟），因连接测试结果时效性很强

🗃️ config_cache自有

通用配置缓存。以 Redis String 结构缓存从 Primary Database 读取的配置项，降低数据库查询压力。支持按命名空间分组和主动失效。key 格式: config:{namespace}:{config_key}。

字段
字段名类型描述
key_pattern *StringRedis key 格式: config:{namespace}:{config_key}
value_structure *JSON配置值 JSON 对象
ttl_secondsInteger可选 TTL，不设置时由主动失效机制控制缓存生命周期

🏷️ SessionData实体

用户会话缓存实体。存储用户登录后的身份认证信息，用于 API Gateway 鉴权和用户上下文传递。缓存在 Redis 中通过 TTL 自动过期。

🏷️ DeploymentStatus实体

部署任务实时状态实体。以 Redis Hash 存储部署执行的实时进度，反映当前时刻的部署快照。由 Deployment Orchestrator 在消费 RabbitMQ 进度消息后更新，供 Web Console 轮询展示。

属性

progress_pct * 输入Integer整体进度百分比，范围 0-100
logs 输入List[String]部署日志行列表，按时间顺序追加
error_message 输入String失败时的错误信息，仅 status=failed 时有意义

finished_at 输入DateTime部署完成时间，终态时由进度消息携带

🏷️ ConnectionTestResult实体

环境连接测试结果缓存实体。存储一次 SSH 连接探测的完整结果，5 分钟 TTL 后自动过期。用于 Web Console 实时显示环境连接状态。

属性
属性名类型描述
environment_id * 输入UUID环境 ID，标识被测试的目标环境

latency_ms * 输入Integer连接延迟毫秒数，不可达时设为 -1

tested_at * 计算DateTime测试完成的时间戳（UTC），由服务端在写入时自动生成

🏷️ CacheConfigEntry实体

配置缓存实体。存储从 Primary Database 读取的配置项的缓存快照，降低数据库查询压力。通过主动失效机制保证缓存与数据库的一致性。

属性
属性名类型描述
namespace * 输入String配置命名空间，如 project / environment / system
config_key * 输入String配置项键名
value * DB 透传JSON配置值，来自 Primary Database 对应配置表
cached_at * 计算DateTime缓存写入时间戳，用于判断缓存新鲜度

🔢 DeploymentState枚举

部署状态枚举。与 Primary Database deployments.status 字段枚举值一致，用于 Redis 缓存和数据库之间的状态同步。

缓存命名空间枚举。定义 Redis key 的一级前缀，避免不同用途的缓存键名冲突，同时也作为调用方区分缓存用途的唯一标识。

📋 CacheEntryDTO

通用缓存条目 DTO。封装 key-value-TTL 三元组，作为 CacheService 各方法之间的通用数据传输对象。支持序列化为 Redis 协议格式。

属性
属性名类型描述

value * 输入Object序列化的缓存值，最终以 JSON 字符串写入 Redis

缓存查询结果 DTO。封装缓存命中/未命中的判断、实际值和剩余 TTL 信息。调用方通过 hit 字段决定是否回源。

业务规则

不变量
  • !Redis 中缓存的数据始终以 Primary Database 中的持久化数据为权威来源，缓存数据允许最终一致性延迟
  • !部署状态缓存（deploy:status:{id}）与 Primary Database deployments 表的同名字段保持最终一致，数据库记录为权威状态
  • !所有 Redis key 必须遵循统一的命名规范 {namespace}:{identifier}[:{sub_identifier}]，namespace 为 CacheNamespace 枚举值之一（session / deploy / connection_test / config）
  • !会话缓存（session:*）必须设置 TTL，默认 3600 秒，禁止创建无 TTL 的会话缓存以防止 Redis 内存泄漏
  • !连接测试结果缓存（connection_test:*）必须设置 TTL 300 秒（5 分钟），因连接测试结果时效性强、过期后无业务价值
  • !部署完成终态（success/failed）后部署状态缓存应由调用方设置 TTL 3600 秒（1 小时），非终态建议 TTL 86400 秒（24 小时），避免已完成的部署永久占用 Redis 内存
  • !配置缓存支持无 TTL 持久化模式，但必须依赖主动失效机制在配置更新时清除，否则调用方将读取过期配置导致数据不一致
跨服务规则
Deployment Orchestrator 在消费 RabbitMQ deploy.progress 队列的 DeployProgressMessage 后调用 CacheService.updateDeploymentStatus() 更新 Redis 中的部署实时状态。Web Console 通过 Deployment Orchestrator 的 GET /api/v1/deployments/{id}/status 查询缓存状态，Deployment Orchestrator 先查 Redis 缓存（CacheService.getDeploymentStatus()），缓存未命中时回源到 Primary Database
Environment Management Service 在执行 SSH 连接测试后调用 CacheService.setConnectionTestResult() 写入测试结果，Web Console 可通过 Environment Management Service 查询最近测试结果。Environment Management Service 内部调用 CacheService.getLatestConnectionTestResult() 获取缓存
各微服务（Project Management Service、Environment Management Service、Key Management Service 等）在读取系统配置时优先调用 CacheService.getConfig()，缓存未命中时从 Primary Database 读取并回填缓存（CacheService.setConfig()）。配置更新时必须调用 CacheService.invalidateConfig() 使对应缓存失效
API Gateway 在用户登录成功后调用 CacheService.setSession() 将会话数据写入 Redis，每次请求鉴权时调用 CacheService.getSession() 校验用户身份。用户登出时调用 CacheService.deleteSession() 清理会话
Redis 服务不可用时不阻塞主业务流程。所有调用方应降级处理：跳过缓存直接查询 Primary Database，并在日志中记录 WARN 级别的 Redis 不可用告警
本服务（Redis 缓存层）不提供 HTTP API 接口，所有操作通过内部 Python 方法调用（CacheService 类）由各服务的 Service 层直接引用。redis-py async client 由各服务自行初始化连接池
各服务连接 Redis 使用统一的连接配置（host/port/db/index/password），通过共享的 ConfigManager 读取。生产环境建议启用 Redis ACL 或密码认证，不同 namespace 可分配不同 db index 做逻辑隔离

错误处理

处理策略

所有 Redis 操作采用防御式编程，捕获连接异常和序列化异常。缓存未命中（key 不存在或已过期）返回 404 语义由调用方决定回源策略。Redis 连接不可用时不阻塞主业务流程，调用方应降级为直接查询 Primary Database。所有未预期异常统一由全局异常处理器返回 500。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
404
缓存未命中
Redis key 不存在或已过期被自动淘汰。调用方应回源到 Primary Database 或上游服务重新获取数据，不可返回空结果给用户
500
Redis 连接异常
Redis 服务不可用、连接拒绝、认证失败或命令超时。CacheService 内部捕获后抛出 RedisConnectionException，调用方应降级处理：跳过缓存直接查询数据库
500
序列化异常
JSON 序列化或反序列化失败（数据格式错误、类型不匹配、结构损坏）。应删除脏数据 key 后重试操作
