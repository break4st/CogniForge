概述

Key Management Service
⚙️ 业务服务
SSH 密钥安全管理的专用服务，负责 SSH 私钥的加密存储与解密使用、密钥的导入与验证、密钥访问权限控制、密钥轮换支持。接收来自 Environment Management Service 的密钥导入请求，对私钥进行 AES-256-GCM 加密后持久化至 Primary Database。为 SSH Execution Service 提供密钥解密接口以用于远程服务器认证。所有密钥操作同步记录审计日志至 Audit Service。
依赖: Primary DatabaseAudit Service
Python 3.11+FastAPIasyncio + uvicornPostgreSQL 15Docker + Docker Compose

服务接口 (1)

🔧 KeyManagementService 5 方法
importKey
(request: KeyImportRequest) -> KeyImportResponse
导入 SSH 私钥。解析并验证 PEM 格式，提取公钥计算 SHA256 指纹，使用 AES-256-GCM 加密私钥主体后持久化。如果提供了 passphrase，先使用 passphrase 解密私钥再处理。
前置条件
request.name 非空且长度 ≤ 100；request.private_key 为合法 PEM 格式 SSH 私钥（支持 RSA/ECDSA/Ed25519）；request.project_id 为有效 UUID；同一项目下 name 唯一；fingerprint 全局唯一
后置条件
私钥已通过 AES-256-GCM 加密后写入 ssh_keys 表，状态为 active。返回 KeyImportResponse（含 key_id/name/fingerprint/created_at）。同步发送审计事件到 Audit Service
ValidationException→ 400name 为空或超长、private_key 非合法 PEM 格式、project_id 非 UUID 格式DuplicateKeyException→ 409同一项目下 name 已存在，或 fingerprint 在全局已存在（重复导入相同密钥）EncryptionException→ 500AES-256-GCM 加密操作失败（主密钥不可用、加密库异常）
decryptKey
(key_id: UUID, passphrase: Optional[str]) -> DecryptResponse
解密 SSH 私钥。按 key_id 查询加密记录，使用主密钥和存储的 IV/auth_tag 执行 AES-256-GCM 解密，返回 PEM 明文私钥。用于 SSH Execution Service 的远程认证场景。
前置条件
key_id 为有效 UUID；key_id 对应密钥在 ssh_keys 表中存在且状态为 active 或 rotated
后置条件
从 ssh_keys 表读取加密记录，使用 AES-256-GCM 解密并返回 DecryptResponse（含 key_id 和 private_key 明文）。同步发送审计事件到 Audit Service。如密钥 passphrase_protected=true，则校验传入的 passphrase 后再解密
KeyNotFoundException→ 404key_id 对应记录在 ssh_keys 表中不存在KeyRevokedException→ 403密钥状态为 revoked，拒绝解密PassphraseRequiredException→ 409密钥 passphrase_protected=true 但未提供 passphrase 参数PassphraseMismatchException→ 409提供的 passphrase 与导入时设置的不匹配DecryptionException→ 500AES-256-GCM 解密失败（密钥损坏、认证标签校验失败）
getKeyMetadata
(key_id: UUID) -> KeyMetadataResponse
查询单个密钥的元数据。返回密钥的所有非敏感属性，用于密钥管理界面的详情展示和跨服务校验。
前置条件
key_id 为有效 UUID 格式
后置条件
返回 KeyMetadataResponse 包含密钥全部元数据字段，不含私钥内容。密钥无论状态（active/rotated/revoked）均可查询

分页查询指定项目下的 SSH 密钥列表。支持按状态过滤，返回密钥摘要（不含私钥）。用于密钥管理面板的列表展示。

revokeKey
(key_id: UUID) -> KeyRevokeResponse
吊销 SSH 密钥。将密钥状态标记为 revoked，使其不可再用于解密。已吊销的密钥元数据保留在数据库中供审计追踪。

业务规则

不变量
  • !同一项目下密钥名称唯一，比较不区分大小写
  • !密钥 fingerprint（SHA256 指纹）全局唯一，不可重复导入相同的 SSH 密钥对
  • !SSH 私钥在持久化时始终使用 AES-256-GCM 加密，不得以明文形式存储在数据库中
  • !解密后的私钥明文仅在 HTTP 响应中传输，服务端不得缓存、持久化或记录日志中的私钥内容
  • !私钥解密日志中不得包含私钥内容，仅记录 key_id、操作者和操作结果
  • !状态为 revoked 的密钥不可被解密使用
  • !密钥名称长度 1-100 字符，不可为纯空白字符串
  • !passphrase_protected=true 的密钥在解密时必须校验 passphrase，不匹配则拒绝解密
状态机
🎯 SshKey
activerotatedrevoked
→密钥轮换（新密钥替换旧密钥，旧密钥标记为 rotated）by 系统/管理员
→密钥吊销或过期（revokeKey 主动吊销 / expires_at 过期自动触发）by 管理员/系统定时任务
→密钥吊销（revokeKey）by 管理员
🚫 密钥一旦进入 revoked 状态不可逆转（不可重新激活或恢复为 rotated）🚫 密钥从 active 到 rotated 的转换不可逆（不可从 rotated 回到 active）🚫 密钥过期后自动视为 revoked，由定时任务扫描 expires_at 字段执行状态变更🚫 revoked 或 rotated 状态的密钥数据保留在数据库中不删除，供审计追踪和历史部署记录引用
⚡ 使用 PostgreSQL 行级锁（SELECT FOR UPDATE）保护状态变更操作。状态更新使用 WHERE key_id = ? AND status = ? 条件更新确保原子性，若影响行数为 0 则说明状态已被其他事务先行变更，返回冲突错误。同一密钥不允许并行状态变更。
跨服务规则
密钥导入和吊销后通过 Audit Service 的 POST /internal/audit/log 接口同步记录审计日志。审计调用失败不影响主流程（fire-and-forget，本地记录 WARN 日志）
SSH Execution Service 调用 POST /internal/keys/{key_id}/decrypt 获取解密密钥后，私钥仅在调用方内存中使用，使用后应立即清除，不得持久化到磁盘
Environment Management Service 调用 POST /internal/keys/import 导入密钥时需确保 project_id 对应的项目在 Project Management Service 中存在且为 active 状态（由 Environment Management Service 自行校验）
密钥轮换操作涉及本服务和 Environment Management Service 协调：本服务将旧密钥标记为 rotated 并创建新密钥，Environment Management Service 需在环境配置中更新引用的 key_id
所有涉及密钥的跨服务操作（导入、解密、吊销）均需通过本服务的内部接口进行，其他服务不得直接操作 ssh_keys 数据库表
主加密密钥（KMS master key）通过环境变量 KMS_MASTER_KEY_ID 注入，不允许硬编码在代码或配置文件中

错误处理

处理策略

Key Management Service 对所有请求参数进行前置校验，校验失败返回 400。密钥存在性校验在每次数据操作前执行，不存在返回 404。业务逻辑冲突（名称重复、指纹重复、状态冲突）返回 409。密钥被吊销后拒绝解密操作返回 403。加密/解密操作失败返回 500。所有未预期异常由全局异常处理器捕获，返回 500 并记录错误日志，同时向 Audit Service 发送失败审计事件。
