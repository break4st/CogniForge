概述

环境管理服务
⚙️ 业务服务
部署环境配置与SSH密钥管理，保障连接安全。本服务负责部署环境的创建、编辑、删除，SSH密钥的上传与加密存储管理（AES-256-GCM），以及远程SSH连接的可用性测试验证。服务通过 FastAPI 暴露REST接口，直接使用 asyncssh 发起远程连接测试，密钥数据通过关系型数据库持久化并以加密形态存储。
依赖: 关系型数据库项目管理服务
Python 3.11+FastAPIasyncssh (Python)PostgreSQL 15

业务规则

不变量
  • !同一项目（project_id）下环境名称（name）必须唯一，不允许出现同名环境
  • !环境类型（type）的合法值必须严格限定为 test、staging、production 三者之一
  • !认证类型（auth_type）为 key 时，key_id 必须非空且引用 ssh_keys 表中已存在的记录
  • !SSH密钥指纹（fingerprint）基于公钥计算，必须在全局唯一，杜绝同一密钥对重复导入
  • !环境连接状态（status）的合法值必须严格限定为 connected、disconnected、unknown 三者之一
  • !创建环境和上传密钥时的 name 字段禁止为空字符串或仅空白字符
  • !SSH端口号（port）必须为有效值范围 1-65535，默认 22
状态机
🎯 Environment (status)

→SSH连接测试成功（TestConnection API 返回 reachable=true）by 用户/运维工程师

⚡ 对同一环境的连接测试请求应串行化执行。使用基于 envId 的分布式锁（Redis SETNX 或数据库行级锁），避免多个并发测试请求同时发起 SSH 连接造成资源竞争。测试超时后锁自动释放（TTL=60秒）。
跨服务规则
环境管理服务作为 ProjectSwitchAPI 的消费者，在「项目管理服务」处理项目切换请求时，需同步返回目标项目的环境配置列表。此处由 API 网关聚合或前端先后调用实现，环境管理服务本身提供按 project_id 查询环境列表的接口供消费
部署引擎服务在创建部署任务前通过 GET /api/v1/environments/{env_id} 读取环境配置。环境删除时需确保无状态为 pending/running 的部署记录引用该环境，此约束由 EnvironmentService.deleteEnvironment 中的 existsActiveDeploymentByEnvironmentId 查询保障
密钥被环境引用（environments.key_id 指向该密钥）时禁止删除，防止环境配置失效。此约束在 KeyManagementService.deleteKey 中通过 countEnvironmentsByKeyId 检查实现

⚠️

错误处理

处理策略

采用分层错误处理策略。参数校验错误直接返回 400 并明确指明非法字段；业务约束违反（名称冲突、引用不存在等）返回 409/404 并附带可读的错误描述；SSH远程操作失败返回 502 并区分认证失败与网络不可达；加密/解密内部错误返回 500 并记录审计日志，不暴露密钥相关细节给调用方。所有错误响应统一格式。
