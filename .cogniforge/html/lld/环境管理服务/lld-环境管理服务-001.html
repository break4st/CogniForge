概述

环境管理服务
⚙️ 业务服务
管理多套部署环境的配置信息，包括环境类型和服务器连接参数。负责环境的创建、编辑、删除，环境类型标签管理（测试/灰度/正式），服务器连接参数配置，环境与项目关联关系管理，以及连接可用性测试。
依赖: PostgreSQL数据库审计日志服务密钥管理服务SSH连接池
PythonFastAPIPostgreSQL 15paramiko

业务规则

不变量
  • !同一项目下环境名称唯一（不区分大小写），软删除的环境名称不计入唯一约束
  • !环境关联的SSH密钥必须存在于密钥管理服务中且状态为 active（如有关联）
  • !环境被软删除后不可恢复，不可用于新的部署操作
  • !环境类型仅允许 test、staging、production 三种值
  • !已删除的环境（deleted_at 非空）在默认查询中被排除，所有业务操作拒绝已删除的环境
状态机
🎯 Environment.status
untestedavailableunavailable
→连接测试成功（test_connection 返回 success=true）by 运维人员 / 系统自动检测
→连接测试失败（test_connection 返回 success=false）by 运维人员 / 系统自动检测
→周期健康检查失败或手动连接测试失败by 系统自动检测 / 运维人员
→重新连接测试成功by 运维人员 / 系统自动检测
🚫 状态转换仅发生在 status 三个合法值之间，不存在单向不可逆转换🚫 每次转换都会更新 updated_at 时间戳🚫 状态转换结果由实际连接测试结果决定，不接受手动强制变更
⚡ 连接测试方法内部通过数据库行锁（SELECT FOR UPDATE）锁定环境记录，防止并发测试导致状态覆盖。连接测试与更新/删除操作互斥，同一环境同一时刻仅允许一个连接测试执行
跨服务规则
创建、更新、删除环境以及执行连接测试时，必须调用审计日志服务记录操作轨迹（POST /api/internal/audit-logs），action 分别对应 environment.create / environment.update / environment.delete / environment.test-connection
创建环境时指定的 key_id 必须向密钥管理服务校验该密钥是否存在且状态为 active，不可仅依赖数据库外键约束
删除环境前必须查询 deployments 表确认无 pending 或 running 状态的部署任务（环境管理服务具备 deployments 表 SELECT 权限）
连接测试时需通过密钥管理服务获取解密后的SSH私钥（调用密钥管理服务的内部接口），凭据使用后立即从内存清除
获取环境详情时返回的 project_name 通过关联查询 projects 表获取（环境管理服务具备 projects 表 SELECT 权限）

错误处理

处理策略

环境管理服务采用分层错误处理：参数校验错误返回4xx明确提示；依赖服务（密钥管理服务、SSH连接池）不可用返回503；业务冲突（重复名称、存在活跃部署）返回409并附带冲突详情；所有异常统一捕获并记录审计日志后返回结构化错误响应

统一错误响应体
