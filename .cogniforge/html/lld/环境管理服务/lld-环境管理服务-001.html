概述

环境管理服务
⚙️ 业务服务
管理部署环境的配置，包括服务器地址、端口、认证方式等。提供环境的创建、编辑、删除、连通性测试等核心功能。
依赖: 数据库SSH连接池审计日志服务密钥管理服务
GoGinGo 1.22+PostgreSQL 15golang.org/x/crypto/ssh

业务规则

不变量
  • !同一项目内环境名称必须唯一（由数据库索引 uq_environments_project_name 保证）
  • !环境必须绑定至少一个SSH密钥才能执行连通性测试
  • !一个环境同一时间只能绑定一个SSH密钥
  • !环境状态仅允许在 active / inactive / error 三种之间转换
  • !有关联部署任务的环境不可删除
状态机
🎯 Environment
activeinactiveerror
→用户手动启用/创建环境by 用户
→用户手动停用环境by 用户
→连通性测试连续失败by 系统
→连通性测试成功或用户手动恢复by 用户或系统
→连通性测试失败（允许从未激活状态测试）by 系统
→用户手动停用异常环境by 用户
🚫 无不可逆转换：所有状态转换均可逆向操作
⚡ 使用乐观锁（updated_at字段）防止并发状态覆盖。更新状态时 WHERE updated_at = :old_updated_at，更新行数为0时说明并发冲突，抛出OptimisticLockError，由调用方决定是否重试
跨服务规则
创建/更新/删除环境后，必须同步调用审计日志服务记录操作，但在审计日志写入失败时不影响主流程（异步非阻塞）
连通性测试必须通过SSH连接池进行，禁止绕过连接池直接建立SSH连接
环境的密钥绑定状态由密钥管理服务维护，环境管理服务通过数据库关联查询或密钥管理服务提供的查询接口获取绑定关系
删除环境前必须检查deploy_tasks表中是否存在关联记录（通过ExistsActiveDeployTasksByEnvironmentId查询），如有则拒绝删除
环境管理服务不直接管理SSH密钥的加解密，仅存储密钥ID作为绑定关系引用

错误处理

处理策略

所有外部接口统一返回标准JSON格式错误体，业务异常通过HTTP状态码区分语义。参数校验在API层前置拦截，数据库约束异常（唯一冲突、外键冲突）由Repository层捕获并转为业务错误码返回。跨服务调用（SSH连接池、审计日志）失败时，环境管理服务仅透传错误信息，不重试。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
请求参数错误
必填字段缺失、字段格式错误（如端口超出1~65535）、字段长度超限等，由Gin的binding校验器前置拦截

资源不存在
按ID查询项目/环境时记录不存在，或关联的外键资源不存在
409

唯一约束违反（同一项目下环境名重复）、依赖约束违反（环境存在部署任务无法删除）
