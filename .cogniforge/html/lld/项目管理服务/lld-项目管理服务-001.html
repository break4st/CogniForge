概述

项目管理服务
⚙️ 业务服务
管理项目的创建、编辑、删除和查询，维护项目间隔离。每个项目作为独立资源单元，拥有独立的部署环境配置和部署历史，项目之间数据完全隔离。服务通过 API 网关对外暴露 RESTful 接口，数据持久化于 PostgreSQL。
依赖: PostgreSQL数据库
GoGinPostgreSQL 15JWT

服务接口 (1)

🔧 ProjectService 5 方法
Create
(ctx context.Context, name string, description string) -> (*Project, error)
创建新项目。校验名称格式和唯一性，生成 UUID 主键，设置时间戳后写入数据库。事务内完成写入
前置条件
name 去除首尾空白后不为空，长度在 1-255 字符之间；系统中不存在同名（不区分大小写）且未软删除的项目
后置条件
新 Project 已插入数据库 projects 表，包含生成的 UUID v4 主键和当前 UTC 时间戳；name 唯一约束已生效
ErrProjectNameConflict→ 409name 与数据库中已存在的未删除项目名称冲突（大小写不敏感比较）ErrInvalidInput→ 400name 为空字符串或超过 255 字符
GetByID
(ctx context.Context, id string) -> (*Project, error)
根据主键查询项目详情，自动过滤已软删除记录
前置条件
id 为有效的 UUID v4 格式字符串
后置条件
返回 id 匹配且 deleted_at IS NULL 的 Project 实体；不存在则返回 ErrProjectNotFound
ErrProjectNotFound→ 404id 在 projects 表中不存在或对应的 deleted_at 非空
Update
(ctx context.Context, id string, name string, description string) -> (*Project, error)
更新项目信息。仅更新请求中提供的字段（非空值覆盖），自动刷新 updated_at 时间戳
前置条件
id 为有效 UUID；项目存在且未删除；若 name 非空则新的 name 不能与现有项目（排除自身）冲突
后置条件
项目记录的 name、description 和 updated_at 已更新；未提供的字段保持原值；返回更新后的完整 Project 实体
ErrProjectNotFound→ 404id 不存在或已被软删除ErrProjectNameConflict→ 409新的 name 已被其他未删除项目占用
Delete
(ctx context.Context, id string) -> error
软删除项目。在事务中检查项目是否存在、是否已有删除标记、是否有进行中的部署任务，满足条件后设置 deleted_at
前置条件
id 为有效 UUID；项目存在且未删除；项目下没有状态为 pending 或 running 的部署任务
后置条件
项目的 deleted_at 字段设置为当前 UTC 时间（软删除）；关联数据物理保留但逻辑上不可见；后续查询自动过滤
ErrProjectNotFound→ 404id 不存在或已被软删除ErrProjectHasActiveDeployments→ 409项目下存在状态为 pending 或 running 的部署任务
List
(ctx context.Context, page int, pageSize int, keyword string) -> ([]*Project, int64, error)
分页查询项目列表。keyword 非空时对 name 字段进行 ILIKE 模糊搜索（PostgreSQL 大小写不敏感匹配）。统计总数时不使用 COUNT(*) 而使用 COUNT(1) 优化性能
前置条件
page >= 1；pageSize 在 [1, 100] 范围内
后置条件
返回当前页的项目指针切片和符合条件的项目总数；结果按 updated_at DESC 排序；deleted_at IS NOT NULL 的记录不包含在结果中
ErrInvalidInput→ 400page < 1 或 pageSize 不在 [1, 100] 范围内

业务规则

不变量
  • !项目名称在系统内全局唯一，比较时忽略大小写和首尾空白
  • !项目只能软删除（设置 deleted_at 时间戳），不可从数据库中物理移除
  • !项目名称最长 255 个字符，去除首尾空白后不可为空
  • !项目描述最长 2000 个字符
  • !存在进行中部署任务（deployments.status 为 pending 或 running）的项目不允许删除
  • !项目查询接口始终过滤已软删除记录（WHERE deleted_at IS NULL）
状态机
🎯 Project
activedeleted
→用户调用 DELETE /api/v1/projects/:id，系统在事务中验证无进行中部署任务后执行软删除by 项目管理员 / 运维人员
🚫 active -> deleted 转换不可逆：一旦软删除，系统不提供恢复接口。如需恢复需通过数据库管理员直接操作 projects 表清除 deleted_at 字段，且恢复后不保证关联资源（环境、部署记录）的一致性
⚡ 删除操作在单个数据库事务中完成：先通过 SELECT ... FOR UPDATE 锁定 project 行，再检查部署任务状态，最后执行 UPDATE deleted_at。利用 PostgreSQL 行级锁防止并发删除和并发部署导致的竞态条件
跨服务规则
项目删除时：项目管理服务不级联删除关联资源。环境配置服务和部署编排服务各自在查询时通过 project_id 过滤已删除项目的记录，确保数据一致性
项目创建/更新/删除操作完成后，通过异步消息或直接调用审计日志服务记录操作事件，记录内容包含操作人、操作类型、资源 ID 和变更详情
API 网关负责 JWT 令牌认证和用户身份提取，将解析后的用户信息注入请求上下文（如 X-User-ID、X-User-Role 请求头），项目管理服务从中获取操作人信息用于鉴权和审计
项目列表接口当前仅返回项目自身信息，后续版本可扩展为返回关联的环境数量等聚合信息，通过调用环境配置服务的聚合接口或数据库 JOIN 查询实现

错误处理

处理策略

通过统一错误中间件捕获业务异常并转换为标准 JSON 错误响应。参数校验失败返回 400，资源不存在返回 404，业务冲突返回 409，服务内部错误返回 500。错误响应统一包含错误码、简短描述和详细说明。不在响应中暴露内部实现细节。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验错误
请求参数校验失败，如名称为空、超长、UUID 格式不合法、分页参数超范围等，detail 字段包含具体校验失败原因
404
资源不存在
请求的项目 ID 在数据库中不存在或已被软删除，detail 字段说明具体资源类型和标识
409
业务冲突
项目名称与现有项目冲突，或项目下存在进行中的部署任务无法删除，detail 字段包含冲突原因
500
服务内部错误
数据库连接故障、未捕获的运行时异常等，记录详细错误栈到服务日志，返回通用错误信息不暴露内部细节
