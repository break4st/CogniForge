概述

项目管理服务
⚙️ 业务服务
项目CRUD与切换管理，维护项目间的数据隔离。提供项目的创建、编辑、删除、列表查询、详情查看以及项目切换功能，确保不同项目之间的数据严格隔离，支持项目级权限控制。
依赖: 关系型数据库缓存
Python 3.11+FastAPIPostgreSQL 15Redis 7

服务接口 (1)

🔧 ProjectService 6 方法
createProject
(request: CreateProjectRequest, userId: UUID) -> ProjectResponse
创建新项目，校验参数后将项目信息写入数据库并返回创建结果
前置条件
当前用户已通过身份认证；request.name 非空且长度≤255字符；同一用户下不存在同名项目
后置条件
projects 表中新增一条项目记录（状态为 active），返回包含新项目ID和创建时间的完整项目信息
ValidationException→ 400项目名称或描述不符合格式要求（为空、超长、含非法字符）ProjectNameConflictException→ 409同一用户下已存在相同名称的项目
listProjects
(userId: UUID, page: int, pageSize: int) -> ProjectListResponse
获取当前用户有权限查看的项目列表，支持分页排序
前置条件
当前用户已通过身份认证；page ≥ 1；pageSize 在 1-100 范围内
后置条件
返回当前用户有权限的项目分页列表，按创建时间降序排列，包含总条数
ValidationException→ 400分页参数超出合法范围（page < 1 或 pageSize > 100）
getProject
(projectId: UUID, userId: UUID) -> ProjectDetailResponse
获取指定项目的详细信息，包含关联的部署环境列表
前置条件
当前用户已通过身份认证；projectId 为有效的UUID格式
后置条件
返回项目完整信息及该项目的环境列表（从环境管理服务获取）；项目不存在或用户无权限时抛出异常
ProjectNotFoundException→ 404指定 projectId 的项目在数据库中不存在ProjectAccessDeniedException→ 403当前用户无权访问该项目
switchProject
(projectId: UUID, userId: UUID) -> ProjectSwitchResponse
切换当前用户的激活项目，返回目标项目的环境配置和新会话令牌
前置条件
当前用户已通过身份认证；目标项目存在于数据库中且状态为 active；当前用户有权访问该项目
后置条件
更新当前用户的活跃项目上下文为指定项目；生成新的 session_token 写入Redis（过期时间24小时）；旧session_token失效；从环境管理服务获取目标项目的环境列表并返回
ProjectNotFoundException→ 404指定 projectId 的项目不存在或状态非 activeProjectAccessDeniedException→ 403当前用户无权切换到该项目
deleteProject
(projectId: UUID, userId: UUID) -> void
软删除指定项目，标记为 deleted 状态并清理关联资源
前置条件
当前用户已通过身份认证；目标项目存在且状态为 active；当前用户有权管理该项目；该项目下无进行中的部署任务
后置条件
项目状态更新为 deleted；该项目的所有活跃 session_token 从Redis中失效；通知环境管理服务清理关联的环境配置
ProjectNotFoundException→ 404指定 projectId 的项目不存在ProjectAccessDeniedException→ 403当前用户无权删除该项目ProjectHasActiveDeploymentsException→ 409该项目下存在进行中（pending/running）的部署任务，无法删除
updateProject
(projectId: UUID, userId: UUID, name: string, description: string) -> ProjectResponse
更新项目的基本信息（名称、描述）
前置条件
当前用户已通过身份认证；目标项目存在且状态为 active；当前用户有权管理该项目；新名称（如有变更）在当前用户下唯一
后置条件
projects 表中对应记录的 name 和/或 description 字段被更新；updated_at 刷新为当前时间；返回更新后的项目信息
ProjectNotFoundException→ 404指定 projectId 的项目不存在或非 active 状态ProjectAccessDeniedException→ 403当前用户无权修改该项目ValidationException→ 400修改后的名称或描述不符合格式要求ProjectNameConflictException→ 409修改后的名称与同一用户下其他项目名称冲突

业务规则

不变量
  • !项目名称在同一用户下必须唯一
  • !项目名称不能为空且长度不得超过255个字符
  • !项目描述长度不得超过2000个字符
  • !每个用户同一时刻有且仅有一个激活项目
  • !项目删除前必须确保无进行中的（pending/running）部署任务
  • !项目会话令牌（session_token）有效期不超过24小时，过期后需重新切换
  • !deleted 状态的项目不显示在项目列表中
状态机
🎯 Project
activedeleted
→用户执行删除操作且项目下无进行中的部署by 项目经理
→暂不支持用户自行恢复，需DBA从数据库恢复by 系统管理员
🚫 项目从 active 转换为 deleted 后，不可通过API恢复为 active（不可逆状态转换）🚫 deleted 状态的项目，其关联的环境配置和部署记录保留在数据库中用于审计追溯，但项目不再出现在用户的项目列表中
⚡ 项目创建时通过数据库（userId + name）唯一约束防止并发重复创建；项目删除时通过数据库行级锁 + 检查进行中的部署记录，防止并发删除和部署同时进行
🎯 ProjectSession
activeexpired
→session_token 超过24小时有效期或用户切换至其他项目生成新tokenby 系统
→用户重新切换到该项目，生成新的 session_tokenby 用户
⚡ 项目切换操作通过Redis原子操作（SET with NX + EX）更新用户会话上下文，保证并发切换时最终只有一个激活项目
跨服务规则
项目切换时（switchProject），必须同步调用环境管理服务的内部接口获取目标项目的环境配置列表
项目删除时（deleteProject），必须通知环境管理服务清理该项目下的所有环境配置和SSH密钥资源
项目详情查询时（getProject），environments 字段通过调用环境管理服务的内部接口获取实时数据
部署引擎服务在执行部署任务前需通过本服务的校验接口确认目标项目仍为 active 状态
API网关在路由请求时需根据 session_token 解析当前项目上下文，通过请求头透传 project_id 至下游服务实现数据隔离

错误处理

处理策略

采用统一的异常处理机制，所有业务异常通过自定义异常类抛出，由全局异常处理器捕获并转换为标准格式的HTTP响应。参数校验失败返回400，资源不存在返回404，权限不足返回403，资源冲突返回409，服务器内部错误返回500。所有错误响应均记录详细上下文到服务端日志以便排查。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验错误
请求参数缺失、格式错误或超出长度限制，由请求进入时的Pydantic模型校验触发
403
权限不足
当前用户无权访问或操作指定资源，由项目级权限校验逻辑触发
404
资源不存在

409
