概述

项目管理服务
⚙️ 业务服务
管理系统的核心业务实体——项目，包括项目创建、配置、状态管理和项目间切换。项目管理服务负责项目的全生命周期管理，提供标准CRUD操作，维护项目与部署环境之间的关联关系，并确保项目间的数据隔离。本服务通过API网关暴露REST接口供前端调用，内部通过SQLAlchemy ORM访问PostgreSQL数据库。
依赖: PostgreSQL数据库环境管理服务
PythonFastAPIPostgreSQLRedis

服务接口 (1)

🔧 ProjectService 5 方法
createProject
(cmd: CreateProjectDTO) -> ProjectResponseDTO
创建一个新项目，校验参数和名称唯一性后写入数据库
前置条件
cmd.name 不为空且长度在 1~255 之间；系统中不存在 name 相同的已存项目
后置条件
在 projects 表中插入一条新记录，id 由数据库自动生成 UUID，created_at 和 updated_at 设为当前时间。如果 cmd.environments 非空，通过环境管理服务验证各环境 ID 有效后写入关联关系
ProjectNameEmptyError→ 400项目名称为空或仅含空白字符ProjectNameConflictError→ 409项目名称与已有项目重复InvalidEnvironmentIdError→ 400指定的环境 ID 不存在于系统中
getProject
(projectId: UUID) -> ProjectResponseDTO
按主键查询单个项目详情并组装环境关联信息
前置条件
projectId 不为 null
后置条件
返回匹配的项目完整信息（含关联环境列表），如果不存在则抛出 ProjectNotFoundError
ProjectNotFoundError→ 404指定 projectId 的记录在 projects 表中不存在
listProjects
(page: int, pageSize: int) -> ProjectListResponseDTO
分页查询项目列表，按创建时间倒序排列
前置条件
page >= 1，1 <= pageSize <= 100
后置条件
返回按 created_at 降序排列的分页项目列表，total 为总记录数。返回空列表而非错误（当无项目时）
InvalidPageParamError→ 400page < 1 或 pageSize > 100 或 pageSize < 1
updateProject
(projectId: UUID, cmd: UpdateProjectDTO) -> ProjectResponseDTO
更新项目的基本信息和环境关联关系
前置条件
projectId 对应的项目存在；cmd.name 不为空且长度在 1~255 之间；修改后的 name 不与除自身外的其他项目重复
后置条件
更新 projects 表中对应记录的 name 和 description 字段，updated_at 更新为当前时间。environments 关联关系被替换为 cmd.environments 指定的新列表
ProjectNotFoundError→ 404指定 projectId 不存在ProjectNameConflictError→ 409新名称与另一已有项目重复InvalidEnvironmentIdError→ 400指定的环境 ID 不存在
deleteProject
(projectId: UUID) -> None
删除指定项目。执行前校验项目下是否有关联环境，有则拒绝删除
前置条件
projectId 对应的项目存在；该项目下无关联的环境记录
后置条件
从 projects 表中物理删除指定记录。如果该项目有关联的部署记录（由部署编排服务管理），则由外部约束阻止删除（应用层校验或数据库级外键约束）
ProjectNotFoundError→ 404指定 projectId 不存在ProjectHasEnvironmentsError→ 409项目下仍有关联的环境记录未清理

findById(id: UUID) -> Project? — 按主键查询项目

业务规则

不变量
  • !项目名称在系统范围内必须唯一，比较时大小写敏感，不允许存在仅大小写不同的两个项目
  • !项目名称不能为空字符串或纯空白字符，长度限制为 1~255 字符
  • !一个项目可以关联零个或多个环境，环境通过 environments 表的 project_id 外键定位到项目
  • !项目 ID 一旦创建不可更改，作为系统中所有关联记录的稳定标识
  • !删除项目时必须确保该项目下无关联环境记录，否则删除操作将被拒绝
状态机
🎯 Project
active
🚫 当前设计下项目不定义状态字段，删除即物理删除。如需软删除或归档功能，需在 projects 表增加 status 字段（ACTIVE/ARCHIVED/DELETED）并在迁移脚本中补充
⚡ 项目更新操作通过乐观锁（基于 updated_at）或行级锁（SELECT FOR UPDATE）防止并发修改导致的更新丢失。创建操作利用数据库唯一索引（idx_projects_name）保证名称唯一性
跨服务规则
项目管理服务与环境管理服务共享项目-环境关联关系。environments 表的 project_id 外键由环境管理服务维护，项目管理服务只读查询。删除项目前需通过 countEnvironmentsByProjectId 确认无关联环境，此约束也可在数据库层通过外键 ON DELETE RESTRICT 保证
项目管理服务与部署编排服务通过 project_id 关联。部署记录引用项目 ID，项目删除前需确认无相关未完成的部署任务（此项由部署编排服务提供查询接口或由数据库外键约束保证）
项目管理服务与文件存储服务通过 project_id 关联。文件记录引用项目 ID，项目删除前需确认无关联文件记录或级联删除
项目级别的权限控制由 API 网关通过 RBAC 模块实现。当前设计下项目管理服务本身不实现权限校验，所有请求由网关鉴权后转发。项目间数据隔离依赖查询时按项目 ID 过滤

错误处理

处理策略

项目管理服务采用分层异常处理策略：API 层捕获所有业务异常并转换为标准 HTTP 错误响应；服务层抛出具有明确业务语义的自定义异常；数据访问层异常由 ORM 自动传播。所有错误响应统一包含 error_code、error 和 detail 字段，前端据此展示对应的错误提示信息。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验错误
请求参数格式不正确或缺少必填字段（如项目名称为空、分页参数超范围）。处理方式：立即返回校验失败详情，不创建或修改任何资源。
404
资源不存在
按 project_id 查询项目时未找到对应记录。处理方式：返回 NOT_FOUND，提示指定 ID 的项目不存在。
409
名称冲突
创建或更新项目时提供的名称已被占用。处理方式：返回 CONFLICT，提示名称已存在，建议使用其他名称。
409
关联资源阻止删除
删除项目时该项目下仍存在关联的环境。处理方式：返回 CONFLICT，提示先删除所有关联环境再删除项目。
