概述

项目管理服务
⚙️ 业务服务
项目核心管理服务，处理项目的创建、编辑、删除以及项目与环境绑定关系。提供项目CRUD操作、项目与环境绑定关系管理、项目列表与概要信息查询、项目上下文切换与状态维护、项目删除时级联清理关联数据等能力。
依赖: PostgreSQL主数据库审计日志服务Redis缓存
Python 3.11FastAPIPostgreSQL 15Redis 7RESTJWT

服务接口 (1)

🔧 ProjectService 6 方法
create_project
(req: ProjectCreateRequest, actor: str) -> Project
创建新项目，校验参数和名称唯一性后写入数据库，返回包含生成ID的完整项目信息
前置条件
req.name 非空且 len ≤ 128；req.description 若提供则 len ≤ 500；不存在同名且 deleted_at IS NULL 的活跃项目
后置条件
新项目记录已持久化到 projects 表（id 自动生成）；已通过审计日志服务记录 create_project 操作
InvalidParameterError→ 400name为空或超长、description超长ProjectNameConflictError→ 409同名活跃项目已存在
list_projects
(page: int, page_size: int) -> dict[total: int, items: list[ProjectSummary]]
分页查询活跃项目列表，排除已软删除项目，聚合环境数量和最新部署状态
前置条件
page ≥ 1；page_size 在 [1, 100] 范围内
后置条件
返回的 items 不包含 deleted_at IS NOT NULL 的项目；env_count 为各项目绑定的环境数量；last_deploy_status 和 last_deployed_at 来自各项目最新的部署记录
InvalidParameterError→ 400page < 1 或 page_size 超出 [1, 100] 范围
get_project
(project_id: uuid) -> ProjectDetail
查询单个项目的完整信息，通过 project_environments + environments 关联查询绑定环境列表
前置条件
project_id 对应的项目存在且 deleted_at IS NULL
后置条件
返回项目全部字段及已绑定的环境列表（含 env_id、env_name、host）；环境列表为空数组而非 null
ProjectNotFoundError→ 404指定ID的项目不存在或已软删除
update_project
(project_id: uuid, req: ProjectUpdateRequest, actor: str) -> Project
更新项目名称和/或描述，校验参数合法性，检查名称唯一性后更新数据库，返回更新后的项目信息
前置条件
project_id 对应项目存在且 deleted_at IS NULL；若更新 name，新名称不得与已有活跃项目冲突
后置条件
项目记录已更新（updated_at 刷新）；已通过审计日志服务记录 update_project 操作；未传入的字段保持不变
ProjectNotFoundError→ 404项目不存在或已软删除InvalidParameterError→ 400name或description超长ProjectNameConflictError→ 409新名称与其他活跃项目冲突
delete_project
(project_id: uuid, actor: str) -> None
软删除项目，级联清理环境绑定关系，阻止存在进行中部署任务的项目被删除
前置条件
project_id 对应项目存在且 deleted_at IS NULL；该项目的所有部署记录状态均为 success 或 failed（无 pending/running）
后置条件
项目已软删除（deleted_at 设为当前时间）；该项目的所有 project_environments 关联记录已物理删除；已通过审计日志服务记录 delete_project 操作
ProjectNotFoundError→ 404项目不存在或已软删除ProjectHasActiveDeploymentError→ 409项目存在 pending 或 running 状态的部署记录
switch_project
(project_id: uuid) -> ProjectSwitchResponse
项目上下文切换，返回目标项目的基本信息和各环境连接状态，供前端刷新上下文面板
前置条件
project_id 对应项目存在且 deleted_at IS NULL
后置条件
返回当前项目ID、名称及所有绑定环境的ID、名称和连接状态；环境列表为空数组而非null（无绑定环境时）

业务规则

不变量
  • !项目名称在未删除的项目中必须唯一，软删除的项目不参与名称唯一性校验，允许后续新项目复用已删除项目的名称
  • !项目与环境的多对多绑定关系通过 project_environments 关联表维护，同一 project_id + environment_id 组合不可重复绑定
  • !删除项目（软删除）时，必须同步物理删除该项目的所有 project_environments 关联记录，保持数据一致性
  • !项目列表查询（GET /api/projects）默认排除 deleted_at IS NOT NULL 的已删除项目，不对外暴露软删除数据
  • !项目概要中的 env_count 必须实时通过 COUNT project_environments WHERE project_id=? 计算，不缓存静态计数
  • !审计日志写入失败不影响主业务流程的结果返回，失败信息记录到服务日志用于排查
状态机
🎯 Project
activedeleted
→delete_project() 被调用，且项目无进行中部署任务by 项目经理（通过API）
🚫 active → deleted 转换不可逆，API不提供恢复已删除项目的接口。如需恢复，需由数据库管理员直接操作修改 deleted_at 字段
⚡ 项目删除操作与同项目的部署操作可能并发，删除前必须检查并确保无 pending/running 状态的部署记录，通过事务包裹检查+删除操作保证原子性
跨服务规则
所有项目创建操作完成后，必须通过 POST /api/audit/logs 调用审计日志服务，action 为 create_project，resource_type 为 project，result 为 success/failure
所有项目更新操作完成后，必须通过 POST /api/audit/logs 调用审计日志服务，action 为 update_project，resource_type 为 project
所有项目删除操作完成后，必须通过 POST /api/audit/logs 调用审计日志服务，action 为 delete_project，resource_type 为 project
项目列表中的 last_deploy_status 和 last_deployed_at 字段来源于 deployments 表（与部署引擎服务共享数据源），通过直接SQL查询获取最新部署记录，不跨服务调用
项目详情中的环境列表（environments）通过 project_environments 和 environments 表关联查询获取，环境连接状态由环境配置服务维护，项目管理服务读取现状态值

错误处理

处理策略

项目管理服务采用统一的REST错误响应格式，所有校验错误返回400，资源不存在返回404，业务冲突返回409，内部错误返回500。审计日志写入失败仅记录服务日志，不影响主业务流程的返回结果（容错处理）。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验错误
请求参数格式错误、字段超长或必填字段缺失，由Pydantic校验器拦截并返回详细错误信息
404
资源不存在
按ID查询项目时未找到对应记录（含已软删除），返回明确的项目不存在提示
409
业务冲突
项目名称重复（唯一键冲突）或项目存在进行中的部署任务时触发，需提示用户修正操作
500
服务器内部错误
数据库连接异常、未知运行时错误，统一返回500，内部记录详细错误栈到服务日志
