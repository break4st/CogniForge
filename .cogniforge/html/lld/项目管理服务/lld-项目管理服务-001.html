概述

项目管理服务
⚙️ 业务服务
提供项目实体的创建、读取、更新、删除(CRUD)操作。项目是部署的顶级隔离单元。
依赖: PostgreSQL（通过 Primary Database LLD 访问项目表）
PythonFastAPIPostgreSQL
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 提供项目实体的创建、读取、更新、删除(CRUD)操作 维护项目数据隔离 为其他服务提供项目有效性校验接口
范围外: 用户认证与授权（由API网关统一处理JWT验证） 环境管理、密钥管理、部署编排等非项目相关操作
拥有组件: CMP-003

🚫 从ARCHIVED或ACTIVE转换到DELETED后不可逆，且触发软删除或硬删除取决于实现策略（通常采用软删除保留审计）🚫 DELETED状态不能转换到任何其他状态
⚡ 使用乐观锁，基于updated_at字段进行版本控制，更新时检查版本一致性
跨服务规则
当其他服务调用项目校验接口时，应保证项目处于ACTIVE状态才视为有效
项目状态变更（如归档、删除）时，应通过消息事件通知下游服务（如环境管理服务），确保关联资源同步处理
删除项目前必须跨服务检查无关联环境（由环境管理服务提供查询接口）

编排流程

项目CRUD流程

项目创建、读取、更新、删除的标准业务流程

1
鉴权 (5s 超时)
验证JWT令牌，提取用户ID
失败处理: 返回401 Unauthorized
2
参数校验 (1s 超时)
校验请求体或路径参数格式和必填项
失败处理: 返回400 Bad Request
3
业务处理 (30s 超时)
调用ProjectService对应方法
失败处理: 根据异常类型返回4xx或5xx
4
响应格式化 (1s 超时)
将领域对象转换为响应DTO并返回
失败处理: 返回500 Internal Server Error
重试策略: 最多 0 次，间隔 0s
可重试错误: 无
不可重试错误: VALIDATION_ERROR, PROJECT_ALREADY_EXISTS, PROJECT_NOT_FOUND, PROJECT_NAME_CONFLICT, UNAUTHORIZED

错误处理

处理策略

服务层捕获所有异常，FastAPI异常处理器统一转换为标准错误响应格式，区分客户端错误和服务器错误。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
404
资源未找到
请求的项目ID不存在，返回404错误，detail包含项目ID。
400
请求参数错误
请求体缺少必填字段或字段格式不正确，返回400错误，detail包含具体校验失败信息。
409
资源冲突
项目名称重复等唯一性约束冲突，返回409错误，detail指明冲突字段。
500
服务器内部错误
数据库连接失败、查询异常等未预期错误，返回500错误，detail为通用错误描述，避免泄露内部细节。
