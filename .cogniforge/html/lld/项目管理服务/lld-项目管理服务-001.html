概述

项目管理服务
⚙️ 业务服务
负责项目的CRUD操作和项目间切换。为项目提供全生命周期管理，包括项目创建、编辑、归档、项目列表查询和详情获取、项目切换与会话管理，以及项目成员的角色权限管理。本服务是系统的核心业务入口，所有操作均需通过API网关认证后访问。
依赖: API网关认证中间件PostgreSQL主数据库Redis缓存审计日志服务
GoGinPostgreSQL 15+Redis 7+JWT (JSON Web Token)
🗄️

业务规则

不变量
  • !项目名称在同一个创建者下必须唯一（不区分 active/archived，包括已归档项目）
  • !每个项目至少有一名 admin 角色的成员
  • !项目管理员（admin 角色）不能将自己从项目中移除
  • !已归档（archived）项目不可执行任何修改操作，包括更新信息和修改成员
  • !从项目中移除最后一名 admin 成员的操作必须被拒绝
  • !将最后一名 admin 成员降级为非 admin 角色的操作必须被拒绝
状态机
🎯 Project（项目）
active（活跃）：项目可正常操作，支持部署、成员管理、配置修改archived（归档）：项目只读，仅可查看基本信息，不可执行部署和修改操作
→创建项目by 创建者（自动成为admin）
→归档项目by admin角色成员
→恢复项目by admin角色成员
🚫 本服务采用软删除策略（归档），不支持物理删除。一旦归档，关联的环境配置和部署历史保留但不可操作。恢复后所有数据完整可用。🚫 从 archived 恢复到 active 不会恢复在归档期间其他服务可能已清理的关联数据（如 Redis 缓存），需由前端触发数据刷新。
⚡ 更新操作采用乐观锁，在 UPDATE 时比较 updated_at 字段。若并发修改导致 updated_at 不匹配（即另一请求已先完成修改），则返回 409 Conflict，由调用方决定重试策略。
跨服务规则
项目归档/删除前必须通过部署编排服务检查是否存在 pending 或 running 状态的部署任务
项目创建/更新/归档/成员变更必须调用审计日志服务记录完整操作信息
项目切换后需同步更新 Redis 中用户会话的 current_project_id，并签发新的 JWT Token（通知认证中间件）
获取项目详情时通过环境管理服务获取关联的环境列表（GET /api/v1/environments?project_id=:projectId）
项目名称唯一性校验仅在本服务内通过查询 projects 表完成，不依赖外部服务

错误处理

处理策略

所有错误统一返回标准化JSON响应体，包含业务错误码、错误分类和详细描述。参数校验错误返回400，认证失败返回401，权限不足返回403，资源不存在返回404，业务冲突返回409。内部错误返回500并记录完整错误日志用于排查。

统一错误响应体
字段类型
codeinteger（HTTP状态码或自定义业务码）
errorstring（错误分类标识，如 invalid_param/unauthorized/forbidden/not_found/conflict/internal_error）
detailstring（详细错误描述，包含冲突字段名、已存在值等上下文信息）
400
参数校验错误
请求参数格式或值无效。触发条件：项目名称为空或超长、page或page_size为负数、role值不在枚举范围内、project_id格式非法。处理方式：返回detail字段指明具体哪个参数无效及原因。
401
认证失败
JWT Token缺失、过期或无效。触发条件：未携带Authorization头、Token过期、Token签名不匹配。处理方式：返回统一认证错误提示，引导用户重新登录。
403
权限不足
用户无权限执行请求的操作。触发条件：非项目成员尝试访问项目详情、非admin成员尝试管理项目成员、admin尝试移除自己。处理方式：detail字段返回具体缺失的权限和所需角色。
404
资源不存在
请求的目标资源未找到。触发条件：projectId对应的项目不存在、userId对应用户不存在、projectId+userId对应的成员记录不存在。处理方式：区分项目不存在、用户不存在、成员不存在三种场景，返回具体描述。
409
业务冲突
请求与当前业务状态冲突。触发条件：创建同名项目、降级/移除最后一名admin、归档有活跃部署任务的项目。处理方式：detail字段说明冲突原因和当前状态。
500
服务器内部错误
未预期的系统错误，包括数据库连接失败、缓存操作失败、数据序列化错误。处理方式：记录完整错误栈和请求追踪ID到日志，返回通用错误提示，detail包含追踪ID供排查。
