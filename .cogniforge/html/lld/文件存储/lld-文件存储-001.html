概述

模块: 文件存储
文件存储模块基于MinIO对象存储，为系统提供可执行文件和部署脚本的统一存储与管理能力。接收Web管理控制台上传的部署包（可执行文件），为部署编排服务提供文件持久化和下载接口，同时支持内部服务存储部署过程中生成的脚本文件。通过MD5校验保证文件完整性，元数据记录在MySQL中便于检索，文件实际内容存储在MinIO中实现读写分离。
依赖: MinIO服务关系型数据库
Python 3.11FastAPIMinIO SDKMySQL 8.0

数据模型 (2)

数据库表 1

🗄️ files

文件元数据表，记录上传到MinIO的每个文件的索引信息。文件实际内容存储在MinIO对象存储中，该表仅记录元数据（文件ID、路径、大小、MD5等）。部署编排服务通过file_url或file_id引用文件

字段
字段名类型描述
id *int主键，自增文件ID（对应SAD契约中的file_id）
project_id *int外键，关联projects.id，文件所属项目
file_name *string原始文件名，上传时保留用于下载展示
file_size *int文件大小，单位字节（对应SAD契约中的file_size）
md5 *string文件MD5哈希值，用于完整性校验和去重（对应SAD契约中的md5）
file_url *string文件访问URL，格式：/api/files/{id}（对应SAD契约中的file_url）
object_key *stringMinIO对象存储中的路径键，格式：{project_id}/{file_id}/{file_name}
bucket *stringMinIO存储桶名称，默认cogniforge-files
content_typestring文件MIME类型，可执行文件为application/octet-stream
file_type *string文件类型分类，枚举值：executable（可执行文件）/script（部署脚本）
created_at *datetime文件上传/创建时间
created_byint上传者用户ID，executable类型记录上传用户，script类型记录触发的部署记录ID

错误处理

文件存储模块错误处理策略：1）参数校验层——上传接口校验file和project_id必填，文件大小上限500MB，超出返回400/413；文件信息查询和下载接口校验file_id合法性（正整数），非法格式返回400；2）MinIO操作层——客户端初始化时健康检查，bucket不存在则自动创建；MinIO读写异常（连接超时、权限错误、bucket不存在）由SDK原生异常捕获，统一转换为FileStorageException（含error_code、operation、bucket、object_key字段）向上传递；写入失败采用指数退避重试（初始500ms，最大3次），重试耗尽后报500；3）数据库层——files表写入使用事务，若MySQL写入成功而MinIO写入失败则标记状态为failed便于人工修复补偿；MD5查重发现相同文件直接返回已有记录避免重复上传；文件采用软删除策略（保留元数据记录仅删除MinIO对象），防止误删不可追溯。对外部服务（部署编排服务）的依赖：若文件存储模块不可用，编排服务应缓存上传结果并定期重试。
