概述

Environment Management Service
⚙️ 业务服务
管理部署环境的微服务，基于 FastAPI 构建，负责环境配置与 SSH 密钥绑定，提供环境的创建、编辑、删除、查询，环境连接参数管理，SSH 密钥与环境绑定，以及连接测试触发等能力。关键操作后调用 Audit Service 记录审计日志，连接测试内部调用 SSH Execution Service 执行轻量探测命令，密钥存储委托给 Key Management Service 加密处理，持久化数据写入 Primary Database（PostgreSQL）。
依赖: API GatewaySSH Execution ServiceKey Management ServiceAudit ServicePrimary Database
Python 3.11+FastAPIPostgreSQL 15OpenAPI 3.0 (自动生成)Docker + Docker Compose

业务规则

不变量
  • !同一项目下不允许存在两个 is_deleted=false 的环境具有相同的 name
  • !环境删除采用软删除机制，is_deleted=true 的记录不应出现在正常查询和列表结果中
  • !环境必须关联一个已存在的项目（project_id 外键约束），创建时 project_id 对应的项目必须存在且未删除
  • !只有已绑定 SSH 密钥（key_id 不为空）的环境才能执行连接测试
  • !环境名称不能为空字符串或仅含空白字符，去除首尾空格后的长度在 1~255 之间
  • !SSH 端口号必须在 1~65535 之间
状态机
🎯 Environment
activedeleted
→调用 deleteEnvironment 方法且关联部署记录检查通过by admin 或 operator 角色用户
🚫 环境从 active 变为 deleted 后不可逆，不允许恢复已删除的环境🚫 deleted 状态为终态，不存在到其他状态的转换
⚡ 删除操作使用数据库行级锁锁定 environments 行记录（SELECT ... FOR UPDATE），在事务中同时查询部署记录，防止并发部署创建绕过关联检查
跨服务规则
环境创建、更新、删除和密钥导入操作完成后，必须同步调用 Audit Service 的 POST /internal/audit/log 接口记录审计日志，其中 actor 为当前操作用户 ID，action 按操作类型使用 environment.create / environment.update / environment.delete / environment.import_key，resource_type 固定为 environment，result 根据操作结果填入 success 或 failure。若审计日志发送失败（网络超时或服务不可达），仅记录 WARN 级别日志，不阻塞业务主流程
连接测试时需调用 SSH Execution Service 的 POST /internal/ssh/execute 接口执行轻量探测命令。传入的 host/port/username/key_id 从当前环境记录的字段中读取，command 固定为探测命令（如 echo 'connection_test'），timeout 设为 10 秒。若 SSH Execution Service 返回 success=true（exit_code=0），将环境的 connection_status 更新为 connected；否则更新为 failed
导入 SSH 密钥时需调用 Key Management Service 的 POST /internal/kms/keys 接口，action 固定为 store，传入 private_key 和可选的 passphrase。KMS 返回 key_id 和 fingerprint 后，将该 key_id 写入环境记录的 key_id 字段。若 KMS 返回失败，不更新环境记录，直接向上层返回错误
环境所属项目存在性校验通过读取 Primary Database 的 projects 表完成（共享数据库），不调用 Project Management Service 的 API

错误处理

处理策略

服务层采用统一的异常处理机制：业务异常以自定义异常类抛出，由 FastAPI 全局异常处理器捕获并转换为标准错误响应格式。参数校验由 FastAPI Pydantic 模型自动完成，校验失败返回 422。调用 SSH Execution Service 和 Key Management Service 时发生的网络超时或服务不可达分别映射为 504 和 502。审计日志调用失败仅记录 WARN 日志，不阻塞业务主流程。数据库操作异常捕获后记录错误日志，避免泄露内部实现细节。所有未预期异常统一返回 500。
