概述

脚本生成引擎
⚙️ 业务服务
根据部署上下文自动生成远程服务器上的启动和停止脚本。根据应用类型（jar/binary/python/custom）选择对应的脚本模板，将部署路径、可执行文件名等变量注入模板后生成完整的启动和停止脚本内容，支持自定义命令扩展和脚本语法校验。
依赖: 部署执行服务
PythonFastAPI

配置定义 1

⚙️ script_template_config自有

脚本模板配置，定义各类应用类型的默认启动/停止脚本模板。模板内容包含 {{deploy_path}} {{artifact_name}} 等可替换变量占位符。

字段
字段名类型描述
app_type *String应用类型：jar / binary / python / custom
shebang *String脚本首行解释器声明，如 #!/bin/bash
start_template *String启动脚本模板内容，含 {{deploy_path}} {{artifact_name}} 等占位符
stop_template *String停止脚本模板内容，含 {{deploy_path}} {{artifact_name}} 等占位符

syntax_check_cmd *String语法校验命令模板，如 bash -n {{script_path}}
supported_vars *List<String>支持的变量占位符列表，如 [deploy_path, artifact_name, java_opts]

服务接口 (1)

🔧 ScriptGenerationService 2 方法
generateScripts
(request: ScriptGenerationRequest) -> ScriptGenerationResponse
根据应用类型和部署路径加载相应模板，注入变量后生成完整的启动/停止脚本并执行语法校验
前置条件
request.app_type 在 [jar, binary, python, custom] 内；request.deploy_path 以 / 开头且不含 ../ 等危险路径；request.artifact_name 在 app_type != custom 时非空
后置条件
返回的 start_script 和 stop_script 均非空且首行为有效 shebang；validated 由真实机器语法校验决定；请求对象未被修改
InvalidAppTypeException→ 400app_type 不在 [jar, binary, python, custom] 范围内InvalidPathException→ 400deploy_path 不是绝对路径或包含 ../ ./ ~ 等危险标记MissingRequiredFieldException→ 400app_type 非 custom 时 artifact_name 为空或未传TemplateRenderException→ 422模板变量替换后脚本内容为空、shebang 丢失或模板格式不合法TemplateLoadException→ 500模板配置读取失败（文件不存在、格式损坏、权限不足）
validateScript
(scriptContent: String, scriptType: String) -> Boolean
对脚本内容进行离线语法校验，使用系统 shell 的 -n（no-exec）模式检查语法正确性
前置条件
scriptContent 非空；scriptType 当前仅支持 'bash'
后置条件
返回 true 仅当脚本通过 bash -n 语法检查；scriptContent 未被修改；无任何副作用（不写入文件、不执行脚本）
EmptyScriptException→ 400scriptContent 为空字符串或仅空白字符UnsupportedScriptTypeException→ 400scriptType 不是 'bash' 等受支持的 shell 类型ShellCheckException→ 500系统 shell 命令执行失败（如 bash 不可用）
数据访问依赖
loadTemplateConfigByAppType(appType: AppType) -> ScriptTemplate?

业务规则

不变量
  • !deploy_path 必须为以 / 开头的绝对路径，不允许包含 ./ ../ ~ $ 等容易引起路径穿越或注入的字符
  • !app_type=custom 时 artifact_name 为可选，其他类型 artifact_name 必须非空
  • !custom_commands 中 start 和 stop 不能同时为有效值（如同时为空则退化为使用对应默认模板）
  • !生成的所有脚本文件首行必须为有效 shebang（#!/bin/bash），否则语法校验认定失败
  • !模板变量替换后脚本内容不得为空字符串
跨服务规则
部署执行服务必须在远程服务器创建好 deploy_path 版本目录后，再将生成的脚本文件通过 SCP/SFTP 传输到该目录中
脚本生成引擎只负责脚本内容的生成和语法校验，脚本的远程传输、权限设置（chmod +x）和执行由部署执行服务通过 SSH 连接池完成
自定义命令中的敏感信息（明文密码、密钥路径、Token）由调用方部署执行服务负责脱敏处理，脚本生成引擎对 custom_commands 内容只做文本替换不做安全检查
脚本生成引擎返回 validated=false 时，部署执行服务应根据环境类型决定后续策略：测试线可继续执行并记录警告，正式线应中止部署并通知用户确认

⚠️

错误处理

处理策略

前置校验与模板渲染异常分离。请求参数在校验层进行格式和枚举值合法性验证，不合规则直接返回 400 拒绝并附明确错误信息。模板渲染阶段的变量替换错误和格式异常捕获后统一返回 422，detail 中标明出错变量名。语法校验不通过不抛异常，通过 validated=false 回传，由调用方决定处理策略。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验失败
app_type 不是合法枚举值、deploy_path 非绝对路径、必填字段缺失。调用方修正后重试。
422
模板渲染错误
模板中使用了不支持的变量占位符、变量替换后脚本内容为空、shebang 缺失或格式错误。
500
内部服务错误
模板配置文件读取失败、系统 shell 命令执行异常、不可预料的内部异常。记录错误日志后返回通用错误。
