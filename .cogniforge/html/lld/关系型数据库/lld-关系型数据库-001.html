概述

关系型数据库
MySQL 8.0，作为系统的核心持久化存储层，存储所有业务数据，包括用户信息、项目信息、环境配置、密钥元数据、部署记录、部署日志和审计日志。为上层业务服务提供ACID事务保障、唯一键约束、外键关联和索引优化查询，支持定时备份和恢复以保证数据安全。各业务服务通过Spring Data JPA / MyBatis访问本数据库。
MySQL 8.0

数据模型 (7)

数据库表 7

🗄️ users权威定义

系统用户表，存储所有平台用户的基本信息和认证凭据。用户通过用户名和密码登录系统，每个用户分配一个角色（admin/ops/dev/lead）控制权限范围。status字段支持用户启用/停用管理。username建立唯一索引。

字段
字段名类型描述
id *bigint用户唯一标识，自增主键
username *varchar(100)用户名，唯一索引，用于登录和展示
password_hash *varchar(255)密码哈希值（BCrypt加密），不含明文密码
role *varchar(20)用户角色：admin（系统管理员）/ ops（运维工程师）/ dev（开发工程师）/ lead（技术负责人）
status *varchar(20)用户状态：active（正常）/ disabled（停用），默认 active
created_at *datetime创建时间
updated_at *datetime最后更新时间

🗄️ projects权威定义

项目主表，存储所有项目的基本信息。每条记录代表一个独立项目，通过外键created_by关联users表。与environments表通过project_id外键关联（一对多）。支持逻辑删除（status字段），删除时将status置为deleted而非物理删除。name建立唯一索引。

字段
字段名类型描述
id *bigint项目唯一标识，自增主键
name *varchar(100)项目名称，唯一索引，用于展示和搜索
descriptiontext项目描述信息，可选
created_by *bigint创建者用户ID，外键关联users表
status *varchar(20)项目状态：active（正常）/ deleted（逻辑删除），默认 active
created_at *datetime创建时间
updated_at *datetime最后更新时间

🗄️ environments权威定义

部署环境配置表，存储每套部署环境的连接参数和配置信息。每条记录代表一个独立的部署环境（如测试线、灰度线、正式线），通过project_id与projects表关联（多对一），通过key_id与ssh_keys表关联（多对一）。同项目内环境名称唯一，联合唯一索引(project_id, name)。支持逻辑删除。

id *bigint环境唯一标识，自增主键
project_id *bigint所属项目ID，外键关联projects表

created_by *bigint创建者用户ID，外键关联users表
created_at *datetime创建时间
updated_at *datetime最后更新时间

🗄️ ssh_keys权威定义

SSH密钥表，存储用户上传的SSH密钥对信息。每条记录代表一个密钥对，公钥明文存储，私钥经过AES-256-GCM加密后Base64编码存储。通过id与environments表的key_id外键关联。fingerprint由服务端从公钥内容自动计算SHA256生成。name和fingerprint分别建立唯一索引。支持逻辑删除。

字段
字段名类型描述
id *bigint密钥唯一标识，自增主键
name *varchar(100)密钥名称，用于展示和标识，唯一索引
public_key *textSSH公钥内容，明文存储（OpenSSH格式，以ssh-rsa/ssh-ed25519等开头）
private_key_encrypted *textSSH私钥内容，经过AES-256-GCM加密后Base64编码存储，格式为 Base64(IV + 密文)
fingerprint *varchar(64)密钥指纹（SHA256:base64编码），上传时由服务端从公钥内容自动计算，唯一索引
status *varchar(20)密钥状态：active（正常）/ deleted（逻辑删除），默认 active
created_by *bigint创建者用户ID，外键关联users表
created_at *datetime创建时间
updated_at *datetime最后更新时间

🗄️ deployment_tasks权威定义

部署任务主表，记录每次一键部署任务的完整信息。每条记录代表一次从触发到完成的部署任务，通过project_id和environment_id关联项目和部署环境。status字段驱动状态机切换：pending -> running -> success/failed/rolled_back。progress字段记录实时进度百分比。按(project_id, status)和(environment_id, status)建立复合索引以支持高效查询。

字段
字段名类型描述
id *bigint部署任务唯一标识，自增主键
project_id *bigint所属项目ID，外键关联projects表
environment_id *bigint目标部署环境ID，外键关联environments表
file_url *varchar(1024)部署包文件存储URL，指向文件存储服务中的可执行文件
versionvarchar(50)部署版本号，用户传入或服务端自动生成（格式：yyyyMMdd-HHmmss）
status *varchar(20)部署状态：pending（待执行）/ running（执行中）/ success（部署成功）/ failed（部署失败）/ rolled_back（已回滚），默认 pending
progress *int部署进度百分比，取值范围 0-100，默认 0
created_by *bigint部署触发者用户ID，外键关联users表
created_at *datetime创建时间
updated_at *datetime最后更新时间

🗄️ deployment_logs权威定义

部署任务日志表，记录每次部署过程中产生的详细日志信息。每条日志通过deployment_id关联到对应的部署任务，按created_at排序用于前端实时展示和历史回溯。该表为append-only设计，数据写入后不做修改。按deployment_id建立索引以支持按任务查询日志。

字段
字段名类型描述
id *bigint日志唯一标识，自增主键
deployment_id *bigint关联部署任务ID，外键关联deployment_tasks表
level *varchar(10)日志级别：INFO / WARN / ERROR
message *text日志消息内容
created_at *datetime日志记录时间

🗄️ audit_logs权威定义

审计日志表，记录所有用户操作和系统事件的完整信息。每条记录代表一次操作事件，由各业务服务通过内部接口上报。该表为append-only设计，数据只增不改。按created_at降序索引以支持高效的分页查询，按(action_type, created_at)和(operator, created_at)建立复合索引以支持多维度筛选。

字段
字段名类型描述
id *bigint审计日志唯一标识，自增主键
action_type *varchar(50)操作类型，如 project_create / deploy_execute / key_upload / environment_create 等
operator *varchar(100)操作人标识（用户名或用户ID）
target_type *varchar(50)操作对象类型，如 project / environment / key / deployment / user
target_idvarchar(100)操作对象ID，关联到具体资源实例
detailtext操作详情，JSON格式存储操作上下文信息
result *varchar(10)操作结果：success / failure / pending
ip_addressvarchar(45)客户端IP地址，支持IPv4和IPv6
created_at *datetime操作发生时间，用于时间范围筛选和排序

错误处理

处理策略

关系型数据库层错误通过JDBC SQLException向上传递，由各业务服务的DAO层（Spring Data JPA / MyBatis）捕获并转为DataAccessException。应用层依据错误码分类处理：唯一键冲突（1062）转为HTTP 409返回前端；外键约束失败（1451/1452）转为HTTP 400或404；事务死锁（1213）自动重试最多3次；连接池耗尽或超时（2000）转为HTTP 503。数据写入类操作全部在Spring事务管理下执行（@Transactional），配置合适的事务隔离级别（READ_COMMITTED）。

1062
唯一键冲突
MySQL错误码1062（Duplicate entry），在INSERT或UPDATE时违反唯一索引约束触发。由以下场景产生：创建项目时name已存在；创建环境时同项目内name重复；创建密钥时name或fingerprint重复。业务服务在DAO层捕获DuplicateKeyException，转为HTTP 409响应。应用层应通过事前查询或异常捕捉方式处理，推荐使用异常捕捉方式以减少额外查询开销。
1452
外键约束失败（添加/修改时引用不存在）
MySQL错误码1452（Cannot add or update a child row: a foreign key constraint fails），在INSERT或UPDATE时外键引用的父表记录不存在。如创建项目时created_by引用不存在的用户、创建环境时project_id或key_id无效。业务服务应在事务内先验证外键存在性，DAO层捕获DataIntegrityViolationException后转为HTTP 400或404响应。
1451
外键约束失败（删除时被引用）
MySQL错误码1451（Cannot delete or update a parent row: a foreign key constraint fails），在DELETE或逻辑删除时父表记录仍被子表记录引用。如删除SSH密钥时environments表仍关联该key_id。业务服务在删除前应通过查询引用计数判断是否可以删除，DAO层捕获DataIntegrityViolationException后转为HTTP 409响应。
1213
事务死锁
MySQL错误码1213（Deadlock found when trying to get lock），多个事务并发操作同一组资源时发生死锁。MySQL InnoDB自动检测并回滚其中一个事务。常见于部署任务状态更新时的并发场景。业务服务DA层应捕获DeadlockLoserDataAccessException并实现重试逻辑（最多3次，每次间隔100ms）。推荐在@Transactional方法上使用重试注解（如Spring Retry的@Retryable）。
1406
字段值超长
MySQL错误码1406（Data too long for column），INSERT或UPDATE时字段值超过列定义的最大长度。如password_hash超过varchar(255)、audit_logs.detail超过text上限等。业务服务在参数校验层应先进行长度验证，避免到达数据库层才报错。DAO层捕获DataIntegrityViolationException后转为HTTP 400响应。
2000
数据库连接异常
非MySQL标准错误码分类，涵盖HikariCP连接池耗尽（Connection is not available, request timed out after XXXms）、连接超时（CommunicationsException）、MySQL服务不可达等。连接池配置：最大连接数20、最小空闲连接5、连接超时30秒、最大存活时间30分钟、空闲检测间隔60秒。连接池异常由业务服务全局异常处理器捕获后转为HTTP 503响应。定时任务：业务服务配置连接池健康检查，发现异常时记录告警日志。
