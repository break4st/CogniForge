概述

SSH Execution Service
⚙️ 业务服务
核心执行引擎，基于 FastAPI 和 Paramiko 构建，通过 SSH 协议在远程服务器上执行命令和传输文件。提供 REST API 供内部服务（Environment Management Service、Deployment Orchestrator）调用以执行 SSH 命令和文件上传，同时消费 RabbitMQ 部署任务队列执行完整的一键部署流程：远程目录创建（带版本标识）→ 文件传输（可执行文件上传）→ 远程脚本生成与执行 → 命令执行结果收集与返回。部署进度通过 MQ 发布消息实时回传，关键操作记录审计日志到 Audit Service。
依赖: Environment Management ServiceAudit ServiceKey Management ServiceRabbitMQPrimary Database
Python 3.11+FastAPIParamikoRabbitMQ 3.12OpenAPI 3.0 (自动生成)Docker + Docker Compose

服务接口 (1)

🔧 SshExecutionService 3 方法
executeCommand
(req: ExecuteCommandRequest) -> ExecuteCommandResponse
通过 SSH 在远程服务器执行单条命令。步骤：建立 SSH 连接 → 密钥认证 → 打开 channel → 执行命令 → 收集 stdout/stderr → 获取 exit_code → 关闭 channel 和连接。连接池满时等待释放
前置条件
req.host 为合法 IP 或域名格式；req.port 在 1~65535 范围内；req.key_id 对应的 SSH 密钥在 KMS 中存在且有效；req.command 非空字符串；req.timeout（如提供）>= 1
后置条件
远程命令已在目标服务器上执行完成；stdout/stderr/exit_code/duration_ms 已完整封装到响应中；SSH 连接已关闭释放；如 exit_code=0 则 success=true，否则 success=false
SshConnectionException→ 502TCP 连接失败、SSH 握手超时、主机密钥不匹配SshAuthenticationException→ 502密钥认证失败（密钥内容无效、密钥被吊销、用户名密码错误）SshCommandTimeoutException→ 504命令执行时间超过 req.timeout（或默认 30 秒）SshChannelException→ 502SSH channel 异常中断、远程服务器关闭连接
uploadFile
(req: FileTransferRequest) -> FileTransferResponse
通过 SFTP 将本地文件上传到远程服务器。自动创建远程目录结构（当 mkdir=true），传输完成后校验文件大小以确保完整性
前置条件
req.local_path 指向的本地文件存在且可读；req.remote_path 为合法的远程路径；req.key_id 对应密钥在 KMS 中有效
后置条件
文件已通过 SFTP 上传到远程路径 req.remote_path；如 req.mkdir=true 则远程目录已通过 mkdir -p 自动创建；传输完成后已校验本地文件大小与远程文件大小一致；SSH 连接已关闭释放
FileNotFoundException→ 400req.local_path 在本地文件系统中不存在SshConnectionException→ 502SFTP 子系统的 SSH 通道建立失败SftpTransferException→ 502传输过程中网络中断、远程磁盘空间不足、远程目录权限不足FileTransferTimeoutException→ 504文件传输超过系统配置的默认超时阈值
processDeployTask
(task: DeploymentTask) -> None
消费 RabbitMQ deploy_tasks 队列消息，执行完整的一键部署流程：① 从 Primary Database 读取 environment_id 对应的 SSH 连接参数 → ② 从 KMS 获取 SSH 私钥明文 → ③ 建立 SSH 连接 → ④ 在远程服务器创建带版本标识的部署目录（如 /opt/deploy/{project_id}/{version}/）→ ⑤ 上传部署文件到远程目录 → ⑥ 远程生成部署脚本 → ⑦ 传输并执行脚本 → ⑧ 收集执行结果并验证 → ⑨ 每步完成后发布进度消息到 MQ → ⑩ 操作完成后记录审计日志 → ⑪ MQ 消息 ack 释放
前置条件
RabbitMQ 消费者连接正常；task.deployment_id/project_id/environment_id/file_path/version 均非空；task.environment_id 在 environments 表中存在且未删除
后置条件
部署任务已按 DeployStep 顺序执行完毕或在中途步骤失败时终止；每个步骤完成后已向 RabbitMQ exchange deploy.tasks 发布 DeployProgressMessage 消息（含 running/success/failed 状态）；失败步骤的后续步骤不再执行；SSH 连接已关闭释放；MQ 消息已 ack
EnvironmentNotFoundException→ Nonetask.environment_id 在 environments 表中不存在SshConnectionException→ None部署过程中建立 SSH 连接失败KmsKeyRetrievalException→ None从 KMS 获取 SSH 密钥内容失败（密钥不存在、解密失败）DeployStepException→ None部署过程中某一步骤执行异常（目录创建失败、文件上传失败、脚本退出码非零）MqPublishException→ None向 RabbitMQ 发布进度消息时连接异常
数据访问依赖
findEnvironmentById(environmentId: UUID) -> Optional[dict] — 读取环境表的 SSH 连接参数（host/port/username/key_id）
getKeyContent(keyId: UUID) -> str — 调用 KMS 获取 SSH 私钥明文内容（PEM 格式字符串）
auditLog(actor: str, action: str, resourceType: str, resourceId: str, detail: dict, result: str) -> None — 调用 Audit Service POST /internal/audit/log 记录审计日志
publishDeployProgress(msg: DeployProgressMessage) -> None — 发布部署进度消息到 RabbitMQ exchange deploy.tasks

业务规则

不变量
  • !SSH 私钥明文内容（PEM 格式字符串）绝对不允许记录到任何日志、异常消息或审计详情中，防止密钥泄露
  • !所有 SSH 连接必须在操作完成后被正确关闭释放，使用 try/finally 或 context manager 确保资源释放，防止连接泄漏
  • !命令执行超时后必须强制终止 Paramiko channel 中的远程进程（通过 channel.close 或 settimeout 机制），防止僵尸进程占用远程服务器资源
  • !SFTP 文件传输完成后必须校验本地文件大小与远程文件大小是否一致，确保传输完整性；不一致视为传输失败
  • !部署步骤严格按 DeployStep 顺序串行执行，前一步失败（exit_code != 0 或异常）则后续步骤不再执行，并发布 failed 状态进度消息
  • !同一 deployment_id 对应的部署任务不允许并发处理；如果 MQ 中存在重复消息，应在处理前检查是否已被处理过（幂等性检查）
状态机
🎯 SshSession
disconnectedconnectingconnectederror
→调用 Paramiko SSHClient.connect()by SshExecutionService
→TCP 握手和密钥认证成功，SSH 会话建立by Paramiko Transport

⚡ SSH 连接池使用 threading.Lock 控制并发访问，最大并发连接数由 ssh_defaults.max_connection_pool 配置控制。超出上限的请求阻塞等待已有连接释放或直接抛出 SshConnectionException（连接池满载）
🎯 DeploymentTask
pendingrunningsuccessfailed
→消费者从 RabbitMQ 拉取消息开始处理by SshExecutionService
→所有步骤（create_directory → upload_file → generate_script → execute_script → verify_result）全部成功完成by SshExecutionService

🚫 部署任务一旦进入 success 或 failed 终态后不可回退🚫 failed 状态的部署任务不会由本服务自动重试
⚡ RabbitMQ 消费者使用 manual ack 机制 + prefetch=1，确保同一消费者同时最多处理一条消息，避免相同 deployment_id 并发处理。处理完成后发送 basic_ack，处理异常时发送 basic_nack(requeue=true) 将消息重新入队
跨服务规则
部署任务处理前需读取 Primary Database 的 environments 表获取环境 SSH 连接参数（host/port/username/key_id）。获取到 key_id 后，调用 Key Management Service 的密钥获取接口（POST /internal/kms/keys, action=retrieve）解密获取 SSH 私钥明文内容。KMS 调用失败时终止部署任务，发布 failed 状态并记录审计日志
文件传输前根据 deploy_step 顺序先在远程服务器创建带版本标识的目录结构，路径格式为 {deploy_root_path}/{project_id}/{version}/。目录创建通过 SSH 执行 mkdir -p 命令完成，创建失败则终止部署流程
部署流程的每个步骤完成后，通过 RabbitMQ 的 deploy.tasks 交换机发布 DeployProgressMessage 进度消息，Deployment Orchestrator 消费后更新 Redis 实时状态和数据库中的部署记录。消息发布失败时记录 ERROR 日志但继续执行后续步骤
关键操作（命令执行、文件上传、部署步骤完成/失败）必须调用 Audit Service 的 POST /internal/audit/log 接口记录审计日志。actor 统一为 ssh_service，action 使用 ssh.command.execute / ssh.file.upload / ssh.deploy.step / ssh.deploy.complete，resource_type 固定为 deployment，resource_id 传入 deployment_id，result 根据操作结果填入 success 或 failure。审计日志发送失败仅记录 WARN 日志，不阻塞业务主流程
Environment Management Service 的连接测试功能通过调用本服务的 POST /internal/ssh/execute 接口传入轻量探测命令（如 echo 'connection_test'）实现。本服务不需要主动调用 Environment Management Service 的 Connection Test API

错误处理

处理策略

服务层采用统一的异常处理机制：Paramiko 操作异常按类型映射为自定义业务异常类，由 FastAPI 全局异常处理器捕获并转换为标准错误响应格式。SSH 连接失败映射为 502，命令执行超时映射为 504，非零 exit_code 不作为 HTTP 异常抛出而是以业务数据 success=false 返回。参数校验由 FastAPI Pydantic 模型自动完成，校验失败返回 422。MQ 消息处理异常记录错误日志并通过 manual nack 将消息重新入队，防止消息丢失。调用 Audit Service 失败仅记录 WARN 日志，不阻塞业务主流程。所有未预期异常统一返回 500。
