概述

SSH Execution Service
⚙️ 业务服务
核心执行引擎，通过 SSH 协议在远程服务器上执行命令和传输文件。消费 RabbitMQ 部署任务队列消息，实际执行远程命令、文件上传、脚本生成和远程执行等部署步骤，并通过 RabbitMQ 发布执行进度。接收来自 Environment Management Service 和 Deployment Orchestrator 的内部 REST 请求执行 SSH 操作。SSH 密钥认证依赖 Key Management Service 获取解密后的私钥材料。所有关键执行事件同步记录审计日志至 Audit Service。
依赖: Key Management ServiceAudit ServiceRabbitMQRemote Servers (SSH)
Python 3.11+FastAPIasyncio + uvicornRabbitMQ 3.12SSH-2Docker + Docker Compose

executeCommand
(request: SSHExecuteRequest) -> SSHExecuteResponse
在远程服务器上执行 shell 命令。从 Key Management Service 获取 key_id 对应 SSH 私钥建立认证连接，执行命令并收集输出。超时后强制关闭通道并返回已收集的部分输出。
前置条件
request.host 非空且为合法 IP/域名格式；request.port 在 1-65535 范围内；request.username 非空；request.key_id 为有效 UUID；request.command 非空且长度 ≤ 65536 字符；request.timeout_seconds ≤ ExecutionConfig.max_timeout_seconds
后置条件
SSH 会话已建立并执行命令，返回 SSHExecuteResponse（含 stdout/stderr/exit_code/duration_ms）。SSH 连接在结果返回后主动关闭。同步发送审计事件到 Audit Service

业务规则

不变量
  • !SSH 命令执行超时不可超过 ExecutionConfig.max_timeout_seconds（默认 600s）
  • !同一部署任务消息从 RabbitMQ 消费后手动 ack，处理失败不重新入队，直接进入死信队列
  • !文件传输前自动递归创建目标路径的父目录，避免因目录不存在导致 SFTP 写入失败
  • !远程部署目录命名规范为 /opt/cogniforge/{project_name}/{version}/，version 由调用方提供
  • !SSH 私钥材料从 Key Management Service 获取后仅存于运行时内存，使用后立即置零清除，不在磁盘或数据库持久化
  • !文件传输目标路径必须是 Unix 绝对路径，以 / 开头
  • !命令执行结果中 stdout 和 stderr 分别截断上限为 1MB，超出部分丢弃并记录截断警告日志
  • !并发部署任务数受 ExecutionConfig.max_concurrent_tasks 限制（默认 5），通过 RabbitMQ QoS prefetch_count 实现
  • !SSH 连接闲置超过 keepalive_interval 秒时发送 keepalive 心跳包检测连接活性

🎯 SSHSession

🚫 SSH 会话从 connected 转为 error 后不可恢复，必须重建新连接🚫 会话进入 disconnected 后所有通道已关闭，不可再执行命令或传输文件
⚡ 每个 HTTP 请求或 MQ 消息创建独立 SSH 会话，会话间互不影响。通过 asyncio 事件循环实现非阻塞 I/O 多路复用。连接池上限由 ExecutionConfig.connection_pool_size 控制（默认 10），超过上限时请求排队等待空闲连接。
🎯 DeployTaskExecution
pendingrunningsuccessfailed
→RabbitMQ 消息到达，消费者 ack 并开始执行部署步骤by SshExecutionService

⚡ 通过 ExecutionConfig.max_concurrent_tasks 控制最大并行部署任务数（默认 5）。使用 RabbitMQ basic.qos（prefetch_count = max_concurrent_tasks）限制同一消费者未 ack 的消息数。超出并发上限的消息在队列等待，不拒绝。
跨服务规则
SSH 密钥材料通过 key_id 从 Key Management Service 的内部接口获取，使用后立即清除内存引用，不持久化存储密钥文件。Key Management Service 不可用时整个操作回滚并报告 503
SSH 命令/文件传输执行完成后通过 Audit Service 的 POST /internal/audit/log 接口同步记录审计日志（含命令摘要、执行结果、目标主机、耗时）。审计调用失败不影响主流程（fire-and-forget，本地记录 WARN 日志）
部署任务通过 RabbitMQ 从 Deployment Orchestrator 流向本服务：exchange deploy.tasks / routing_key deploy.execute。消息体为 DeployTaskMessage JSON。本服务处理完成后不直接回复响应消息——处理结果通过 deploy.progress 队列推送进度到 Deployment Orchestrator
部署进度通过 RabbitMQ 从本服务流向 Deployment Orchestrator：exchange deploy.progress / routing_key deploy.progress.update。每步执行完毕即时发布 DeployProgressMessage，消息持久化确保不丢失
文件传输和命令执行共享同一 SSH 会话通道（一个 TCP 连接上的多个 channel），避免多次认证握手。先建立会话，再在会话中开 channel 执行各步骤
Environment Management Service 和 Deployment Orchestrator 调用本服务前需确保 key_id 对应 SSH 密钥已在 Key Management Service 中注册且状态为 active

错误处理

处理策略

SSH Execution Service 对所有请求参数进行前置校验，校验失败返回 400。SSH 连接阶段错误根据类型区分：认证失败返回 401，网络不可达返回 502，超时返回 408。Key Management Service 调用失败返回 503。文件传输的写入冲突返回 409。所有未预期异常由全局异常处理器捕获，返回 500 并记录错误日志，同时向 Audit Service 发送失败审计事件。消息队列消费失败时根据错误类型决定重试或进入死信队列。
