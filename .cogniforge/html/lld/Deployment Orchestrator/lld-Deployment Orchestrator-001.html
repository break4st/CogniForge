概述

模块: Deployment Orchestrator
部署编排服务，核心调度引擎，负责编排整个部署流程。接收部署请求后异步编排执行流程：从 Key Management Service 获取解密后的 SSH 密钥，通过 SSH Execution Service 在远程服务器上创建版本文件夹、传输可执行文件、生成并推送执行脚本、触发远程执行并收集结果。部署过程中的日志通过 WebSocket 实时推送给前端，任务状态变更同步写入审计日志。
依赖: Key Management ServiceSSH Execution ServiceAudit Service
GoGin / Go-ZeroPostgreSQL 15+Redis 7+RabbitMQgolang.org/x/crypto/sshSCP / SFTP

错误处理

所有对外接口统一返回 JSON 格式错误：{ code: int, message: string }。400 参数校验失败、404 资源不存在、409 资源冲突、500 服务内部错误。 部署任务创建阶段：先校验 project_id 和 environment_id 在数据库中的存在性，再检查目标环境当前是否存在状态为 pending 或 running 的活跃部署任务，存在则返回 409 禁止并发部署，确保同一环境同一时间只能有一个部署任务在执行。 部署执行流程编排（RabbitMQ 异步消费者）：任务创建成功后发送消息到部署队列（exchange: cogniforge.deploy, routing_key: deployment.execute），消费者按步骤顺序执行——1）查询 deployments 表获取环境关联的 key_id，调用 Key Management Service 的 GET /api/internal/keys/:id/decrypt 获取解密后的 SSH 密钥，若调用失败（网络错误或密钥不存在）标记任务为 failed 并记录 error_message；2）依次调用 SSH Execution Service 的 POST /api/internal/ssh/execute（创建远程版本文件夹、生成并推送执行脚本、触发远程执行）和 POST /api/internal/ssh/transfer（传输可执行文件到远程服务器），任一步骤返回非零 exit_code 或失败响应则终止后续步骤并标记任务为 failed；3）每次调用 SSH Execution Service 后，将执行结果写入 deployment_logs 表并通过 WebSocket 频道广播；4）所有步骤完成后标记任务为 success 或 failed，写入完成时间，同步调用 Audit Service 的 POST /api/audit/logs 记录审计日志（action 为 trigger_deployment / deployment_completed，resource_type 固定为 deployment），审计日志写入失败仅记录 warn 日志不阻塞业务。 RabbitMQ 消费者采用手动 ACK（manual ack）模式：消息处理成功时手动确认（basic.ack），处理失败时根据错误类型决定——可重试错误（SSH 超时、网络抖动）进入重试队列最多 3 次、间隔 30 秒，不可重试错误（参数错误、密钥无效）直接进入死信队列（DLQ）并标记部署任务为 failed。消费者启动时恢复所有状态为 pending 但实际已中断的任务，将其标记为 cancelled。 数据库写操作统一使用事务，deployments 表和 deployment_logs 表在同一个事务内写入（当写入日志时），确保日志与任务状态变更的原子性。Redis 缓存用于 deployments 表状态查询加速（缓存键格式 deployment:status:{id}），部署状态变更时主动失效缓存。 WebSocket 连接管理：使用 gorilla/websocket 库，每个部署任务支持多个并发 WebSocket 客户端连接。当部署任务状态进入终态（success / failed / cancelled）时向所有活跃客户端发送结束帧后关闭连接。客户端断开时自动清理会话资源。读超时 60 秒，写超时 10 秒，Ping/Pong 间隔 30 秒用于心跳保活。
