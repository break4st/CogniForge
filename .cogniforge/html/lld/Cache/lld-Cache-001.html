概述

模块: Cache

Redis 缓存层，为各业务模块提供统一的热点数据缓存能力，降低数据库查询压力。采用 Cache-Aside 模式：查询时优先读缓存，缓存未命中则回查数据库并回填缓存；数据变更时主动删除或更新缓存，由消息队列异步触发缓存重建。缓存 Key 按业务模块分层命名（cache:<module>:<entity>:<id>），每个缓存条目携带 TTL，过期后自动失效避免数据脏读。支持缓存统计和批量清理操作，供运维监控和管理使用。

🗄️

数据模型 (6)

CacheKeySchema

字段类型描述
patternstring缓存 Key 模板，如 cache:class:{classId}:members
modulestring所属模块：class / grade / statistics
descriptionstring缓存内容说明
ttlSecondsnumber缓存过期时间（秒），默认值

ClassMemberListCache

字段类型描述
keystringcache:class:{classId}:members，如 cache:class:5:members
valueStudentResponse[]班级成员列表的 JSON 序列化数据
ttlSecondsnumber300 秒（5 分钟），班级成员变动不频繁

GradeTreeCache

字段类型描述
keystringcache:grade:tree
valueobject年级-班级层级树结构的 JSON 序列化数据：{ gradeId, gradeName, classes: [{ classId, className, studentCount }] }
ttlSecondsnumber600 秒（10 分钟），年级结构相对稳定

StatisticsCache

字段类型描述
keystringcache:statistics:{dimension}:{id}，如 cache:statistics:student:42 或 cache:statistics:class:3
valueobject统计计算结果的 JSON 序列化数据，包含各项统计指标的键值对
ttlSecondsnumber1800 秒（30 分钟），统计计算成本高，适当延长缓存时效

CacheConfigEntry

字段类型描述
keyPrefixstring缓存 Key 前缀，如 cache:class
defaultTtlSecondsnumber默认过期时间（秒）
maxSizenumber该前缀下的最大缓存条目数，防止内存溢出
evictionPolicystring淘汰策略：TTL（自动过期） / LRU（配合 Redis allkeys-lru），默认 TTL

CacheMetrics

字段类型描述
hitsnumber缓存命中次数
missesnumber缓存未命中次数
hitRatefloat缓存命中率，hits / (hits + misses)
totalKeysnumber当前缓存中的 Key 总数
usedMemoryBytesnumberRedis 已用内存字节数

接口定义 (9)

获取缓存

Cache.get(key: string)

根据 Key 获取缓存值。命中时返回反序列化后的对象，未命中返回 null。调用方判断返回值后决定是否回填

设置缓存

Cache.set(key: string, value: object, ttlSeconds?: number)

写入缓存条目，value 自动序列化为 JSON。ttlSeconds 缺省时使用对应 Key 前缀的默认 TTL

删除缓存

Cache.del(key: string)

主动删除指定缓存条目。在对应业务数据发生变更时调用（如班级成员变更后删除 cache:class:{classId}:members），下次查询时重新回填

按前缀批量删除

Cache.delByPrefix(prefix: string)

按 Key 前缀批量删除缓存条目。用于某个模块的大量数据变更场景（如批量重新分班），通过 Redis SCAN + DEL 实现，避免 KEYS 阻塞

缓存存在检查

Cache.exists(key: string): boolean

检查指定 Key 是否存在于缓存中，不返回实际值。用于预热判断等场景

缓存 TTL 查询

Cache.ttl(key: string): number

查询指定缓存条目的剩余过期时间（秒）。返回 -2 表示 Key 不存在，-1 表示未设置 TTL（永不过期）

批量获取缓存

Cache.mget(keys: string[]): (object | null)[]

批量获取多个缓存值，返回与 keys 输入顺序对应的数组。某 Key 不存在时对应位置为 null。用于一次性加载多个学生信息等场景，减少网络往返

缓存统计

Cache.stats(): CacheMetrics

获取缓存层的运行统计数据，包括命中次数、未命中次数、命中率、Key 总数和内存使用量。由运维监控定期采集，用于评估缓存效果和容量规划

清空缓存

Cache.flushAll()

清空所有缓存条目。仅在系统维护或数据大面积回滚时使用，调用前需确认影响范围。生产环境慎用

⚠️

错误处理

缓存操作异常统一以 CacheException 形式抛出，不影响主业务流程的正常执行。读缓存失败（Redis 连接超时、命令执行异常等）时，Cache.get 降级返回 null，调用方自动回查数据库保证业务可用；写缓存失败仅记录 WARN 级别日志，不阻塞业务操作完成。Key 或 Value 序列化异常（如 JSON 序列化失败）记录错误日志并返回 null 或 false。批量操作（mget/delByPrefix）中单个 Key 失败不影响其他 Key 的操作结果，最终以 AggregateException 形式汇总失败情况。Redis 连接断开时，所有缓存操作自动降级（fail-open 策略），同时启动重连机制（指数退避，最多重试 3 次）。
