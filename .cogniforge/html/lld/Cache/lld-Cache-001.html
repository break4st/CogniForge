概述

模块: Cache

Redis 缓存层，提升热点数据的查询性能，减轻数据库压力。缓存层以独立中间件形态存在，被 Student Service、Class Service、Grade Service、Statistics Service 通过 Redis 客户端程序化接入（不暴露 REST 接口）。缓存策略采用 Cache-Aside 模式：读操作先查缓存，命中则直接返回，未命中则回查数据库并将结果写入缓存；写操作先更新数据库，再删除缓存中的对应条目，确保数据一致性。缓存键按业务模块分层命名，支持按前缀批量失效。默认 TTL 按数据热度分档设置：高频读低变更数据（如班级/年级列表）120 秒，中频读数据（如学生详情）300 秒，低频读数据或统计结果（如统计分析）600 秒。缓存值使用 JSON 序列化存储，Redis 数据类型以 String 为主，列表类数据采用整体序列化方式（非 Redis List 结构），简化一致性和失效管理。

数据模型 (3)

cache_key_schema

字段类型描述
student:detail:{id}String学生详情缓存。键如 student:detail:1，值为学生详情 JSON，TTL 300 秒。适用于 GET /internal/students/{id} 的查询结果缓存。
student:list:{query_hash}String学生列表缓存。query_hash 为查询参数（name,student_no,class_id,page,page_size）的 MD5 摘要，值为分页结果 JSON，TTL 120 秒。适用于 GET /internal/students 的查询结果缓存。键名例：student:list:a1b2c3d4e5。
class:detail:{id}String班级详情缓存。键如 class:detail:1，值为班级详情 JSON（含实时计算的 student_count），TTL 300 秒。适用于 GET /internal/classes/{id} 的查询结果缓存。
class:list:{query_hash}String班级列表缓存。query_hash 为查询参数（grade_id,name,page,page_size）的 MD5 摘要，值为分页结果 JSON，TTL 120 秒。适用于 GET /internal/classes 的查询结果缓存。
class:exists:{id}String班级存在性校验缓存。键如 class:exists:1，值为 {"exists":true,"id":1,"name":"一班"} JSON，TTL 300 秒。适用于 GET /internal/classes/{id}/exists 的结果缓存。
grade:detail:{id}String年级详情缓存。键如 grade:detail:1，值为年级详情 JSON，TTL 300 秒。适用于 GET /internal/grades/{id} 的查询结果缓存。
grade:list:{query_hash}String年级列表缓存。query_hash 为查询参数（page,page_size）的 MD5 摘要或仅 'all' 表示全量列表，值为分页结果 JSON，TTL 120 秒。适用于 GET /internal/grades 的查询结果缓存。
grade:classes:{id}String年级班级结构缓存。键如 grade:classes:1，值为该年级下的班级列表 JSON，TTL 120 秒。适用于 GET /internal/grades/{id}/classes 的查询结果缓存。
grade:exists:{id}String年级存在性校验缓存。键如 grade:exists:1，值为 {"exists":true,"id":1,"name":"一年级"} JSON，TTL 300 秒。适用于 GET /internal/grades/{id}/exists 的结果缓存。
stat:student:{id}:{date_range_hash}String学生统计缓存。date_range_hash 为 start_date 和 end_date 的摘要，无日期范围时为 'all'，值为学生统计结果 JSON，TTL 600 秒。适用于 GET /internal/statistics/students/{id} 的结果缓存。
stat:class:{id}:{param_hash}String班级统计缓存。param_hash 为 subject、start_date、end_date 的摘要，值为班级统计结果 JSON，TTL 600 秒。适用于 GET /internal/statistics/classes/{id} 的结果缓存。
stat:grade:{id}:{param_hash}String年级统计缓存。param_hash 为 subject、start_date、end_date 的摘要，值为年级统计结果 JSON，TTL 600 秒。适用于 GET /internal/statistics/grades/{id} 的结果缓存。

cache_ttl_policy

字段类型描述
HOT_SHORT_TTLnumber120 秒。适用于列表类缓存（学生列表、班级列表、年级列表、年级班级结构），这些数据按分页查询且查询参数组合多，缓存收益中等，需保持较好新鲜度。
WARM_MEDIUM_TTLnumber300 秒。适用于详情类缓存和存在性校验缓存（学生详情、班级详情、年级详情、班级存在性、年级存在性），这些数据按 ID 精确查询，缓存命中率高，变更频率低。
COLD_LONG_TTLnumber600 秒。适用于统计结果缓存（学生统计、班级统计、年级统计），统计计算成本高且结果相对稳定，依赖统计数据写入时主动失效来保证新鲜度。

invalidation_strategy

字段类型描述
学生写操作失效rule学生 Create/Update/Delete 后：1）DELETE student:detail:{id}（精确键）；2）SCAN 0 MATCH student:list:* 批量删除所有学生列表缓存（前缀通配）；3）如涉及 class_id 变更，还需 SCAN 0 MATCH class:detail:{class_id} 删除新旧班级详情缓存（因为班级详情含 student_count 实时计数，实际为 SQL 实时聚合，但如对 class detail 有缓存则需失效）。
班级写操作失效rule班级 Create/Update/Delete 后：1）DELETE class:detail:{id}（精确键）；2）DELETE class:exists:{id}；3）SCAN 0 MATCH class:list:* 批量删除所有班级列表缓存；4）如涉及 grade_id 变更，DELETE grade:detail:{grade_id} 和 DELETE grade:classes:{grade_id}（因为年级详情含 class_count、年级班级结构包含班级信息）；5）SCAN 0 MATCH grade:list:* 批量删除年级列表缓存（列表项含 class_count）。
年级写操作失效rule年级 Create/Update/Delete 后：1）DELETE grade:detail:{id}；2）DELETE grade:exists:{id}；3）DELETE grade:classes:{id}；4）SCAN 0 MATCH grade:list:* 批量删除所有年级列表缓存；5）因年级变更会影响关联班级的 grade_name 显示，需 SCAN 0 MATCH class:list:* 和 DELETE class:detail:*（按前缀批量删除班级缓存，使下次查询时回填最新的年级名称）。
统计数据写操作失效rule学习数据录入或批量导入后：1）DELETE stat:student:{student_id}:*；2）如涉及班级/年级维度的统计失效，需 DELETE stat:class:{class_id}:* 和 DELETE stat:grade:{grade_id}:*；3）SCAN 0 MATCH stat:* 模式匹配可选，因统计查询参数组合多，精确失效目标键即可，其余统计缓存依靠 TTL 自然过期。
批量失效的安全说明noteSCAN 命令替代 KEYS 命令进行通配匹配，避免阻塞 Redis 单线程。生产环境中 SCAN 的 COUNT 参数建议设为 100，分批次遍历键空间。对统计缓存的 SCAN 操作仅建议在低峰期执行或配合限流，避免大量键扫描影响 Redis 性能。

接口定义 (5)

缓存读取操作（Cache Get）

Redis GET {key}

读取指定键的缓存值。由各微服务在查询数据时调用。核心逻辑：1）构造缓存键（按缓存键命名规范拼接）；2）调用 Redis GET 命令获取值；3）如果值存在且未过期，反序列化 JSON 后直接返回（缓存命中）；4）如果值不存在或已过期（返回 nil），回查数据库获取最新数据，然后序列化为 JSON 并调用 Redis SETEX 写入缓存（含 TTL），再返回数据。所有缓存操作应设置合理的超时时间（Redis 命令超时默认 2 秒），超时或连接异常时降级为直接查数据库，不阻塞业务流程。

参数类型描述
keystring缓存键，按 student:detail:{id} / class:list:{query_hash} 等规范格式构造
timeout_msnumberRedis 命令执行超时，默认 2000 毫秒，超时后降级查数据库

缓存写入操作（Cache Set）

Redis SETEX {key} {ttl} {value}

写入指定键的缓存值，同时设置过期时间。由各微服务在缓存未命中回查数据库后调用，将查询结果写入缓存。核心逻辑：1）将查询结果对象序列化为 JSON 字符串；2）调用 Redis SETEX 命令，同时设置键和 TTL；3）写入失败（如 Redis 不可用）不抛异常，仅记录 WARN 日志，不影响业务流程——下次查询时再次尝试写入。SETEX 是原子操作，确保键和 TTL 同时设置，避免 SET + EXPIRE 之间出现竞态。

参数类型描述
keystring缓存键
ttlnumber过期时间（秒），根据缓存键类型参考 TTL 分档策略设定
valuestringJSON 序列化的缓存值

缓存删除操作（Cache Delete）

Redis DEL {key}

删除指定键的缓存值。由各微服务在写操作（Create/Update/Delete）完成后调用，执行 Cache-Aside 的 Delete 策略。核心逻辑：1）写操作先执行数据库事务（INSERT/UPDATE/DELETE）；2）数据库事务成功后，立即调用 DEL 删除受影响缓存键；3）DEL 为异步非阻塞操作，删除失败仅记录 WARN 日志，不引发事务回滚；4）对于列表类缓存的前缀批量删除，使用 SCAN 0 MATCH {prefix}* 遍历匹配的键后逐个 DEL。SCAN 操作建议使用游标分批执行，避免长时间阻塞 Redis。

参数类型描述
keystring要删除的精确缓存键

缓存前缀批量删除（Cache Scan & Delete）

Redis SCAN 0 MATCH {prefix}* COUNT 100 → DEL {key1} {key2} ...

按前缀模式匹配并批量删除缓存键。适用于列表类缓存的批量失效场景。核心逻辑：1）使用 SCAN 命令以游标方式迭代匹配指定前缀的键，COUNT 参数设为 100 控制每批返回量；2）对每批返回的键列表执行 DEL 命令（可单条或批量 DEL）；3）重复 SCAN 直到游标返回 0（遍历完成）；4）SCAN 只返回当前存活且匹配的键，不保证返回所有键（与 KEYS 不同），但渐进式扫描不影响 Redis 服务稳定性。此操作仅在写操作触发缓存失效时执行，频率较低，对 Redis 整体性能影响可控。

参数类型描述
prefixstring缓存键前缀，如 student:list:、class:list:、grade:list:
countnumber每次 SCAN 返回的最大键数量，默认 100

Redis 连接管理

redis://{host}:{port}/{db}

Redis 客户端连接配置与管理。各微服务通过 Redis 客户端连接池与缓存层通信。连接池配置：最大连接数 20，最小空闲连接数 5，连接超时 2 秒，读取超时 2 秒，空闲连接检测间隔 60 秒（发送 PING 心跳）。Redis 部署模式：单机模式（开发环境）或哨兵模式/Cluster 模式（生产环境）。Database 选择：统一使用 db=0。密码认证通过 Redis AUTH 命令配置。客户端建议使用 Lettuce（Java）或 redis-py（Python）等成熟客户端库，支持连接池、自动重连和异步操作。

参数类型描述
hoststringRedis 服务器主机地址
portnumberRedis 服务器端口，默认 6379
passwordstringRedis 认证密码（可选）
dbnumberRedis 数据库索引，统一使用 0
pool_max_activenumber连接池最大活跃连接数，默认 20
pool_max_idlenumber连接池最大空闲连接数，默认 5
timeout_msnumber连接/读写超时（毫秒），默认 2000

错误处理

Cache 层按以下规则处理异常：1）Redis 连接失败——微服务在启动时或运行中无法连接 Redis，不应影响业务正常运行，所有缓存操作降级为直接查数据库，记录 WARN 级日志"Redis 不可用，已降级为直连数据库"，Redis 恢复后自动重连并恢复正常缓存流程；2）缓存操作超时——Redis 命令执行超过 2000 毫秒超时阈值时，中断当前命令并降级查数据库，记录 WARN 日志"Redis 命令超时"，包含操作类型（GET/SET/DEL/SCAN）和键名前缀（不记录完整键名以防止敏感信息泄露）；3）反序列化异常——从 Redis 读取的缓存值 JSON 格式异常或与预期结构不匹配时，视为缓存失效，删除该键并回查数据库重建缓存，记录 WARN 日志"缓存反序列化失败，已清除"；4）序列化异常——写入缓存时对象序列化失败（如循环引用、非 JSON 可序列化类型），放弃缓存写入，记录 ERROR 日志"缓存值序列化失败"并排查数据模型；5）SCAN 阻塞风险——SCAN 命令在键数量极大（数百万级别）时即使分批遍历也可能产生性能影响，建议在低峰期执行批量失效，或考虑将列表缓存键的失效策略优化为按版本号管理（维护缓存版本计数器，版本变更时所有缓存自然过期），此优化作为后续迭代项；6）缓存穿透——对于数据库中不存在的数据（如按 ID 查学生不存在），不应写入空值缓存以避免缓存穿透，而是直接返回 404，由调用方处理。如确需防止对同一不存在 ID 的反复穿透查询，可采用布隆过滤器策略（Bloom Filter），此优化作为后续迭代项；7）缓存雪崩——大量缓存同时过期可能导致短时数据库压力激增，通过 TTL 分档策略（120/300/600 秒差异化过期时间）和为每个缓存键的 TTL 增加 ±10% 随机偏移量来避免大量键同时过期；8）缓存击穿——热点缓存键在过期瞬间遭遇高并发查询时，多个请求同时回查数据库，通过互斥锁（分布式锁或单实例 synchronized）控制只有一个请求回查数据库并重建缓存，其余请求等待缓存重建完成后直接读取缓存，锁等待超时默认 500 毫秒，超时后降级查数据库。所有缓存操作记录结构化日志，包含操作类型（GET/SET/DEL/SCAN）、键名前缀（模糊化）、命中状态（hit/miss）、耗时（毫秒）和结果状态（success/fallback/error），日志级别：正常命中 DEBUG，缓存未命中 INFO，降级查数据库 WARN，系统异常 ERROR。
