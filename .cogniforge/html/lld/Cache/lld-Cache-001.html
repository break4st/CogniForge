概述

模块: Cache
缓存层（Redis 7+），为系统各业务服务提供高速数据缓存能力，降低主数据库查询压力并加速热点数据访问。覆盖四大缓存域：部署任务实时状态缓存（供 Deployment Orchestrator 和 Web Console 实时推送部署进度）、用户会话信息缓存（供 API Gateway 鉴权会话校验）、SSH 连接池状态缓存（供 SSH Execution Service 复用连接减少握手开销）、热点配置数据缓存（供各业务服务快速读取配置）。所有缓存项均设置 TTL 过期策略，保证数据最终一致性。
GoRedis 7+

错误处理

缓存层作为系统加速中间件，所有缓存操作失败不应影响主业务流程的可用性。上层服务在调用缓存接口时必须实现降级策略：缓存不可用时直接回退到数据库查询。 (1) 连接管理 — 使用 go-redis 连接池（pool_size=100, min_idle_conns=10, conn_max_lifetime=30min）。连接超时 5s，读写超时 3s。初始化时采用懒加载模式，首次操作时建立连接，避免启动时因 Redis 不可用导致服务启动失败。 (2) 超时处理 — 操作超时返回独立错误类型 ErrCacheTimeout，上层服务捕获后降级到数据库查询，不向上层调用方透传超时错误。连接池耗尽时返回 ErrPoolExhausted，调用方应退避重试（指数退避：100ms、200ms、400ms，最大 3 次）。 (3) 缓存穿透防护 — 对查询结果为空的数据，设置短 TTL 空值缓存（30s），避免恶意请求穿透到数据库。热门 Key 使用互斥锁（SETNX）控制回填并发，防止缓存雪崩。 (4) 缓存一致性 — 采用 Cache-Aside 模式：读请求先查缓存，未命中则查数据库并回填；写请求先更新数据库，再删除缓存（延迟双删，第一次立即删除，第二次 500ms 后延迟删除）。配置数据采用短 TTL（5 分钟）实现最终一致性。部署状态数据通过 Redis Pub/Sub 广播变更事件，各订阅方实时更新本地状态。 (5) 键管理 — 所有业务键使用前缀命名空间隔离：cogniforge:deploy:*、cogniforge:session:*、cogniforge:sshpool:*、cogniforge:config:*。禁止使用 KEYS 命令（改用 SCAN 游标遍历）。批量操作使用 Pipeline 减少 RTT。 (6) 数据序列化 — 缓存值统一使用 JSON 序列化，序列化/反序列化错误返回 ErrSerialization，上层服务捕获后清空该缓存键并回填。Hash 结构的字段值均存储为字符串类型，数值字段在应用层进行类型转换。 (7) 过期策略 — 所有缓存键必须设置 TTL，禁止永不过期的缓存项。TTL 根据数据特征差异化配置：部署状态 1 小时、会话 24 小时、SSH 连接池 30 分钟、热点配置 5 分钟。Redis 内存达到 maxmemory 限制时，采用 allkeys-lru 淘汰策略自动清理冷数据。
