组件树 (1)

DeployDashboard/deploy/:taskId

部署进度看板容器组件，负责数据获取、WebSocket 连接管理和子组件协调

State
taskData: DeployTaskData | nullwsState: WSConnectionStatelogs: LogEntry[]loading: booleanpageError: string | null
行为
  • mount 时从路由参数获取 taskId，调用 GET /api/v1/deploy/:taskId 加载初始任务数据
  • 初始数据加载成功后，发起 WS /api/v1/ws/deploy/:taskId WebSocket 连接
  • 收到 WS progress 事件时更新 taskData.progress 和 taskData.currentStep
  • 收到 WS log 事件时将日志行转为 LogEntry 追加到 logs 列表
  • 收到 WS error 事件时更新 taskData.status=failed 并设置 pageError
  • 收到 WS complete 事件时更新 taskData.status=success 并设置 completedAt
  • WS 连接断开时自动触发指数退避重连，最多重试 5 次
  • unmount 时主动关闭 WebSocket 连接并清理所有定时器
边界情况
  • ⚠️ taskId 路由参数无效时显示「任务不存在」错误提示
  • ⚠️ 初始 GET 请求失败时展示错误状态页，提供「重新加载」按钮
  • ⚠️ WS 重连超 5 次后显示「实时更新已断开」，仍可通过手动刷新页面恢复
  • ⚠️ 部署进行中页面被刷新时，重新执行 GET + WS 恢复流程
  • ⚠️ 同一浏览器打开多个标签页查看同一任务时各自独立维护 WS 连接
DeployHeader/deploy/:taskId

部署头部信息栏，展示任务标识、状态标签、版本号和操作按钮

Props
taskId: string *status: string *version: string *startedAt: string *canCancel: boolean
Events
@onCancel(string (taskId))
State
confirmVisible: booleancancelling: boolean
行为
  • 根据 status 显示对应颜色 Ant Design Badge（running=processing / success=success / failed=error / cancelled=default）
  • 点击「取消部署」按钮 → 弹出 Modal.confirm 确认框，文案「确认取消该部署任务？此操作不可撤销」
  • 用户确认后触发 onCancel(taskId)，按钮置为 loading 状态并显示「正在取消…」
  • 部署结束后隐藏取消按钮，展示部署总耗时（completedAt - startedAt）
边界情况
  • ⚠️ 取消请求发出后后端超时未响应，loading 持续但允许用户刷新页面重新获取状态
  • ⚠️ 取消请求发出后部署恰好完成，以 WS 推送的最新 status 为准
DeployProgressBar/deploy/:taskId

部署进度条组件，Ant Design Progress 封装，可视化展示整体完成度

Props
progress: integer *status: string *
行为
  • progress 变化时 Progress 组件以 transition 动画平滑过渡
  • status=running 时显示条纹动态效果（strokeColor=blue）
  • status=success 时置为 100%，strokeColor=green
  • status=failed 时 strokeColor=red 并停止动画
  • status=cancelled 时 strokeColor=grey
边界情况
  • ⚠️ progress 超出 0-100 范围时 clamp 到合法区间
  • ⚠️ progress 从低值跳变到高值时保留动画过渡而非瞬间跳变
DeployStepDisplay/deploy/:taskId

部署步骤指示器，使用 Ant Design Steps 组件展示部署各阶段

Props
currentStep: string *steps: string[]
State

  • 存在预定义 steps 时，将 currentStep 匹配到对应索引并高亮
  • 已完成步骤显示 Steps.STATUS_FINISH（对勾图标）
  • 当前步骤显示 Steps.STATUS_PROCESS（加载图标）

  • ⚠️ 步骤回退（如失败重试）时 activeIndex 同步回退

  • ⚠️ 日志行内容超长时自动换行（word-break: break-all），保留原始缩进格式
  • ⚠️ 搜索无匹配结果时显示「未找到匹配的日志行」
  • ⚠️ 大量日志持续推送时以 requestAnimationFrame 节流渲染，避免阻塞 UI

DeploySummary/deploy/:taskId

部署结果摘要，在部署完成后展示结果汇总信息

Props
status: string *version: string *startedAt: string *completedAt: string *
Events
@onViewHistory(void)
行为
  • 仅在 status 为 success / failed / cancelled 时渲染
  • 计算并展示部署总耗时（completedAt - startedAt 格式化输出）
  • status=success 时展示绿色成功图标 + 版本号信息
  • status=cancelled 时展示灰色图标 + 文案「已被用户取消」
  • 底部提供「查看部署历史」链接按钮，点击触发 onViewHistory

  • ⚠️ status===success 但 progress<100 时仍以 success 为准

缓存策略

部署任务数据不做客户端持久缓存，每次 mount 时重新从 REST API 获取最新状态。WS 实时消息仅在页面内存中按 FIFO 暂存，上限 2000 条，超出后丢弃最早 10% 的日志。页面刷新后日志不恢复，需从完整日志文件查看

交互流程 (5)

查看部署实时进度

用户从部署任务入口进入看板，实时观察部署任务从开始到完成的完整过程

1
步骤1: 用户点击部署任务项或触发部署后自动导航到 /deploy/:taskId
2
步骤2: DeployDashboard mount → 读取路由参数 taskId → 调用 GET /api/v1/deploy/:taskId 获取初始任务快照
3
步骤3: 初始数据加载完成 → 建立 WebSocket 连接 WS /api/v1/ws/deploy/:taskId
4
步骤4: 收到 WS progress 事件 → DeployProgressBar 平滑推进进度条，DeployStepDisplay 高亮当前步骤
5
步骤5: 收到 WS log 事件 → DeployLogViewer 实时追加日志并保持自动滚动
6
步骤6: 收到 WS complete 事件 → 状态切换为 success → 隐藏操作按钮 → DeploySummary 展示完成摘要
7
步骤7: WebSocket 连接自动关闭 → 页面停留在完成态供用户查看
部署失败处理与排查

部署执行中出现错误时，用户查看错误详情并根据排查建议采取相应操作

1
步骤1: WebSocket 推送 error 事件 或 GET 响应中 status=failed
2
步骤2: DeployProgressBar 变红停止动画，DeployStepDisplay 当前步骤标记 ERROR
3
步骤3: DeployErrorPanel 展开显示错误摘要和排查建议列表
4
步骤4: 用户根据排查建议（如检查 SSH 密钥、服务器磁盘空间、目录权限等）确认问题
5
步骤5: 用户点击「重试部署」→ 确认弹窗 → 调用重试 API → 页面重置进度和日志 → 重建 WS 连接
6
步骤6: 或用户点击「取消任务」→ 确认弹窗 → 调用取消 API → 页面更新为 cancelled 状态
取消正在执行的部署

用户在部署运行中手动中止当前部署任务

1
步骤1: 部署状态为 running 时 DeployHeader 渲染「取消部署」按钮
2
步骤2: 用户点击取消 → Modal.confirm 弹窗，文案「确认取消该部署任务？此操作不可撤销」
3
步骤3: 用户确认 → DeployHeader 按钮变为 loading + 「正在取消…」
4
步骤4: 调用 POST /api/v1/deploy/:taskId/cancel 发送取消请求
5
步骤5: WS 推送 status=cancelled 或下次 GET 返回 cancelled
6
步骤6: DeployProgressBar 变灰，DeployHeader 隐藏操作按钮，DeploySummary 显示「已被用户取消」
7
步骤7: WebSocket 连接关闭
日志查看和检索

用户在部署过程中查看和搜索部署日志的交互操作

1
步骤1: 日志实时追加，autoScroll=true 自动跟随最新日志
2
步骤2: 用户向上滚动浏览历史日志 → autoScroll 暂停 → 底部出现「回到最新」浮动按钮
3
步骤3: 用户点击「回到最新」→ 恢复 autoScroll，滚动到底部
4
步骤4: 用户输入搜索关键词 → 日志列表实时过滤，匹配文本高亮
5
步骤5: 用户选择日志级别过滤 ALL/INFO/WARN/ERROR → 按级别筛选条目
6
步骤6: 清除搜索和过滤条件 → 恢复完整日志列表
页面刷新后状态恢复

用户意外刷新页面后自动从 API 恢复部署看板状态

1
步骤1: 页面刷新 → DeployDashboard 重新 mount
2
步骤2: 从路由参数重新提取 taskId
3
步骤3: 调用 GET /api/v1/deploy/:taskId 获取当前时刻最新任务快照
4
步骤4: 若返回 status 为 running/progress，建立新的 WebSocket 连接继续接收实时更新
5
步骤5: 若返回 status 为 terminal（success/failed/cancelled），直接展示终态页面

错误处理

处理策略

统一错误处理分层：API 请求错误通过 Axios 拦截器捕获；WebSocket 异常在连接管理层处理；渲染异常由 ErrorBoundary 兜底。所有用户可见错误均提供可操作的重试或取消选项

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
4xx
客户端请求错误
请求参数无效、鉴权失败、任务不存在等。展示具体错误信息，引导用户检查操作或重新登录
5xx
服务端错误
后端服务异常。展示「服务暂时不可用，请稍后重试」，提供重试按钮
WS_CONNECTION_ERROR
WebSocket 连接异常
WebSocket 连接断开或建立失败。自动触发指数退避重连（1s/2s/4s/8s/16s），超过 5 次后显示「实时连接已断开」，提供手动刷新按钮
DEPLOY_TIMEOUT
部署超时
部署任务超过预期时间未完成。展示当前进度和已运行时长，建议用户检查目标服务器状态或取消重试
