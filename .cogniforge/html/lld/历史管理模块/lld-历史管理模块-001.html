概述

历史管理模块
⚙️ 业务服务
记录每次部署详情，提供历史查询和回滚功能。回滚操作本质是调用部署引擎将 current 指向指定版本目录。
依赖: 本地数据库 (CTR-007)SSH客户端模块 (CTR-008)
Node.js (主进程)Electron (主进程框架)SQLite (数据库)ssh2 (SSH库)
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 部署记录存储与查询 回滚操作（切换符号链接） 部署历史清理（随环境删除）
范围外: 部署执行逻辑（由部署引擎负责） 环境配置管理（由环境管理模块负责） SSH连接管理（由SSH客户端模块负责） GUI渲染（由GUI前端负责）
拥有组件: CMP-006
实现契约: CTR-006
消费契约: CTR-007 CTR-008

服务接口 (1)

🔧 HistoryService 3 方法
listHistory
(environmentId: string, page: number, pageSize: number) -> { records: DeploymentRecordView[], total: number }
查询某个环境下的部署历史记录，支持分页
前置条件
environmentId 非空
后置条件
返回指定环境的分页部署记录列表
InvalidRequestError→ 400参数无效
getDetail
(recordId: string) -> DeploymentRecordView
根据ID返回指定的部署记录详情
前置条件
recordId 对应的记录必须存在
后置条件
返回记录的详细信息
RecordNotFoundError→ 404记录不存在
rollback
(recordId: string) -> void
执行回滚操作，调用SSH客户端切换符号链接
前置条件
对应的部署记录存在且状态允许回滚（如 success）
后置条件
目标环境的部署版本切换为指定记录的版本
RecordNotFoundError→ 404记录不存在RollbackError→ 500SSH执行失败
数据访问依赖
findByEnvironmentIdPaginated(environmentId, page, pageSize) -> { records: DeploymentRecord[], total: number }
findById(recordId) -> DeploymentRecord
不变量
  • !每个部署记录必须关联一个有效的环境
  • !回滚操作只能针对状态为 success 的部署记录，且目标环境必须存在
  • !部署记录一旦创建不可修改，仅可通过删除环境时清理
状态机
🎯 DeploymentRecord
successfailedrolled_back
→回滚操作by 用户
🚫 状态 rolled_back 不可逆回到 success
⚡ 单环境同一时间只允许一个回滚操作，通过环境锁控制
跨服务规则
回滚操作需协调 SSH 客户端模块与本地数据库：先执行 SSH 切换符号链接，成功后更新当前部署版本记录，若 SSH 失败则记录错误但不更改数据库状态

编排流程

历史管理主流程

历史管理模块的查询与回滚流程

1
接收IPC请求 (60s 超时)
接收来自渲染进程的IPC请求，解析action和参数
失败处理: 返回INVALID_ACTION或INVALID_REQUEST错误
2
调用业务逻辑 (60s 超时)
根据action调用对应的HistoryService方法（listHistory, getDetail, rollback）
失败处理: 返回对应的业务异常，如RECORD_NOT_FOUND，并记录错误日志
3
返回响应 (60s 超时)
将结果或错误信息封装成标准响应格式返回给渲染进程
失败处理: 返回500内部错误
重试策略: 最多 3 次，间隔 30s
可重试错误: NETWORK_ERROR, TIMEOUT
不可重试错误: AUTH_ERROR, CONFIG_ERROR

错误处理

处理策略

所有错误统一通过标准响应格式返回，包含错误码、简要信息和可选详细描述，便于前端处理和排查。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
4xx
客户端错误
请求参数无效（如环境ID或部署ID缺失、格式错误）返回400；请求的资源不存在（如部署记录不存在）返回404。
5xx
服务器端错误
本地数据库操作失败返回500；SSH执行回滚命令失败（如权限不足、目标主机不可达）返回502或500；未预期内部错误返回500并记录日志。
