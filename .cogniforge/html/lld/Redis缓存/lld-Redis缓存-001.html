概述

Redis缓存
🗄️ 数据库层
高性能缓存服务，用于SSH连接池状态管理、WebSocket会话管理和高频读取数据缓存加速，以及部署进度的临时存储。基于Redis 7实现，提供高可用的键值存储能力，支持数据过期策略和持久化。
Redis 7Python 3.11
🗄️

数据模型 (4)

数据库表 1

🗄️ ssh_connection_pool_state权威定义

SSH连接池运行时状态，记录每个连接池的活跃连接数、健康状态和心跳信息。Key结构: ssh:pool:{pool_id}，使用Redis Hash存储，不设TTL，由SSH连接池服务手动管理生命周期。

字段
字段名类型描述

host *string目标服务器地址

login_user *string登录用户名
active_connections *integer当前活跃连接数
max_connections *integer最大连接数
idle_connections *integer空闲连接数
last_heartbeat *datetime(ISO8601)最近心跳时间戳
error_messagestring错误信息（status=error时）
created_at *datetime(ISO8601)连接池创建时间
updated_at *datetime(ISO8601)连接池最近更新时间
状态存储 3

🗃️ websocket_session权威定义

WebSocket长连接会话管理，记录前端与部署引擎之间的实时通信会话。Key结构: ws:session:{session_id}，使用Redis Hash存储，默认TTL=1800秒（30分钟无活动自动过期）。

🗃️ cache_entry引用

↳ 引用自: lld-PostgreSQL主数据库-001 / projects, environments, deployments

高频读取数据的缓存条目，以KV结构缓存PostgreSQL中的热点数据。Key结构: cache:{namespace}:{key}，支持自定义TTL。数据源为PostgreSQL主数据库，缓存仅为加速读取。

字段
字段名类型描述

cache_key *string缓存键，在namespace内唯一
cache_value *string(JSON)缓存值，JSON序列化后存储
ttl *integer过期时间（秒），默认300（5分钟）

🗃️ deployment_progress权威定义

部署任务实时进度数据，记录每个进行中部署任务的执行状态、进度百分比和当前步骤。Key结构: deploy:progress:{deployment_id}，使用Redis Hash存储，部署完成后保留1小时（TTL=3600）自动清理。

迁移策略

工具: 原生Redis迁移（redis-cli + Redis Replication）命名: V{序号}__{描述}.redis

回滚策略: RDB快照恢复：迁移前手动执行SAVE生成RDB快照，迁移失败时通过redis-cli --rdb恢复。键结构变更采用双写过渡期，旧键自然过期后清理。

📈

容量估算

1年: SSH连接池状态≤50条; WebSocket会话≤200条（并发）; 缓存条目≤50,000条; 部署进度≤10,000条/年（每个部署一条）3年: SSH连接池状态≤100条; WebSocket会话≤500条（并发）; 缓存条目≤100,000条; 部署进度≤30,000条/3年
热表: deployment_progress（部署期间高频读写） websocket_session（实时通信持续访问） cache_entry（项目列表/环境列表等高频率查询）

分区策略: Redis内置的key分区（16384个hash slot），通过集群模式自动分片。单实例模式无需手动分区。存储的键按数据域前缀（ssh:/ws:/cache:/deploy:）自然分类，Resp3协议支持自动路由。

🔗

连接配置

连接池: 10-50（按服务实例数动态调整，每个服务默认创建20个连接的连接池）超时: 连接超时5秒，命令超时3秒
服务账号权限
SSH连接池服务redis_sshssh:pool:*的所有Hash操作（HSET/HGET/HDEL/HGETALL）
部署引擎服务redis_deploydeploy:progress:*的所有Hash操作 ws:session:*的所有Hash操作
项目管理服务redis_cachecache:project:*的SET/GET/DELETE/EXPIRE
环境配置服务redis_cachecache:environment:*的SET/GET/DELETE/EXPIRE
审计日志服务redis_cachecache:audit:*的GET（只读缓存）

错误处理

处理策略

Redis操作异常采用熔断+重试机制，连接失败时自动重试3次（间隔指数退避），写入失败时业务层回退到直接查询PostgreSQL。缓存穿透场景由业务层自行处理（空值缓存或布隆过滤器）。当Redis内存达到maxmemory上限时，采用allkeys-lru淘汰策略释放空间。
