概述

密钥存储服务
⚙️ 业务服务
加密存储SSH私钥和密码，提供安全的凭证存取接口。所有敏感数据在写入数据库前使用 AES-256-GCM 加密，对外 API 仅返回元数据，解密能力仅限于内部服务间调用，确保凭证的全生命周期安全。
依赖: PostgreSQL数据库
GoGinPostgreSQL 15

服务接口 (1)

🔧 KeyStorageService 5 方法
StoreKey
(req: CreateKeyRequest) -> (KeyResponse, error)
创建并加密存储一个新的密钥凭证，SSH密钥自动提取公钥计算指纹
前置条件
req.name、req.type、req.value、req.project_id 均非空；req.type 为 KeyType 枚举值之一；同一 project_id 下 name 尚未被占用
后置条件
密钥明文经 AES-256-GCM 加密后写入 deployment_keys 表，返回不含明文的 KeyResponse；若 type 为 ssh_key，自动解析私钥并计算 fingerprint
InvalidArgumentError→ 400必填字段 name/type/value/project_id 为空InvalidKeyTypeError→ 400type 不在 [ssh_key, password] 枚举范围InvalidSSHKeyError→ 400type 为 ssh_key 但 value 不是合法的 PEM 格式 SSH 私钥KeyNameConflictError→ 409同一 project_id 下 name 已存在EncryptionError→ 500AES-256-GCM 加密过程失败（加密密钥未初始化/系统错误）PersistenceError→ 500数据库写入失败（连接异常/约束冲突）
GetKey
(id: string) -> (KeyResponse, error)
根据密钥ID获取单个密钥的元数据信息
前置条件
id 非空且为有效的 UUID 格式
后置条件
返回 key 的完整元数据（不含明文）；id 不存在或已软删除时返回 KeyNotFoundError
InvalidIDError→ 400id 为空或无法解析为 UUIDKeyNotFoundError→ 404指定 id 的密钥不存在或已软删除QueryError→ 500数据库查询异常（超时/连接断开）
ListKeys
(projectId: string, page: int, pageSize: int) -> (KeyListResponse, error)
按项目ID分页查询密钥列表，仅返回未删除的密钥
前置条件
projectId 非空；page >= 1；pageSize 在 1-100 范围内
后置条件
返回指定 projectId 下所有未删除密钥的元数据列表（按 created_at 降序）和总条数；无匹配时 total=0、items 为空数组
InvalidArgumentError→ 400projectId 为空或 page < 1 或 pageSize 超出 1-100 范围QueryError→ 500数据库查询异常
DeleteKey
(id: string) -> (error)
软删除指定的密钥记录，要求密钥未被任何环境引用
前置条件
id 非空且密钥存在且未删除；密钥未被任何环境引用
后置条件
密钥被软删除（deleted_at 设为当前时间）；之后通过 GetKey、ListKeys 或 DecryptValue 均不可见
InvalidIDError→ 400id 为空或无法解析为 UUIDKeyNotFoundError→ 404指定 id 的密钥不存在或已被删除KeyInUseError→ 409密钥正在被环境配置引用（environments.key_id 存在关联记录），无法删除PersistenceError→ 500数据库更新失败
DecryptValue
(id: string) -> (DecryptedValueResponse, error)
内部方法：解密指定密钥的加密值并返回明文，仅限经授权的内部服务调用

后置条件
返回解密后的密钥明文；id 不存在或已软删除时返回 KeyNotFoundError；解密失败时返回 DecryptionError

业务规则

不变量
  • !所有密钥明文在写入数据库前必须经过 AES-256-GCM 加密，数据库中不存储任何明文凭证
  • !同一项目（project_id）下密钥名称（name）必须唯一，避免混淆
  • !SSH 密钥入库时必须自动从私钥中提取公钥并计算 SHA256 指纹，密码类型不计算指纹
  • !对外 API（POST/GET /api/v1/keys）的响应中不得包含密钥明文或加密后的密文字段，仅返回元数据
  • !密钥删除采用软删除（设置 deleted_at），不可物理删除，确保审计追溯能力
  • !数据加密密钥必须从外部注入（环境变量或 KMS），不硬编码在代码或数据库中，应用层仅持有内存中的加密密钥引用
状态机
🎯 DeploymentKey
activedeleted
→调用 DELETE /api/v1/keys/{id} 接口，将 deleted_at 设为当前时间by 用户（通过Web控制台或API）
→不可逆by
🚫 deleted -> active 不可逆，密钥一旦删除不可恢复🚫 active -> deleted 为单向转换，已删除的密钥不再参与任何查询和解密操作
⚡ 密钥创建时由 deployment_keys 表的 (project_id, name) 唯一索引保证同一项目下名称不重复；密钥删除时不涉及并发修改，软删除操作幂等
跨服务规则
环境配置服务和部署编排服务通过 REST API 创建/查询/删除密钥，通过 INTERNAL /internal/api/v1/keys/{id}/decrypt 获取解密凭证用于 SSH 连接，使用完毕后必须立即丢弃明文，不缓存
密钥的创建和删除操作完成后，密钥存储服务必须调用审计日志服务的 INTERNAL 接口记录审计日志，action 分别为 key.add 和 key.delete，detail 中包含密钥名称和类型
环境配置服务在创建或更新环境时录入 key_id 引用，密钥存储服务删除密钥前需查询 environments 表确认无引用关系，引用存在时拒绝删除并返回 409
部署编排服务在执行部署任务前通过 SSH 连接池获取凭证，SSH 连接池调用密钥存储服务的解密接口获取明文凭证，凭证仅用于建立当前会话，会话结束即丢弃

错误处理

处理策略

密钥存储服务采用分层错误处理。参数校验错误直接返回4xx明确提示；加密/解密失败属于不可恢复的内部错误，返回500并记录完整异常堆栈，不泄露任何密钥片段；数据库操作错误捕获后统一转换为结构化错误响应；所有错误响应中不泄露密钥明文或加密密钥的任何片段。
