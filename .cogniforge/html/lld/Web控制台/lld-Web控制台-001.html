概述

Web控制台
🖥️ 前端
单页应用，提供项目管理、环境配置、部署操作和日志查看的图形界面。采用 React + Ant Design 技术栈构建，通过 HTTP 和 WebSocket 与 API 网关通信，实现一键自动化部署流程的完整交互体验。全局状态使用 React Context + useReducer 管理，页面路由基于 React Router v6。
依赖: API网关项目管理服务环境配置服务部署编排服务审计日志服务
ReactAnt DesignWebSocketJWT
🧩

组件树 (1)

App/

应用根组件。初始化全局状态 Provider 和路由配置，执行认证恢复检查。所有子组件包裹在 AuthProvider、ProjectProvider 等 Context 中。

State
initialized: boolean
行为
  • mount 时从 localStorage 读取 JWT token 和用户信息，尝试恢复登录会话
  • 配置 Axios 全局拦截器：请求头注入 Authorization: Bearer token，响应 401 时触发 token 静默刷新
  • 监听 window.online/offline 事件，网络恢复时自动重新校验认证状态
  • 注册 React Router v6 路由表，为受保护路由配置 AuthGuard 守卫
边界情况
  • ⚠️ token 恢复时调用 refresh token 接口发现 refresh token 也已过期，清除全部存储并跳转登录页
  • ⚠️ 网络离线不影响当前页面展示，恢复后自动重试未完成的请求
  • ⚠️ 多个并发请求同时返回 401 时仅触发一次 refresh token 流程
  • ⚠️ refresh token 请求本身返回 401 时不陷入死循环
MainLayout/

主体布局组件。采用 Ant Design Layout 组件实现左右结构，左侧为可收起侧边栏，右侧为顶部导航栏和内容区。内容区由 React Router Outlet 填充。

State

行为

  • 侧边栏收起/展开状态持久化到 localStorage
  • 窗口宽度小于 768px 时自动收起侧边栏
边界情况
  • ⚠️ 浏览器窗口 resize 时动态调整侧边栏状态
  • ⚠️ 窄屏模式下点击菜单项自动收起侧边栏

ProjectListPage/projects

项目列表页面。以 Ant Design Table 展示项目信息，支持分页、搜索、创建和删除操作。是用户登录后的默认页面。

行为

  • ⚠️ 网络请求失败时 Table 显示 error 状态并提供重试按钮
  • ⚠️ 多用户并发操作时，删除可能返回 404，提示「项目已被删除」并刷新列表
ProjectCreateModal/projects

创建项目的弹窗表单。表单包含项目名称（必填）和描述（选填），使用 Ant Design Form + Modal 组件。名称提交前做唯一性校验提示。

  • ⚠️ 弹窗关闭时重置表单到初始状态，不清空已填内容（关闭确认提示）
ProjectDetailPage/projects/:id

项目详情页面。以标签页（Tabs）组织三个功能区：环境管理、部署操作、项目基本信息。路由参数 :id 变化时重新加载数据。

环境管理区块。以表格形式展示当前项目下的部署环境列表。每行展示环境名称、类型、服务器地址和连通状态。提供创建环境和连通性测试操作。

  • ⚠️ 环境数据在多次切换项目时防止数据错乱（使用 AbortController 取消旧请求）

DeployDetailDrawer/projects/:id

部署详情抽屉组件。从页面右侧滑出，展示单个部署任务的完整信息：进度步骤、状态时间线和实时日志。部署进行中时自动刷新状态并建立 WebSocket 连接。

Props
visible: boolean *deploymentId: string *onClose: function *

@onDeploymentComplete({ id: string, status: string })

  • ⚠️ 多次打开关闭抽屉时防止 WebSocket 内存泄漏（每次关闭严格清理）
  • ⚠️ 部署任务 ID 不存在时展示错误状态
  • ⚠️ 页面路由变化时自动关闭抽屉并清理资源
LogViewer/projects/:id

实时日志查看器组件。通过 WebSocket 接收部署过程中的日志消息，按步骤分组并以时间线形式渲染。支持自动滚动、日志分级着色和手动重连。

Props
deploymentId: string *deploymentStatus: string *
Events
@onWsStatusChange({ connected: boolean, error?: string })
State
logs: LogEntry[]wsConnected: booleanreconnectAttempts: numberautoScroll: booleanactiveStep: string | null
行为
  • mount 且 deploymentStatus 为 pending/running 时建立 WebSocket 连接到 WS /api/v1/ws/deployments/:id/logs
  • 接收到 log 类型消息时追加到 logs 数组并自动滚动到底部
  • 接收到 status 类型消息时更新部署状态和当前步骤
  • 接收到 error 类型消息时高亮显示并终止步骤进度
  • 日志按 step 字段分组，每组对应一个部署步骤标题
  • 提供「暂停自动滚动」按钮，用户手动滚动时自动暂停
  • 提供「复制全部日志」按钮，导出纯文本格式
  • 日志级别着色：info 白色、warn 黄色、error 红色
边界情况
  • ⚠️ WebSocket 连接断开自动指数退避重连（1s/2s/4s/8s/16s），最多 5 次
  • ⚠️ 5 次重连失败后展示「连接已断开」状态和手动重连按钮
  • ⚠️ 日志缓冲区超过 1000 条时丢弃最早的 10% 防止内存溢出
  • ⚠️ 部署完成后服务端关闭 WebSocket，前端标记连接已结束，显示部署结果摘要
  • ⚠️ 用户离开页面时主动关闭 WebSocket 连接
  • ⚠️ 快速切换多个部署任务时，仅保持最新任务的 WebSocket 连接
  • ⚠️ 日志消息乱序到达时按时间戳重新排序

项目列表数据缓存到全局 ProjectStore，切换页面时不再重新请求。创建、编辑或删除项目后手动刷新列表。环境列表按项目 ID 缓存在页面级 EnvironmentStore，切换项目时重新请求并覆盖缓存。部署历史按项目 ID 缓存在页面级 DeploymentStore，新部署触发后追加到历史列表头部。WebSocket 日志仅在内存中暂存，关闭部署详情抽屉时清理。token 持久化到 localStorage，其余状态在页面刷新时从 API 重新加载。

交互流程 (6)

用户登录流程

用户在登录页完成身份认证，获取系统访问权限。系统验证凭证后签发 JWT token，前端持久化 token 并进入主界面。

1
用户在 /login 页面输入用户名和密码，点击「登录」按钮
2
前端表单校验：用户名非空、密码非空且不少于 6 位
3
调用 POST /api/v1/auth/login 发送认证请求
4
后端验证凭证成功后返回 access_token、refresh_token 和用户信息
5
AuthStore 存储 token 和用户信息，token 同步写入 localStorage
6
Axios 拦截器默认请求头设置为 Authorization: Bearer <token>
7
前端通过 React Router 跳转到 /projects 项目列表页
8
登录成功后 24 小时内无操作自动触发登出（空闲超时）
项目切换流程

用户在全局范围内切换当前操作的项目。切换后项目详情页、环境列表和部署信息全部更新为选中项目的数据。

1
用户在 GlobalHeader 的 ProjectSelector 下拉列表中点击目标项目
2
ProjectSelector 触发 onChange 事件携带新项目 ID
3
ProjectStore 更新 currentProject 为选中项目
4
React Router 调用 navigate(/projects/:newId) 跳转路由
5
ProjectDetailPage 检测路由参数 id 变化，重新加载项目详情
6
EnvironmentSection 检测 projectId 变化，重新请求环境列表
7
DeploySection 检测 projectId 变化，重新加载部署历史
8
侧边栏和全局Header的当前项目名称同步更新
创建部署环境流程

用户在项目内添加新的部署环境，配置服务器连接信息，关联 SSH 密钥，并进行连通性验证确保环境可用。

1
用户在项目详情页的环境管理标签页点击「添加环境」按钮
2
EnvironmentCreateModal 弹窗打开，加载可用密钥列表
3
用户填写环境名称、选择环境类型（测试/灰度/正式）
4
用户输入目标服务器地址（IP/域名）、SSH 端口（默认 22）、登录用户名
5
用户从密钥下拉选择器中选择关联的 SSH 密钥（可选）
6
点击「提交」按钮，前端校验所有必填字段
7
调用 POST /api/v1/environments 创建环境
8
创建成功后关闭弹窗，环境列表自动刷新
9
用户点击新创建环境行的「连通性测试」按钮
10
ConnectionTestButton 调用 POST /api/v1/environments/:id/verify
11
测试结果显示：绿色「已连通 + 延迟 ms」或红色「不可达 + 错误详情」
一键部署流程

用户选择目标环境和版本号，触发自动化部署。系统返回部署任务 ID，前端自动打开部署详情面板展示进度。

1
用户在项目详情页的部署标签页中选择目标环境（Select 下拉）
2
系统自动校验所选环境的连通状态，不可达时发出警告
3
用户输入部署版本号（如 v1.2.3），可选填可执行文件路径
4

5
后端返回 201 及 deployment_id，status 为 pending
6

7
DeployDetailDrawer 从右侧滑入，展示部署进度面板
8
LogViewer 建立 WebSocket 连接到 WS /api/v1/ws/deployments/:id/logs
9
实时日志逐行追加到日志查看器，按步骤分组展示
10
部署过程中每一步完成后进度步骤自动更新为绿色勾
11
部署成功时所有步骤标记为完成，显示「部署成功」结果
12
部署失败时失败步骤标记为红色叉，显示错误日志摘要
实时日志查看流程

用户通过 WebSocket 连接实时查看部署过程的日志输出。支持自动滚动、日志分级着色和断线重连。

1
部署触发成功后，DeployDetailDrawer 打开并挂载 LogViewer
2

5

8
用户可手动暂停/恢复自动滚动，方便查看历史日志
9
WebSocket 意外断开时自动重连（指数退避），日志区域显示「连接中…」

部署完成后服务端发送完成消息并关闭 WS，LogViewer 显示部署结果摘要
审计日志查询流程

管理员进入审计日志页面，通过多维度筛选条件查询操作记录，追溯系统变更历史。

⚠️

错误处理

处理策略

前端采用统一错误拦截策略。Axios 响应拦截器捕获 HTTP 错误，401 自动跳转登录页，403 显示权限不足提示，500 系列显示服务异常提示并允许重试。WebSocket 连接断开时自动重连（指数退避，最多 5 次），连接彻底失败时显示离线提示并提供手动重连按钮。表单校验错误由 Ant Design Form 组件就地展示。网络离线时显示全局断网横幅，恢复后自动隐藏。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring

认证失败
token 过期或无效时，Axios 拦截器自动调用 refresh token 接口续期；续期失败则清除 token 并跳转登录页
403
权限不足
页面级权限在路由守卫中判断，接口级权限错误统一展示 Ant Design 的 Result 组件并说明所需角色

资源不存在
项目/环境/部署任务不存在时，展示对应空状态和返回按钮，不清除页面 URL
