概述

模块: MySQL

关系型数据库 MySQL 是系统数据持久化的核心存储层，使用 InnoDB 引擎保证事务 ACID 特性。负责持久化存储项目元数据、环境配置及加密密钥、部署历史记录、用户账号信息等结构化数据，为上层服务（项目管理服务、环境管理服务、部署编排服务、SSH执行代理）提供一致性和事务性数据访问能力。所有表统一使用 utf8mb4 字符集，主键采用 BIGINT 自增 ID，公共时间字段标准化为 created_at / updated_at / deleted_at。逻辑删除（deleted_at 软删除）作为默认删除策略，避免级联数据丢失。

UserDAL

DAL::User::

用户数据访问接口，提供用户账号的 CRUD 及鉴权查询。所有用户相关的 SQL 操作统一封装在此接口下。

参数类型描述
InsertSQLINSERT INTO users (...) VALUES (...) — 创建新用户，校验邮箱和用户名唯一性

错误处理

MySQL 层错误处理策略： 1. 连接异常：数据库连接超时或丢失时，上层调用方应重试最多 3 次，间隔指数退避（100ms/200ms/400ms）。重试耗尽后返回 500 DB_CONNECTION_ERROR。 2. 唯一键冲突：INSERT 或 UPDATE 触发重复唯一键时，MySQL 返回 1062 错误码。DAL 层捕获后转换为应用层的 DUPLICATE_* 错误码（如 DUPLICATE_PROJECT_NAME、DUPLICATE_EMAIL）。 3. 外键约束失败：插入/更新外键字段引用不存在的主键时，MySQL 返回 1452 错误码。DAL 层捕获后返回 400 REFERENCE_NOT_FOUND。 4. 死锁检测：InnoDB 自动检测死锁并回滚其中一笔事务。死锁发生时上层应重试事务最多 3 次。死锁错误码 1213。 5. 超时控制：所有查询设置 innodb_lock_wait_timeout = 5s。锁等待超时（错误码 1205）时立即回滚，不重试。 6. 事务隔离：所有写操作在事务中执行，隔离级别 READ COMMITTED。单次 DAL 调用为隐式事务，跨表操作在应用层使用显式事务（BEGIN/COMMIT/ROLLBACK），使用 defer 模式确保事务最终提交或回滚。 7. 索引优化：高频查询字段（project_id、environment_id、deployment_id、email）必须建索引；联合索引按最左前缀原则设计，覆盖高频查询场景。 8. 连接池配置：最大连接数 100，最小空闲连接 10，连接最大存活时间 30 分钟，避免长时间空闲连接被 MySQL 服务端断开。 9. 慢查询监控：执行时间超过 1s 的查询记录到慢查询日志，并发送告警至运维。SQL 必须使用索引扫描，全表扫描超过 1000 行的 SQL 需 DBA 审核。 10. 数据归档：deployment_logs 保留 30 天、audit_logs 保留 90 天，过期数据由定时任务物理删除，避免单表数据膨胀导致性能下降。
