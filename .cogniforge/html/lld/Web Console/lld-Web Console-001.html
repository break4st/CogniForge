概述

Web Console
🖥️ 前端
基于 React 18 + Ant Design 5 的单页应用，提供远程自动化部署系统的用户操作界面。通过 API Gateway 与后端微服务通信，覆盖项目管理、环境配置与 SSH 密钥绑定、一键部署与进度可视化、部署历史与审计日志查询等核心功能。
依赖: API Gateway
React 18Ant Design 5
🧩

组件树 (1)

App/

根组件，注入全局 Store 和路由配置，执行认证检查和路由守卫

行为
  • mount 时检查 localStorage 中是否存在 Token，存在则调用 POST /api/v1/auth/verify 验证会话有效性
  • 根据认证状态动态加载对应的路由表（已认证加载 MainLayout，未认证加载 LoginPage）
边界情况
  • ⚠️ Token 过期时自动清理 localStorage 并跳转登录页
  • ⚠️ API Gateway 不可达时展示白屏fallback提示
LoginPage/login

用户登录页面，提供用户名密码表单进行身份认证

Events
@onLoginSuccess({ token: string, user: UserInfo })
State
loading: booleanerror: string | null
行为
  • 用户提交表单时调用 POST /api/v1/auth/login 进行认证

  • 认证失败时展示错误提示信息

  • ⚠️ 已登录用户访问 /login 时自动跳转到 /projects
  • ⚠️ 浏览器禁用了 localStorage 时提示用户开启

环境详情页面，支持编辑环境参数、导入 SSH 密钥和测试 SSH 连接

DeployStatusPage/deployments/:deployId

部署进度实时可视化页面，包含进度条、步骤状态列表和实时日志

State
status: DeploymentStatus | nullloading: booleanpollingActive: booleanlogExpanded: boolean
行为
  • mount 时调用 GET /api/v1/deployments/{deployId}/status 获取初始状态
  • 如果状态为 pending 或 running，启动定时轮询（每 3 秒一次）
  • 每次轮询更新：进度条百分比、当前步骤高亮状态、步骤列表、日志行追加
  • 状态变为 success 或 failed 时停止轮询
  • 提供「展开完整日志」按钮和「返回部署历史」链接
边界情况
  • ⚠️ 部署 ID 不存在时展示 404 页面
  • ⚠️ 浏览器标签页不可见时（Page Visibility API）暂停轮询以减少请求，切回时恢复
  • ⚠️ 轮询连续失败 3 次时停止轮询并提示「状态获取异常，请手动刷新页面」
  • ⚠️ 部署执行超过 30 分钟时在页面顶部展示提示横幅

状态设计

全局状态
AuthStore
全局认证状态，管理用户 Token、当前用户信息和权限列表。Token 持久化到 localStorage，页面刷新后通过 API 验证有效性。
AuthStore
App LoginPage MainLayout
ProjectStore
项目列表全局状态，缓存项目数据减少重复请求。页面切换时不重新加载，仅在 CRUD 操作后刷新。
ProjectStore
MainLayout ProjectListPage ProjectDetailPage DeployPage
缓存策略

项目列表缓存至 ProjectStore，页面间切换不重复请求，创建/编辑/删除操作后重新加载。AuthStore 的 Token 持久化至 localStorage，页面刷新后调用 POST /api/v1/auth/verify 验证。部署状态轮询数据仅在 DeployStatusPage 页面级状态中维护，离开页面时销毁。环境列表和审计日志数据不全局缓存，每次进入页面重新请求。

交互流程 (5)

项目管理流程

用户在 Web Console 中创建和管理项目的完整操作流程

1
用户登录后进入 /projects 项目列表页
2
点击「新建项目」按钮，在弹出的表单 Modal 中填写项目名称和描述
3
提交表单后调用 POST /api/v1/projects，创建成功后列表自动刷新
4
点击已有项目行进入项目详情页 /projects/:id
5
在详情页可点击编辑按钮修改项目信息（PUT /api/v1/projects/{id}）或删除项目（DELETE /api/v1/projects/{id}）
环境配置与连接测试流程

用户为项目配置部署环境、导入 SSH 密钥并测试连接可用性的完整流程

1
进入项目详情页后点击「环境管理」进入 /projects/:id/environments
2
点击「新建环境」填写表单：环境名称、服务器地址、SSH 端口（默认 22）、登录用户名
3
提交表单后调用 POST /api/v1/environments，创建成功后在列表中选择该环境
4
进入环境详情页 /projects/:id/environments/:envId
5
点击「导入 SSH 密钥」弹窗，粘贴私钥内容或选择文件上传，提交后调用 POST /api/v1/environments/{envId}/import-key
6
点击「测试连接」按钮调用 POST /api/v1/environments/{envId}/test-connection
7
等待测试结果返回（loading 状态），展示成功/失败状态和延迟 latency_ms
一键部署流程

用户选择环境和部署文件执行一键部署，并实时查看部署进度的完整流程

1
进入项目详情页后点击「一键部署」进入 /projects/:id/deploy
2
从下拉框选择目标部署环境（展示所有可用环境列表）
3
填写部署文件路径（远程服务器上可执行文件的绝对路径）
4
填写版本标识（如 v1.2.3）
5
点击「立即部署」按钮，前端校验必填字段
6
调用 POST /api/v1/projects/{id}/deploy 提交部署请求
7
提交成功后自动跳转到 /deployments/{deployment_id} 进度页面
8
页面自动轮询 GET /api/v1/deployments/{deployId}/status（每 3 秒），展示进度条和步骤状态
9
日志面板实时滚动追加输出日志行
10
部署完成（success/failed）时停止轮询，展示最终结果和操作建议
部署历史查看流程

用户查看指定项目的所有历史部署记录并浏览详细日志

1
进入项目详情页后点击「部署历史」进入 /projects/:id/deployments
2
页面以表格形式展示所有历史部署记录（版本号、目标环境、状态、触发时间、持续时间）
3
用户可翻页浏览更多历史记录
4
点击某条部署记录行跳转到 /deployments/{deploymentId} 查看详细步骤和日志
审计日志查询流程

管理员用户查询和导出系统操作审计日志

1
管理员从侧边栏导航点击「审计日志」进入 /audit-logs
2
页面默认展示最近 24 小时的操作审计日志
3
通过筛选面板选择操作类型（action）、资源类型（resource_type）、时间范围
4
筛选条件变更后自动重新请求数据
5
点击「导出 CSV」按钮触发下载，浏览器下载审计日志文件

处理策略

前端采用统一错误处理机制：API 请求错误通过 Ant Design message 组件展示通知；网络异常展示友好提示带重试按钮；路由鉴权失败自动重定向到登录页；表单校验由 Ant Design Form 统一处理并展示字段级别错误。
