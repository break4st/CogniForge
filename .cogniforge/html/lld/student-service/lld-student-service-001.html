概述

模块: student-service

学生服务负责学生基本信息的增删改查管理。作为系统的核心基础服务，它为其他模块（班级服务、学习统计服务）提供学生数据支撑。服务采用 RESTful API 设计，数据存储使用关系型数据库，提供标准的 CRUD 接口及按条件检索能力。

🗄️

接口定义 (9)

CreateStudent

POST /api/v1/students

创建新学生档案

GetStudent

GET /api/v1/students/{id}

根据ID查询学生详情

UpdateStudent

PUT /api/v1/students/{id}

更新学生基本信息

DeleteStudent

DELETE /api/v1/students/{id}

删除学生记录（逻辑删除：将状态标记为退学）

SearchStudents

GET /api/v1/students

分页条件查询学生列表

BatchGetStudents

POST /api/v1/students/batch

批量查询学生信息（供内部服务调用）

CreateContact

POST /api/v1/students/{student_id}/contacts

添加学生联系人

ListContacts

GET /api/v1/students/{student_id}/contacts

查询学生联系人列表

UpdateStudentStatus

PATCH /api/v1/students/{id}/status

更新学生状态（在读/休学/毕业/退学）

错误处理

统一错误响应格式，使用 HTTP 状态码标识错误类型。所有错误响应遵循标准 JSON 结构：{"code": "错误码", "message": "错误描述", "details": {}}。服务内部异常会被全局异常处理器捕获并转换为友好错误信息。 错误码定义： - STUDENT_NOT_FOUND (404)：学生记录不存在，按ID查询/更新/删除不存在的学生时触发 - STUDENT_NO_DUPLICATE (409)：学号已存在，创建学生时学号与现有记录冲突时触发 - INVALID_STUDENT_STATUS (400)：非法的学生状态值，传入的状态值不在允许范围内时触发 - STUDENT_HAS_ACTIVE_CLASS (409)：学生有未结束的班级关联无法删除，删除仍在班级中的学生时触发 - INVALID_PARAMETER (400)：请求参数校验失败，必填字段缺失或格式错误时触发 - INTERNAL_ERROR (500)：服务器内部错误，数据库异常或其他未预期错误时触发
