概述

DeployUI
🖥️ 前端
部署入口的模态框组件，作为环境管理页面的一部分，为用户提供文件选择/拖拽、部署触发及实时进度展示功能。
依赖: DeploymentService
React 18Ant Design
基于: PRD prd-current v1 · SAD sad-001 v1
📐 模块边界
范围内: 部署模态框的显示与关闭控制 文件选择/拖拽交互 部署 API 调用(上传文件并获取 deploy_id) WebSocket 连接建立与进度消息解析 进度步骤的界面渲染 错误信息的格式化与高亮显示 部署过程中的用户操作(取消、重试等)
范围外: 环境管理页面的其他功能(如环境配置、监控) 部署任务的真实执行逻辑(由 DeploymentService 处理) 部署历史记录的管理 项目管理、密钥管理等功能
拥有组件: CMP-012
消费契约: CTR-009

组件树 (1)

DeployModal环境详情页内嵌模态框

模态框外壳,管理部署生命周期状态,协调子组件通信

Props
visible: boolean *environmentId: number *onClose: function *
Events
@onDeploySuccess({ deploy_id: number })@onDeployError(ErrorInfo)
State
phase: stringfile: File / nullprogress: DeployProgress / nullerror: ErrorInfo / nullws: WebSocket / null
行为
  • 打开模态框后焦点自动落于文件上传区域
  • 用户点击「开始部署」:校验文件,发起 POST 请求上传,phase 变为 uploading
  • 上传成功返回 deploy_id 后,建立 WebSocket 连接,phase 变为 deploying
  • 收到 WebSocket 消息更新 progress,直至 status 变为 completed 或 failed,对应 phase 切换
  • 部署完成后 3 秒自动关闭模态框,并回调 onClose / onDeploySuccess
  • 任何环节出错设置 error 并切换 phase 到 failed
边界情况
  • ⚠️ 文件大小超过前端限制(100MB):提示「文件过大,请压缩后重试」,阻止提交
  • ⚠️ 部署过程中用户强行关闭模态框:弹出确认对话框,确认后断开 WebSocket 并重置状态
  • ⚠️ 短时间内重复打开模态框:重置内部状态,允许重新部署
  • ⚠️ WebSocket 断线重连失败后,保留最后进度,并显示「连接已中断,部署可能仍在后台执行」
FileUploaderDeployModal 的子组件

提供文件拖放和点击选择功能,并反馈选中文件名

Props

@onDragEnter(none)@onDragLeave(none)

  • ⚠️ 拖拽区域与模态框滚动/点击无冲突(阻止事件冒泡)
ProgressDisplayDeployModal 的子组件

以步骤条形式展示部署进度,实时反映当前状态

Props
progress: DeployProgress *phase: string *
行为
  • 使用 Ant Design Steps 组件渲染步骤列表,current_step 控制当前激活步骤
  • 每个步骤展示名称(如「校验环境」「上传文件」「执行部署」「更新版本」)和状态(wait/process/finish/error)
  • 当 phase 为 failed 且 progress.error 存在时,对应步骤标记为错误,并在步骤下显示错误详情
  • progress.message 实时显示在步骤条下方区域
边界情况
  • ⚠️ 如果 WebSocket 推送的步骤数量与前端预设步骤数不一致,以推送为准并动态调整步骤条
  • ⚠️ 部署已完成但 progress.status 未及时更新,保持最后状态,不重复标记
ErrorDisplayDeployModal 的子组件

当部署过程中出现错误时,高亮显示错误信息,并允许关闭或重试

Props
error: ErrorInfo / null *onRetry: functiononClose: function
行为
  • 当 error 不为 null 时,以 Ant Design Alert 或 Result 呈现,包含错误码、详情,并提供关闭按钮
  • 如果错误可重试(如网络错误),提供「重试」按钮调用 onRetry
  • 错误消失后,父组件需重置相关状态
边界情况
  • ⚠️ 连续出现多个错误:只显示最近一个,旧的自动清除
  • ⚠️ 用户主动关闭错误后,允许其手动重新部署,不清除文件选择

交互流程 (3)

上传并部署文件

用户触发部署的主要流程

1
步骤1: 用户在环境详情页点击「部署」按钮,调用父组件方法显示 DeployModal
2
步骤2: 模态框展示 FileUploader,用户将 .zip 文件拖入区域或点击选择
3
步骤3: 文件验证后,下方显示文件名,用户点击「开始部署」
4
步骤4: 前端通过 POST /api/environments/{environment_id}/deploy 发送文件,请求头 Content-Type: multipart/form-data
5
步骤5: 接口响应 202,返回 {deploy_id: xxx, status: processing}
6
步骤6: 立即建立 WebSocket 连接至 /ws/deploy/{deploy_id},并切换到 ProgressDisplay 视图
7
步骤7: WebSocket 逐条推送进度消息,格式预期为 {current_step, total_steps, message, status},客户端更新步骤条
8
步骤8: 最终推送 status: completed,模态框提示部署成功,3 秒后自动关闭,环境详情页刷新数据
9
步骤9: 若推送 status: failed 并携带 error,ErrorDisplay 高亮错误,部署流程终止
上传失败

部署文件上传阶段发生错误

1
步骤1: POST 请求返回 4xx(如 400 DISK_SPACE_LOW)
2
步骤2: 前端解析错误体,ErrorDisplay 展示「磁盘空间不足」,阻止后续步骤
3
步骤3: 用户可关闭错误提示,重新选择文件或关闭模态框
WebSocket 中断

部署过程中 WebSocket 连接意外断开

1
步骤1: 部署过程中 WebSocket 连接意外断开
2
步骤2: 前端尝试自动重连(最多 3 次),期间保留当前进度显示
3
步骤3: 重连成功则继续接收消息;失败则显示「实时进度连接丢失」,但不影响后台实际部署,用户可稍后手动查看结果

错误处理

处理策略

所有 API 错误按后端约定格式 {code: integer, error: "string", detail: "string"} 解析,并映射为用户可读的中文提示。WebSocket 异常采用重连加降级提示的方式,部署关键错误直接阻断流程并高亮显示。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
4xx
客户端错误
如文件类型错误、磁盘空间不足等,在模态框内展示具体错误信息,禁止继续部署
5xx
服务端错误
提示「服务器繁忙,请稍后重试」,保留重试入口
WebSocket
WebSocket 连接错误
连接断开自动重试 3 次(间隔 2 秒),仍失败则提示连接异常,停止进度动画,允许用户手动刷新状态
