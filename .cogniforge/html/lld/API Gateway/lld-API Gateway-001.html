概述

模块: API Gateway

基于 Node.js/Express 的统一 API 网关层，部署于 Nginx 之后、业务服务之前。采用中间件链模式处理请求：全局中间件（CORS、请求日志、鉴权）→ 路由级中间件（参数校验）→ 业务模块路由分发。路由规则按 URL 前缀将请求转发至对应的内部业务 Service（Student/Class/Grade/Statistics）。认证模块基于 JWT，在网关层统一完成 token 签发、校验和续期，下层业务服务不再感知用户身份细节。限流采用令牌桶算法，按 IP 和用户维度分别限制。所有请求的出入时间、状态码和响应时长记录为审计日志。

接口定义 (9)

用户登录

POST /api/auth/login

用户身份认证，验证用户名密码后签发 JWT Token

用户登出

POST /api/auth/logout

将当前 Token 加入黑名单使其失效

Token 验证

GET /api/auth/verify

验证当前 Token 是否有效，返回用户身份信息

Token 续期

POST /api/auth/refresh

为未过期的 Token 签发新 Token，延长有效期

健康检查

GET /api/health

网关及各下游服务的存活检测，返回各服务状态

路由: 学生管理

前缀 /api/students/* → StudentService

学生相关请求路由至 StudentService，包括 CRUD 和搜索

路由: 班级管理

前缀 /api/classes/* → ClassService

班级相关请求路由至 ClassService，包括成员管理

路由: 年级管理

前缀 /api/grades/* → GradeService

年级相关请求路由至 GradeService，包括班级归属

路由: 学习统计

前缀 /api/statistics/* → StatisticsService

统计相关请求路由至 StatisticsService，包括各类汇总

⚠️

错误处理

全局统一在 ErrorHandlerMiddleware 捕获异常并返回标准 JSON 格式：{ code: number, message: string, details?: any }。4xx 错误直接返回后端校验提示（如用户名密码错误、Token 过期、参数不合法、请求频率过高），5xx 错误返回 '系统内部错误' 并记录完整错误栈到审计日志。认证失败细分：Token 缺失 → 401, Token 过期 → 401(带 'token_expired' 标识), Token 无效 → 401, 权限不足 → 403。限流触发时返回 429 并在 Response header 中附带 X-RateLimit-Remaining（剩余配额）和 X-RateLimit-Reset（重置时间）。对于下游业务服务返回的错误码（如 StudentService 的 404），网关透传不修改。请求超时默认设为 30s，超时返回 504。
