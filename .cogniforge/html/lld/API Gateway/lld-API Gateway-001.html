概述

API Gateway
🔀 网关层
系统的统一入口网关，基于 FastAPI 构建，负责请求路由转发、JWT 身份认证、API 限流与防滥用、跨域策略管理以及请求响应日志记录。前端 Web Console 的所有请求均通过 API Gateway 进行鉴权和路由，网关将请求转发至对应的领域微服务并将响应返回前端。网关层不处理业务逻辑，仅承担边缘服务职责。
依赖: Project Management ServiceEnvironment Management ServiceDeployment OrchestratorAudit ServiceKey Management ServiceRedis
Python 3.11+FastAPIRedis 7OpenAPI 3.0 (自动生成)Docker + Docker Compose

认证授权

公开端点: /api/v1/auth/login /api/v1/health
认证方式: JWT Bearer Token，令牌携带在 Authorization 请求头中，格式为 Bearer {access_token}。网关在 AuthMiddleware 中解析并校验 JWT 签名和过期时间，校验通过后将 user_id 和 role 注入请求上下文供下游中间件和路由使用。
Token 策略: access_token 有效期为 2 小时，refresh_token 有效期为 7 天。access_token 过期后前端应使用 refresh_token 调用 POST /api/v1/auth/refresh 获取新的令牌对。refresh_token 过期后用户需重新登录。

错误处理

处理策略

网关采用统一的错误处理机制：所有异常在网关层被捕获并转换为标准错误响应格式后返回前端。请求转发至上游服务时，网关透传上游返回的错误码和信息。上游服务不可达（连接超时或拒绝连接）时，网关统一返回 502 Bad Gateway 或 504 Gateway Timeout。限流触发时返回 429 Too Many Requests。参数校验由 FastAPI 的 Pydantic 模型自动完成，校验失败返回 422。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
请求参数错误
请求体或查询参数格式不正确，网关直接拒绝不转发上游

未认证
JWT 令牌缺失、过期或无效，前端应重定向至登录页
