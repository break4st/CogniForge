概述

部署编排服务
核心部署引擎，负责编排整个部署流程：文件上传、版本目录创建、脚本生成、状态跟踪。接收部署请求并创建部署任务，异步驱动状态机流转：pending → running → success/failed。通过消息队列向SSH执行服务派发远程操作任务，使用WebSocket向Web控制台实时推送部署进度。
依赖: 关系型数据库消息队列文件存储
Java 17Spring Boot 3.x + Spring CloudMySQL 8.0RabbitMQ 3.xMinIO / 本地文件系统

数据模型 (3)

🔗 deployment_tasks引用

部署任务主表，记录每次一键部署任务的完整信息。每条记录代表一次从触发到完成的部署任务，通过 project_id 和 environment_id 关联项目和部署环境，通过 status 字段驱动状态机切换。本服务关心以下字段：

字段
字段名类型描述
id *bigint部署任务唯一标识，自增主键
project_id *bigint所属项目ID，外键关联 projects 表
environment_id *bigint目标部署环境ID，外键关联 environments 表
file_url *varchar(1024)部署包文件存储URL，指向文件存储服务中的可执行文件
versionvarchar(50)部署版本号，用户传入或服务端自动生成（格式：yyyyMMdd-HHmmss），用于创建版本化部署目录
status *varchar(20)部署状态：pending（待执行）/ running（执行中）/ success（部署成功）/ failed（部署失败）/ rolled_back（已回滚），默认 pending
progress *int部署进度百分比，取值范围 0-100，默认 0
created_by *bigint部署触发者用户ID
created_at *datetime创建时间
updated_at *datetime最后更新时间

🔗 deployment_logs引用

↳ 引用自: lld-Primary Database-001 / deployment_logs

部署任务日志表，记录每次部署过程中产生的日志信息。每条日志通过 deployment_id 关联到对应的部署任务，按创建时间排序用于前端实时展示和部署历史回溯。本服务关心以下字段：

字段
字段名类型描述

deployment_id *bigint关联部署任务ID，外键关联 deployment_tasks 表
level *varchar(10)日志级别：INFO / WARN / ERROR
message *text日志消息内容
created_at *datetime日志记录时间
配置定义 1

⚙️ DeploymentStateMachine自有

部署任务状态机配置，定义部署任务的合法状态流转路径。基于 Spring State Machine 实现，提供并发控制防止同一环境重复触发部署。

字段
字段名类型描述
states *Array<string>部署状态集合：[pending, running, success, failed, rolled_back]
initial_state *string初始状态：pending
transitions *Array<object>状态流转定义：[{from: pending, on: START, to: running}, {from: running, on: COMPLETE, to: success}, {from: running, on: FAIL, to: failed}]
concurrent_lock_ttl *integer部署任务并发锁 TTL（秒），防止同一环境重复触发，默认30秒

接口定义 (4)

POST/api/deployments触发一键部署
触发一次自动化部署任务。接收前端传入的项目ID、环境ID、部署包URL和可选版本号，校验参数完整性（project_id、environment_id、file_url 为必填），校验项目和环境的有效性，自动生成版本号（如未提供），创建部署任务记录（状态：pending），通过消息队列向SSH执行服务派发远程部署任务，并通过WebSocket向前端推送部署进度。

INTERNALAMQP exchange: deploy.task.direct, routing key: deploy.task.execute部署任务分发
部署编排服务向消息队列发送SSH执行任务消息，由SSH执行服务消费处理。消息内容包含目标服务器连接信息和部署包信息。发送前从密钥管理服务内部接口获取解密后的SSH私钥，组装完整的任务消息后发布到AMQP exchange。SSH执行服务消费消息后创建远程部署目录、上传文件、生成启动/停止脚本并执行。

错误处理

处理策略

部署编排服务采用统一异常处理机制，通过 Spring @ControllerAdvice 全局拦截业务异常和系统异常。参数校验异常（必填项缺失）返回400；资源不存在（项目、环境、部署任务未找到）返回404；并发冲突（同一环境已有正在执行的部署任务）返回409；RabbitMQ 消息发送异常和未预期系统异常返回500，detail 在生产环境脱敏。所有异常统一封装为标准 JSON 响应格式。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
请求参数错误
参数校验失败。包括触发部署时 project_id/environment_id/file_url 为必填项缺失、分页参数 page/size 不是合法正整数等。服务层在校验入口处立即抛出 IllegalArgumentException，由全局异常处理器捕获后封装返回。
404
资源不存在
请求的目标资源不存在。包括：按ID查询的部署任务不存在、触发部署时指定的 project_id 对应的项目不存在、或 environment_id 对应的部署环境不存在。抛出 ResourceNotFoundException。
409
部署并发冲突
同一部署环境已有正在执行的部署任务（status = running），无法创建新的部署任务。部署编排服务需等待当前任务完成或超时后才能触发新的部署。抛出 BusinessConflictException，detail 中附带当前执行中的 deployment_id。
500
服务器内部错误
未预期的运行时异常（数据库连接失败、SQL执行异常、RabbitMQ 消息发送异常等）。全局异常处理器捕获 Exception 后统一返回500，error字段为 InternalServerError，detail 字段在生产环境统一返回「服务器内部错误，请稍后重试」，避免泄露内部堆栈信息。
