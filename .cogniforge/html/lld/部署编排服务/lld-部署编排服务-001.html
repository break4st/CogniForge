概述

模块: 部署编排服务
部署编排服务是CogniForge一键部署流程的核心调度模块，负责接收部署触发请求并编排完整的部署流程：创建版本化部署目录、通过SSH执行服务在远程服务器创建目录结构、通过文件传输接口上传可执行文件、生成执行脚本、执行部署脚本，同时跟踪部署进度并通过WebSocket实时推送状态到前端。支持部署历史查询和版本回滚。
依赖: 关系型数据库（MySQL）SSH执行服务文件存储
Java 17Spring Boot 3Spring Data JPAMySQL 8WebSocket (STOMP)REST (JSON)

progress *int整体部署进度百分比，0-100，默认0

project_idint所属项目ID
environment_idint目标环境ID

file_urlstring可执行文件存储地址URL
deploy_scriptstring部署脚本内容（Shell脚本）
Response 202

⚠️

错误处理

部署编排服务采用分层错误处理策略：1）参数校验层——部署触发接口对project_id、environment_id、version、file_url、deploy_script五个必填字段进行非空校验，校验失败返回400 Bad Request并指明具体问题字段；2）部署流程编排层——部署任务创建后异步执行编排流程，任一子步骤失败（如远程目录创建失败、文件上传失败、脚本执行返回非零退出码）则标记整体部署状态为failed并记录失败步骤和错误日志，不阻塞后续清理流程；编排流程遇到SSH执行服务调用失败（网络超时、连接拒绝）时标记对应步骤为failed并终止后续步骤，返回错误日志说明下游服务异常信息；3）跨服务调用层——对SSH执行服务的远程执行接口（POST /api/ssh/execute）和文件传输接口（POST /api/ssh/upload）设置30秒超时，超时或连接失败则捕获异常并将部署状态标记为failed，同时记录完整错误日志到deployment_log表供排查；4）数据库层——deployment表通过project_id和environment_id建立外键索引保障数据完整性，deployment_step和deployment_log通过deployment_id建立外键索引并设置级联删除，当部署记录被删除时关联的步骤和日志自动清除；5）WebSocket推送层——WebSocket连接中断时服务端记录断连日志，前端可重新建立连接后通过部署状态查询接口（GET /api/deployments/{id}/status）获取断连期间的状态变更和日志补齐，确保前端状态不丢失；6）全局异常处理——所有未捕获异常统一返回500 Internal Server Error，服务端记录完整错误堆栈。所有错误响应统一采用格式：{"error": {"code": "string错误码", "message": "string错误描述"}}。
