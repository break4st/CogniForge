概述

模块: 部署编排服务

部署编排服务作为自动化部署系统的调度中枢，负责编排完整的部署生命周期。接收来自 API网关 转发的部署请求后，调用项目管理服务的 ValidateProjectExistence 校验项目存在性，从环境管理服务获取目标环境的服务器连接参数与解密后的SSH凭证，在 MySQL 创建部署记录（初始状态 pending），组装完整部署任务包发送至消息队列 deployment.tasks 主题，由 SSH执行代理 异步消费执行。部署过程中持续消费 SSH执行代理 回写至 deployment.logs 主题的日志行与状态变更消息：日志行写入 deployment_logs 表同时通过 WebSocket 实时推送至前端，状态变更同步更新 deployments 表 status/started_at/finished_at 字段。同时提供 REST 接口 GetDeploymentLogs 支持轮询拉取历史日志（配合 offset 偏移量实现增量获取），用于 WebSocket 断线后的日志恢复。使用 Redis 缓存活跃部署的 WebSocket 会话映射，支持服务重启后的会话恢复。版本号命名规则强制约束为 ^[a-zA-Z0-9._-]+$，确保远程服务器创建目录时的兼容性。

接口定义 (5)

TriggerDeployment

POST /api/projects/{projectId}/deployments

触发一键部署，异步执行。请求处理流程：1) 校验 projectId 对应的项目存在（调用项目管理服务 ValidateProjectExistence）；2) 校验 environment_id 对应环境存在且已配置SSH密钥（调用环境管理服务 GetEnvironment + GetSSHKeyInfo）；3) 校验 version 格式符合 ^[a-zA-Z0-9._-]+$；4) 从环境管理服务获取解密后的SSH私钥；5) 在 deployments 表创建记录（status=pending）；6) 组装 DeploymentTaskMessage 发送至消息队列 deployment.tasks 主题；7) 返回202及部署记录ID。全部同步校验通过后才写入数据库和发送MQ，任一校验失败均不创建记录。

Response: {deployment_id: {'type': 'integer', 'description': '部署记录ID'}, status: {'type': 'string', 'description': '初始状态，pending'}, created_at: {'type': 'datetime', 'description': '创建时间'}}

参数类型描述
path:projectIdinteger项目ID，路径参数
body:environment_idinteger目标环境ID，必填，须存在且 has_ssh_key=true
body:artifact_pathstring可执行文件路径，必填，长度 1-1024
body:versionstring版本号，必填，须匹配正则 ^[a-zA-Z0-9._-]+$，长度 1-255，用于远程服务器创建版本文件夹

GetDeploymentLogs

GET /api/projects/{projectId}/deployments/{depId}/logs

拉取部署过程的实时日志（配合WebSocket实现实时推送）。根据 offset 参数从 deployment_logs 表查询 sequence >= offset 的日志行，按 sequence 升序返回。每次最多返回100行（避免单次响应过大），客户端可通过 next_offset 连续轮询直至 finished=true。WebSocket 断线重连场景：客户端记录最后收到的 sequence，重连后调用本接口传入该 sequence 作为 offset 即可补齐缺失日志。部署未结束时 finished=false，客户端应继续轮询或等待 WebSocket 推送。

Response: {logs: {'type': 'array', 'item_type': 'string', 'description': '日志行列表，每行字符串格式：[时间戳] [级别] 消息内容'}, next_offset: {'type': 'integer', 'description': '下一次请求的偏移量，等于当前 offset + 返回行数'}, finished: {'type': 'boolean', 'description': '部署是否已结束，true 表示 status 已变为 success 或 failure'}}

参数类型描述
path:projectIdinteger项目ID，路径参数
path:depIdinteger部署记录ID，路径参数
query:offsetinteger日志偏移量，从0开始，默认0，表示从第几条日志开始拉取

DeploymentLogWebSocket

WS /ws/projects/{projectId}/deployments/{depId}/logs

WebSocket 实时日志推送端点。前端通过原生 WebSocket 客户端建立持久连接，服务端持续推送部署过程中的日志行及状态变更。推送的 JSON 消息结构见 data_models 中的 WebSocketLogMessage 定义。连接生命周期：建立时服务端将连接注册至 Redis（key=deployment:ws:{depId}），推送期间按日志产生顺序逐条发送，部署完成（status=success/failure）后推送 final 类型消息并主动关闭连接。服务重启时 Redis 中的连接映射失效，前端应监听 onclose 事件并在重连后调用 GetDeploymentLogs 补齐缺失数据。

参数类型描述
path:projectIdinteger项目ID，路径参数
path:depIdinteger部署记录ID，路径参数

HandleDeploymentLogMessage

INTERNAL (MQ consumer)

内部消费者，订阅消息队列 deployment.logs 主题。消费 SSH执行代理 回写的 DeploymentLogMessage。处理逻辑：type=log 时写入 deployment_logs 表 → 从 Redis 读取 depId 对应的 WebSocket 连接 → 构造 WebSocketLogMessage 推送至前端；type=status_change 时更新 deployments 表 status 字段（running 时设 started_at，success/failure 时设 finished_at）→ 推送 status/final 类型 WebSocket 消息 → status=failure 时写入 error_message。消息处理失败时进入死信队列，最多重试3次。

参数类型描述
message:typestring消息类型，log 或 status_change
message:deployment_idinteger部署记录ID
message:sequenceinteger日志行序号（type=log 时有效）
message:log_linestring日志行内容（type=log 时有效）
message:levelstring日志级别（type=log 时有效）
message:statusstring部署状态（type=status_change 时有效）
message:error_messagestring错误信息（type=status_change 且 status=failure 时有效）
message:timestampstring消息产生时间

SendDeploymentTask

INTERNAL (MQ producer)

内部生产者，由 TriggerDeployment 流程触发。在部署记录创建成功后，将完整任务包发送至消息队列 deployment.tasks 主题。任务包结构见 data_models 中的 DeploymentTaskMessage 定义。发送时设置消息持久化标志和 TTL（24小时），确保消息不会丢失也不会被过期丢弃。发送失败时回滚部署记录（标记为 failure 并记录错误信息），返回502给前端。

参数类型描述
message:task_idstring任务唯一标识，UUID v4
message:deployment_idinteger部署记录ID
message:project_idinteger项目ID
message:server_hoststring远程服务器地址
message:server_portintegerSSH端口
message:usernamestringSSH登录用户名
message:ssh_private_keystring解密后的SSH私钥内容
message:ssh_passphrasestring密钥口令，无口令时为 null
message:artifact_pathstring可执行文件路径
message:versionstring版本号

错误处理

统一错误处理策略： 1. 项目不存在：TriggerDeployment 时 projectId 对应项目不存在或已逻辑删除，返回 404，错误码 PROJECT_NOT_FOUND。 2. 环境不存在：TriggerDeployment 时 environment_id 对应环境不存在、已逻辑删除或不属于该项目，返回 404，错误码 ENVIRONMENT_NOT_FOUND。 3. SSH密钥未配置：TriggerDeployment 时目标环境的 has_ssh_key=false，返回 400，错误码 SSH_KEY_NOT_CONFIGURED。 4. SSH密钥解密失败：TriggerDeployment 时从环境管理服务获取SSH密钥时解密失败，返回 500，错误码 SSH_KEY_DECRYPT_FAILED，记录错误日志人工介入。 5. 版本号格式校验失败：TriggerDeployment 时 version 不匹配正则 ^[a-zA-Z0-9._-]+$ 或长度为0，返回 400，错误码 INVALID_VERSION_FORMAT。 6. artifact_path 校验失败：TriggerDeployment 时 artifact_path 为空或超过1024字符，返回 400，错误码 INVALID_ARTIFACT_PATH。 7. environment_id 校验失败：TriggerDeployment 时 environment_id 为空或非正整数，返回 400，错误码 INVALID_ENVIRONMENT_ID。 8. MQ发送失败：TriggerDeployment 时将任务包发送至 deployment.tasks 时连接异常或写入超时，回滚部署记录（标记为 failure 记录错误信息），返回 502，错误码 MQ_SEND_FAILED。 9. MQ消费异常：HandleDeploymentLogMessage 消费 deployment.logs 消息时处理失败，将消息投递至死信队列，最多重试3次，超过后记录异常日志人工排查。 10. 部署记录不存在：GetDeploymentLogs 时 depId 对应部署记录不存在，返回 404，错误码 DEPLOYMENT_NOT_FOUND。 11. 数据库异常：MySQL 查询或写入失败时捕获异常，返回 500，错误码 DB_ERROR，同时记录错误日志用于排查。 12. Redis异常：WebSocket 会话管理写入 Redis 失败时降级处理（不阻断日志推送），仅记录错误日志，不影响核心部署流程。 13. WebSocket推送失败：HandleDeploymentLogMessage 向前端推送 WebSocket 消息时连接已断开，从 Redis 移除该连接映射，日志仍正常写入 deployment_logs 表，前端重连后可调用 GetDeploymentLogs 补齐。 14. 超时控制：数据库查询超时设为 5s，MQ 发送超时设为 3s，超时后返回 504，错误码 GATEWAY_TIMEOUT。
