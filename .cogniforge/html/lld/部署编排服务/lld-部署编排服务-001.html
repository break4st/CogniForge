概述

部署编排服务
⚙️ 业务服务
部署任务的核心编排引擎，负责执行部署的完整工作流：传输文件 -> 创建目录 -> 生成脚本 -> 执行命令。接收API网关的部署请求，通过SSH连接池服务获取远程服务器连接句柄，在远程服务器上完成文件传输、版本目录创建、启动/停止/健康检查脚本生成和命令执行，通过WebSocket实时推送各步骤状态和日志流，最终将部署结果持久化到数据库供版本追溯和回滚。
依赖: SSH连接池服务文件存储PostgreSQL数据库
PythonFastAPIPostgreSQLSSH/SCP/SFTPWebSocket

业务规则

不变量
  • !同一项目(project_id)下同一环境(environment_id)中，同一时刻最多只能有一条部署记录的status为PENDING或RUNNING
  • !部署步骤必须严格按照sequence序号从小到大串行执行，sequence N必须在前一步（sequence N-1）的status为SUCCESS时才能执行
  • !deploy_records.status必须始终为DeployStatus枚举中的合法值（PENDING/RUNNING/SUCCESS/FAILED/ROLLED_BACK），不允许其他字符串
  • !回滚创建的新部署记录必须填写rollback_from字段，指向被回滚的原始部署记录ID
  • !部署版本号（version）在同一个项目中通过file_records的project_id+version唯一索引保障，不允许同一项目出现重复版本号
状态机
🎯 DeployTask
PENDINGRUNNINGSUCCESSFAILEDROLLED_BACK

→用户选择此版本作为回滚目标发起rollback_deployby 用户
🚫 SUCCESS -> RUNNING 不可逆：已成功的部署无法重新执行🚫 FAILED -> RUNNING 不可逆：已失败的部署无法重新执行，必须新建部署🚫 ROLLED_BACK -> 任何状态 不可逆：被回滚过的部署版本不可再发生任何状态转换🚫 PENDING -> FAILED 直跳不可逆：PENDING状态的部署可在未进入RUNNING前被取消或系统异常标记为FAILED，但FAILED不可回退到PENDING
⚡ 通过数据库事务+行级锁（SELECT ... FOR UPDATE）校验并发：在createDeployRecord事务中，先以project_id+environment_id过滤deploy_records表并对命中行加互斥锁，检查是否存在PENDING/RUNNING状态的记录。不存在时允许插入新记录。结合复合索引idx_deploy_records_project_env_created加速过滤查询。唯一索引保障同一project_id+environment_id+created_at组合的唯一性（虽不直接防并发创建，但事务内锁机制兜底）。
跨服务规则
调用SSH连接池服务GetConnection必须在30秒内返回，超时视为目标服务器不可达，当前部署标记为FAILED，error_message记录「SSH连接超时」
从SSH连接池获取的连接句柄有有效期（expires_at），单次部署全程必须在此时间内完成，若部署步骤超过连接有效期，需在下一个步骤开始前重新获取连接
SCP/SFTP文件传输失败时，部署编排服务必须在当前步骤异常处理中清理远程服务器上已创建的部分目录和文件，并调用SSH连接池服务归还连接（release），防止连接泄漏
密钥认证失败（SSH连接池返回401）表示密钥已吊销或指纹不匹配，部署编排服务不得重试，直接标记部署为FAILED，并通过审计日志记录密钥异常事件，提醒安全管理员核查
文件存储服务的可执行文件在部署传输前应校验checksum（SHA256），若校验和不匹配则立即终止部署并标记FAILED，防止部署损坏的文件
所有部署变更（创建、取消、回滚）完成后必须写入审计日志（audit_logs），记录操作人、操作类型（DEPLOY_START/DEPLOY_CANCEL/DEPLOY_ROLLBACK）、部署ID、版本号和结果

错误处理

处理策略

部署编排服务的错误分三层处理：1) 请求校验层——参数缺失或格式错误直接返回400；2) 业务校验层——部署冲突(409)、资源不存在(404)由服务方法显式抛出业务异常；3) 执行层——SSH连接失败、SCP传输异常、脚本执行错误等运行时错误，捕获后标记对应步骤为FAILED，等待重试耗尽后标记部署为FAILED并记录错误信息到deploy_records.error_message，通过WebSocket推送失败状态。所有SSH操作设置超时（30秒），调用SSH连接池设置gRPC超时（30秒），超时或不可用按依赖方错误处理。
