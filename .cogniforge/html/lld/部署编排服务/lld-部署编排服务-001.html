概述

部署编排服务
⚙️ 业务服务
核心服务，编排一键部署的完整流程，调度执行层各模块协作。接收前端部署请求，通过Redis Stream异步处理部署任务，协调密钥获取、环境连接、文件传输、脚本生成、远程执行等子任务，通过WebSocket实时推送进度和日志到前端看板，支持版本回滚和取消操作。
依赖: API网关密钥管理服务环境管理服务版本管理服务审计日志服务文件存储Redis缓存SSH连接池文件传输引擎脚本生成引擎远程命令执行器PostgreSQL主数据库
GoGinRedis 7+golang.org/x/crypto/sshSCP/SFTP (通过 golang.org/x/crypto/ssh)gorilla/websocket

业务规则

不变量
  • !同一个(project_id, environment_id)组合下，最多只能有一个状态为pending或running的部署任务
  • !部署任务的progress值必须在0到100之间，且与状态变化同步更新：pending=0, running>0且<100, success=100, failed=当前值, rolled_back=100
  • !每个活跃的deployment_versions记录必须唯一对应一个project_id+environment_id组合下的active版本
  • !rollback类型任务的file_path必须在创建时设置为引用原部署任务的文件路径，不可单独指定
  • !部署版本号在同一项目下必须唯一，格式为语义化版本号 v{major}.{minor}.{patch}
  • !WebSocket推送的日志行sequence必须在同一任务内严格递增且无跳号
状态机
🎯 DeployTask
pendingrunningsuccessfailedcancelledrolled_back
→后台worker消费到队列消息开始执行部署by DeploymentOrchestratorService.ProcessDeployTask
→所有部署步骤完成且健康检查通过by DeployStepExecutor
→部署步骤中发生不可恢复的错误（SSH连接失败/文件传输失败/健康检查不通过）by DeployStepExecutor
→用户主动取消部署任务by DeploymentOrchestratorService.CancelDeployTask
→用户发起版本回滚操作by DeploymentOrchestratorService.CreateRollbackTask
→队列消费重试耗尽后仍无法执行by DeploymentOrchestratorService.ProcessDeployTask
→用户取消尚未开始执行的任务by DeploymentOrchestratorService.CancelDeployTask
🚫 success/failed/cancelled/rolled_back等终态不可再转换为running🚫 rolled_back状态不可再转换（防止反复回滚同一版本）🚫 cancelled状态不可转换到rolled_back（取消的任务不允许执行回滚）
⚡ 同一(project_id, environment_id)下最多一个任务处于pending或running状态。在CreateDeployTask入口和ProcessDeployTask入口两处进行并发检查（数据库唯一约束校验 + Redis分布式锁兜底）。使用Redis SET NX命令实现分布式锁，锁key=cong:deploy:{project_id}:{env_id}，TTL=task_timeout_minutes
跨服务规则
调用密钥管理服务的KeyVerifyAPI验证SSH密钥有效性失败时，直接终止部署流程并报错，不可跳过密钥验证步骤
部署进度每变更一次（每步开始/结束），必须通过审计日志服务的RecordAuditLog接口记录审计事件，事件包含task_id、operator、action、timestamp
部署成功完成后，必须将版本信息写入版本管理服务的deployment_versions表（本服务有直接写权限），并在完成后通知版本管理服务刷新缓存
部署前必须从文件存储的DownloadFile接口获取部署文件的元数据和内容，校验MD5完整性后再传输到远程服务器
调用环境管理服务获取环境配置时，优先从Redis缓存读取（使用Cache:GetEnvironment），缓存未命中时回退到数据库查询
每个部署步骤的日志行必须同步写入Redis（SetDeployTaskState + AppendDeployTaskLog）和PostgreSQL（deployment_task_logs），Redis用于实时推送，PG用于持久化归档
WebSocket推送连接建立时，若Redis中任务状态为running，需先推送历史日志（从PG中查询），再进入增量推送模式
回滚操作必须在同一项目同一环境内执行，不允许跨环境回滚
调用远程命令执行器的ExecuteCommand接口时，必须设置命令超时时间（默认60秒），超时未返回时主动断开SSH会话并报错

错误处理

处理策略

部署编排服务的错误分三层处理：参数校验和权限校验在API入口层即时返回4xx错误；部署执行过程中的错误（SSH连接失败、文件传输失败、脚本执行异常等）由步骤执行器捕获，记录到任务日志和错误字段，触发任务状态变更为failed，并逐级上报；不可恢复的系统错误（队列消费异常、数据库连接中断）触发告警和自动重试，重试耗尽后标记任务失败并将消息转入死信队列。

统一错误响应体
字段类型
codeinteger
errorstring
detailstring
400
参数校验错误
请求参数缺失、格式错误或类型不匹配，调用方需修正请求后重试。包括：project_id为空、environment_id为空、file_path格式无效等。
403
权限不足
当前用户不具有执行部署/回滚/取消操作的权限。JWT角色校验失败时返回，需确认用户角色和项目成员关系。
404
资源不存在
引用的项目、环境、密钥、部署文件或部署任务不存在。触发条件包括：项目被归档、环境被删除、密钥未绑定、文件已被清理。
409
并发冲突
该项目环境下已有正在执行的部署任务（pending或running状态），无法并发执行新任务。调用方需等待当前任务完成或取消后再试。
500
内部服务错误
部署编排服务内部异常，包括：数据库操作失败、Redis连接中断、消息序列化错误等。自动触发告警，运维人员需检查服务健康状态。
502
下游服务调用失败
调用密钥管理服务、环境管理服务、版本管理服务、审计日志服务等下游服务时返回非预期错误。触发条件：下游服务宕机、网络分区、请求超时。
504
部署执行超时
部署任务整体执行时间超过配置的task_timeout_minutes（默认30分钟）。触发条件：文件传输卡顿、远程脚本执行挂起、SSH连接长时间无响应。处理方式：自动终止任务并标记为failed。
