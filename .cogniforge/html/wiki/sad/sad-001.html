系统概述

本系统为面向K12学校的学生综合管理平台，覆盖学生信息、班级结构、年级配置及学习统计四大核心业务域。系统采用微服务架构风格，通过API Gateway统一对外暴露服务，各业务域独立部署、独立伸缩，支持学校信息化管理的高效运转。

🏗️

架构设计

采用前后端分离的微服务架构。前端为单页应用（SPA），通过API Gateway与后端通信。后端按业务域拆分为四个微服务：student-service、class-service、grade-service、statistics-service，另设统一的auth-service负责认证授权。服务间通过gRPC同步通信，最终一致性场景通过异步消息队列（RabbitMQ）解耦。数据层采用PostgreSQL为主库，Redis做缓存加速，Elasticsearch支持全文检索与统计聚合。

组件设计 (10)

api-gateway

service

统一API入口，负责请求路由、认证鉴权、限流熔断、请求日志

  • JWT令牌校验
  • 接口限流与熔断
  • 访问日志记录

student-service

service

学生信息管理核心服务，处理学生档案的增删改查及组合查询

  • 学生基本信息CRUD
  • 学号唯一性校验
  • 按姓名/学号/年级等多条件组合查询
  • 学生信息导入导出

class-service

service

班级信息管理服务，处理班级生命周期及学生分班管理

  • 班级创建/撤销/调整
  • 学生与班级关联管理
  • 班级合并与拆分
  • 班级容量控制

grade-service

service

年级信息管理服务，处理年级配置及批量升级操作

  • 年级增删改查
  • 年级批量升级
  • 年级-班级层级关联维护
  • 年级配置参数管理

statistics-service

service

学习统计服务，采集学习数据并提供多维度统计分析

  • 学生成绩录入与查询
  • 出勤数据管理
  • 作业完成情况跟踪
  • 按学生/班级/年级维度统计
  • 统计结果可视化数据接口

auth-service

service

统一认证授权服务，管理用户身份和访问权限

  • 用户注册与登录
  • JWT令牌颁发与刷新
  • 基于RBAC的权限控制
  • 用户角色管理（管理员/教师/学生）

postgresql-primary

主数据库，存储各业务域的核心结构化数据

  • 班级与年级关系数据存储
  • 学习统计数据存储
  • 用户账号与权限数据存储

redis-cache

缓存层，加速高频读取数据及缓解数据库压力

db

拓扑结构

系统采用分层部署拓扑。最外层为Nginx反向代理层，承接HTTPS请求并转发至API Gateway。API Gateway层水平部署2个实例，后接服务注册与发现中心（Consul）。业务服务层各微服务均部署2副本，通过Kubernetes管理容器编排。数据层PostgreSQL采用主从架构（1主2从），Redis采用哨兵模式（3节点），Elasticsearch部署3节点集群。消息队列RabbitMQ部署为镜像队列集群（3节点）。前端静态资源通过CDN分发。

📊

数据流

用户请求流程：用户通过浏览器/客户端发起HTTPS请求 → Nginx反向代理 → API Gateway（校验JWT令牌、路由转发）→ 对应的微服务处理请求 → 查询缓存（Redis，未命中则查数据库）→ 返回响应。 数据写入流程：管理员在前端提交学生信息表单 → API Gateway → student-service → 写入PostgreSQL → 发送变更事件到消息队列 → statistics-service消费事件异步更新统计缓存。 统计查询流程：教师请求班级统计报表 → API Gateway → statistics-service → 优先查Redis缓存（命中则直接返回）→ 缓存未命中则查Elasticsearch聚合 → 返回结果并回填缓存。 批量升级流程：管理员触发年级升级 → grade-service → 更新年级状态 → 发布升级事件到消息队列 → class-service消费事件同步调整班级年级关联。
