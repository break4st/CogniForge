产品需求文档 自动化部署管理平台（DeployFlow）

2026-05-23T11:12:00 · 作者: pm_agent
📋

概述

DeployFlow 是一款面向开发与运维团队的轻量级自动化部署管理平台。系统支持用户创建和管理多个项目，每个项目可独立配置多套部署环境（如测试线、灰度线、正式线），通过 SSH 密钥实现安全连接。用户只需将打包好的可执行文件上传，系统即可一键完成远程服务器的版本文件夹创建、文件推送与执行脚本生成，实现从构建产物到线上运行的端到端自动化部署。该平台致力于降低手动部署的出错率，提升多项目并行交付效率。

📝

功能需求 (6)

1. 项目管理

支持用户创建、编辑、删除和切换多个项目。每个项目拥有独立的名称、描述和部署环境配置集合，项目之间数据完全隔离，满足多项目并行管理的需求。
验收条件
  • 用户可在项目列表页面创建新项目，填写项目名称与描述信息后成功保存
  • 用户可编辑已有项目的基本信息（名称、描述），修改后即时生效
  • 用户可删除不再需要的项目，删除前系统弹出二次确认对话框
  • 用户可通过下拉菜单或切换按钮在多个项目间灵活切换，切换后页面数据（环境列表、部署记录）切换至对应项目
  • 当前激活项目的名称在页面顶部或导航栏显著位置显示

2. 多环境部署配置

每个项目下支持用户自定义多套部署环境（如测试线、灰度线、正式线等）。每套环境包含独立的远程服务器连接信息（主机地址、端口、认证方式）和目标部署路径，支持环境级别的灵活启停。
验收条件
  • 用户可在当前项目下创建新的部署环境，填写环境名称（如'测试线'）、主机地址、SSH 端口（默认22）、部署目标路径
  • 支持为每套环境选择认证方式：SSH 私钥文件上传 或 密码认证
  • 用户可编辑已有环境的配置信息，修改后保存即时生效
  • 用户可删除或临时禁用某套环境（禁用后不参与部署，但配置保留）
  • 同一项目下环境名称必须唯一，系统在创建时进行校验并提示

3. SSH 密钥安全管理

系统支持用户上传或粘贴 SSH 私钥作为远程服务器的认证凭据，密钥在存储和传输过程中加密保护，确保连接安全性。同时支持密钥有效性验证。
验收条件
  • 用户可通过文件上传或文本框粘贴方式录入 SSH 私钥
  • 私钥内容在数据库中加密存储，前端展示时脱敏处理（仅显示密钥指纹或前后若干字符）
  • 用户可对已配置的密钥发起连接测试，系统返回连接成功或失败的具体原因
  • 支持 ED25519 和 RSA（至少 2048 位）两种私钥格式
  • 密钥与部署环境绑定，修改密钥后历史密钥不可恢复

4. 一键自动化部署

用户选择目标环境和待部署的可执行文件包后，系统通过 SSH 连接远程服务器，自动创建以版本号或时间戳命名的版本文件夹，将文件推送至目标路径，并在服务器端生成启动/停止/重启等执行脚本，完成端到端的一键部署。
验收条件
  • 用户在部署界面选择目标环境、上传或指定构建产物（可执行文件包），点击'开始部署'按钮触发部署流程
  • 部署过程中实时展示部署进度日志（连接中 → 创建文件夹 → 上传文件 → 生成脚本 → 完成）
  • 远程服务器自动创建格式为 'v{version}_{timestamp}' 的版本文件夹于目标路径下
  • 系统自动在远程服务器生成可执行的启动脚本（start.sh / start.bat）、停止脚本（stop.sh / stop.bat）和重启脚本（restart.sh / restart.bat）
  • 部署完成后系统展示部署结果摘要（目标服务器、版本文件夹路径、耗时），支持一键跳转至部署记录详情

5. 版本管理与回滚

每次部署自动记录版本信息，包括版本号、部署时间、目标环境、部署文件清单。用户可查看历史部署记录，并选择任一历史版本执行快速回滚操作。
验收条件
  • 部署记录列表展示每次部署的版本号、目标环境、部署时间、状态（成功/失败/回滚中）
  • 用户点击任一历史部署记录可查看详情（部署文件列表、日志输出、目标路径）
  • 对成功部署的版本，用户可执行'回滚'操作，系统自动将目标环境切换至该历史版本的文件夹并重启服务
  • 回滚操作本身也生成一条部署记录（类型标记为'回滚'），确保操作可追溯
  • 支持手动清理旧版本文件夹（系统默认保留最近 N 个版本，N 可配置）

6. 部署日志与审计

系统完整记录每次部署操作的详细日志，包括操作人、时间、目标环境、执行步骤和输出结果，支持日志检索与导出，满足审计与问题排查需求。
验收条件
  • 每次部署操作自动生成详细的结构化日志（时间戳、步骤名称、命令、标准输出、错误输出、执行耗时）
  • 用户可在部署记录详情页查看完整的步骤级日志
  • 支持按项目、环境、时间范围、状态筛选部署记录
  • 支持将部署日志导出为文本文件或 JSON 格式
  • 日志保留策略可配置（默认保留 90 天）

用户故事 (6)

运维工程师

以便：30 秒内完成测试环境的更新部署，第一时间验证代码改动
技术负责人

以便：实现灰度到正式的无缝衔接，降低发布风险
运维工程师
作为 运维工程师，我想要 发现新版本存在线上问题时，在部署记录中选择上一个稳定版本执行一键回滚
以便：在 1 分钟内将服务恢复至正常状态，最大限度缩短故障时间
安全审计员

以便：满足合规审计要求，完整追溯每一次线上变更的发起人和执行细节
项目经理

以便：实时掌握各项目的交付进度和线上版本分布情况
