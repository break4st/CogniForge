概述

构建一个自动化部署管理平台，允许用户管理多个项目，每个项目下可配置多套部署环境（如测试、灰度、生产）。用户通过上传打包好的可执行文件，系统利用 SSH 密钥认证安全连接远程服务器，自动创建版本文件夹并生成执行脚本，完成一键式部署。平台提供实时部署日志和部署历史记录，支持版本回滚，同时确保敏感数据加密存储，满足多项目并行管理与安全合规需求。

功能需求 (6)

REQ-001 项目创建与管理draft高 v1

用户可以创建、编辑、删除项目，并在多个项目间灵活切换当前工作项目。每个项目承载独立的部署环境和历史记录。
验收条件
  • 项目名称在系统内必须唯一
  • 新创建的项目立即出现在项目列表中
  • 切换当前项目时，环境列表和部署历史视图自动刷新为对应该项目的数据
  • 删除项目时需要二次确认，并同步删除其下所有环境配置和历史记录，或弹出明确警告
  • 系统至少支持管理 10 个项目

REQ-002 环境配置管理draft高 v1

在指定项目下，管理该项目的多套部署环境。每套环境包含连接配置（服务器地址、端口、SSH 私钥、登录用户）和部署行为配置（目标基础路径、版本文件夹命名规则、执行脚本模板）。
依赖: REQ-001
验收条件
  • 同一项目下环境名称不可重复
  • SSH 私钥必须为有效格式，系统提供“测试连接”按钮进行连通性校验
  • 执行脚本模板支持占位变量（如 {{version_path}}、{{app_name}}、{{port}}），部署时自动替换为实际值
  • 单个项目下最多可保存 50 套环境
  • 修改环境配置不应影响已完成的部署历史记录

REQ-003 部署文件上传与参数配置draft高 v1

准备部署时，用户可以上传打包的可执行文件（支持 .zip, .tar.gz, .tgz），自定义版本标识，并填写备注。系统对文件进行完整性校验。
依赖: REQ-001, REQ-002
验收条件
  • 上传文件大小限制为 500MB，上传过程显示进度条
  • 支持拖拽上传
  • 版本标识可由用户自定义，若留空则自动生成“v_YYYYMMDD_HHmmss”格式字符串
  • 部署前计算并展示文件校验和（如 MD5 或 SHA256），确保文件完整性
  • 提供本次部署的备注输入框

REQ-004 一键自动化部署执行draft高 v1

用户选定项目和目标环境，上传文件后点击部署，系统通过 SSH 连接远程服务器，依次执行：创建版本目录、上传文件、生成并赋予脚本执行权限、执行启动脚本。整个过程中日志实时输出。
依赖: REQ-002, REQ-003, REQ-006
验收条件
  • 部署过程划分为连接服务器、创建目录、上传文件、生成脚本、执行脚本等步骤，每步显示状态和耗时
  • 任一步骤失败立即停止部署，并显示详细错误信息（如“目录权限不足”）
  • 执行脚本设置超时时间（默认 60 秒），超时视为部署失败
  • 上传到服务器的脚本自动赋予可执行权限（chmod +x）
  • 部署成功后返回成功状态，并自动记录到部署历史
  • 提供取消正在执行部署的操作按钮

REQ-005 部署历史记录与回滚draft中 v1

提供按项目筛选的部署历史列表，包含时间、环境、版本、状态、耗时等。支持查看详细日志，并可从历史记录发起快速回滚到某一版本。
依赖: REQ-004
验收条件
  • 历史列表按时间倒序排列，支持分页
  • 可按环境和状态（成功/失败）过滤记录
  • 点击单条记录可展开查看完整部署日志
  • 点击“回滚”按钮将跳转至部署准备页面，并预填充该历史版本标识，提示用户是否使用原文件重新部署
  • 历史记录不可删除，或仅管理员有权删除

REQ-006 安全与密钥管理draft高 v1

系统禁止使用密码登录，仅支持 SSH 私钥认证。私钥可上传并加密存储，或引用本地路径。提供测试连接和私钥脱敏保护。
验收条件
  • 连接远程服务器仅允许 SSH 密钥认证，不提供密码输入框
  • 上传的私钥必须经过 AES-256 加密后存储，使用时解密
  • 提供“测试连接”功能，验证密钥有效性和网络可达性
  • 环境详情中私钥字段脱敏显示（如“****”），不允许查看原始内容，仅支持更换
  • 支持生成或导入公钥，并给出在服务器上授权的操作指导

用户故事 (6)

US-001 DevOps 工程师
作为 DevOps 工程师，我想要 创建新项目，并为该项目添加测试、灰度和生产环境
以便：集中管理所有发布目标，避免手动记忆服务器信息
US-002 后端开发人员
作为 后端开发人员，我想要 在完成构建后，直接将可执行文件包部署到测试环境
以便：快速在测试服务器上验证新功能，无需自行登录服务器操作
US-003 发布经理
作为 发布经理，我想要 在执行部署时看到实时日志，并在失败时快速定位错误
以便：确保生产发布万无一失，及时响应问题
US-004 运维人员
作为 运维人员，我想要 在服务器上自动创建带版本号的文件夹，并执行预定义的启动脚本
以便：每次发布都有独立的版本目录，方便回滚和问题追溯
US-005 团队负责人
作为 团队负责人，我想要 查看某个项目的历史部署记录，并一键回滚到上一个稳定版本
以便：在线上出现严重问题时能快速止损
US-006 系统管理员
作为 系统管理员，我想要 确保所有远程连接均使用 SSH 密钥，并在系统中绝不暴露私钥
以便：满足企业安全合规要求，防止服务器凭据泄露
