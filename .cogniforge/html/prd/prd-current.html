概述

CogniDeploy 是一款面向开发者的轻量级自动化部署管理工具。用户可在本地为多个项目创建独立的多套部署环境（如测试线、灰度线、正式线），并通过安全密钥配置远程服务器连接。当本地完成打包后，只需一键操作，系统即能自动将可执行文件上传至目标服务器，创建带版本号的时间戳目录，并生成标准化的执行与启停脚本，彻底告别手动 SCP、SSH 和重复编写部署脚本的繁琐工作，同时支持环境间隔离、版本回溯与多项目快速切换，极大提升交付效率。

功能需求 (7)

REQ-001 项目管理draft高 v1

用户可创建、编辑、删除多个项目，每个项目有独立名称和描述，并承载一套独有的部署环境。
验收条件
  • 新建项目时，必填项目名称，选填描述，提交后项目即出现在列表中。
  • 可编辑已有项目信息，且变更后输入验证无误。
  • 删除项目时有二次确认，确认后项目、其所有环境及部署历史一并移除。
  • 项目列表支持按名称模糊搜索和按时间/名称排序。
  • 在左侧导航区域点击任一项目即可切换，切换后右侧界面刷新为该项目的环境与部署详情。

REQ-002 部署环境管理draft高 v1

在每个项目下，允许用户创建多套环境（如测试线、灰度线、正式线），配置服务器连接信息和部署参数。
依赖: REQ-001
验收条件
  • 项目详情页内可新增环境，需填写环境名称、服务器IP/域名、SSH端口（默认22）、认证方式（密码或私钥）、远程部署根路径。
  • 支持通过文本框粘贴 SSH 私钥，或从本地拖拽上传私钥文件，系统使用 AES-256 加密存储私钥。
  • 环境可被编辑或删除，删除后对应远程版本目录不受影响（仅移除配置），避免误删代码。
  • 每个环境卡片上显示最近一次连接测试结果，并提供“测试连接”按钮实时验证。
  • 可配置部署后自动执行的脚本模板（可选），如重启服务命令。

REQ-003 安全连接与密钥管理draft高 v1

安全存储 SSH 私钥或密码，实现免密登录远程服务器，所有敏感凭证在落盘与传输过程中均加密。
依赖: REQ-002
验收条件
  • 用户可输入密码或上传私钥，私钥在存储前使用主密钥（用户首次设定）加密，数据库中仅存密文。
  • 界面中密钥字段仅显示指纹（如“SHA256:xxxx”）或部分掩码，完整内容不可见。
  • “测试连接”功能弹出加载动画，连接成功显示服务器操作系统版本，失败则明确提示错误（认证失败/超时/主机不可达）。
  • 连接参数（IP、端口）支持格式校验，错误时给出前端提示。
  • 私钥文件支持拖拽或文件浏览器选择，上传后自动解析并验证是否为合法私钥格式。

REQ-004 一键部署draft高 v1

在指定项目环境界面，用户选择本地打包好的文件，点击部署后自动完成上传、解压（若需要）、版本文件夹创建、软链接切换及脚本生成。
依赖: REQ-002, REQ-003
验收条件
  • 部署入口在环境详情页顶部，点击“部署”打开模态框，可拖拽或浏览本地文件（支持 .zip/.tar.gz 及单个二进制文件）。
  • 部署流程实时展示步骤进度：连接服务器 → 上传文件 → 解压（若压缩包）→ 创建版本目录 → 更新 current 软链接 → 执行可选启动脚本。
  • 远程目标路径标准化：`releases/20260525124400/`（上传内容），`current → releases/20260525124400`（软链接），若配置了执行模板，还会生成 `start.sh`、`stop.sh` 并赋予可执行权限。
  • 部署中途失败应自动执行回滚（删除已创建的版本文件夹和临时文件），并在界面高亮错误步骤及原因。
  • 部署前系统检查远程 root 路径是否存在，不存在则尝试自动创建；若磁盘剩余空间低于阈值（可配置，如 100MB），则提醒用户并阻止部署。

REQ-005 版本管理与部署历史draft中 v1

每次部署生成一条带时间戳的版本记录，可浏览历史、查看详情、回滚至任一历史版本。
依赖: REQ-004
验收条件
  • 环境详情页下方展示“部署历史”列表，每条包含版本标识（时间戳）、部署时间、上传文件名、部署状态（成功/失败）、操作人（暂留默认）。
  • 成功版本提供“回滚”操作，点击后远程将 `current` 链接切换为对应版本的目录，并记录一次回滚历史。
  • 点击历史条目可展开详情，显示文件大小、部署耗时、远程脚本输出日志。
  • 提供“清理旧版本”功能，设置保留最近 N 个版本，其余自动删除（需确认）。
  • 回滚操作需二次确认，且回滚结果会实时反馈。

REQ-006 执行脚本生成draft中 v1

根据用户预设的模板，在部署后自动在远程服务器版本目录下生成标准化的启动与停止脚本，并可通过界面远程调用。
依赖: REQ-004
验收条件
  • 环境配置中提供“启动命令”和“停止命令”模板输入框，支持变量如 `%APP_NAME%`、`%PORT%` 等。
  • 部署成功后，自动在版本目录生成 `start.sh`、`stop.sh` 文件，内容为填充后的模板，并 `chmod +x`。
  • 在环境详情页提供“启动服务”/“停止服务”按钮，点击后通过 SSH 远程执行对应脚本，并将输出返回界面。
  • 若执行失败，返回脚本的 stderr 和退出码，便于排查。

REQ-007 多项目切换与全局视图draft中 v1

提供全局项目概览界面，方便快速掌握各项目最新部署状态和快速跳转。
依赖: REQ-001, REQ-002
验收条件
  • 首页仪表盘展示所有项目卡片，每个卡片显示项目名、最近一次部署环境及状态（绿色成功/红色失败）、部署时间。
  • 左侧导航栏固定项目列表，高亮当前选中项目，支持拖动排序或按字母排序。
  • 全局搜索框支持输入项目名或环境名，过滤显示匹配结果。
  • 点击仪表盘卡片或导航项目名，直接进入该项目环境列表。

用户故事 (6)

US-001 开发者
作为 开发者，我想要 创建多个项目
以便：隔离不同产品的部署配置
US-002 运维人员
作为 运维人员，我想要 为同一项目添加多套环境，并分别配置服务器和密钥
以便：安全地将构建物推送至对应阶段
US-003 安全管理员
作为 安全管理员，我想要 要求所有 SSH 私钥以加密形态存储，且界面无法直接查看完整密钥
以便：确保凭证安全
US-004 日常使用者
作为 日常使用者，我想要 在界面选择项目和环境，点击部署
以便：自动完成上传、版本创建和脚本生成，替代手动 SCP 和 SSH
US-005 项目负责人
作为 项目负责人，我想要 查看历史部署记录并执行回滚
以便：在新版本出问题时快速恢复服务
US-006 工程师
作为 工程师，我想要 利用部署后生成的标准化启停脚本，并在界面远程执行
以便：无需登录服务器即可管理服务
