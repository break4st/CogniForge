概述

本产品是一款面向开发与运维人员的一站式自动化部署工具，旨在解决多项目、多环境下可执行文件手动部署的低效与安全风险。用户可在本地集中管理多个项目，每个项目可配置测试、灰度、正式等多套独立环境，通过 SSH 密钥安全连接远程服务器。核心功能是一键将本地构建产物上传至目标服务器，自动创建版本控制目录并生成可执行脚本，同时支持软链接更新与服务重启，实现完整的自动化部署流程。工具还提供部署历史记录与日志追踪，保障发布过程的可追溯与快速回滚。

功能需求 (6)

REQ-001 项目管理draft高 v1

支持用户创建、编辑、删除多个项目，每个项目拥有独立的名称、本地产物目录、部署脚本模板等配置，项目间可灵活切换。
验收条件
  • 用户能够创建新项目，输入项目名称并保存，项目列表即时刷新显示。
  • 双击或选择项目后可切换当前活跃项目，界面标题或指示器随之变化。
  • 每个项目的本地产物目录可自定义配置，部署时默认读取该目录下的待上传文件。
  • 项目可被编辑（修改名称、路径等）或删除，删除前需二次确认。

REQ-002 环境管理draft高 v1

在每个项目下，用户可以创建多套部署环境（如测试线、灰度线、正式线），配置连接信息（IP、端口、密钥、部署根目录等），并支持标记保护环境。
依赖: REQ-001
验收条件
  • 在选定项目下，可新增环境，填写环境名称、服务器 IP、SSH 端口（默认22）、认证密钥文件路径、远程部署根目录等信息。
  • 密钥文件路径支持浏览选择，系统检查文件有效性，且仅记录路径，不存储密钥内容。
  • 环境列表显示环境名称、服务器、保护标记等关键信息，支持编辑和删除。
  • 可勾选‘生产环境保护’，勾选后执行部署需弹出额外确认对话框。
  • 每个项目下的环境独立管理，切换项目时环境列表自动刷新。

REQ-003 一键部署draft高 v1

用户选择目标和环境后，一键触发：通过 SFTP 上传本地产物到远程版本目录，自动创建以项目名+时间戳+版本号命名的文件夹，生成并执行启动脚本，可选更新 current 软链接。
依赖: REQ-001, REQ-002
验收条件
  • 部署前检查：验证本地产物文件存在、远程连接可达、目标路径可写等。
  • 文件上传通过 SFTP 协议进行，显示实时进度（文件大小、百分比）。
  • 远程自动创建版本目录，格式如 ‘/deploy_root/versions/项目名-时间戳’，并设置适当权限。
  • 根据项目配置的脚本模板，动态生成可执行启动脚本（如 start.sh），内含正确的环境参数（如 JAVA_OPTS、profile 等）。
  • 支持上传后软链接更新：将 ‘current’ 软链接指向最新版本目录。
  • 部署失败时明确报错信息，并记录日志，不影响已存在的版本目录。
  • 生产环境部署需弹出强提示二次确认。

REQ-004 部署记录与日志draft中 v1

系统记录每次部署的历史信息，包括时间、目标环境、版本、结果，并可查看详细的传输与执行日志。
依赖: REQ-003
验收条件
  • 部署历史列表显示每个部署记录的基本信息。
  • 点击某条记录可查看详细日志，包含 SFTP 传输详情、远程命令输出等。
  • 日志支持复制、导出为文本文件。
  • 部署历史与项目关联，切换项目后只显示当前项目的历史记录。

REQ-005 脚本模板管理draft中 v1

允许用户自定义项目级的部署脚本模板，支持变量替换（如环境名、端口号等），适应不同技术栈的启动方式。
依赖: REQ-001
验收条件
  • 提供默认模板（如 Java -jar 方式），用户可以编辑保存。
  • 模板中可以使用预定义变量，系统在生成时自动替换为实际环境参数。
  • 模板编辑界面提供语法高亮（可选）和简单的错误提示。
  • 修改模板后不影响历史已部署的脚本。

REQ-006 多平台服务器支持draft低 v1

部署目标服务器需同时支持 Linux 和 Windows（SSH 服务已开启），脚本模板和文件路径可根据目标系统自动适配。
依赖: REQ-002, REQ-003
验收条件
  • 环境配置中可指定服务器操作系统类型，默认为 Linux。
  • 若选择 Windows，生成的脚本为 .bat 或 .ps1，路径使用反斜杠或自动转换。
  • 连接、上传、执行命令在 Windows 目标上正常运行（需测试 OpenSSH 服务）。

用户故事 (6)

US-001 多项目管理者
作为 多项目管理者，我想要 创建并切换不同的‘项目’配置
以便：为电商平台和内部OA系统分别设定独立的部署规则，互不干扰
US-002 运维工程师
作为 运维工程师，我想要 为‘电商平台’项目添加‘测试线’和‘正式线’两套环境，配置各自的服务器密钥与部署路径
以便：确保测试和生产部署完全隔离，避免配置串扰
US-003 后端开发者
作为 后端开发者，我想要 本地 build 出 jar 包后，在工具中选择‘电商平台-测试线’环境并点击一键部署
以便：jar 被自动传到测试服务器、新版本目录创建完毕、启动脚本生成正确，我可以在浏览器验证新功能
US-004 发布负责人
作为 发布负责人，我想要 查看部署历史记录及详细日志
以便：快速确认某个版本是否部署成功，或者在出错时根据日志排查问题
US-005 技术组长
作为 技术组长，我想要 自定义部署脚本模板，加上 JVM 内存参数和自定义环境变量
以便：适配团队使用的 Java 微服务启动规范，不用每次手动改启动命令
US-006 运维人员
作为 运维人员，我想要 为 Windows 测试服务器配置部署环境
以便：能够同样通过工具将 .NET 编译产物一键部署到 Windows 测试机，无需手动远程桌面复制
