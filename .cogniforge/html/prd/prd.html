概述

本平台为用户提供一站式远程部署解决方案。用户可以创建并管理多个项目，每个项目独立配置测试、灰度、正式等多套部署环境。通过 SSH 密钥安全连接远程服务器，选择目标环境和打包好的可执行文件，一键完成文件上传、版本文件夹创建、执行脚本生成以及服务启动，彻底告别手动登录服务器执行繁琐命令的时代。同时支持部署历史追溯与版本回滚，保障发布的安全与可回溯性。

功能需求 (6)

REQ-001 项目管理draft高 v1

用户可创建、编辑、删除项目。每个项目代表一个独立的业务系统，拥有自己的名称、描述以及独立的环境配置集。支持项目列表展示、搜索和项目间的快速切换，当前激活的项目会高亮显示，后续部署操作均基于此项目。
验收条件
  • 能成功创建新项目，输入必填项（项目名称），并可填写可选描述。
  • 在项目列表中能按名称搜索，选择某一项目后，应用界面标题或上下文切换至该项目。
  • 编辑项目时修改名称、描述生效，删除项目时需二次确认，且若项目下还有环境配置，应提示是否一并删除。
  • 切换项目后，环境列表自动刷新为该项目的环境，不会残留上一个项目的数据。

REQ-002 多环境配置管理draft高 v1

在每个项目下，用户可自由定义多套部署环境（如测试线、灰度线、正式线）。环境配置包括：环境名称、远程主机地址（IP/域名）、SSH 端口（默认22）、认证方式（优先支持密钥对，也可扩展密码）、远程部署根路径、环境变量（键值对，可选，部署时会写入脚本）等。支持环境的增、删、改、查。
依赖: REQ-006
验收条件
  • 在当前项目下点击“新建环境”，填写环境名称、主机等必填信息，选择密钥或输入密码，测试连接按钮可验证网络与凭证。
  • 环境列表显示所有已配置环境，可编辑、删除，编辑后保存立即生效。
  • 删除环境时提示确认，删除后不可恢复。
  • 密钥管理模块支持导入本机私钥或生成密钥对，密钥文件加密存储，使用时需项目授权。

REQ-003 一键自动化部署draft高 v1

用户选定当前项目、目标环境，选择一个本地打包好的可执行文件（或压缩包），填入部署版本号（如 v1.2.3，也可自动生成时间戳版本），点击“部署”。系统自动执行：使用配置的 SSH 连接远程服务器；在远程部署根目录下创建以版本号命名的文件夹；上传部署文件至该文件夹；若为压缩包自动解压；根据预设模板生成标准启动脚本（start.sh）、停止脚本（stop.sh）及检查状态脚本，并赋予执行权限；执行用户定义的部署后钩子（可选）；实时回显部署日志，最后反馈成功/失败状态。
依赖: REQ-001, REQ-002, REQ-006
验收条件
  • 选择环境、上传文件后点击部署，进度条或日志区域实时展示连接、上传、创建文件夹、生成脚本等步骤。
  • 部署成功后，通过 SSH 登录服务器，在对应路径下可看到版本文件夹及其内容，start.sh 能正确拉起服务。
  • 部署过程中若任意步骤失败（如连接超时、磁盘不足），系统应明确报错并终止后续操作，已创建的部分可选保留或自动清理（根据设置）。
  • 支持部署版本号的合法性校验（不允许路径穿越字符），空版本号时自动生成时间戳版本。

REQ-004 版本历史与回滚draft中 v1

系统记录每次部署的详情：时间、环境、版本号、操作人、部署包摘要（MD5）、状态（成功/失败）。用户可在项目-环境维度下查看历史部署列表，针对任意成功版本提供“回滚”按钮。回滚操作自动切换到目标版本的文件夹，并执行其启动脚本（或重新生成脚本），实现快速恢复。
依赖: REQ-003
验收条件
  • 部署完成后，历史记录生成，包含上述关键信息。
  • 在环境详情页可查看到历史列表，支持按时间、版本号过滤。
  • 点击回滚，系统连接服务器，切换到指定版本目录，执行启动脚本或重启服务，操作日志显示成功。
  • 若目标版本文件夹已不存在（被手动清理），回滚时应报错并提示。

REQ-005 部署脚本模板管理draft低 v1

系统提供默认的启动/停止脚本模板，用户可根据项目特性自定义脚本模板，如启动命令、健康检查逻辑。模板可关联到项目或环境，部署时自动渲染（可注入环境变量、端口等）。支持模板版本管理。
依赖: REQ-003
验收条件
  • 在项目或环境设置中可编辑脚本模板，提供默认占位符。
  • 部署时生成的脚本内容与模板一致且环境变量正确替换。
  • 模板变更后，历史版本不受影响，新部署才使用新模板。

REQ-006 安全连接与密钥管理draft高 v1

集中管理 SSH 密钥对，支持导入 OpenSSH 格式私钥，也可在工具内生成密钥对并导出公钥。密钥以加密方式存储在本机，部署时读取内存中的解密私钥进行认证，绝不明文落地。可设定密钥适用范围（全局或特定项目）。
验收条件
  • 支持导入密钥文件或粘贴密钥内容，并设置密码短语。
  • 生成密钥对后能下载公钥。
  • 环境配置时可选择已保存的密钥进行连接，连接测试通过。
  • 未授权的用户或进程无法直接读取原始密钥文件。

用户故事 (5)

US-001 开发工程师
作为 开发工程师，我想要 在选择项目和测试线环境后，上传打包好的可执行文件并点击部署
以便：自动完成上传、创建版本文件夹和生成启动脚本，免去手动 SCP 和 SSH 操作的麻烦
US-002 运维工程师
作为 运维工程师，我想要 为每个业务系统创建独立项目，并为其配置多套环境（测试/灰度/正式）
以便：部署时不会选错目标，保证不同环境隔离
US-003 发布经理
作为 发布经理，我想要 查看某个应用在正式线上部署的历史版本，并在出现问题时一键回滚到上一个稳定版本
以便：缩短故障恢复时间
US-004 安全管理员
作为 安全管理员，我想要 要求所有远程连接必须使用 SSH 密钥认证，且密钥集中加密存储
以便：部署时仅内存使用，杜绝密钥泄露风险
US-005 多项目并行开发的团队成员
作为 多项目并行开发的团队成员，我想要 在工具内快速切换到另一个项目，查看其独有的环境列表，并立即进行部署
以便：无需退出重新配置，高效管理多项目
