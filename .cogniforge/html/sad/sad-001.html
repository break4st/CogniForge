系统概述

系统定位

本系统采用前后端分离的 Web 架构，核心为后端 API 服务 + 前端单页应用，并引入异步任务执行和实时日志推送机制。系统角色目前统一为“用户”，拥有全部操作权限。用户通过浏览器界面完成项目和环境的配置、部署触发、历史查看与回滚等全部功能。后端负责数据持久化、SSH 安全连接、文件传输、版本化管理以及日志实时推送。整体追求轻量、易部署、易扩展。

👤
用户
  • 项目管理（创建、编辑、删除）
  • 环境管理（创建、编辑、删除）
  • 密钥管理（添加、删除、测试连接）
  • 触发部署与查看实时日志
  • 查看部署历史与执行回滚
🏗️

架构设计

前后端分离 + 异步任务执行 + 实时通信
系统逻辑上划分为接入层、服务层和实时通道。接入层使用 Nginx 提供静态资源和反向代理；服务层包含后端 API 服务、部署执行器、SSH 客户端模块和密钥加密服务；数据层采用 PostgreSQL；实时通道通过 WebSocket 集成于 API 服务中。后端 API 处理同步 CRUD 请求，部署任务异步执行并通过 WebSocket 向前端推送实时日志。

数据流

1
一键部署与实时日志流
1. 前端调用 POST /api/deployments，上传文件和 environment_id→2. 后端 API 服务创建部署记录（状态：pending），存储临时文件→3. 后端返回 202 和 deployment_id→4. 前端建立 WebSocket 连接 ws://.../deployments/{id}/logs→5. 后端启动异步部署任务（部署执行器）→6. 部署执行器逐步执行：解密密钥 -> SSH 连接 -> 远程创建版本目录 -> SFTP 上传文件 -> 生成启动脚本并赋予执行权限 -> 更新符号链接→7. 每一步通过 WebSocket 推送日志消息到前端→8. 部署完成，执行器更新部署记录状态为 success 或 failed，并推送最终消息→9. 前端实时渲染日志并反映最终状态
2
测试远程连接流
1. 前端调用 POST /api/environments/{id}/test-connection→2. 后端 API 服务获取环境配置，通过密钥加密服务解密私钥→3. 使用 SSH 客户端模块尝试连接远程服务器→4. 返回连接结果（成功/失败信息）给前端
3
回滚流程
1. 前端调用 POST /api/deployments/{id}/rollback→2. 后端 API 服务验证目标部署记录是否成功→3. 创建新的部署记录（类型为 rollback，状态 pending）→4. 启动回滚任务：部署执行器连接远程，将 current 符号链接指向目标版本目录→5. 推送回滚日志，更新记录状态

技术风险 (4)

ID描述等级缓解措施
RISK-001远程服务器网络不稳定导致部署中断中提供取消机制；保留已传输的部分文件；下次部署时可由操作员手动清理。
RISK-002上传大尺寸部署包可能导致服务器内存压力中限制上传文件大小（如 500MB）；使用流式读取。
RISK-003主密钥泄露导致所有私钥被解密中主密钥由运维团队安全管理，禁止写入代码仓库；生产环境使用密钥管理服务。
RISK-004同时部署到同一环境可能产生冲突中通过部署记录状态检查，禁止同一环境有运行中的部署时再次触发。
