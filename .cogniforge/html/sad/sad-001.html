系统概述

系统定位

自动化部署系统提供将打包好的可执行文件一键部署到指定远程服务器的能力。支持用户自定义多套部署环境（测试线、灰度线、正式线），每套环境通过SSH密钥配置安全连接。部署时自动在远程服务器创建版本文件夹并生成执行脚本，全过程可视化展示进度与日志。系统同时支持多项目管理，每个项目拥有独立的部署环境配置，可在项目间灵活切换。

👤

  • 为每个环境配置SSH密钥和连接参数
  • 选择目标环境并触发一键部署
  • 查看部署进度与实时日志
  • 管理部署版本和回滚
👤

  • 查看项目下所有部署环境配置
  • 查看项目整体部署状态和历史
👤

  • 查看部署日志和结果

架构设计

微服务架构
系统采用前后端分离的微服务架构。前端为单页应用，通过API网关统一路由请求至后端微服务。服务层按业务领域拆分为项目管理、环境管理、部署编排、SSH执行四个独立服务，彼此通过消息队列解耦异步任务。数据层使用关系型数据库持久化配置与记录，Redis缓存实时状态，消息队列承载异步部署任务。架构支持水平扩展，满足多项目多环境并发部署的场景需求。

组件设计 (9)

接入层 1

🖥️ Web管理控制台

frontend

基于SPA的浏览器端管理界面，提供项目管理、环境配置、部署触发、日志查看等交互功能

  • 提供项目CRUD操作界面
  • 提供部署环境配置表单
  • 提供一键部署操作入口
  • 实时展示部署进度与日志
  • 实现项目间切换导航
网关层 1

🔀 API网关

gateway

统一API入口，负责请求路由、身份认证、限流与跨域处理

  • 统一接收前端HTTP请求并路由至对应服务
  • 接口鉴权与访问控制
  • 请求速率限制
  • 跨域资源共享(CORS)处理
  • 请求日志记录
服务层 4

⚙️ 项目管理服务

service

管理项目元数据，提供项目的创建、查询、更新、删除功能

  • 创建、编辑、删除项目
  • 查询项目列表与详情
  • 维护项目与环境的关联关系
  • 项目级别权限校验

⚙️ 环境管理服务

service

管理部署环境的配置信息，包括服务器连接参数与SSH密钥的安全存储

  • 创建、编辑、删除部署环境
  • 安全加密存储SSH私钥
  • 管理服务器地址、端口、用户名等连接参数
  • 环境与项目的关联管理

⚙️ 部署编排服务

service

编排部署流程，接收部署请求、创建部署记录、推送部署任务至消息队列、通过WebSocket推送实时日志

  • 接收并验证部署请求
  • 创建部署记录并持久化
  • 将部署任务发送至消息队列
  • 监听SSH执行代理的回执并更新状态
  • 通过WebSocket向前端推送实时日志
  • 管理版本文件夹命名规则

⚙️ SSH执行代理

service

消费消息队列中的部署任务，通过SSH连接远程服务器执行文件传输和脚本生成

  • 消费消息队列中的部署任务
  • 建立SSH安全连接至远程服务器
  • 在远程服务器创建版本文件夹
  • 传输可执行文件至远程服务器
  • 自动生成并执行启动脚本
  • 回写部署执行状态与日志
数据层 3

🗄️ MySQL

db

关系型数据库，持久化存储项目、环境、部署记录等结构化数据

  • 存储项目元数据
  • 存储环境配置及加密密钥
  • 存储部署历史记录
  • 存储用户账号信息
  • 保证数据一致性与事务支持

⚡ Redis

cache

内存缓存，用于部署实时状态缓存和WebSocket会话管理

  • 缓存部署实时状态
  • 管理WebSocket连接会话
  • 缓存热点配置数据
  • 实现部署状态变更发布订阅

📨 消息队列

mq

异步消息中间件，解耦部署编排服务与SSH执行代理，实现可靠的任务投递

  • 接收并暂存部署任务
  • 可靠投递任务至SSH执行代理
  • 失败重试与死信处理
  • 削峰填谷，平滑处理并发部署请求

数据流

1
项目创建流程
运维人员/项目经理在Web管理控制台填写项目信息并提交→Web管理控制台发送POST请求至API网关→API网关鉴权通过后将请求路由至项目管理服务→项目管理服务校验输入参数→项目管理服务将项目信息写入MySQL→返回创建成功的项目数据至Web管理控制台→Web管理控制台刷新项目列表展示新项目
2
环境配置流程
运维人员在Web管理控制台选择目标项目→进入环境管理页面填写服务器连接参数→Web管理控制台发送POST请求至API网关→API网关路由至环境管理服务→环境管理服务校验参数并存储连接配置至MySQL→运维人员上传SSH私钥→环境管理服务加密私钥后存储至MySQL→返回配置成功结果至Web管理控制台
3
一键部署流程
运维人员在Web管理控制台选择目标环境和部署包→填写版本号并触发部署操作→Web管理控制台发送POST请求至API网关→API网关路由至部署编排服务→部署编排服务创建部署记录写入MySQL→部署编排服务将部署任务发送至消息队列→SSH执行代理消费消息队列中的部署任务→SSH执行代理通过SSH连接远程服务器→在远程服务器创建版本文件夹（以版本号命名）→传输可执行文件至远程服务器→自动生成启动脚本并执行→SSH执行代理实时回写执行日志至消息队列/Redis→部署编排服务通过WebSocket推送日志至Web管理控制台→部署完成后SSH执行代理回写最终状态至MySQL→Web管理控制台展示部署完成状态
4
多项目切换流程
用户在Web管理控制台查看项目列表→Web管理控制台发送GET请求至API网关→API网关路由至项目管理服务→项目管理服务从MySQL查询所有项目列表→返回项目列表至Web管理控制台渲染展示→用户点击目标项目进入详情→Web管理控制台再次请求该项目及其环境列表→项目管理服务与环境管理服务返回关联数据→Web管理控制台切换显示目标项目的内容
