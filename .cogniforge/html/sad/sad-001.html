系统概述

系统定位

SmartDeploy 是一个面向开发者和运维团队的轻量级自动化部署平台，采用前后端分离架构，前端提供友好的 Web 操作界面，后端提供 RESTful API 服务，并负责实际的部署逻辑执行。系统通过项目管理、环境配置、脚本模板、部署执行和历史追踪等模块，实现一键部署和版本回滚。

架构设计

微服务架构
系统采用前后端分离架构，前端为单页应用（SPA），后端拆分为多个职责清晰的微服务，包括管理服务（处理项目、环境、模板、历史等 CRUD 操作）、部署执行服务（负责实际的 SSH 连接、文件上传、脚本生成和执行）、WebSocket 服务（用于实时推送部署日志）。各服务通过 RESTful API 和消息队列进行通信，共享同一个数据库。

数据流

1
部署执行流程
用户在 Web 前端选择项目和环境，上传文件，填写版本号和备注，点击开始部署→前端调用管理服务 POST /api/projects/{project_id}/deployments 接口→管理服务校验参数，存储上传文件到文件存储，创建部署记录（状态为 pending），将任务消息发送到 RabbitMQ→部署执行服务从队列消费任务，获取部署详情，通过 SSH 连接远程服务器→在远程服务器上执行：创建版本目录，上传文件，根据模板生成启停脚本并赋权→如果选择启动，则执行 start.sh→执行过程中实时发送日志到 RabbitMQ，WebSocket 服务消费并推送到前端→部署完成后更新部署记录状态为成功或失败，保存日志
2
回滚流程
用户在历史记录中选择一条成功部署，点击回滚→前端调用管理服务 POST /api/deployments/{deployment_id}/rollback→管理服务根据历史记录找到当时的文件和环境信息，创建新的部署任务（使用原版本号）→后续流程与部署执行流程相同，但会覆盖目标目录
3
项目管理流程
用户通过前端创建/编辑/删除项目→前端调用管理服务相应的 REST API→管理服务更新数据库，前端刷新项目列表→切换项目时，前端存储当前项目 ID，后续请求携带该项目 ID 以获取对应环境、历史等
4
环境管理流程
用户进入某个项目，查看环境列表，新建或编辑环境→前端调用管理服务接口，管理服务将加密后的认证信息存储到数据库→测试连接时，前端调用测试连接接口，管理服务创建临时 SSH 连接验证，返回结果→删除环境时需二次确认，管理服务软删除数据
5
脚本模板管理流程
用户（团队主管）在项目或全局设置中编辑脚本模板→前端提供编辑器，支持语法高亮和变量提示→保存后模板存入数据库→部署执行时，部署执行服务读取模板，根据实际参数替换变量并生成脚本
