系统概述

系统定位

自动部署系统是一个基于 Web 的一键式自动化部署平台，支持用户创建和管理多个项目，每个项目拥有独立的部署环境配置（如测试线、灰度线、正式线）。系统通过 SSH 密钥认证安全连接远程服务器，自动完成可执行文件上传、版本化目录创建、执行脚本生成等部署流程，并提供实时部署状态和日志展示。系统采用前后端分离的微服务架构，通过异步消息队列驱动部署任务执行，确保高可用和可扩展性。

  • 执行连接测试验证配置
  • 触发生成部署并监控状态

架构设计

微服务架构
系统采用前后端分离的微服务架构，整体分为四层：接入层（Web Console）提供用户交互界面；网关层（API Gateway）统一入口、路由和认证；服务层由多个职责单一的服务组成，包括项目管理、环境管理、密钥管理、部署编排、SSH执行和审计服务；数据层包含关系型数据库、缓存、消息队列和文件存储。各服务之间通过 REST API 和消息队列解耦通信，部署任务通过异步消息驱动，支持实时状态推送。

组件设计 (12)

接入层 1

🖥️ Web Console

frontend

单页应用前端，提供项目、环境、密钥管理和部署操作的可视化界面

  • 项目和部署环境的 CRUD 操作界面
  • SSH 密钥上传和管理界面
  • 一键触发部署操作
  • 实时展示部署日志和状态（WebSocket）
  • 多项目切换和导航
网关层 1

🔀 API Gateway

gateway

系统的统一入口网关，负责请求路由、用户认证、限流和日志记录

  • 统一接收所有前端请求并进行路由分发
  • 用户身份认证和会话管理
  • 请求限流和防护
  • 请求日志记录
  • 转发 WebSocket 连接至相应服务
服务层 6

⚙️ Project Management Service

service

管理项目生命周期，提供项目的创建、查询、修改和删除功能

  • 项目的 CRUD 操作
  • 维护项目与环境的关联关系
  • 项目列表查询和搜索

⚙️ Environment Management Service

service

管理部署环境的配置，包括服务器连接参数、环境标识等

  • 部署环境的 CRUD 操作
  • 环境与项目的绑定关系管理
  • 连接配置参数的验证
  • 连接测试能力（委托 SSH Execution Service 执行）

⚙️ Key Management Service

service

负责 SSH 密钥的安全存储、管理和生命周期控制

  • SSH 私钥的加密存储
  • 密钥的上传和删除
  • 密钥与环境的关联管理
  • 为 SSH Execution Service 提供密钥解密接口

⚙️ Deployment Orchestrator

service

部署流程编排引擎，管理部署任务的创建、调度和执行状态跟踪

  • 接收部署请求并创建部署任务
  • 将部署任务拆分为步骤并发布到消息队列
  • 跟踪部署状态和进度
  • 通过 WebSocket 推送实时部署日志
  • 管理版本化目录结构

⚙️ SSH Execution Service

service

远程命令执行服务，通过 SSH 连接到远程服务器并执行部署操作

  • 建立 SSH 连接到远程服务器
  • 执行远程命令（创建目录、传输文件、生成脚本等）
  • 实时回传命令执行日志
  • 处理连接错误和重试逻辑

⚙️ Audit Service

service

记录系统中所有关键操作和变更的审计日志

  • 记录用户操作行为（部署、配置变更等）
  • 持久化审计日志到数据库
  • 提供审计日志查询接口
数据层 4

🗄️ PostgreSQL

database

主数据库，存储项目、环境、密钥元信息、部署记录和审计日志

  • 持久化存储项目和环境配置数据
  • 存储部署记录和审计日志
  • 存储用户账号信息
  • 保证数据一致性和事务完整性

📦 Redis

cache

缓存和会话存储，用于提升系统响应速度和维护实时状态

  • 用户会话存储
  • 部署实时状态缓存
  • WebSocket 连接管理信息
  • 分布式锁（防止部署冲突）

⚡ RabbitMQ

infrastructure

异步消息队列，解耦部署任务的生产和消费

  • 接收部署任务消息
  • 分发任务到 SSH Execution Service
  • 确保任务可靠投递和至少一次消费
  • 支持任务确认和重试

⚡ File Storage

infrastructure

存储用户上传的可执行文件和部署产物

  • 接收和存储上传的可执行文件
  • 为部署任务提供文件下载/传输路径
  • 文件版本管理
  • 存储部署生成的脚本等中间产物

数据流

1
项目创建流程
用户在 Web Console 填写项目信息并提交→API Gateway 接收请求并认证，路由至 Project Management Service→Project Management Service 验证数据并写入 PostgreSQL→返回创建成功结果至 Web Console→Audit Service 记录项目创建操作
2
部署环境配置流程
用户在 Web Console 选择项目并添加部署环境→API Gateway 路由请求至 Environment Management Service→Environment Management Service 验证服务器连接参数→用户上传 SSH 密钥至 Key Management Service，密钥加密存储至 PostgreSQL→密钥 ID 返回并关联到环境配置→用户触发连接测试，Environment Management Service 委托 SSH Execution Service 执行测试→SSH Execution Service 从 Key Management Service 获取解密密钥，建立连接→测试结果实时返回 Web Console
3
一键自动化部署流程
用户上传可执行文件至 File Storage→用户在 Web Console 选择目标环境和版本，点击部署→Deployment Orchestrator 接收部署请求，创建部署记录（状态: pending）→Deployment Orchestrator 向 RabbitMQ 发布部署任务消息→SSH Execution Service 从 MQ 消费部署任务→SSH Execution Service 通过 SSH 连接远程服务器→在远程服务器创建版本化目录结构（如 /deploy/{project}/{env}/{version}/）→从 File Storage 传输可执行文件到远程服务器→在远程服务器生成执行脚本（start.sh/stop.sh/restart.sh 等）→执行启动脚本，验证部署结果→SSH Execution Service 将执行日志实时推送至 Deployment Orchestrator→Deployment Orchestrator 通过 WebSocket 实时推送日志至 Web Console→部署完成，Deployment Orchestrator 更新部署状态为 success/failed→Audit Service 记录部署操作
4
部署状态监控流程
用户打开 Web Console 的部署详情页面→Web Console 通过 REST API 获取部署初始状态→Web Console 建立 WebSocket 连接到 Deployment Orchestrator→Deployment Orchestrator 通过 Redis 获取实时状态并持续推送更新→Web Console 实时渲染部署日志和进度条→部署结束后 WebSocket 连接自动关闭
