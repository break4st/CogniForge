系统概述

系统定位

本平台定位为本地运行的 Web 应用，旨在为开发、运维、发布等角色提供一站式的项目、环境与部署管理工具。用户通过浏览器访问本地服务，完成项目创建、多环境配置、基于 SSH 的自动化部署、版本历史追溯与一键回滚等操作。系统强调安全与溯源，所有 SSH 密钥加密存储且仅在内存中使用，部署过程全程留痕。

架构设计

本地 B/S 架构（前后端分离）
前端负责交互与展示，后端负责业务逻辑、安全代理及持久化，两者通过 RESTful API 通信。接入层基于 React 的单页应用，服务层基于 Python FastAPI，数据层采用 SQLite 与本地文件系统。

组件设计 (11)

接入层 2

🖥️ Web 前端 UI

frontend

提供项目管理、环境配置、部署操作、历史回滚、密钥管理、模板编辑等可视化界面；实时回显部署日志。

  • 渲染用户界面
  • 接收用户输入并调用后端 API
  • 展示实时部署日志（SSE）
  • 管理前端路由与状态

🔀 API 网关/认证

gateway

统一接收前端请求，进行基础请求校验；未来可接入本地 token 认证，当前提供透传功能。

  • 路由转发
  • 基础参数校验
  • (未来) 认证鉴权
服务层 6

⚙️ 项目管理服务

service

负责项目的增删改查、项目间切换上下文逻辑。

  • 创建项目
  • 编辑项目
  • 删除项目（校验关联环境）
  • 查询项目列表
  • 切换当前激活项目

⚙️ 环境配置服务

service

管理每个项目下的多套环境（主机、端口、认证方式、部署路径、环境变量等），提供连接测试。

  • 增删改查环境配置
  • 测试 SSH 连接
  • 管理环境变量键值对
  • 绑定密钥

⚙️ 密钥管理服务

service

支持导入、生成密钥对；使用主密钥加密存储私钥；提供解密接口（仅内存传输）。

  • 导入 SSH 私钥
  • 生成密钥对
  • 加密存储私钥
  • 解密私钥供内部调用
  • 删除密钥

⚙️ 部署执行引擎

service

接收部署请求，按步骤执行 SSH 连接、文件夹创建、文件上传、压缩包解压、脚本生成、钩子执行；实时推送日志。

  • 解析部署请求
  • 协调 SSH 客户端执行步骤
  • 调用脚本模板服务渲染脚本
  • 管理部署流程生命周期
  • 推送实时日志

⚙️ 脚本模板服务

service

管理默认及自定义的启动/停止/检查脚本模板，支持环境变量渲染。

  • 存储和检索模板
  • 渲染模板（注入环境变量、端口等）
  • 模板版本管理

⚙️ 版本历史服务

service

记录每次部署的元信息（版本、环境、时间、状态、校验码）；提供回滚触发逻辑。

  • 记录部署历史
  • 查询部署历史
  • 处理回滚请求
  • 验证目标版本存在性
基础设施层 3

⚡ SSH 客户端模块

infrastructure

封装 SSH 连接、命令执行、文件传输（SFTP）功能，供部署引擎和环境服务调用。

  • 建立 SSH 连接（密钥认证）
  • 执行远程命令
  • SFTP 文件上传/下载
  • 管理连接会话

⚡ 数据库访问层

infrastructure

通过 ORM 提供对 SQLite 的 CRUD 操作，管理项目、环境、部署历史、模板等实体。

  • ORM 实体定义
  • 会话管理
  • 数据查询与持久化
  • 数据库迁移

⚡ 文件存储管理

infrastructure

管理密钥文件、部署包暂存区、模板文件的本地读写。

  • 安全读写加密密钥文件
  • 暂存上传的部署包
  • 清理过期文件
  • 管理模板文件存储

数据流

1
一键自动化部署流程
1. 用户在前端选择项目、环境，上传文件包，填写版本号，点击部署→2. 前端发送 POST /api/deploy 请求→3. API 网关路由到部署执行引擎→4. 部署引擎调用环境配置服务获取目标主机、端口、部署路径及环境变量→5. 部署引擎调用密钥管理服务获取解密后的私钥（内存中）→6. 部署引擎通过 SSH 客户端模块建立远程连接→7. SSH 客户端在远程部署根路径创建以版本号命名的文件夹→8. SSH 客户端通过 SFTP 上传部署文件（若为压缩包则远程解压）→9. 部署引擎调用脚本模板服务渲染启动/停止/检查脚本→10. SSH 客户端将生成的脚本上传至版本文件夹并赋予执行权限→11. 若配置了部署后钩子，SSH 客户端执行钩子命令→12. 各步骤日志通过部署引擎推送至 SSE 频道，前端实时展示→13. 部署完成后，部署引擎调用版本历史服务记录部署详情（版本、环境、MD5、状态等）→14. 前端接收成功/失败状态并展示
2
版本回滚流程
1. 用户在前端查看某环境的历史部署列表→2. 用户点击某条成功记录的“回滚”按钮→3. 前端发送 POST /api/deploy/rollback 请求（携带 deployment_id）→4. 版本历史服务接收请求，验证该部署记录存在且为成功状态→5. 版本历史服务调用 SSH 客户端模块检查远程目标版本文件夹是否存在→6. 若不存在，返回错误提示；若存在，继续→7. 版本历史服务触发部署执行引擎（或直接调用 SSH 客户端）→8. SSH 客户端连接远程，切换到目标版本目录→9. 执行该目录下的 start.sh（或重新渲染并执行）→10. 实时推送操作日志至前端→11. 版本历史服务新增一条历史记录，状态为“回滚成功”，并关联原部署→12. 前端展示回滚结果
