系统概述

系统定位

自动化部署系统实现将打包好的可执行文件自动化部署到指定远程服务器的功能。系统支持用户自定义多套部署环境（测试线、灰度线、正式线），每套环境可通过SSH密钥配置安全连接，部署时自动在远程服务器上创建版本文件夹并生成执行脚本，实现一键式自动化部署。用户可创建和管理多个项目，每个项目拥有独立的部署环境配置，支持在项目间灵活切换，满足多项目并行管理的需求。

架构设计

微服务架构
系统采用微服务架构风格，将业务功能拆分为项目管理、环境管理、密钥管理、部署编排和SSH执行等多个独立服务。各服务通过API网关统一对外暴露接口，服务间通过REST API或消息队列进行异步通信。前端采用Vue 3单页应用，通过WebSocket实现部署进度的实时推送。

组件设计 (11)

接入层 1

🖥️ Web Console

frontend

基于Vue 3和Element Plus的Web管理界面，提供项目管理、环境配置、密钥管理和一键部署等交互功能

  • 提供项目管理界面（创建、编辑、删除、切换项目）
  • 提供部署环境管理界面（创建、编辑、删除环境）
  • 提供SSH密钥管理界面（上传、配置、测试连通性）
  • 提供一键部署操作入口和进度展示
  • 实时接收并展示部署进度和结果
  • 展示操作审计日志
网关层 1

🔀 API Gateway

gateway

统一API入口网关，基于FastAPI构建，负责请求路由、JWT认证鉴权、请求转发和限流

  • 统一路由转发到各微服务
  • JWT Token认证与鉴权
  • 请求速率限制
  • 请求日志记录
  • CORS跨域处理
  • WebSocket连接代理
服务层 6

⚙️ Project Management Service

service

项目管理微服务，负责项目的创建、编辑、删除和查询，维护项目与环境的关联关系

  • 项目的创建、编辑、删除
  • 项目列表查询和详情查看
  • 项目与环境的关联管理
  • 验证项目名称唯一性

⚙️ Environment Management Service

service

环境管理微服务，负责部署环境的创建、编辑、删除和查询，维护环境连接参数

  • 部署环境的创建、编辑、删除
  • 环境类型管理（测试线、灰度线、正式线）
  • 环境连接参数配置（主机地址、端口、用户名等）
  • 环境与项目的关联绑定
  • 环境配置的完整性校验

⚙️ Key Management Service

service

密钥管理微服务，负责SSH密钥的上传、安全存储、配置管理和连通性测试

  • SSH密钥的上传和加密存储
  • 密钥与环境的关联绑定
  • SSH连接连通性测试
  • 密钥的安全加密存储（AES-256）
  • 密钥的删除和轮换
  • 密钥文件的权限管理

⚙️ Deployment Orchestrator

service

部署编排服务，负责部署任务的创建、调度、状态管理，是部署流程的核心调度模块

  • 接收一键部署请求并创建部署任务
  • 通过消息队列异步调度SSH执行服务
  • 管理部署状态（待部署、部署中、成功、失败）
  • 生成版本文件夹路径和执行脚本
  • 通过WebSocket推送实时部署进度
  • 记录和查询部署日志

⚙️ SSH Execution Service

service

SSH执行服务，负责通过Paramiko库建立SSH连接到远程服务器并执行部署操作

  • 根据环境配置建立SSH连接到远程服务器
  • 在远程服务器创建版本文件夹
  • 上传可执行文件到远程服务器
  • 在远程服务器上生成和执行部署脚本
  • 实时回传命令执行日志
  • 处理SSH连接异常和自动重试

⚙️ Audit Service

service

审计日志服务，负责记录系统中所有关键操作的审计日志，支持追溯和排查

  • 记录用户操作日志（增删改查操作）
  • 记录部署操作的全链路日志
  • 记录密钥操作日志（上传、删除、测试）
  • 提供审计日志查询和筛选接口
  • 审计日志的持久化存储和归档
数据层 3

🗄️ Primary Database

db

MySQL 8.0主数据库，存储项目信息、环境配置、密钥元数据、部署记录和审计日志等持久化数据

  • 存储项目信息表
  • 存储部署环境配置表
  • 存储SSH密钥元数据表
  • 存储部署记录和日志表
  • 存储审计日志表
  • 保证数据ACID事务一致性

⚡ Cache

cache

Redis 7.x缓存，用于用户会话管理、部署任务实时状态缓存和热点数据加速

  • 缓存用户JWT会话信息
  • 缓存部署任务实时状态（内存级快速读取）
  • 缓存项目列表和环境配置热点数据
  • 缓存SSH连接测试临时结果

📨 Message Queue

mq

RabbitMQ消息队列，用于异步解耦部署编排服务与SSH执行服务，支持任务可靠投递

  • 异步投递部署任务到SSH执行服务
  • 解耦部署编排和远程执行，提升系统吞吐
  • 保障任务消息不丢失（持久化队列）
  • 支持失败任务的重试机制

数据流

1
项目创建流程
运维人员/项目经理在Web Console填写项目信息表单→Web Console发送POST /api/projects请求到API Gateway→API Gateway验证JWT Token，将请求转发到Project Management Service→Project Management Service校验项目名称唯一性→Project Management Service将项目数据写入Primary Database→Project Management Service返回创建成功响应→API Gateway将响应返回给Web Console→Web Console刷新项目列表展示新项目
2
环境与密钥配置流程
运维人员在Web Console选择项目，进入环境管理页面→Web Console发送POST /api/projects/{id}/environments请求到API Gateway→API Gateway转发请求到Environment Management Service→Environment Management Service将环境配置写入Primary Database→返回成功后，Web Console提示上传SSH密钥→运维人员选择密钥文件并提交到API Gateway→API Gateway转发POST /api/environments/{id}/keys到Key Management Service→Key Management Service对密钥内容进行AES-256加密后存储密钥元数据到Primary Database→密钥存储成功后，Web Console提供连通性测试入口→运维人员点击测试，发送POST /api/environments/{id}/keys/test→Key Management Service从数据库获取密钥，解密后建立SSH连接到目标服务器→返回测试结果（成功/失败、延迟、服务器信息）→Web Console展示测试结果
3
一键部署流程
运维人员在Web Console中选择项目的目标环境和版本号→填写部署信息后点击一键部署按钮→Web Console发送POST /api/projects/{id}/deployments到API Gateway→API Gateway转发到Deployment Orchestrator→Deployment Orchestrator创建部署记录并写入Primary Database（状态：pending）→Deployment Orchestrator将部署任务消息投递到RabbitMQ的deployment.execute队列→Deployment Orchestrator通过WebSocket推送部署状态（pending→running）→SSH Execution Service从RabbitMQ消费部署任务消息→SSH Execution Service通过Key Management Service获取加密密钥并解密→SSH Execution Service建立SSH连接到远程服务器→SSH Execution Service在远程服务器创建版本文件夹→SSH Execution Service上传可执行文件到远程服务器→SSH Execution Service生成并执行部署脚本→SSH Execution Service实时回传执行日志到Deployment Orchestrator→Deployment Orchestrator通过WebSocket推送实时日志到Web Console→SSH执行完成后，SSH Execution Service返回最终结果到消息队列→Deployment Orchestrator更新Primary Database中的部署状态和日志→Deployment Orchestrator通过WebSocket推送部署最终结果（success/failed）→Web Console展示部署结果详情
4
部署进度监控流程
运维人员触发部署后，Web Console自动建立WebSocket连接 /ws/deployments/{id}→Deployment Orchestrator接受WebSocket连接并开始推送消息→运维人员在Web Console实时看到进度百分比和操作日志→部署过程中，各阶段状态通过WebSocket持续推送→部署完成后，WebSocket连接关闭→运维人员可随时通过GET /api/deployments/{id}查询历史部署详情
5
审计日志记录流程
用户通过Web Console执行任何关键操作（创建/编辑/删除项目、环境、密钥、触发部署）→API Gateway将操作信息（操作用户、操作类型、操作对象、时间、IP等）发送到Audit Service→Audit Service将审计记录写入Primary Database的审计日志表→审计日志支持按时间、用户、操作类型等条件筛选查询→运维人员/项目经理可在Web Console查看审计日志
