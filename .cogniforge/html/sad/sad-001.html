系统概述

系统定位

DeployFlow 是轻量级自动化部署平台，采用前后端分离架构。前端为 React SPA，后端基于 FastAPI 提供 RESTful API 与 WebSocket 实时日志。部署任务通过消息队列异步执行，Worker 负责 SSH 连接与文件传输。数据持久化使用 PostgreSQL，Redis 用于缓存与消息传递。私钥等敏感信息经 AES-256 加密存储，确保安全性。

架构设计

前后端分离分层架构 + 异步任务队列
系统分为接入层、服务层、任务执行层和数据层。前端通过 HTTPS 请求 API，WebSocket 接收日志；服务层按业务模块划分，异步任务由 Worker 处理；层间通过 REST、WebSocket、消息队列和 SQL 进行通信。

组件设计 (11)

接入层 2

🖥️ Frontend App

frontend

基于 React 的单页应用，使用 Ant Design 构建界面，提供项目管理、环境配置、部署操作、实时日志展示和历史回滚等交互功能。

  • 渲染所有用户界面
  • 发送 REST API 请求
  • 建立 WebSocket 连接获取实时日志
  • 上传文件

🔀 API Server

gateway

FastAPI 后端入口，统一处理认证、路由转发和 WebSocket 协商，协调各个业务服务模块。

  • 接收前端 HTTP 请求并进行路由分发
  • 管理 WebSocket 连接与认证
  • 协调 Project/Environment/Deployment 等服务
服务层 5

⚙️ Project Service

service

项目业务模块，负责项目的增删改查、名称唯一性校验以及删除时的级联操作。

  • 创建、查询、更新、删除项目
  • 确保项目名称唯一
  • 删除项目时级联删除所属环境与历史

⚙️ Environment Service

service

环境配置模块，管理项目下的环境信息、SSH 认证凭据，提供连接测试功能。

  • 添加、修改、删除环境
  • 上传私钥并加密存储 (AES-256)
  • 测试远程连接并返回详细结果
  • 加密存储密码和 passphrase

⚙️ Deployment Service

service

部署核心服务，接收部署请求，创建部署记录，并将任务推送到消息队列；管理部署历史与回滚。

  • 创建部署任务并保存到数据库
  • 发布任务消息到队列
  • 触发回滚流程
  • 维护部署历史状态

⚙️ Log Service

service

实时日志服务，从消息队列消费 Worker 产生的日志事件，通过 WebSocket 推送给客户端。

  • 订阅日志 Topic
  • 向关联的 WebSocket 连接推送日志
  • 支持日志导出（可选）

⚙️ History Service

service

部署历史查询与回滚触发服务。

  • 按项目或环境查询部署历史列表
  • 触发回滚（调用 Deployment Service）
  • 清理旧版本（可选）
任务执行层 1

⚙️ Deployment Worker

service

独立的工作进程，消费部署任务，执行 SSH 连接、文件传输、脚本生成、软链接更新，并实时发送日志。

  • 从消息队列获取部署任务
  • 通过 SFTP/SCP 上传文件
  • 解压并放置到版本文件夹
  • 生成 start.sh / stop.sh / restart.sh 并赋权
  • 创建或更新 current 软链接
  • 发送实时日志到 Log Service
数据层 3

🗄️ Database

database

PostgreSQL 数据库，存储项目、环境、部署历史、用户（未来）等数据。

  • 持久化所有业务数据
  • 提供 ACID 事务支持
  • 支持按项目隔离查询

⚡ Cache

infrastructure

Redis 实例，同时充当缓存、消息队列和日志广播通道。

  • 缓存会话或频繁查询数据
  • 作为消息队列传输部署任务
  • 作为 PUB/SUB 通道广播日志

⚡ File Storage

infrastructure

本地文件系统目录，用于存储上传的部署包、私钥文件。

  • 保存用户上传的部署文件
  • 保存加密后的私钥文件
  • 提供文件读取给 Worker

数据流

1
部署流程
用户在前端选择项目、环境，上传部署文件，点击部署→前端调用 POST /api/deploy，API Server 接收请求→Deployment Service 创建部署记录（状态 pending），将任务消息（包含文件路径、环境配置）发布到 Redis 队列→Deployment Worker 从队列拉取任务，从 File Storage 读取部署文件→Worker 通过 SSH (SFTP/SCP) 连接到目标服务器，在 deploy_root 下创建版本文件夹并上传文件→Worker 解压文件（若为压缩包），生成 start.sh/stop.sh/restart.sh，并赋予可执行权限→Worker 更新或创建软链接 current 指向新版本文件夹→若配置了自动启动，Worker 执行 start.sh→Worker 实时发送日志（通过 Redis PUB/SUB 到 Log Service，再由 WebSocket 推送给前端）→部署完成后，Worker 更新部署记录状态为 success/failed→前端通过 WebSocket 收到完成通知，并刷新历史列表
2
回滚流程
用户在前端打开部署历史列表，选择一个历史版本，点击回滚→前端调用 POST /api/deployments/{id}/rollback→API Server 路由到 Deployment Service，后者创建回滚任务（类型标记为 rollback）并推送到消息队列→Deployment Worker 消费任务，通过 SSH 连接到目标服务器→Worker 修改 current 软链接指向目标版本文件夹→Worker 执行目标版本文件夹中的 restart.sh 或 start.sh 以重启服务→Worker 发送日志并更新部署历史记录，将当前活跃版本标记为目标版本→前端收到回滚完成通知，界面更新
3
项目切换数据加载
用户在前端顶部切换到另一个项目→前端发送 GET /api/projects/{new_project_id}/environments 获取环境列表→同时发送 GET /api/deployments?project_id={new_project_id} 获取关联的部署历史→前端更新环境选择器和历史记录视图，无需刷新页面
