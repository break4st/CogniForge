系统概述

系统定位

自动化部署系统提供将打包好的可执行文件一键部署到远程服务器的能力。支持多项目并行管理、多套部署环境（测试线、灰度线、正式线）独立配置、SSH密钥安全连接，部署时自动在远程服务器创建版本目录并生成启动/停止脚本，实现全流程自动化。

👤
运维人员
  • 管理部署环境（新增/编辑/删除测试线、灰度线、正式线）
  • 配置和管理SSH安全密钥
  • 选择可执行文件和目标环境触发一键部署
  • 查看部署结果和历史记录
👤
项目经理
  • 创建、编辑和删除项目
  • 为项目关联多套部署环境
  • 在项目间切换查看部署配置和状态
  • 统筹管理多个项目的发布进度
🏗️

架构设计

分层单体架构（初期）+ 模块化演进
采用前后端分离的分层架构。前端为单页应用提供交互界面，后端按业务领域划分为环境管理、项目管理、部署执行、密钥管理、审计日志等模块。各模块通过REST API通信，部署执行引擎通过SSH协议与远程服务器交互。数据层使用关系型数据库存储项目和环境配置，密钥信息加密存储。

组件设计 (16)

表现层 3

🖥️ Web管理控制台

frontend

基于SPA框架的浏览器端管理界面，提供项目、环境、部署等功能的操作面板

  • 提供用户登录和权限管理界面
  • 展示项目列表和环境配置
  • 触发一键部署操作并实时展示进度
  • 管理SSH密钥的增删改

🖥️ 部署状态仪表盘

frontend

展示部署任务的实时状态和运行历史的面板组件

  • 轮询部署任务状态并实时更新界面
  • 展示部署历史记录和详情
  • 高亮展示失败任务和异常信息

🖥️ 项目切换导航

frontend

项目列表切换导航组件，支持在多个项目间快速切换上下文

  • 展示用户有权限的所有项目列表
  • 切换时触发环境配置加载
  • 标识当前选中的活动项目
API网关层 3

🔀 REST API Gateway

gateway

统一的API入口，负责路由分发、身份认证和请求校验

  • 请求路由到对应业务服务
  • JWT令牌校验和用户身份识别
  • 请求参数校验与格式化
  • 跨域和安全性头处理

🔀 认证中间件

gateway

JWT令牌认证中间件，拦截未授权请求并验证访问令牌

  • JWT令牌签发和刷新
  • 令牌有效性校验与过期处理
  • 用户身份注入请求上下文

🔀 请求校验

gateway

请求参数格式校验和数据清洗中间件

  • 请求参数类型和格式校验
  • 请求体Schema验证
  • 防止注入和恶意请求过滤
业务服务层 5

⚙️ 项目管理服务

service

处理项目的CRUD操作以及项目与环境的关系管理

  • 创建、编辑、删除项目
  • 为项目关联/解绑部署环境
  • 查询项目列表和详情
  • 项目切换时加载对应环境数据

⚙️ 环境管理服务

service

管理部署环境的配置，包括连接参数和环境类型

  • 新增、编辑、删除部署环境
  • 管理环境类型标签（测试/灰度/正式）
  • 维护环境与项目的关联关系
  • 验证环境连接可用性

⚙️ 部署执行服务

service

核心部署引擎，负责版本目录创建、文件传输和脚本生成

  • 接收部署请求并创建部署任务
  • 在远程服务器创建带版本号的目录结构
  • 传输可执行文件和配置文件
  • 生成启动脚本和停止脚本
  • 收集部署结果并反馈状态

⚙️ 密钥管理服务

service

SSH密钥的安全存储和管理，包括加密和解密操作

  • SSH密钥的加密存储
  • 密钥的添加、更新和删除
  • 部署时提供解密后的密钥用于连接
  • 密钥访问权限控制

⚙️ 审计日志服务

service

记录所有用户操作和系统事件的审计轨迹

  • 记录部署操作的全过程日志
  • 记录项目和环境的配置变更
  • 记录密钥操作的安全事件
  • 提供日志查询和导出功能
基础设施层 5

⚙️ SSH连接池

service

管理到远程服务器的SSH连接复用，避免频繁建立连接

  • SSH连接的生命周期管理
  • 连接复用和超时回收
  • 断线重连机制
  • 连接健康检查

⚙️ 文件传输模块

service

通过SCP/SFTP协议将可执行文件和配置传输到远程服务器

  • 上传可执行文件到目标目录
  • 传输配置文件和脚本
  • 大文件分片传输支持
  • 传输完整性校验

⚙️ 脚本生成引擎

service

根据部署上下文自动生成远程服务器上的启动和停止脚本

  • 根据应用类型生成启动脚本模板
  • 生成停止脚本
  • 支持自定义脚本扩展
  • 脚本语法校验

🗄️ 关系型数据库

database

存储项目、环境、部署记录等结构化数据

  • 项目数据持久化
  • 环境配置持久化
  • 部署历史记录存储
  • 审计日志存储
  • 加密密钥密文存储

⚡ 缓存

infrastructure

缓存会话信息和频繁读取的配置数据

  • 用户会话状态缓存
  • 项目列表缓存
  • 环境配置缓存
  • 部署任务状态临时存储

数据流

1
一键部署流程
运维人员在Web控制台选择目标项目和部署环境→上传或选择已打包好的可执行文件→系统生成部署版本号并创建部署任务→部署执行服务从密钥管理服务获取该环境的SSH密钥→部署执行服务通过SSH连接池建立到远程服务器的连接→在远程服务器创建版本目录（如 /deploy/{project}/{env}/{version}/）→文件传输模块通过SCP将可执行文件和配置上传到版本目录→脚本生成引擎在远程服务器生成启动和停止脚本→执行启动脚本，应用开始运行→收集启动状态（成功/失败）并记录审计日志→前端轮询部署状态并展示最终结果
2
项目管理流程
项目经理在Web控制台创建新项目→填写项目名称、描述等基本信息→为项目创建或关联部署环境（测试、灰度、正式线）→每个环境配置连接参数和SSH密钥→保存后项目和环境数据写入数据库→后续可在项目列表中选择查看不同项目的部署配置
3
SSH密钥管理流程
运维人员添加SSH密钥，填写密钥名称和密钥内容→密钥管理服务对密钥内容进行加密后存入数据库→加密后的密钥密文存储在数据库中→部署执行时，密钥管理服务解密并临时提供给SSH连接池→部署完成后清除内存中的密钥明文→运维人员可随时更新或删除密钥
