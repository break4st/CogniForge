系统概述

系统定位

自动化部署系统是一个支持多项目、多环境、一键式远程部署的平台。用户可创建多个项目，每个项目独立配置多套部署环境（测试线、灰度线、正式线），通过 SSH 安全连接实现可执行文件的自动化上传、版本目录创建和执行脚本生成，完成自动化部署全流程。系统采用前后端分离的分层架构，以 RESTful API 为核心通信方式，确保各模块高内聚低耦合。

架构设计

分层架构 + 微服务风格
系统采用前后端分离的分层架构，前端为单页应用（SPA），后端划分为多个职责单一的服务模块，通过 API 网关统一接入。服务层内部采用领域驱动设计划分边界，数据存储统一通过数据访问层管理，部署任务通过消息队列异步处理，保证系统可伸缩性和可靠性。

组件设计 (10)

表现层 1

🖥️ Web 管理控制台

frontend

基于 Vue 3 + Element Plus 构建的单页应用，提供项目、环境、部署任务的图形化管理界面。通过 WebSocket 实时展示部署日志和结果反馈。

  • 项目 CRUD 操作界面
  • 部署环境配置管理界面
  • 一键部署操作入口（选择项目/环境/版本文件）
  • 部署日志实时展示（WebSocket）
  • 连接验证触发和结果展示
  • 审计日志检索与展示
网关层 1

🔀 API 网关

gateway

系统统一入口，基于 FastAPI 中间件实现，负责请求路由、JWT 身份认证、RBAC 权限校验、流量控制和跨域处理。

  • 统一认证鉴权（JWT Token 校验与解析）
  • 请求路由转发至对应微服务
  • 基于角色的权限控制（RBAC）
  • 请求限流和超时控制
  • 跨域处理（CORS）
  • 网关层访问日志记录
服务层 5

⚙️ 项目服务

service

项目管理核心服务，维护项目的生命周期和元数据，提供项目维度的权限隔离。

  • 创建/编辑/删除项目
  • 项目列表查询与详情获取
  • 项目与部署环境的关联管理
  • 项目间的数据隔离与权限控制

⚙️ 环境配置服务

service

管理每个项目下的多套部署环境配置，包括连接参数、环境类型（测试/灰度/正式）和环境变量。

  • 环境的创建/编辑/删除
  • 环境类型管理（测试/灰度/正式）
  • 连接参数（主机、端口、用户名）维护
  • 环境变量配置管理
  • 环境与项目的关联维护

⚙️ 密钥管理服务

service

安全管理 SSH 密钥和密码凭据，提供加密存储、密钥注入和连通性验证，确保凭据明文不出库。

  • SSH 密钥对的生成和导入
  • 密码认证凭据管理
  • 密钥和密码的 AES-256 加密存储
  • 连通性验证（预检机制）
  • 部署时的密钥安全注入（临时解密）

⚙️ 部署编排服务

service

自动化部署的核心调度服务，以异步任务方式编排完整部署流程：从消息队列消费部署请求，依次执行文件上传、目录创建、脚本生成、远程执行和结果反馈。

  • 接收和解析部署请求参数（从消息队列消费）
  • 编排部署流程（上传文件 / 创建目录 / 生成脚本 / 执行部署）
  • 通过 SSH 连接远程服务器执行操作
  • 实时的部署进度和日志推送（WebSocket）
  • 部署结果持久化和状态更新（success/failed）
  • 多版本目录管理和清理策略

⚙️ 审计日志服务

service

记录系统中所有关键操作的不可变审计日志，支持操作追溯和合规审查，日志仅允许追加写入。

  • 记录用户操作日志（增删改查操作）
  • 记录部署操作全链路事件
  • 审计日志持久化存储（仅追加写入，不可修改或删除）
  • 多维度检索（按时间/操作类型/用户/项目）
  • 操作时间、操作人、操作内容、结果完整记录
基础设施层 3

🗄️ 关系型数据库

database

PostgreSQL 15+ 存储项目信息、环境配置、部署记录和审计日志等结构化数据。

  • 项目数据持久化（projects 表）
  • 环境配置数据持久化（environments 表）
  • 部署记录持久化（deployments 表）
  • 审计日志持久化（audit_logs 表，仅追加）
  • 密钥元数据存储（keys 表，密文存储）

⚡ 消息队列

infrastructure

RabbitMQ 承载异步部署任务，解耦部署请求发起方与执行方，提升系统响应速度和可靠性。

  • 部署任务异步投递（deploy_tasks 队列）
  • 任务队列消费者负载均衡
  • 部署任务失败重试机制
  • 任务状态的发布与订阅

⚡ 缓存

infrastructure

Redis 7+ 提供会话缓存、项目列表缓存和 WebSocket 连接管理。

  • JWT 黑名单（登出后令牌失效）缓存
  • 项目和环境列表缓存，减少数据库查询
  • WebSocket 连接状态管理
  • 部署进度临时存储

数据流

1
一键部署流程
用户在 Web 控制台选择目标项目和部署环境→用户上传或选择已打包的可执行文件，指定版本号→前端调用 POST /api/v1/projects/{project_id}/environments/{env_id}/deployments 发起部署请求→API 网关校验 JWT Token 和 RBAC 权限，转发至部署编排服务→部署编排服务接收请求，创建部署任务记录（状态: pending），写数据库→部署编排服务将任务消息发布到 RabbitMQ 的 deploy_tasks 队列→部署编排服务立即返回 task_id（HTTP 202）给前端（异步模式）→部署编排服务（消费者）从消息队列取出任务开始执行→调用密钥管理服务获取解密后的 SSH 凭据（临时解密，用完即焚）→通过 SSH 连接到远程目标服务器→在远程服务器创建版本目录（/opt/app/{project}/{version}/）→通过 SFTP/SCP 上传可执行文件到版本目录→基于部署模板生成执行脚本，上传至服务器→设置脚本执行权限（chmod +x）并执行脚本→将部署过程中的每一步日志通过 WebSocket 实时推送给前端→部署完成，更新任务状态为 success/failed→调用审计日志服务写入完整的部署审计记录
2
项目管理流程
用户在 Web 控制台创建项目（填写名称和描述）→请求经 API 网关路由至项目服务→项目服务创建项目记录并持久化到 PostgreSQL→用户进入项目后，可添加多套部署环境（测试/灰度/正式）→环境配置请求经 API 网关路由至环境配置服务→环境配置服务创建环境记录，关联密钥凭据 ID→用户通过连通性验证接口预检环境连接是否正常→用户可随时编辑环境参数或删除不再使用的环境→支持在 Web 控制台的项目选择器灵活切换当前项目上下文
3
安全连接验证流程
用户在密钥管理界面选择凭据类型（SSH 密钥或密码）→SSH 密钥方式：上传私钥或由系统生成密钥对→密码方式：输入远程服务器登录密码→密钥管理服务使用 AES-256 加密凭据后存储（明文不出库）→用户配置环境时关联已注册的凭据 ID→用户可触发连通性验证（POST /api/v1/credentials/{id}/verify）→密钥管理服务使用临时解密凭据建立 SSH 会话→执行预设验证命令（如 uname -a）确认连接正常→返回验证结果和延迟信息给前端展示→部署时部署编排服务通过密钥管理服务获取临时解密凭据
4
审计追溯流程
各个服务在关键操作点调用审计日志服务记录操作→记录内容包括：操作人、操作时间、操作类型、操作对象、请求详情、操作结果→部署操作额外记录：目标环境、部署版本、远程服务器、执行时长、日志摘要→审计日志持久化到 PostgreSQL 的 audit_logs 表（仅追加写入）→审计日志不支持修改或删除，保证日志的不可篡改性→授权用户可通过 Web 管理界面按时间/操作类型/用户等维度检索审计日志
