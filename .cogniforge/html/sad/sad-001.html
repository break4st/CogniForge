系统概述

系统定位

实现将打包好的可执行文件自动化部署到指定远程服务器的功能，支持多环境、多项目管理，通过密钥配置安全连接，自动在远程服务器上创建版本文件夹并生成执行脚本，实现一键式自动化部署。系统采用分层架构，前端通过 API Gateway 统一接入，业务层按领域拆分为项目、部署、环境等微服务，确保各模块职责清晰、可独立扩展。

👤
开发者
  • 一键部署可执行文件到指定环境
  • 查看部署历史与版本记录
  • 在项目间切换查看
👤
运维人员
  • 配置多套部署环境（测试线、灰度线、正式线）
  • 管理 SSH 密钥对与安全连接
  • 查看部署日志与错误详情
👤

  • 创建、编辑、删除项目
  • 为项目分配环境配置
  • 管理项目成员与权限

架构设计

分层架构 + 微服务
系统采用分层架构，自顶向下分为四层：展示层（Web UI）、接入层（API Gateway）、业务层（领域服务）、基础设施层（数据存储与中间件）。各业务服务按领域职责拆分，通过 API Gateway 统一对外暴露 RESTful 接口，服务间通过同步调用或异步消息队列通信。部署执行引擎作为核心服务，负责 SSH 连接、文件传输与远程脚本生成。

组件设计 (10)

展示层 1

🖥️ Web UI

frontend

基于浏览器的人机交互界面，提供项目管理、环境配置、一键部署、部署历史查看等功能

  • 项目列表展示与 CRUD 操作
  • 部署环境配置表单
  • 一键部署触发与进度展示
  • 部署历史与版本查看
  • SSH 密钥管理界面
接入层 1

🔀 API Gateway

gateway

系统统一入口网关，负责请求路由、认证鉴权、限流熔断、请求转发与日志记录

  • 统一接入所有客户端请求
  • 身份认证与权限校验
  • 请求路由到对应业务服务
  • 限流与熔断保护
  • 统一错误处理与日志记录
业务层 5

⚙️ Project Service

service

项目管理领域服务，负责项目的创建、编辑、删除、列表查询以及与部署环境的关系绑定

  • 项目 CRUD 操作
  • 项目与环境关联管理
  • 项目成员权限管理
  • 项目级别的配置隔离

⚙️ Environment Service

service

环境配置管理服务，负责多套部署环境（测试线、灰度线、正式线）的独立配置与 SSH 连接信息管理

  • 部署环境的创建与配置
  • SSH 连接信息（主机、端口、用户）管理
  • 环境级别的密钥绑定管理
  • 环境状态健康检查

⚙️ Deploy Service

service

核心部署编排服务，接收部署请求后协调文件传输、远程执行、版本创建等全流程，支持异步任务处理

  • 接收并校验部署请求
  • 编排完整部署流程
  • 调用 Version Manager 创建版本文件夹
  • 调用 SSH Executor 传输文件与执行脚本
  • 记录部署日志与状态
  • 异步任务进度推送

⚙️ SSH Executor

service

SSH 远程执行引擎，负责建立安全连接、传输文件、执行远程命令，支持密钥认证方式

  • 建立 SSH 安全连接
  • 通过 SCP/SFTP 传输可执行文件
  • 远程创建目录与生成脚本
  • 执行远程部署命令并捕获输出
  • 连接异常处理与重试机制

⚙️ Version Manager

service

版本管理服务，负责自动生成版本标识、在远程服务器创建版本化文件夹并生成部署执行脚本

  • 基于时间戳/语义化生成版本号
  • 在远程服务器创建版本文件夹结构
  • 自动生成 start.sh/stop.sh 等执行脚本
  • 维护版本历史记录与元数据
基础设施层 3

🗄️ Relational Database

db

关系型数据库，持久化存储项目信息、环境配置、密钥元数据、部署记录、版本历史等结构化数据

  • 项目管理数据持久化
  • 环境配置信息存储
  • 部署记录与审计日志存储
  • 版本历史元数据存储

⚡ Cache

cache

缓存中间件，缓存频繁读取的环境配置、SSH 连接信息、部署状态等，降低数据库压力

  • 缓存环境配置与密钥信息
  • 缓存部署进度与状态
  • 缓存项目列表
  • 提升系统响应速度

📨 Message Queue

mq

消息队列，解耦部署请求的提交与执行，支持异步任务处理与状态通知

  • 异步部署任务队列
  • 部署状态变更通知
  • 服务间异步事件通信
  • 削峰填谷，避免突发部署请求压垮系统

数据流

1
一键部署流程
开发者通过 Web UI 选择项目、目标环境和可执行文件，点击部署→Web UI 调用 API Gateway 的 POST /api/v1/deploy 发起部署请求→API Gateway 鉴权后转发请求到 Deploy Service→Deploy Service 校验请求参数，生成部署任务 ID，将任务推入 Message Queue→Deploy Service 返回部署任务 ID 给前端，前端开始轮询状态→Deploy Service 从 Message Queue 消费部署任务→Deploy Service 调用 Environment Service 获取目标环境的 SSH 连接配置→Deploy Service 调用 Version Manager 生成版本号并在远程创建版本文件夹及脚本→Deploy Service 调用 SSH Executor 上传可执行文件到远程版本文件夹→SSH Executor 通过 SSH 连接执行远程部署脚本（启动服务）→SSH Executor 返回执行结果与日志给 Deploy Service→Deploy Service 更新部署记录状态并持久化到 Database→Deploy Service 通过消息队列/WebSocket 推送最终部署结果给 Web UI→开发者在 Web UI 上查看部署结果与日志
2
环境配置流程
运维人员通过 Web UI 进入环境管理页面→运维人员填写环境名称、类型（测试线/灰度线/正式线）、SSH 连接信息→运维人员上传或选择已配置的 SSH 密钥→Web UI 调用 API Gateway 的 POST /api/v1/environments→Environment Service 保存环境配置到 Database，并更新 Cache→Environment Service 执行 SSH 连接测试，验证配置有效性→运维人员收到环境创建成功通知
3
项目管理流程
项目经理通过 Web UI 创建新项目，填写项目名称与描述→项目经理为项目关联已配置的部署环境→Web UI 调用 API Gateway 的 POST /api/v1/projects→Project Service 将项目信息持久化到 Database→开发者可在项目列表中选择该项目进行部署操作
4
版本回滚流程
开发者在 Web UI 查看部署历史与版本列表→开发者选择某个历史版本，点击回滚→Web UI 调用 API Gateway 的 POST /api/v1/deploy/rollback→Deploy Service 查询该版本的部署元数据与文件路径→Deploy Service 调用 SSH Executor 在远程服务器停止当前服务→Deploy Service 调用 SSH Executor 重新执行指定版本的启动脚本→部署成功后在 Database 中记录回滚操作与当前活跃版本
