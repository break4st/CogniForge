系统概述

学生管理系统是一套面向 K12 学校的综合管理平台，覆盖学生信息、班级、年级的全生命周期管理以及学习统计与分析。系统采用前后端分离的微服务架构，通过 API 网关统一接入，各业务领域拆分为独立服务，支撑教务管理员、班主任、教师、校长及家长/学生等多角色的使用场景。

🏗️

架构设计

系统采用微服务架构风格，前端为单页应用（SPA），后端按业务领域拆分为学生服务、班级服务、年级服务、统计服务四个独立微服务，服务间通过 HTTP/REST 进行同步通信，通过消息队列进行异步解耦。统一由 API Gateway 负责路由、鉴权与限流。数据层采用关系型数据库作为主存储，Redis 作为缓存加速，各服务持有独立的数据库 schema 或专用表空间以保障领域隔离。

组件设计 (9)

Web UI

service

基于现代前端框架构建的单页应用，提供学生管理、班级管理、年级管理、统计看板等可视化界面，面向教务管理员、教师、班主任、校长及家长等不同角色提供差异化视图。

  • 提供学生信息增删改查操作界面
  • 提供班级与年级管理界面
  • 提供学习统计看板与趋势图表
  • 支持按角色权限动态展示功能菜单
  • 通过 API Gateway 与后端服务通信

API Gateway

service

系统的统一入口，负责请求路由、身份认证、权限校验、流量控制与请求日志记录。所有客户端请求必须经过 API Gateway 才能访问后端微服务。

  • 统一接入所有客户端请求并进行路由分发
  • 基于 JWT 进行用户身份认证与角色鉴权
  • 请求限流与熔断保护后端服务
  • 请求/响应日志记录与审计
  • 跨域处理与协议适配

Student Service

service

负责学生领域核心业务，管理学生从入学到毕业全生命周期的信息维护，包括基本信息管理、学号唯一性校验、学生检索以及数据的导入导出。

  • 学生基本信息的增删改查
  • 学号唯一性校验与管理
  • 支持按姓名、学号、年级等条件组合查询学生
  • 学生信息的批量导入与导出
  • 学生与班级、年级的关联关系维护

Class Service

service

负责班级领域业务，管理班级的新建、调整与解散，维护班级-年级层级关系，支持班主任指派与班级学生名单查询。

  • 班级信息的增删改查
  • 班级与年级的归属关系管理
  • 班主任的指派与更换
  • 班级学生名单查询
  • 班级数量统计与容量管理

Grade Service

service

负责年级领域业务，管理年级的新建、配置与学段分类，维护年级与班级的层级结构，支持按学年维度组织和查询。

  • 年级信息的增删改查
  • 年级按学段（小学/初中/高中）和学年管理
  • 年级与班级的层级关联维护
  • 年级内班级数量统计
  • 年级配置信息查询

Statistics Service

service

负责学习数据的采集、聚合与分析，提供多维度统计报表与趋势分析，支持异步计算大批量统计数据，保证统计结果的实时性。

  • 按学生、班级、年级维度聚合统计数据
  • 学习成绩分布分析与趋势图表数据生成
  • 出勤率统计
  • 统计报表数据导出
  • 异步消费消息队列事件更新统计结果

Relational Database

db

系统主存储，采用 MySQL/PostgreSQL 关系型数据库，按服务拆分 schema 或使用独立数据库实例，存储学生、班级、年级、用户及统计等持久化数据。

  • 持久化存储学生、班级、年级等核心业务数据
  • 保障数据的 ACID 事务特性
  • 支持复杂查询与多维度聚合查询
  • 按业务领域进行逻辑或物理隔离
  • 数据备份与恢复

Cache

cache

基于 Redis 的分布式缓存层，用于缓存热点查询数据与频繁访问的配置信息，降低数据库读压力，提升接口响应速度。

  • 缓存学生信息热点查询结果
  • 缓存班级与年级配置信息
  • 缓存统计中间结果提升聚合效率
  • 实现分布式锁保障关键操作的互斥
  • 管理会话状态与临时数据

Message Queue

mq

基于消息队列的异步通信层，用于服务间的异步事件通知与解耦，特别适用于统计数据的异步汇总计算场景。

  • 学生数据变更事件的通知与广播
  • 异步触发统计数据计算任务
  • 削峰填谷避免统计服务突发压力
  • 保障消息的可靠投递与至少一次语义
  • 服务间解耦与事件驱动编排

拓扑结构

系统部署采用分层拓扑结构。最外层为负载均衡层，将用户请求分发到 API Gateway 集群。第二层为 API Gateway 集群，负责认证鉴权后将请求路由到内网的各业务微服务实例。第三层为微服务层，包含 Student Service、Class Service、Grade Service、Statistics Service，各服务均以多实例方式部署以实现高可用。第四层为数据层，包含关系型数据库主从集群、Redis 缓存集群和消息队列集群。Web UI 通过 CDN 或反向代理对外提供服务。所有微服务实例部署在同一 Kubernetes 集群内，通过服务发现进行内部通信。

📊

数据流

1）用户通过浏览器访问 Web UI，Web UI 发起 HTTP 请求至 API Gateway。2）API Gateway 验证 JWT Token 中的用户身份与角色，按路由规则将请求转发至对应的微服务。3）微服务首先查询 Redis 缓存，若命中则直接返回；若未命中则查询关系型数据库，并将结果回写缓存后返回。4）对于涉及统计数据变更的操作（如成绩录入），Student/Class Service 发送事件消息到 Message Queue。5）Statistics Service 异步消费消息队列中的事件，进行统计聚合计算后更新到数据库，并将结果缓存至 Redis。6）用户查询统计时，Statistics Service 直接从缓存或数据库返回聚合数据。7）跨服务的数据关联查询（如按年级查学生列表），通过服务间 HTTP 调用协同完成。
