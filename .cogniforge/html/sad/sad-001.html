系统概述

系统定位

自动化部署管理系统是一个基于Web的企业级部署平台，支持将打包好的可执行文件自动化部署到指定远程服务器。系统采用前后端分离的BFF架构模式，后端以服务化方式组织业务逻辑，通过SSH协议与远程服务器安全通信。支持多项目管理、多环境配置（测试线、灰度线、正式线）、SSH密钥安全认证、版本自动管理与执行脚本生成，实现一键式自动化部署全流程。

架构设计

分层架构 + BFF模式 + 服务化后端
系统采用前后端分离架构，前端为单页应用（SPA），后端通过BFF层为前端提供聚合接口。核心业务逻辑划分为多个职责单一的服务模块，通过依赖注入和事件驱动方式协作。与远程服务器的通信通过SSH连接池统一管理，确保连接复用和资源控制。密钥等敏感信息通过独立的密钥管理服务进行加解密存储，数据层使用PostgreSQL持久化业务数据与文件制品。

组件设计 (10)

展示层 1

🖥️ Web控制台

frontend

基于React的浏览器端单页应用，提供项目、环境、部署全流程的可视化操作界面

  • 项目CRUD操作界面和项目切换
  • 多环境配置管理界面（增删改查）
  • SSH密钥上传和管理界面
  • 部署操作入口（选择环境 + 版本 -> 执行部署）
  • 部署进度实时展示和结果通知
  • 已部署版本列表和历史查看
网关层 1

🔀 API网关

gateway

系统的统一入口网关，负责请求路由、身份认证、权限校验和请求限流

  • 前端请求的路由分发
  • 用户身份认证与会话管理
  • 基于角色的接口访问控制（RBAC）
  • 请求速率限制和防滥用
  • WebSocket连接管理
业务服务层 5

⚙️ 项目管理服务

service

管理系统的核心业务实体——项目，包括项目创建、配置、状态管理和项目间切换

  • 项目的创建、更新、删除和查询
  • 项目配置的读写（项目级设置）
  • 项目与环境的关联管理
  • 项目间切换的数据隔离

⚙️ 环境管理服务

service

管理部署环境的配置，包括连接参数、关联密钥和状态检测

  • 部署环境的CRUD操作
  • 环境连接参数配置（主机、端口、用户等）
  • 环境与SSH密钥的绑定管理
  • 环境连接测试（连通性检测）

⚙️ 部署编排服务

service

部署任务的核心编排引擎，负责执行部署的完整工作流：传输文件 -> 创建目录 -> 生成脚本 -> 执行命令

  • 接收并校验部署请求
  • 协调部署工作流中各步骤的执行
  • 在远程服务器创建版本目录结构
  • 通过SSH传输可执行文件到远程服务器
  • 在远程服务器生成启动/停止等执行脚本
  • 收集并返回部署执行结果和日志
  • 记录部署历史用于版本追溯

⚙️ SSH连接池服务

service

管理到远程服务器的SSH连接，提供连接复用、健康检测和并发控制

  • SSH连接的创建、复用和回收
  • 连接池大小控制和资源管理
  • SSH连接健康心跳检测
  • 断线自动重连机制
  • 并发连接数限制

⚙️ 密钥管理服务

service

SSH密钥的加密存储、生命周期管理和安全审计

  • SSH密钥的AES-256加密存储
  • 密钥的上传、更新、吊销和删除
  • 密钥与环境的绑定关系管理
  • 密钥使用审计日志
  • 密钥格式校验和指纹计算
数据层 2

🗄️ PostgreSQL数据库

database

系统的主数据库，存储项目、环境、部署记录、密钥等所有结构化业务数据

  • 项目、环境、密钥等实体数据的持久化
  • 部署历史记录和日志的存储
  • 事务性数据的一致性和完整性保障
  • 历史数据的查询和归档支持

⚡ 文件存储

infrastructure

管理部署所需的可执行文件的存储和版本化

  • 可执行文件的上传和下载
  • 文件版本管理（同一文件多版本共存）
  • 文件的完整性校验（MD5/SHA256）
远程执行层 1

⚡ 目标远程服务器集群

infrastructure

由多台远程Linux服务器组成的集群，是部署任务最终的执行目标

  • 接收SSH/SCP/SFTP连接请求
  • 接收可执行文件并持久化到文件系统
  • 执行启动/停止/状态检查脚本
  • 返回命令执行结果和日志输出

数据流

1
一键部署流程
用户通过Web控制台选择目标项目和部署环境，选择要部署的版本→前端发送部署请求到API网关，网关鉴权后路由到部署编排服务→部署编排服务接收请求，创建部署任务记录并返回任务ID→部署编排服务通过SSH连接池服务获取目标服务器的SSH连接→SSH连接池服务从密钥管理服务获取解密后的私钥，建立SSH连接→SSH连接池返回可用连接句柄给部署编排服务→部署编排服务在远程服务器创建版本目录（如 /app/{project}/{env}/v{version}/）→部署编排服务通过SCP/SFTP将可执行文件传输到远程服务器的版本目录→部署编排服务在远程服务器生成启动脚本(start.sh)、停止脚本(stop.sh)、状态检查脚本(health.sh)→部署编排服务执行启动脚本，开始运行部署的程序→部署编排服务通过WebSocket向前端实时推送各步骤的状态和日志→部署编排服务将部署结果（成功/失败、日志、耗时等）持久化到数据库→前端收到最终结果，展示部署成功或失败详情
2
SSH密钥配置流程
安全管理员通过Web控制台上传SSH公钥或私钥文件→前端将密钥文件发送到API网关，网关路由到密钥管理服务→密钥管理服务对密钥进行格式校验和指纹计算→密钥管理服务使用AES-256对密钥内容进行加密→加密后的密钥密文存入PostgreSQL数据库，元数据（指纹、算法、创建时间）明文存储→安全管理员在环境管理界面将密钥绑定到指定环境→环境管理服务更新环境的密钥绑定关系，持久化到数据库
3
多环境配置管理流程
项目经理通过Web控制台为指定项目创建新的部署环境→前端发送创建环境请求到API网关，网关鉴权后路由到环境管理服务→环境管理服务调用SSH连接池服务进行连接测试，验证参数有效性→连接测试通过后，环境管理服务将环境配置持久化到PostgreSQL数据库→新创建的环境在项目环境列表中可见→支持对环境参数进行编辑修改或删除
4
版本回溯与回滚流程
用户通过Web控制台查看指定项目的已部署版本列表→部署编排服务从数据库中查询该项目的所有部署历史记录→用户选择目标回滚版本，发起回滚操作→部署编排服务启动回滚部署任务（重新传输指定版本的文件并部署）→回滚完成后更新部署历史，记录回滚操作→用户在Web控制台确认回滚后的版本运行状态
5
可执行文件上传流程
开发人员通过Web控制台选择目标项目，上传可执行文件并指定版本号→前端通过multipart/form-data将文件发送到API网关，网关路由到文件存储→文件存储对上传的文件进行完整性校验（SHA256）→文件存储将文件持久化到磁盘或对象存储，版本号与文件关联记录到数据库→上传成功后返回文件ID和版本信息给前端→后续部署操作可从已上传的文件版本中选择目标版本
