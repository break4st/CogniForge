系统概述

系统定位

实现将打包好的可执行文件自动化部署到指定远程服务器的功能。支持用户自定义多套部署环境（如测试线、灰度线、正式线），每套环境可通过密钥配置安全连接，部署时自动在远程服务器上创建版本文件夹并生成执行脚本，实现一键式自动化部署。用户可创建和管理多个项目，每个项目拥有独立的部署环境配置，支持在项目间灵活切换，满足多项目并行管理的需求。

架构设计

前后端分离分层架构
系统采用前后端分离架构，前端提供 Web 管理控制台，后端按业务领域划分为项目管理、环境配置、部署编排、密钥管理、审计日志等独立服务模块。通过 API 网关统一路由和鉴权，部署任务通过消息队列异步处理以提升响应速度，密钥凭据加密存储保障安全性。

组件设计 (10)

表现层 1

🖥️ Web 管理控制台

frontend

提供项目、环境、部署任务的图形化管理界面

  • 项目 CRUD 操作界面
  • 部署环境配置管理界面
  • 一键部署操作入口
  • 部署日志和结果实时展示
  • 连接验证触发和结果展示
  • 审计日志检索展示
网关层 1

🔀 API 网关

gateway

系统统一入口，负责请求路由、认证鉴权、流量控制

  • JWT 身份认证和 RBAC 权限校验
  • 请求路由转发至对应微服务
  • 请求限流和超时控制
  • 跨域处理（CORS）
  • 网关层访问日志记录
服务层 5

⚙️ 项目服务

service

管理项目生命周期和元数据，提供项目维度隔离

  • 创建/编辑/删除项目
  • 项目列表查询与详情获取
  • 项目与部署环境关联管理
  • 项目间数据隔离与权限控制

⚙️ 环境配置服务

service

管理每套部署环境的连接参数和配置信息

  • 环境创建/编辑/删除
  • 环境类型管理（测试/灰度/正式）
  • 连接参数（主机、端口、用户名）维护
  • 环境变量配置管理
  • 环境与项目和凭据的关联维护

⚙️ 部署编排服务

service

自动化部署核心调度，编排完整部署流程

  • 从消息队列消费部署请求
  • 编排部署流程（上传文件/创建目录/生成脚本/执行）
  • 通过 SSH 连接远程服务器执行操作
  • 实时推送部署进度和日志（WebSocket）
  • 部署结果持久化和状态更新

⚙️ 密钥管理服务

service

安全管理 SSH 密钥和密码凭据

  • SSH 密钥对生成和导入
  • 密码认证凭据管理
  • 凭据的 AES-256 加密存储
  • 连通性验证（预检机制）
  • 部署时密钥安全注入（临时解密）

⚙️ 审计日志服务

service

记录所有关键操作的不可变审计日志

  • 记录用户操作日志
  • 记录部署全链路事件
  • 审计日志持久化（仅追加，不可修改删除）
  • 多维度检索（时间/操作类型/用户/项目）
基础设施层 3

🗄️ 关系型数据库

database

存储项目、环境、部署记录、审计日志等结构化数据

  • 项目数据持久化
  • 环境配置数据持久化
  • 部署记录持久化
  • 审计日志持久化（仅追加）
  • 密钥元数据存储（密文）

⚡ 消息队列

infrastructure

承载异步部署任务，解耦请求发起方与执行方

  • 部署任务异步投递
  • 任务消费者负载均衡
  • 任务失败重试机制

⚡ 缓存

infrastructure

提供会话缓存和临时状态存储

  • JWT 黑名单缓存
  • 项目和环境列表缓存
  • WebSocket 连接状态管理
  • 部署进度临时存储

数据流

1
一键部署流程
用户在前端选择项目和环境，上传可执行文件并指定版本号→前端调用部署触发 API，请求经 API 网关路由至部署编排服务→部署编排服务创建部署任务记录（status: pending），写入数据库→部署编排服务将任务消息发布到消息队列，立即返回 task_id（HTTP 202）→消费者从消息队列取出任务开始执行→调用密钥管理服务获取解密后的 SSH 凭据→通过 SSH 连接到远程目标服务器→在远程服务器创建版本目录（如 /opt/app/{project}/{version}/）→通过 SFTP 上传可执行文件到版本目录→基于模板生成部署执行脚本并上传至服务器→设置执行权限并运行脚本→每一步日志通过 WebSocket 实时推送给前端→部署完成更新状态为 success/failed→调用审计日志服务写入完整审计记录
2
项目管理与多环境配置流程
用户创建项目（名称和描述），请求经网关路由至项目服务→项目服务创建项目记录持久化到数据库→用户在项目下添加多套部署环境（测试/灰度/正式）→环境配置服务创建环境记录，关联凭据 ID→用户通过连通性验证接口预检环境连接状态→用户可在项目选择器间灵活切换上下文
3
安全凭据管理流程
用户选择凭据类型（SSH 密钥或密码）→SSH 密钥: 上传私钥内容或系统生成密钥对→密码: 输入远程服务器登录密码→密钥管理服务使用 AES-256 加密凭据后存储（明文不出库）→用户配置环境时关联已注册凭据→验证连通性时服务临时解密建立 SSH 会话执行预检命令→部署时编排服务通过密钥管理服务获取临时解密凭据
4
审计追溯流程
各服务在关键操作点调用审计日志服务记录操作→记录: 操作人、时间、类型、对象、请求详情、结果→部署操作额外记录: 目标环境、版本、服务器、执行时长→审计日志追加写入数据库（不可修改或删除）→授权用户通过管理界面按多维条件检索审计日志
