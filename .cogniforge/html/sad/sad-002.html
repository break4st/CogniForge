系统概述

系统定位

一键自动化部署系统是一个基于 Web 的部署管理平台，采用前后端分离的分层微服务架构。核心能力包括：多项目独立管理与灵活切换、多套部署环境（测试/灰度/正式）自定义配置、SSH 密钥安全连接、一键式自动化部署编排、部署过程实时可视化与日志推送、部署历史追溯与版本回滚。系统通过 API 网关统一接入和认证，长时部署任务通过消息队列异步解耦，SSH 执行引擎负责远程服务器操作，全操作审计日志确保可追溯性。架构遵循最小权限原则，各服务无状态设计支持独立水平扩展。

架构设计

分层微服务架构
系统采用严格的分层微服务架构，从上到下分为五层：展示层（Web 控制台 SPA）→ 网关层（API 网关统一路由、认证、限流、跨域）→ 服务层（六个领域服务 + 一个回滚管理服务，各自承担单一职责）→ 数据层（PostgreSQL 持久化、Redis 缓存与实时状态、RabbitMQ 异步消息）→ 外部集成层（SSH 协议连接远程服务器）。服务间同步通信采用 RESTful API，长时部署任务通过消息队列异步编排实现削峰填谷和任务解耦。部署进度通过 SSE（Server-Sent Events）实现前端实时推送，避免轮询开销。

组件设计 (13)

展示层 1

🖥️ Web Console

frontend

基于 React 18 + Ant Design 5.x 的单页应用，提供完整的用户操作界面和部署可视化体验

  • 项目列表展示与 CRUD 操作界面
  • 部署环境配置表单与 SSH 密钥管理界面
  • 一键部署触发按钮与进度可视化（进度条 + 实时日志流）
  • 部署历史记录查看与版本回滚操作
  • 审计日志查询与导出
  • 多项目间快速切换导航
网关层 1

🔀 API Gateway

gateway

基于 Nginx + OpenResty 的统一入口网关，负责请求路由转发、身份认证、限流和 SSE 连接管理

  • 统一路由转发至各微服务
  • JWT 请求身份认证与会话校验
  • API 限流与防滥用
  • SSE 连接代理与长连接管理
  • 跨域策略（CORS）管理
  • 请求响应日志记录
服务层 7

⚙️ Project Management Service

service

管理项目生命周期的领域服务，每个项目拥有独立的环境配置和部署历史

  • 项目的创建、编辑、删除、查询
  • 项目与环境的关系绑定与管理
  • 项目级别的配置参数管理
  • 项目列表分页和搜索

⚙️ Environment Management Service

service

管理部署环境配置的领域服务，负责环境参数管理与连接测试

  • 环境的创建、编辑、删除、查询
  • 环境连接参数（主机、端口、用户名、标签）管理
  • SSH 密钥与环境的绑定关系管理
  • 触发环境连接测试并返回结果

⚙️ Key Management Service

service

SSH 密钥安全管理的专用服务，负责密钥的加密存储、解密使用和访问控制

  • SSH 私钥的导入、验证和 AES-256 加密存储
  • 按需解密并提供 SSH 连接使用的密钥
  • 密钥访问权限控制（按项目隔离）
  • 密钥指纹计算与展示
  • 支持密钥轮换

⚙️ SSH Execution Service

service

核心执行引擎，通过 SSH-2 协议在远程服务器上执行命令、传输文件、生成管理脚本

  • SSH 会话建立与密钥认证
  • 远程目录创建（带版本标识的部署目录）
  • 可执行文件上传传输
  • 远程管理脚本生成（启动/停止/重启/状态检查）与执行
  • 命令执行结果收集、解析与返回
  • 执行进度实时发布到消息队列

⚙️ Deployment Orchestrator

service

部署流程的编排引擎，负责任务接收、状态管理、步骤编排和进度分发

  • 部署任务接收、校验与状态管理
  • 部署步骤编排与执行调度
  • 通过 RabbitMQ 异步下发执行任务
  • 消费进度消息并更新实时状态（Redis + DB）
  • 部署结果汇总与通知
  • 部署历史记录持久化维护

⚙️ Rollback Manager

service

版本回滚管理服务，负责回滚操作编排和历史版本管理

  • 查询指定部署的历史版本列表
  • 回滚操作请求接收与校验
  • 回滚步骤编排（备份当前版本 → 恢复目标版本 → 验证）
  • 回滚过程中的进度跟踪与推送
  • 回滚操作记录审计

⚙️ Audit Service

service

全操作审计日志服务，记录所有关键操作事件，支持查询和导出

  • 记录项目创建、修改、删除操作
  • 记录环境配置变更
  • 记录 SSH 密钥导入和使用
  • 记录每次部署请求与结果
  • 记录回滚操作
  • 审计日志持久化存储、查询与导出
数据层 3

🗄️ Primary Database

database

PostgreSQL 15 关系型数据库，存储系统全部持久化数据

  • 项目数据的持久化存储（projects 表）
  • 环境配置数据的持久化（environments 表）
  • SSH 密钥密文存储（keys 表）
  • 部署历史记录存储（deployments 表）
  • 版本快照记录存储（deployment_snapshots 表）
  • 审计日志存储（audit_logs 表）
  • 数据完整性与一致性保障

📦 Redis

cache

Redis 7 内存缓存，加速数据访问和实时状态追踪

  • 用户会话缓存与分布式 session
  • 部署任务实时状态缓存（status + progress + logs）
  • 环境连接测试结果缓存
  • 配置缓存降低数据库查询压力

📦 RabbitMQ

mq

RabbitMQ 3.12 消息队列，用于解耦部署请求与执行，支持异步事件驱动

  • 部署任务消息异步投递（deploy.tasks 交换机）
  • 部署进度状态变更通知分发（deploy.progress 交换机）
  • 回滚任务异步投递（rollback.tasks 交换机）
  • 服务间事件驱动通信
  • 削峰填谷，平滑处理并发部署高峰
外部集成层 1

⚙️ Remote Servers

service

外部远程 Linux 服务器，承载部署目标环境，通过 SSH-2 协议接入

  • 提供 SSH 可访问的远程执行环境
  • 接收部署文件并存储到版本目录
  • 执行部署管理脚本（启动/停止/重启）
  • 返回命令执行结果与退出码

📊

数据流

1
项目管理流程
用户通过 Web Console 填写项目表单（名称、描述、标签）→Web Console 调用 POST /api/v1/projects 经 API Gateway 转发→API Gateway 校验 JWT 身份认证→Gateway 转发请求到 Project Management Service→Project Management Service 校验项目参数合法性→写入 Primary Database projects 表持久化→发送审计事件到 Audit Service (/internal/audit/log)→返回 201 创建结果经 Gateway 到前端展示
2
环境配置与密钥导入流程
用户在 Web Console 选择目标项目，进入环境管理页面→填写环境参数或导入 SSH 私钥→导入密钥：调用 POST /api/v1/keys/import 经 Gateway 到 Key Management Service→Key Management Service 验证密钥格式，计算指纹→密钥 AES-256 加密后存入 Primary Database keys 表→返回 key_id 给 Environment Management Service 绑定环境→创建环境：调用 POST /api/v1/projects/{id}/environments 写入 DB→用户点击「测试连接」→ Environment Management Service 调用 SSH Execution Service 执行探测命令→连接测试结果经 Gateway 返回前端展示
3
一键部署流程
用户在 Web Console 选择项目、目标环境和可执行文件（拖拽/选择上传）→Web Console 将文件编码为 base64，调用 POST /api/v1/projects/{id}/deploy→API Gateway 认证后转发到 Deployment Orchestrator→Orchestrator 创建部署记录写入数据库，状态 pending→Orchestrator 发布任务消息到 RabbitMQ deploy.tasks 交换机→Orchestrator 将部署 ID 和状态写入 Redis 缓存→Web Console 建立 SSE 连接 GET /api/v1/deployments/{id}/stream 监听实时推送→SSH Execution Service 消费队列消息，开始执行部署→在远程服务器创建版本目录 /opt/deploy/{project}/{version}/→上传可执行文件到远程服务器→生成启动/停止/重启/状态检查脚本并传输→执行部署脚本（启动服务），收集输出和退出码→每完成一步，SSH Execution Service 通过 deploy.progress 交换机发布进度消息→Orchestrator 消费进度消息，更新 Redis 实时状态和数据库记录→Orchestrator 通过 SSE push 进度给 Web Console→部署完成，前端展示成功/失败结果和完整日志
4
部署历史查看与回滚流程
用户在 Web Console 进入项目部署历史页面→Web Console 调用 GET /api/v1/projects/{id}/deployments 分页查询历史记录→历史列表展示每次部署的时间、环境、版本号、状态→用户选择一条历史记录查看详情（日志、文件清单等）→用户点击「回滚到此版本」确认回滚操作→Web Console 调用 POST /api/v1/projects/{id}/rollback 提交回滚请求→API Gateway 认证后转发到 Rollback Manager→Rollback Manager 创建回滚记录写入数据库，状态 pending→Rollback Manager 发布回滚任务到 RabbitMQ rollback.tasks 交换机→SSH Execution Service 消费回滚消息→在远程服务器备份当前版本目录→将目标历史版本的部署文件恢复到部署目录→执行服务重启脚本验证恢复状态→回滚进度通过 SSE 实时推送到前端→回滚完成，更新数据库记录和审计日志
5
审计日志记录流程
各微服务在执行关键操作时构建标准化审计事件→调用 Audit Service 的 POST /internal/audit/log 接口→Audit Service 校验事件格式，补充时间戳和来源标识→审计日志写入 Primary Database audit_logs 表→审计日志通过 Web Console 管理界面查询和导出
